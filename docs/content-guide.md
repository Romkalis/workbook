# Как писать уроки

Формат файлов описан в [AGENTS.md](../AGENTS.md). Ниже практические приёмы.

## Порядок работы

1. Сначала соберите материал: прочитайте все источники модуля, запустите примеры кода, снимите свои скриншоты, если картинки из статей использовать нельзя.
2. Набросайте оглавление раздела: `h2` для раздела, `h3` с уникальным `id` для подтем. По ним строятся оглавление и поиск.
3. Пишите своими словами. Если в источнике ошибка или он устарел, скажите об этом в тексте.
4. Добавьте схемы там, где процесс легче показать, чем описать. Текст при этом остаётся.
5. В конце: вопросы для самопроверки (`details.q`), глоссарий, источники и `quiz.json`.

## Структура типичного урока

`intro` (о модуле, чему научитесь) → темы → `practice` (практика и тест на платформе) → `checklist` (типичные ошибки) → `questions` → `glossary` → тест (автоматически) → `sources`.

## id и ссылки

Идентификаторы латиницей через дефис: `reflow-repaint`. Они становятся якорями `/lessons/<slug>#id`, по ним же ведёт поиск, поэтому после публикации их лучше не менять.

## Чек-лист перед коммитом

- [ ] Есть `alt` у картинок и текстовое пояснение у схем
- [ ] Внешних ссылок на картинки и скрипты нет
- [ ] `npm run build` проходит, поиск находит новые подтемы
- [ ] Страница на 430 px без горизонтальной прокрутки

## Понятность для студента

- При первом использовании объясняйте термин обычными словами; английское название оставляйте рядом для поиска в документации. Итоговый словарь не заменяет объяснение в тексте.
- Перед сложным примером назовите задачу. После него проследите один конкретный вызов и поясните результат, а не только повторите названия конструкций.
- Не используйте в обязательном примере синтаксис, который ещё не разобран. Переносите пример после нужных объяснений; редкие приёмы помечайте как дополнительные.
- В заданиях указывайте исходные данные и критерии успеха. В инструкциях запуска — папку, необходимые файлы, настройки и ожидаемый результат команд.
- Различайте гарантии языка и типичное поведение реализации. Не обещайте фиксированное число layout, обязательную плавность или универсальное действие настройки без условий.
- После изменения объяснения проверьте соответствующие вопросы и ответы теста, подписи схем и итоговый список: они не должны повторять прежнюю неточность.
- Сохраняйте опубликованные якоря при перестановке тем. Число вопросов именно теста сверяйте с quiz.json; не путайте его с общим числом вопросов для самопроверки.
