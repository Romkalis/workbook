# Инструкции для агентов

Проект: «Учебник» — конспекты модулей RS School на русском, одно приложение на Next.js (App Router, TypeScript). Читатель — студент, который учится по этим страницам. Всё, что вы делаете, должно быть полезно ему при чтении, на любом экране и без лишнего шума.

## Команды

- `npm run dev` — запуск на http://localhost:3000
- `npm run build` — сборка (контент и поисковый индекс готовятся на этом этапе)
- `npm run typecheck` — проверка типов, запускать перед завершением работы
- `sh scripts/setup.sh` — первичная настройка на новой машине (npm install; репозиторий уже создан)

## Принципы

1. **Просто.** Минимум библиотек. Сейчас в зависимостях только next, react, react-dom и zustand. Новую библиотеку добавляйте, только если без неё нельзя, и объясните зачем в сообщении коммита.
2. **Семантика.** `header`, `nav`, `main`, `article`, `section`, `figure`, `dialog`, `details`, `button` вместо `div` с обработчиком. Один `h1` на страницу, заголовки по порядку.
3. **Компоненты.** Один компонент — один файл в `src/components/` и свой `*.module.css`. Компонент делает одно дело и не знает про конкретный урок.
4. **Токены.** Цвета, шрифты, отступы и радиусы берутся из `src/styles/tokens.css` через `var(--...)`. Сырых цветов и «магических» пикселей в компонентах быть не должно. Подробности: `docs/design-system.md`.
5. **Серверное по умолчанию.** `'use client'` только там, где нужны состояние, эффекты или обработчики событий. Сейчас клиентские: Header, ThemeToggle, Sidebar, Search, Quiz, Lightbox, ProseBehavior.
6. **Состояние.** Общее для разных частей экрана (меню, поиск) живёт в `src/store/ui.ts` (zustand). Локальное остаётся в `useState`. Тема хранится в `data-theme` на `<html>` и в localStorage, не в сторе.

## Структура

```
content/lessons/<slug>/
  lesson.json          метаданные: title, stage, order, kicker, heading, lead, chips
  sections/NN-<id>.html  по одному <section id="..."> на файл, порядок по номеру
  quiz.json            [{ q, o: [..], a: индекс верного, why }]
src/app/               страницы: главная, lessons/[slug], design-system, search-index.json
src/components/        компоненты интерфейса
src/lib/               content.ts (чтение контента), search.ts, html.ts, types.ts
src/store/ui.ts        zustand
src/styles/            tokens.css, base.css, prose.css (стили HTML-контента, всё под .prose)
public/img/<lesson>/   картинки уроков
```

Оглавление, подтемы и поиск строятся автоматически из `content/`: раздел берётся из `<h2>`, подтемы из `<h3 id="...">`. У каждого `h3` должен быть уникальный в рамках урока `id`.

## Как добавить урок

1. Создать `content/lessons/<slug>/` с `lesson.json`, `sections/` и `quiz.json` (формат выше). Новый `order` не должен повторять существующие.
2. Раздел «Источники» оформляется как `<section id="..." class="sources">`: он автоматически ставится после теста.
3. Теста в `sections/` быть не должно: его рисует компонент `Quiz` из `quiz.json`.
4. Проверить `npm run build`, мобильную ширину (ниже) и поиск по новым терминам.

## Правила контента (HTML в `content/`)

- Язык русский, тон живой, без канцелярита и шаблонных ИИ-оборотов. Не поддакивайте источникам: если материал устарел или неточен, пишите об этом в тексте.
- Разметка только из компонентов `prose.css`: `.note`, `.warn`, `.tbl > table`, `pre > code`, `details.q` (вопросы), `dl.gloss`, `figure.dg` (схемы), `figure.shot` (скриншоты). Образцы на странице `/design-system`.
- **Визуализация дополняет текст, а не заменяет его.** У каждой схемы или картинки должно быть полное текстовое объяснение рядом (абзац и подпись `figcaption`).
- Схемы только на чистом CSS (`figure.dg`), с `aria-hidden="true"` на анимированной части, паузой по наведению и отключением при `prefers-reduced-motion`.
- Скриншоты лежат локально в `public/img/`, внешних картинок и CDN в контенте нет. У каждой картинки есть `alt`.
- Код в примерах запускайте перед тем, как вставить в текст. Факты сверяйте с первоисточником. Что взято не из материалов модуля, помечайте («из общих знаний»). Если источник не удалось открыть или он не разобран, так и пишите в разделе «Источники».
- Тест: 4 варианта, один верный, у каждого вопроса есть `why`. Верные ответы распределяйте по разным позициям.

## Мобильная версия (обязательно)

- Страница должна иметь viewport meta (в `layout.tsx` он уже есть). Не добавляйте фиксированную ширину и `min-width` вне прокручиваемых контейнеров.
- Проверка: эмуляция 430×932, DPR 3 (iPhone 16 Pro Max). `document.documentElement.scrollWidth` равен 430, `visualViewport.scale` равен 1, горизонтальной прокрутки нет. Широкие таблицы, код и скриншоты скроллятся внутри своих блоков.
- Анимации не должны быть единственным носителем смысла.

## Git

Вся разработка ведётся через git. Репозиторий: https://github.com/Romkalis/workbook (ветка `main`, remote `origin`).

- Перед началом работы: `git status` и `git pull`, чтобы не править устаревшую копию.
- Каждое законченное изменение фиксируется отдельным коммитом и отправляется `git push`. Незакоммиченных правок в конце работы не остаётся.
- Крупную или рискованную правку (новый урок, массовая переработка текстов) делайте в отдельной ветке и сливайте в `main` после проверки.
- Сборку `out/`, `.next/` и `node_modules/` не коммитим, они в `.gitignore`.

## Перед завершением работы

1. `npm run typecheck` и `npm run build` без ошибок.
2. Обе темы (светлая и тёмная) выглядят нормально, контраст читаемый.
3. Поиск находит новые разделы, ссылки из оглавления ведут куда надо.
4. Коммиты на русском или английском, одно изменение — один коммит.
