Сохранить состояние: localStorage

Корзина не должна пропадать при перезагрузке. localStorage хранит строки по ключу, только для этого сайта, без срока давности:

export interface KeyValueStorage {
  getItem(key: string): string | null;
  setItem(key: string, value: string): void;
}

export function loadState<T>(storage: KeyValueStorage, key: string, isValid: (x: unknown) => x is T, fallback: T): T {
  try {
    const raw = storage.getItem(key);
    if (raw === null) return fallback;
    const data: unknown = JSON.parse(raw);
    return isValid(data) ? data : fallback;
  } catch {
    return fallback; // битый JSON или хранилище недоступно
  }
}

export function saveState(storage: KeyValueStorage, key: string, value: unknown): void {
  try {
    storage.setItem(key, JSON.stringify(value));
  } catch {
    // переполнено или запрещено (приватный режим) — работаем без сохранения
  }
}

Три правила. Прочитанное — unknown: данные мог сохранить старый код с другой формой, их мог поправить пользователь в DevTools, поэтому нужна проверка (предикат, как в TypeScript Basic). Хранилище может отказать: setItem бросает исключение при переполнении, а в некоторых режимах приватности доступ к хранилищу запрещён (из общих знаний), и это не должно ронять приложение. Хранилище передаётся параметром: в браузере localStorage, в тестах объект на Map.

Сохранять удобно подпиской на стор: store.subscribe((s) => saveState(localStorage, 'cart', s)). Тогда ни одно действие не «забудет» сохранить данные.

В localStorage не кладут секреты и токены доступа: его читает любой скрипт на странице, включая внедрённый через XSS (подробнее — в уроке JWT-авторизация).

Задача 12. Корзина, которая переживает перезагрузку ★★☆ практика

Напишите createPersistentCart(storage): при создании читает корзину из ключа shop:cart с проверкой формы (строки с id-строкой и целыми price и quantity от 1; неверные строки отбрасываются), а после каждого изменения сохраняет её подпиской. Возвращает стор с add(id, price) и getState().

Зачем: сохранение через подписку нельзя «забыть»: любое новое действие сохранится автоматически. А проверка при чтении защищает от данных, которые сохранила прошлая версия приложения с другой формой корзины.

Решение и разбор
// persistent.ts
export interface Line {
  id: string;
  price: number;
  quantity: number;
}
export interface KeyValueStorage {
  getItem(k: string): string | null;
  setItem(k: string, v: string): void;
}
const KEY = 'shop:cart';

function isLine(x: unknown): x is Line {
  return (
    typeof x === 'object' && x !== null &&
    'id' in x && typeof x.id === 'string' &&
    'price' in x && Number.isInteger(x.price) &&
    'quantity' in x && Number.isInteger(x.quantity) && (x.quantity as number) >= 1
  );
}

function load(storage: KeyValueStorage): Line[] {
  try {
    const data: unknown = JSON.parse(storage.getItem(KEY) ?? '[]');
    return Array.isArray(data) ? data.filter(isLine) : [];
  } catch {
    return [];
  }
}

export function createPersistentCart(storage: KeyValueStorage) {
  let lines = load(storage);
  const save = () => {
    try {
      storage.setItem(KEY, JSON.stringify(lines));
    } catch {
      /* хранилище недоступно — корзина работает без сохранения */
    }
  };
  return {
    getState: () => lines,
    add(id: string, price: number) {
      const found = lines.find((l) => l.id === id);
      lines = found ? lines.map((l) => (l === found ? { ...l, quantity: l.quantity + 1 } : l)) : [...lines, { id, price, quantity: 1 }];
      save();
    },
  };
}

Неверные строки отбрасываются по одной, а не вся корзина. Если в сохранённых данных одна строка испорчена, пользователь не теряет остальные товары. Ключ с префиксом shop: не пересечётся с ключами других частей сайта на том же домене. Для простоты сохранение вызывается внутри add. Со стором из раздела это делается подпиской: store.subscribe(save).

Задача 13. Миграция сохранённых данных ★★★ с подвохом

Раньше корзина сохранялась как { "g1": 2, "b1": 1 } (id → количество), теперь — как { version: 2, lines: [{ id, quantity }] }. Напишите loadCart(raw: unknown), которая понимает обе формы: старую превращает в новую, новую проверяет, всё остальное даёт пустую корзину.

Зачем: у пользователей в браузерах лежат данные, сохранённые прошлой версией приложения. Без миграции после обновления сайта корзина у всех опустеет. Номер версии в данных позволяет различать формы надёжно, а не угадывать по признакам.

Решение и разбор
// migrate.ts
export interface CartV2 {
  version: 2;
  lines: { id: string; quantity: number }[];
}

const isPositiveInt = (x: unknown): x is number => Number.isInteger(x) && (x as number) >= 1;

export function loadCart(raw: unknown): CartV2 {
  const empty: CartV2 = { version: 2, lines: [] };
  if (typeof raw !== 'object' || raw === null || Array.isArray(raw)) return empty;

  if ('version' in raw) {
    if (raw.version !== 2 || !('lines' in raw) || !Array.isArray(raw.lines)) return empty;
    const lines = raw.lines.filter(
      (l: unknown): l is CartV2['lines'][number] =>
        typeof l === 'object' && l !== null && 'id' in l && typeof l.id === 'string' && 'quantity' in l && isPositiveInt(l.quantity),
    );
    return { version: 2, lines };
  }

  // версия 1: { [id]: quantity }
  const lines = Object.entries(raw)
    .filter(([, q]) => isPositiveInt(q))
    .map(([id, quantity]) => ({ id, quantity: quantity as number }));
  return { version: 2, lines };
}

Новая форма узнаётся по полю version, а старая — по его отсутствию. Поэтому в новые данные версию записывают всегда, начиная с первой же версии. Тогда следующая миграция (v2 → v3) будет простым switch по номеру. После загрузки старой корзины её стоит сразу сохранить в новой форме, и старая перестанет встречаться. Неизвестная версия (например, 3 от более новой вкладки) даёт пустую корзину, а не ошибку: угадывать будущий формат нельзя.

Задача 14. Хранилище, которое отказывает ★☆☆ разминка

Напишите тест: если setItem бросает исключение (переполнение или запрет), функция сохранения из раздела не роняет приложение, а loadState при недоступном getItem возвращает значение по умолчанию. Используйте объекты-заглушки вместо localStorage.

// persist.ts
export interface KeyValueStorage {
  getItem(key: string): string | null;
  setItem(key: string, value: string): void;
}
export function loadState<T>(storage: KeyValueStorage, key: string, isValid: (x: unknown) => x is T, fallback: T): T {
  try {
    const raw = storage.getItem(key);
    if (raw === null) return fallback;
    const data: unknown = JSON.parse(raw);
    return isValid(data) ? data : fallback;
  } catch {
    return fallback;
  }
}
export function saveState(storage: KeyValueStorage, key: string, value: unknown): void {
  try {
    storage.setItem(key, JSON.stringify(value));
  } catch {
    // работаем без сохранения
  }
}

Зачем: хранилище — внешняя система, и оно отказывает: квота 5–10 МБ (из общих знаний), запрет в настройках браузера. Заглушка, которая бросает, воспроизводит это за одну строку, без хитрых настроек браузера.

Решение и разбор
// persist.test.ts
import { expect, it } from 'vitest';
import { loadState, saveState } from './persist.js';

const broken = {
  getItem(): string | null {
    throw new Error('SecurityError');
  },
  setItem(): void {
    throw new Error('QuotaExceededError');
  },
};

it('сохранение при отказе хранилища не бросает', () => {
  expect(() => saveState(broken, 'cart', [1, 2])).not.toThrow();
});

it('чтение при отказе хранилища даёт значение по умолчанию', () => {
  const isArr = (x: unknown): x is number[] => Array.isArray(x);
  expect(loadState(broken, 'cart', isArr, [])).toEqual([]);
});

Заглушка с явными типами методов совместима с KeyValueStorage, и TypeScript проверит это при передаче. Мутант без try/catch падает на обоих тестах. Это как раз та защита, которую «упрощают» при рефакторинге со словами «тут же никогда не бывает ошибки».
