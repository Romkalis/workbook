Всё вместе даёт четыре слоя с зависимостями в одну сторону:

Отрисовкаrender: состояние → DOMда, только пишетjsdom: подать состояние, проверить разметку
Обработчикисобытия → вызовы сторада, только читаетjsdom: кликнуть, проверить состояние

Цикл замкнут: событие → изменение стора → подписка → render → новый экран → новое событие. Данные идут по кругу в одном направлении, поэтому любую ошибку можно найти по шагам: правильно ли обработчик понял клик, правильно ли модель посчитала, правильно ли render нарисовал. Этот поток называют однонаправленным потоком данных, на нём построены Redux и архитектура Elm (из общих знаний).

import { createStore } from './store.js';
import { renderCart, type CartState } from './render.js';
import { addLine, removeLine } from './cart-actions.js';

export function mountCart(root: HTMLElement, initial: CartState) {
  const store = createStore(initial);
  store.subscribe((state) => renderCart(root, state)); // стор → экран
  renderCart(root, store.getState());
  return {
    add: (item: { id: string; title: string; price: number }) => store.setState((s) => addLine(s, item)),
    remove: (id: string) => store.setState((s) => removeLine(s, id)),
    getState: store.getState,
  };
}

Задача 18. Два вида одного состояния ★★☆ практика

Соберите из стора, render-функций и делегирования маленькое приложение: каталог из трёх товаров с кнопками «В корзину» и бейдж в шапке с числом товаров в корзине. Каталог и бейдж подписаны на один стор и ничего не знают друг о друге. Нажатие кнопки меняет только стор.

// store.ts
export function createStore<S>(initial: S) {
  let state = initial;
  const listeners = new Set<(s: S, p: S) => void>();
  return {
    getState: (): S => state,
    setState(update: (prev: S) => S): void {
      const prev = state;
      const next = update(prev);
      if (Object.is(next, prev)) return;
      state = next;
      listeners.forEach((l) => l(state, prev));
    },
    subscribe(l: (s: S, p: S) => void) {
      listeners.add(l);
      return () => listeners.delete(l);
    },
  };
}

Зачем: это весь урок на одной странице: событие → стор → подписчики → экран. Два независимых вида одного состояния не могут разойтись, потому что рисуются из одних данных.

Решение и разбор
// app.ts
import { createStore } from './store.js';

interface Product {
  id: string;
  title: string;
}
interface State {
  products: Product[];
  cart: Record<string, number>;
}

const cartCount = (s: State) => Object.values(s.cart).reduce((a, b) => a + b, 0);

function renderCatalog(root: HTMLElement, s: State) {
  root.replaceChildren(
    ...s.products.map((p) => {
      const card = document.createElement('article');
      card.dataset.id = p.id;
      const button = document.createElement('button');
      button.type = 'button';
      button.dataset.action = 'add';
      button.textContent = s.cart[p.id] ? `В корзине: ${s.cart[p.id]}` : 'В корзину';
      card.append(Object.assign(document.createElement('h3'), { textContent: p.title }), button);
      return card;
    }),
  );
}

function renderBadge(badge: HTMLElement, s: State) {
  const n = cartCount(s);
  badge.textContent = String(n);
  badge.hidden = n === 0;
}

export function mountShop(catalog: HTMLElement, badge: HTMLElement, products: Product[]) {
  const store = createStore<State>({ products, cart: {} });
  store.subscribe((s) => renderCatalog(catalog, s));
  store.subscribe((s) => renderBadge(badge, s));
  renderCatalog(catalog, store.getState());
  renderBadge(badge, store.getState());

  catalog.addEventListener('click', (event) => {
    if (!(event.target instanceof Element)) return;
    const id = event.target.closest('[data-action="add"]')?.closest<HTMLElement>('[data-id]')?.dataset.id;
    if (!id) return;
    store.setState((s) => ({ ...s, cart: { ...s.cart, [id]: (s.cart[id] ?? 0) + 1 } }));
  });
  return store;
}

Обработчик висит на контейнере каталога и переживает его перерисовку: после каждого клика renderCatalog заменяет карточки, но делегированный слушатель на catalog остаётся. Обработчики на самих кнопках пришлось бы вешать заново. Бейдж и каталог узнают об изменении одновременно, из одного состояния. Посмотрите, как мало изменится, если добавить третий вид, например мини-корзину: одна функция render и одна подписка.
