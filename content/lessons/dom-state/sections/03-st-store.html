Стор: состояние, изменения, подписчики

Состояние нужно где-то хранить, менять по правилам и сообщать об изменениях тем, кто рисует. Минимальный стор — это 15 строк:

export type Listener<S> = (state: S, prev: S) => void;

export function createStore<S>(initial: S) {
  let state = initial;
  const listeners = new Set<Listener<S>>();
  return {
    getState: (): S => state,
    setState(update: (prev: S) => S): void {
      const prev = state;
      const next = update(prev);
      if (Object.is(next, prev)) return; // ничего не изменилось — не беспокоим подписчиков
      state = next;
      listeners.forEach((listener) => listener(state, prev));
    },
    subscribe(listener: Listener<S>): () => void {
      listeners.add(listener);
      return () => listeners.delete(listener);
    },
  };
}

Изменение задаётся функцией «старое состояние → новое», а не присваиванием поля. Это значит, что состояние не меняют на месте, а создают новое: { ...prev, lines: [...prev.lines, line] }. Зачем: подписчик получает и новое, и старое состояние и может сравнить их ссылкой (prev.lines === state.lines — «корзина не менялась, перерисовывать не надо»). Если менять массив на месте, старое и новое — один объект, и сравнение ничего не скажет. Эта идея — иммутабельность, она подробно разобрана в уроке Основы ФП.

subscribe возвращает функцию отписки — тот же договор, что у mount/unmount из прошлого урока. Готовые библиотеки (Redux, zustand, на котором сделан этот учебник) устроены так же, только с удобствами.

Изменения с именами

Когда изменений много, их удобно назвать и собрать в одном месте — чистые функции «состояние + данные → новое состояние»:

import type { CartLine, CartState } from './render.js';

export const addLine = (state: CartState, item: Omit<CartLine, 'quantity'>): CartState => {
  const found = state.lines.find((l) => l.id === item.id);
  return {
    lines: found
      ? state.lines.map((l) => (l === found ? { ...l, quantity: l.quantity + 1 } : l))
      : [...state.lines, { ...item, quantity: 1 }],
  };
};

export const removeLine = (state: CartState, id: string): CartState => ({
  lines: state.lines.filter((l) => l.id !== id),
});

Вызов: store.setState((s) => addLine(s, product)). Вся логика корзины — в чистых функциях, их тестируют без DOM, без стора и без браузера. Это тот же код, что в задачах урока Testing Intro: там вы уже писали его с тестами.

Задача 3. Счётчик через стор ★☆☆ разминка

Используя createStore из раздела, сделайте счётчик с кнопками «+» и «−» и выводом. Кнопки только вызывают setState, а вывод обновляется подпиской. Число не может быть меньше 0.

Зачем: разделение «кто меняет» и «кто показывает» на маленьком примере: кнопки не знают про вывод, вывод не знает про кнопки. Завтра появится третья кнопка или второй вывод, и ни одна часть не изменится.

Решение и разбор
// counter.ts
import { createStore } from './store.js';

export function mountCounter(inc: HTMLButtonElement, dec: HTMLButtonElement, out: HTMLElement) {
  const store = createStore({ count: 0 });
  const render = (s: { count: number }) => {
    out.textContent = String(s.count);
    dec.disabled = s.count === 0;
  };
  store.subscribe(render);
  render(store.getState());
  inc.addEventListener('click', () => store.setState((s) => ({ count: s.count + 1 })));
  dec.addEventListener('click', () => store.setState((s) => (s.count === 0 ? s : { count: s.count - 1 })));
  return store;
}

Ограничение «не меньше 0» живёт в изменении, а не в кнопке: при нуле функция возвращает прежнее состояние, и стор даже не оповещает подписчиков. Блокировка «−» на нуле — подсказка пользователю, но защита всё равно в данных. Первый render вызывается вручную: подписка сработает только при изменении.

Задача 4. Отписка ★☆☆ разминка

Напишите тест для createStore: после вызова функции отписки слушатель больше не вызывается, а другие слушатели продолжают получать изменения. Используйте Vitest и шпион vi.fn().

// store.ts
export type Listener<S> = (state: S, prev: S) => void;
export function createStore<S>(initial: S) {
  let state = initial;
  const listeners = new Set<Listener<S>>();
  return {
    getState: (): S => state,
    setState(update: (prev: S) => S): void {
      const prev = state;
      const next = update(prev);
      if (Object.is(next, prev)) return;
      state = next;
      listeners.forEach((l) => l(state, prev));
    },
    subscribe(listener: Listener<S>): () => void {
      listeners.add(listener);
      return () => listeners.delete(listener);
    },
  };
}

Зачем: неработающая отписка — утечка: удалённый со страницы компонент продолжает перерисовываться при каждом изменении. Ошибка тихая и проявляется медленным приложением через полчаса работы.

Решение и разбор
// store.test.ts
import { expect, it, vi } from 'vitest';
import { createStore } from './store.js';

it('после отписки слушатель молчит, остальные работают', () => {
  const store = createStore(0);
  const first = vi.fn();
  const second = vi.fn();
  const offFirst = store.subscribe(first);
  store.subscribe(second);

  offFirst();
  store.setState((n) => n + 1);

  expect(first).not.toHaveBeenCalled();
  expect(second).toHaveBeenCalledWith(1, 0);
});

Тест специально отписывает первого из двух слушателей. Мутант с pop() удаляет последнего добавленного, то есть не того, и тест это ловит. Если бы отписывали единственного слушателя, такой мутант прошёл бы. Проверка toHaveBeenCalledWith(1, 0) заодно фиксирует договор: слушатель получает новое и старое состояние.

Задача 5. Изменение, которое ничего не меняет ★★☆ практика

Напишите действие removeTodo(state, id) так, чтобы при отсутствии задачи с таким id оно возвращало тот же объект состояния. Убедитесь тестом, что стор в этом случае не оповещает подписчиков.

// store.ts
export function createStore<S>(initial: S) {
  let state = initial;
  const listeners = new Set<(s: S, p: S) => void>();
  return {
    getState: (): S => state,
    setState(update: (prev: S) => S): void {
      const prev = state;
      const next = update(prev);
      if (Object.is(next, prev)) return;
      state = next;
      listeners.forEach((l) => l(state, prev));
    },
    subscribe(l: (s: S, p: S) => void) {
      listeners.add(l);
      return () => listeners.delete(l);
    },
  };
}

Зачем: перерисовка без изменений — лишняя работа и, хуже, потерянный фокус и мигание интерфейса. Возврат прежнего объекта — договор «ничего не изменилось», который стор понимает через Object.is.

Решение и разбор
// remove.ts
export interface TodoState {
  todos: { id: string; title: string }[];
}

export function removeTodo(state: TodoState, id: string): TodoState {
  if (!state.todos.some((t) => t.id === id)) return state;
  return { todos: state.todos.filter((t) => t.id !== id) };
}

filter всегда создаёт новый массив, даже если ничего не убрал. Поэтому без предварительной проверки стор получил бы «новое» состояние и перерисовал экран зря. Проверка some стоит прохода по массиву, но экономит перерисовку, и это выгодный обмен.

Задача 7. Действие «изменить количество» ★★☆ практика

Напишите чистое действие setQuantity(state, id, quantity) для корзины: количество ограничено сверху остатком stock строки; 0 и меньше удаляют строку; неизвестный id или то же количество возвращают прежнее состояние.

Зачем: правила корзины живут в одной функции с ясным входом и выходом. Интерфейс может вызвать её из поля ввода, кнопок «±» или голосового помощника, и правила для всех будут одинаковы.

Решение и разбор
// quantity.ts
export interface Line {
  id: string;
  price: number;
  quantity: number;
  stock: number;
}
export interface Cart {
  lines: Line[];
}

export function setQuantity(state: Cart, id: string, quantity: number): Cart {
  const line = state.lines.find((l) => l.id === id);
  if (!line) return state;
  if (quantity <= 0) return { lines: state.lines.filter((l) => l !== line) };
  const next = Math.min(Math.floor(quantity), line.stock);
  if (next === line.quantity) return state;
  return { lines: state.lines.map((l) => (l === line ? { ...l, quantity: next } : l)) };
}

Выход за остаток не ошибка, а «столько, сколько есть». Пользователь ввёл 10 при остатке 3 и получил 3. Это решение интерфейса, и оно зафиксировано в функции. Другое разумное решение — отказать с сообщением. Главное, что правило в одном месте. Math.floor защищает от дробного ввода. Сравнение с текущим количеством избавляет от лишней перерисовки, как в задаче про noop.

Задача 8. Reducer и действия-объекты ★★★ с подвохом

Переведите корзину на схему reducer: действия — объекты размеченного объединения { type: 'add', product } | { type: 'remove', id } | { type: 'clear' }, функция cartReducer(state, action) возвращает новое состояние, в default — проверка полноты через never. Добавьте к стору метод dispatch(action).

Зачем: действия-объекты можно записать в лог, отправить по сети, воспроизвести для отладки («что сделал пользователь перед ошибкой»). Это идея Redux, а never не даст забыть обработать новое действие, как в задаче про состояние загрузки в TypeScript Basic.

Решение и разбор
// reducer.ts
export interface Line {
  id: string;
  price: number;
  quantity: number;
}
export interface Cart {
  lines: Line[];
}
export type CartAction =
  | { type: 'add'; product: { id: string; price: number } }
  | { type: 'remove'; id: string }
  | { type: 'clear' };

export function cartReducer(state: Cart, action: CartAction): Cart {
  switch (action.type) {
    case 'add': {
      const found = state.lines.find((l) => l.id === action.product.id);
      return {
        lines: found
          ? state.lines.map((l) => (l === found ? { ...l, quantity: l.quantity + 1 } : l))
          : [...state.lines, { ...action.product, quantity: 1 }],
      };
    }
    case 'remove':
      return { lines: state.lines.filter((l) => l.id !== action.id) };
    case 'clear':
      return state.lines.length === 0 ? state : { lines: [] };
    default: {
      const unreachable: never = action;
      return unreachable;
    }
  }
}

export function createCartStore(initial: Cart) {
  let state = initial;
  const log: CartAction[] = [];
  const listeners = new Set<(s: Cart) => void>();
  return {
    getState: () => state,
    dispatch(action: CartAction) {
      log.push(action);
      const next = cartReducer(state, action);
      if (next === state) return;
      state = next;
      listeners.forEach((l) => l(state));
    },
    subscribe(l: (s: Cart) => void) {
      listeners.add(l);
      return () => listeners.delete(l);
    },
    history: () => [...log],
  };
}

Внутри каждой ветки switch TypeScript знает точный вид действия: в 'add' есть product, в 'remove' — id. Журнал history показывает силу схемы: можно восстановить состояние, применив все действия к начальному (log.reduce(cartReducer, initial)). Так работает «путешествие во времени» в инструментах разработчика Redux (из общих знаний).
