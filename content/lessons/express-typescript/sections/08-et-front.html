Подключаем фронтенд и публикуем

CORS

Фронтенд на Vite работает на http://localhost:5173, API — на :3000. Это разные источники (origin), и браузер не отдаст странице ответ, пока сервер не разрешит это заголовком Access-Control-Allow-Origin. Механизм разобран в уроке «Клиент-серверное взаимодействие». Пакет cors ставит этот заголовок, а на предварительный запрос OPTIONS отвечает 204. Проверено через curl:

$ curl -si -H 'Origin: http://localhost:5173' localhost:3123/api/health
Access-Control-Allow-Origin: http://localhost:5173

CORS защищает пользователей браузера, а не ваш сервер. Запрос из curl или Postman с чужим Origin всё равно доходит до сервера и получает ответ: мы проверили, что сервер отвечает, просто с заголовком для localhost:5173, и браузер чужой странице этот ответ не отдаст. Проверять права пользователя всё равно нужно на сервере (JWT-авторизация).

Запрос с фронтенда:

const API_URL = import.meta.env.VITE_API_URL ?? 'http://localhost:3000';

export async function fetchQuote(items: { productId: string; quantity: number }[], promo?: string) {
  const res = await fetch(`${API_URL}/api/cart/quote`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ items, promo }),
  });
  if (!res.ok) throw new Error((await res.json()).error);
  return (await res.json()) as { subtotal: number; discount: number; total: number };
}

Без заголовка Content-Type: application/json express.json() не тронет тело, и req.body окажется undefined. Сервер честно ответит 400. Это самая частая причина вопроса «почему сервер не видит мои данные». Почему fetch не бросает ошибку при 400 и зачем проверять res.ok, разобрано в Country Search. Сам этот клиентский код в браузере не запускался; тот же запрос проверен через supertest.

Деплой

GitHub Pages и Netlify в базовом варианте отдают только статические файлы, Node-сервер они не запускают. Для API нужен хостинг с Node: Render, Railway, Fly.io и подобные (из общих знаний, условия бесплатных тарифов меняются, проверяйте на сайте). Общая схема почти везде одна:

  1. Команда сборки: npm ci && npm run build. typescript лежит в devDependencies, а некоторые хостинги их не ставят при NODE_ENV=production. Если сборка пишет «tsc: not found», дело в этом.
  2. Команда запуска: npm start, то есть node dist/server.js. Не tsx: он нужен только для разработки.
  3. Переменные окружения: CLIENT_ORIGIN — адрес опубликованного фронтенда. PORT хостинг обычно задаёт сам, поэтому сервер читает его из process.env, а не жёстко пишет 3000.
  4. На фронтенде VITE_API_URL — адрес API. Переменные с префиксом VITE_ попадают в код при сборке, поэтому секретов там быть не должно.

Бесплатные серверы часто засыпают без запросов, и первый запрос после паузы идёт десятки секунд. Перед записью интервью откройте /api/health, чтобы разбудить сервер. Или храните данные прямо во фронтенде, как разрешает задание, и не зависьте от этого.
