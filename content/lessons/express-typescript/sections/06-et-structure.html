Структура: app отдельно от server

src/
  domain/        чистая логика без Express: товары, корзина
    products.ts
    cart.ts
  routes/        HTTP-слой: разбирает запрос, вызывает domain, отвечает
    products.ts
    cart.ts
  http-error.ts
  app.ts         createApp(): собирает приложение, но НЕ слушает порт
  server.ts      читает env и вызывает listen
tests/
  cart.test.ts   unit-тесты domain
  api.test.ts    тесты HTTP через supertest
// src/server.ts
import { createApp } from './app.js';

const port = Number(process.env.PORT ?? 3000);
const app = createApp(process.env.CLIENT_ORIGIN);

app.listen(port, () => {
  console.log(`API: http://localhost:${port}`);
});

Почему так

  • Тесты не занимают порт. Тест импортирует createApp() и отдаёт его supertest. Если бы app.ts сам вызывал listen(3000), два тестовых файла поспорили бы за порт, а запущенный npm run dev ломал бы тесты.
  • Логика не знает про HTTP. calculateCart принимает массив и возвращает объект. Её можно тестировать без сервера и даже скопировать во фронтенд, чтобы показывать сумму мгновенно. Сервер остаётся источником истины.
  • Настройки через окружение. Порт и адрес фронтенда берутся из process.env (о переменных окружения), потому что на хостинге они другие.

Это тот же принцип единственной ответственности из Clean Code, применённый к папкам.
