Типы запроса и ответа

Обработчик Express получает req и res. Если написать обработчик прямо внутри app.get(...), TypeScript выведет их типы сам (контекстная типизация, о ней здесь). Но по умолчанию req.body имеет тип any, а req.query — «что угодно из строки запроса». Это надо уточнять.

Четыре параметра Request

Request — обобщённый тип (generic) с четырьмя параметрами по порядку:

Request<Params, ResBody, ReqBody, Query>
//      :id      что     что пришло  ?search=...
//               отвечаем в теле

Пример из нашего API: параметр пути :id и ответ — товар.

// src/routes/products.ts
productsRouter.get('/:id', (req: Request<{ id: string }>, res: Response<Product>) => {
  const product = PRODUCTS.find((p) => p.id === req.params.id);
  if (!product) throw new HttpError(404, 'Товар не найден');
  res.json(product);
});

Response<Product> — обещание компилятору: res.json() примет только Product. Попробуйте написать res.json({ title: 1 }), и редактор подчеркнёт ошибку. Это защищает от случайного изменения формы ответа, на которую рассчитывает фронтенд.

Строка запроса: всегда строки

В адресе /api/products?minPrice=1000 значение minPrice приходит строкой "1000", а не числом. HTTP передаёт текст, и Express ничего не угадывает. Поэтому тип Query честно описан строками, а перевод в число с проверкой — отдельная функция:

// src/routes/products.ts
import { Router, type Request, type Response } from 'express';
import { filterProducts, PRODUCTS, type Product, type ProductFilters } from '../domain/products.js';
import { HttpError } from '../http-error.js';

export const productsRouter = Router();

type ProductsQuery = { search?: string; category?: string; minPrice?: string; maxPrice?: string };

function toNumber(value: string | undefined, name: string): number | undefined {
  if (value === undefined || value === '') return undefined;
  const n = Number(value);
  if (!Number.isInteger(n) || n < 0) throw new HttpError(400, `${name} должен быть целым числом ≥ 0`);
  return n;
}

productsRouter.get('/', (req: Request<{}, Product[], unknown, ProductsQuery>, res: Response<Product[]>) => {
  const filters: ProductFilters = {
    search: req.query.search,
    category: req.query.category,
    minPrice: toNumber(req.query.minPrice, 'minPrice'),
    maxPrice: toNumber(req.query.maxPrice, 'maxPrice'),
  };
  res.json(filterProducts(PRODUCTS, filters));
});

Тип ProductsQuery со строками — это допущение, а не проверка. По адресу ?search=a&search=b Express отдаст массив. Для учебного API это допустимо, а в серьёзном проекте строку запроса проверяют так же, как тело (следующий раздел).

Обратите внимание на {} в позиции Params: у маршрута / параметров пути нет. А unknown в позиции тела — у GET-запроса тела нет, и мы не обещаем, что оно есть.

Деньги — в целых копейках

В Product цена хранится в копейках: 150000 вместо 1500.00. В JavaScript 0.1 + 0.2 равно 0.30000000000000004, потому что дробные числа хранятся в двоичном виде приблизительно. Сумма корзины из десятка позиций может разойтись на копейку с тем, что посчитал фронтенд. С целыми числами такого нет, а рубли с копейками показывают только при выводе ((price / 100).toFixed(2)). Это из общих знаний, но на интервью такой вопрос задают часто.
