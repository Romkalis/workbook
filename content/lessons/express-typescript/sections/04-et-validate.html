Проверка входных данных

Главное правило сервера: всё, что пришло по сети, — unknown. Аннотация req.body as QuoteBody только отключает проверку компилятора. Она ничего не проверяет во время работы, это разобрано в разделе про as.

Type guard для тела запроса

Функция с возвращаемым типом body is QuoteBody называется type guard (охранник типа, подробно в TypeScript Advanced). Она проверяет значение во время выполнения, а компилятор после if считает тело проверенным:

// src/routes/cart.ts
import { Router, type Request, type Response } from 'express';
import { calculateCart, type CartLine, type CartTotals } from '../domain/cart.js';
import { PRODUCTS } from '../domain/products.js';
import { HttpError } from '../http-error.js';

export const cartRouter = Router();

interface QuoteBody {
  items: { productId: string; quantity: number }[];
  promo?: string;
}

function isQuoteBody(body: unknown): body is QuoteBody {
  if (typeof body !== 'object' || body === null || !('items' in body) || !Array.isArray(body.items)) return false;
  if ('promo' in body && typeof body.promo !== 'string') return false;
  return body.items.every(
    (i: unknown) =>
      typeof i === 'object' && i !== null &&
      'productId' in i && typeof i.productId === 'string' &&
      'quantity' in i && Number.isInteger(i.quantity) && (i.quantity as number) >= 1,
  );
}

cartRouter.post('/quote', (req: Request<{}, CartTotals, unknown>, res: Response<CartTotals>) => {
  if (!isQuoteBody(req.body)) throw new HttpError(400, 'Неверное тело запроса');
  const lines: CartLine[] = req.body.items.map(({ productId, quantity }) => {
    const product = PRODUCTS.find((p) => p.id === productId);
    if (!product) throw new HttpError(400, `Нет товара ${productId}`);
    return { productId, price: product.price, quantity };
  });
  res.json(calculateCart(lines, req.body.promo));
});

Что здесь важно:

  • Цена берётся с сервера, а не от клиента. Клиент присылает только productId и quantity. Если бы сервер принимал цену из запроса, любой мог бы купить что угодно за копейку, отправив запрос из Postman.
  • quantity — целое число от 1. Ноль, минус и дробь отсекаются сразу.
  • Если товара нет, это 400 (клиент прислал неверные данные), а не 500 (сломался сервер).

Задача 8. Создание товара с проверкой тела ★★☆ практика

Напишите POST /api/products: тело { title, category, price } проверяется предикатом, категория — из фиксированного списка, цена — целое число от 0. Ответ 201 с созданным товаром (id генерирует сервер) и заголовком Location: /api/products/<id>. Для неверного тела ответ 400 со списком ошибок по полям.

Зачем: список ошибок по полям («price: должно быть целым числом») позволяет фронтенду подсветить именно нужное поле формы. Один общий «Неверное тело» заставит пользователя гадать.

Решение и разбор
// validate.ts
const CATEGORIES = ['books', 'games', 'home'] as const;
type Category = (typeof CATEGORIES)[number];

export interface NewProduct {
  title: string;
  category: Category;
  price: number;
}

export function validateNewProduct(body: unknown): { ok: true; value: NewProduct } | { ok: false; errors: string[] } {
  if (typeof body !== 'object' || body === null) return { ok: false, errors: ['тело должно быть объектом'] };
  const errors: string[] = [];
  const title = 'title' in body ? body.title : undefined;
  const category = 'category' in body ? body.category : undefined;
  const price = 'price' in body ? body.price : undefined;

  if (typeof title !== 'string' || title.trim() === '') errors.push('title: непустая строка');
  if (typeof category !== 'string' || !(CATEGORIES as readonly string[]).includes(category)) {
    errors.push(`category: одно из ${CATEGORIES.join(', ')}`);
  }
  if (typeof price !== 'number' || !Number.isInteger(price) || price < 0) errors.push('price: целое число ≥ 0');

  if (errors.length > 0) return { ok: false, errors };
  return { ok: true, value: { title: (title as string).trim(), category: category as Category, price: price as number } };
}
// app.ts
import express from 'express';
import { randomUUID } from 'node:crypto';
import { validateNewProduct, type NewProduct } from './validate.js';

export function createApp(store = new Map<string, NewProduct & { id: string }>()) {
  const app = express();
  app.use(express.json());
  app.post('/api/products', (req, res) => {
    const result = validateNewProduct(req.body);
    if (!result.ok) return res.status(400).json({ error: 'Неверные данные', details: result.errors });
    const product = { id: randomUUID(), ...result.value };
    store.set(product.id, product);
    res.status(201).location(`/api/products/${product.id}`).json(product);
  });
  return app;
}

Вместо предиката здесь функция-результат: она возвращает либо значение, либо все ошибки сразу. Предикат умеет сказать только «да/нет». Тип результата — размеченное объединение по полю ok: после if (!result.ok) компилятор знает, что дальше есть value. Утверждения as в конце безопасны, потому что выше каждое поле проверено. Это ровно та работа, которую автоматизирует библиотека схем вроде Zod. Id генерирует сервер (randomUUID): клиенту нельзя доверять уникальность.

А как в больших проектах

Писать такие проверки вручную утомительно, и они разрастаются. В реальных проектах обычно берут библиотеку схем, например Zod: описываете схему один раз, получаете и проверку, и тип через z.infer. Это из общих знаний, в уроке Zod не используется: для трёх маршрутов хватит ручной проверки, а лишняя зависимость — ещё одна вещь, которую надо объяснить на интервью. Если API разрастётся, это хороший кандидат на «что бы я улучшил». Как переписать эти проверки на Zod — в уроке Zod: проверка данных схемами.
