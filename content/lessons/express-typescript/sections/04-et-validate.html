Проверка входных данных

Главное правило сервера: всё, что пришло по сети, — unknown. Аннотация req.body as QuoteBody только отключает проверку компилятора. Она ничего не проверяет во время работы, это разобрано в разделе про as.

Type guard для тела запроса

Функция с возвращаемым типом body is QuoteBody называется type guard (охранник типа, подробно в TypeScript Advanced). Она проверяет значение во время выполнения, а компилятор после if считает тело проверенным:

// src/routes/cart.ts
import { Router, type Request, type Response } from 'express';
import { calculateCart, type CartLine, type CartTotals } from '../domain/cart.js';
import { PRODUCTS } from '../domain/products.js';
import { HttpError } from '../http-error.js';

export const cartRouter = Router();

interface QuoteBody {
  items: { productId: string; quantity: number }[];
  promo?: string;
}

function isQuoteBody(body: unknown): body is QuoteBody {
  if (typeof body !== 'object' || body === null || !('items' in body) || !Array.isArray(body.items)) return false;
  if ('promo' in body && typeof body.promo !== 'string') return false;
  return body.items.every(
    (i: unknown) =>
      typeof i === 'object' && i !== null &&
      'productId' in i && typeof i.productId === 'string' &&
      'quantity' in i && Number.isInteger(i.quantity) && (i.quantity as number) >= 1,
  );
}

cartRouter.post('/quote', (req: Request<{}, CartTotals, unknown>, res: Response<CartTotals>) => {
  if (!isQuoteBody(req.body)) throw new HttpError(400, 'Неверное тело запроса');
  const lines: CartLine[] = req.body.items.map(({ productId, quantity }) => {
    const product = PRODUCTS.find((p) => p.id === productId);
    if (!product) throw new HttpError(400, `Нет товара ${productId}`);
    return { productId, price: product.price, quantity };
  });
  res.json(calculateCart(lines, req.body.promo));
});

Что здесь важно:

  • Цена берётся с сервера, а не от клиента. Клиент присылает только productId и quantity. Если бы сервер принимал цену из запроса, любой мог бы купить что угодно за копейку, отправив запрос из Postman.
  • quantity — целое число от 1. Ноль, минус и дробь отсекаются сразу.
  • Если товара нет, это 400 (клиент прислал неверные данные), а не 500 (сломался сервер).

А как в больших проектах

Писать такие проверки вручную утомительно, и они разрастаются. В реальных проектах обычно берут библиотеку схем, например Zod: описываете схему один раз, получаете и проверку, и тип через z.infer. Это из общих знаний, в уроке Zod не используется: для трёх маршрутов хватит ручной проверки, а лишняя зависимость — ещё одна вещь, которую надо объяснить на интервью. Если API разрастётся, это хороший кандидат на «что бы я улучшил».
