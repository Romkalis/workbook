Настройка проекта

Зависимости

mkdir shop-api && cd shop-api
npm init -y
npm pkg set type=module
npm i express cors
npm i -D typescript tsx vitest supertest @types/express @types/cors @types/supertest @types/node

Две группы пакетов. В dependencies то, что нужно серверу в работе: Express и cors. В devDependencies то, что нужно только разработчику: компилятор, тесты и пакеты @types/*. Сам Express написан на JavaScript, а его типы лежат отдельно в репозитории DefinitelyTyped. Без @types/express TypeScript скажет, что не знает, что такое express. Строка type=module включает ES-модули (import/export) для файлов .js.

tsconfig.json для Node

// tsconfig.json
{
  "compilerOptions": {
    "target": "es2022",
    "module": "nodenext",
    "moduleResolution": "nodenext",
    "rootDir": "src",
    "outDir": "dist",
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "verbatimModuleSyntax": true,
    "skipLibCheck": true,
    "types": ["node"]
  },
  "include": ["src"]
}
module и moduleResolution: nodenext
Компилятор ищет и проверяет импорты по тем же правилам, что и сам Node. Для сервера, который запускает Node без сборщика (Vite, Webpack), это правильный выбор. Почему он отличается от настроек фронтенда, разобрано в TypeScript Advanced.
rootDir / outDir
Исходники в src/, готовый JavaScript в dist/. Папку dist добавьте в .gitignore.
strict, noUncheckedIndexedAccess
Строгий режим. Второй флаг делает record[key] типом T | undefined: если промокода нет в словаре, компилятор заставит это обработать (подробнее).
verbatimModuleSyntax
Импорт только типа пишется как import { type Product }. Так видно, какие импорты исчезнут после сборки.
skipLibCheck
Не проверять файлы .d.ts из node_modules: быстрее, и чужие ошибки в типах не ломают вашу сборку.

Почему в импортах пишут .js, хотя файлы .ts

Самое неожиданное место для новичка:

import { HttpError } from '../http-error.js'; // файл на диске — http-error.ts

При nodenext TypeScript требует относительные импорты с расширением и не переписывает их при сборке. После tsc в dist/ лежит http-error.js, и Node найдёт его ровно по этой строке. Если написать '../http-error' без расширения, tsc выдаст ошибку: в ES-модулях Node не подставляет расширения сам.

Как запускать: tsx, tsc и сам Node

npm pkg set scripts.dev="tsx watch src/server.ts"
npm pkg set scripts.build="tsc"
npm pkg set scripts.start="node dist/server.js"
npm pkg set scripts.typecheck="tsc --noEmit"
npm pkg set scripts.test="vitest run"

tsx запустит сервер даже с ошибкой типов: он типы просто вырезает. Поэтому typecheck должен быть в CI или pre-commit хуке (Husky), иначе TypeScript превращается в комментарии.

А сам Node умеет запускать .ts? Начиная с Node 22.18 включено «отбрасывание типов» (type stripping), в нашем Node 22.23 process.features.typescript равно "strip". Но команда node src/server.ts на этом проекте падает с ERR_MODULE_NOT_FOUND: Node ищет буквально app.js, а рядом лежит app.ts. Для нативного запуска импорты нужно писать с .ts и включать в tsconfig rewriteRelativeImportExtensions. Кроме того, Node не поддерживает синтаксис, который требует генерации кода: enum и свойства-параметры конструктора (constructor(readonly status: number)). Для учебного проекта tsx проще. Подробности в документации Node: Modules: TypeScript.
