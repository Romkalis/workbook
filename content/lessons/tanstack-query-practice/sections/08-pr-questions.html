Вопросы для самопроверки

Чем опасна опечатка в ключе внутри invalidateQueries?

Ошибки не будет: библиотека просто не найдёт записей с таким ключом, и данные не обновятся. Фабрика ключей убирает эту проблему: строку ключа пишут один раз.

Почему useSession с запросом избранного внутри — неудачное решение?

Запрос избранного подключается у каждого, кто вызывает useSession, даже если избранное ему не нужно. Лучше вынести его в отдельный хук.

Что плохого в том, чтобы при ошибке вернуть из queryFn пустой список?

Пользователь увидит «ничего нет» вместо «не удалось загрузить», а библиотека сочтёт запрос успешным и не повторит его.

Зачем передавать signal из queryFn в fetch?

Чтобы библиотека могла оборвать настоящий HTTP-запрос, когда он стал не нужен. Без этого запрос долетит до конца впустую.

Почему в setQueryData создают новый объект через spread, а не меняют старый?

Библиотека и React замечают изменение по новой ссылке. Если поменять старый объект на месте, ссылка та же, и экран не обновится.

Когда SSE лучше опроса, а когда нужен WebSocket?

SSE лучше, когда сервер должен сообщать об изменениях быстро и без пустых запросов. WebSocket нужен, когда и клиент постоянно отправляет данные по тому же каналу: чат, игра, совместное редактирование.

Словарь

Фабрика ключей
Объект с функциями, которые создают ключи запросов. Все ключи в одном файле.
AbortSignal
Объект, через который можно отменить запрос.
Infinite query
Запрос, который хранит данные постранично и умеет догружать следующую страницу.
Placeholder data
Временные данные, которые показываются, пока грузятся настоящие.
Дедупликация
Удаление повторов, например одинаковых карточек на соседних страницах.
SSE
Server-Sent Events: открытое соединение, по которому сервер присылает события клиенту.
WebSocket
Открытое соединение, по которому обе стороны обмениваются сообщениями.
