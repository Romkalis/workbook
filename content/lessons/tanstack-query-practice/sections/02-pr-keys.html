Фабрика ключей: все ключи в одном файле

Эта тема всплывает в трёх разборах из четырёх, поэтому начнём с неё.

Ключ используется в двух местах: когда данные читают (useQuery) и когда их обновляют (invalidateQueries, setQueryData). Если ключи в этих местах не совпадут, обновление молча не сработает.

// файл A
useQuery({ queryKey: ['favorites', userId], queryFn: fetchFavorites });

// файл B, полгода спустя
queryClient.invalidateQueries({ queryKey: ['favorite', userId] }); // опечатка: нет буквы s

Ошибки не будет. Просто избранное перестанет обновляться, и искать причину придётся долго.

Решение: объект с функциями

Фабрика ключей — обычный объект, где каждый ключ создаёт функция. Ключи больше не набирают руками, их получают вызовом.

// queryKeys.ts
export const queryKeys = {
  auth: {
    all: () => ['auth'] as const,
    me: () => ['auth', 'me'] as const,
  },
  games: {
    all: () => ['games'] as const,
    hall: (hallType: string) => ['games', 'hall', hallType] as const,
    category: (hallType: string, categoryId: string) =>
      ['games', 'hall', hallType, 'category', categoryId] as const,
  },
};

// использование
useQuery({ queryKey: queryKeys.games.hall('main'), queryFn: ... });

as const говорит TypeScript, что это не «какой-то массив строк», а именно ['auth', 'me']. Тогда редактор подсказывает ключи, а опечатка в имени функции сразу подсвечивается как ошибка.

Что это даёт

  • Нет опечаток. Строки пишутся один раз, в одном файле.
  • Обновление целой ветки. Ключи сравниваются по началу, поэтому invalidateQueries({ queryKey: queryKeys.games.all() }) обновит и hall('main'), и category('main', 'puzzle'), и любой ключ, который начинается с 'games'.
  • Всё видно сразу. Чтобы понять, что вообще кешируется в приложении, достаточно открыть один файл.
