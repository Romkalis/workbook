Разбор 4. useSearchResults: бесконечная прокрутка

Поиск игр: результаты подгружаются страницами, пока пользователь листает вниз. Для этого есть useInfiniteQuery.

Как работает useInfiniteQuery

Обычный useQuery хранит один ответ. useInfiniteQuery хранит список страниц: в data.pages лежит массив ответов, по одному на загруженную страницу. Чтобы получить следующую, вызывают fetchNextPage().

Две обязательные настройки:

  • initialPageParam — номер (или курсор) первой страницы;
  • getNextPageParam(lastPage, allPages) — по уже загруженному решает, какой номер запросить дальше. Вернуть undefined значит «страниц больше нет», и hasNextPage станет false.
const EMPTY_ITEMS = [];

export function useSearchResults({ debouncedSearchQuery, appliedProviderIds, appliedCategoryIds, isPreQuery }) {
  const { data, hasNextPage, isFetchingNextPage, fetchNextPage, ...rest } = useInfiniteQuery({
    queryKey: ['gamesSearch', debouncedSearchQuery, appliedProviderIds, appliedCategoryIds], // ← ключ руками
    queryFn: ({ pageParam, signal }) =>
      searchGames(debouncedSearchQuery, appliedProviderIds, appliedCategoryIds, pageParam, signal),
    initialPageParam: 1,
    getNextPageParam: (lastPage, allPages) => {
      if (lastPage.data.items.length === 0) return undefined;
      const loaded = allPages.reduce((sum, page) => sum + page.data.items.length, 0);
      return loaded < lastPage.data.total ? allPages.length + 1 : undefined;
    },
    enabled: !isPreQuery,
    placeholderData: keepPreviousData,
    staleTime: SEARCH_STALE_TIME_MS,
    gcTime: SEARCH_GC_TIME_MS,
  });

  const allSearchGames = useMemo(() => {
    const items = data?.pages.flatMap((page) => page.data.items) ?? EMPTY_ITEMS;
    const seen = new Set();
    return mapToPreview(items).filter((game) => {
      if (seen.has(game.id)) return false; // такая игра уже была на прошлой странице
      seen.add(game.id);
      return true;
    });
  }, [data]);

  return { allSearchGames, hasNextPage, isFetchingNextPage, fetchNextPage, ...rest };
}

Правильный признак конца списка

getNextPageParam не просто смотрит, пустая ли последняя страница. Он складывает, сколько элементов уже загружено, и сравнивает с total, который присылает сервер. Если загружено меньше, просит следующую страницу. Так конец списка определяется верно, даже если сервер иногда присылает неполные страницы. Мы проверили эту логику на библиотеке: при пяти элементах по два на странице загрузились ровно три страницы, и hasNextPage стал false.

keepPreviousData: поиск без мигания

Пользователь меняет фильтр — меняется ключ — для библиотеки это совершенно новый запрос, у которого данных ещё нет. Без настройки список на время загрузки станет пустым и снова заполнится: экран мигает на каждый символ.

placeholderData: keepPreviousData подставляет данные прошлого запроса, пока грузится новый. По сути это функция (previousData) => previousData, которую библиотека экспортирует готовой. Её передают, а не вызывают: keepPreviousData, без скобок.

Чтобы отличить старые данные от новых, есть флаг isPlaceholderData. Можно слегка затемнить список, пока он true, вместо того чтобы показывать скелетон.

Зачем убирать повторы

Пока пользователь листает, данные на сервере могут измениться: появилась новая игра, и все остальные сдвинулись на одну позицию. Тогда последняя игра второй страницы окажется и первой на третьей. Бесконечная прокрутка по номерам страниц не гарантирует, что страницы не пересекутся. Поэтому повторы отсекают по id через Set.

Без этого в списке появятся две одинаковые карточки, а React ещё и предупредит о повторяющихся key.

Что исправить

Только ключ: он снова набран руками. Добавляем его в фабрику в ветку games:

// queryKeys.ts
games: {
  all: () => ['games'] as const,
  search: (query: string, providerIds: string[], categoryIds: string[]) =>
    ['games', 'search', query, providerIds, categoryIds] as const,
},

// в хуке
queryKey: queryKeys.games.search(debouncedSearchQuery, appliedProviderIds, appliedCategoryIds),

Теперь invalidateQueries({ queryKey: queryKeys.games.all() }) обновит заодно и результаты поиска. Остальной код не трогаем: он написан правильно. Не переписывайте то, что работает.
