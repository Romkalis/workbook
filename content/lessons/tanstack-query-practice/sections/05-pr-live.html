Разбор 3. useLiveBalanceSync: кеш обновляется событием

Сервер сам присылает событие «баланс изменился» по каналу SSE (как он устроен, разберём в разделе про способы доставки данных). Хук ловит событие и записывает новый баланс прямо в кеш. Запроса к серверу нет, а экран обновляется мгновенно.

export function useLiveBalanceSync() {
  const queryClient = useQueryClient();
  const { subscribe } = useSSE();

  const handleBalanceUpdate = useCallback((event) => {
    // (1) меняем баланс в кеше пользователя
    queryClient.setQueryData(queryKeys.auth.me(), (oldData) => {
      if (!oldData) return oldData;
      if (event.type !== 'balance_changed') return oldData;
      const newBalance = parseFloat(event.payload.balance);
      return { ...oldData, balance: { ...oldData.balance, realAmount: newBalance } };
    });

    // (2) иногда тут же перезапрашиваем того же пользователя
    if (event.type === 'balance_changed') {
      const me = queryClient.getQueryData(queryKeys.auth.me());
      if (me && !me.hasActivity) {
        queryClient.invalidateQueries({ queryKey: queryKeys.auth.me() });
      }
    }

    // (3) так же правим кеш кошелька...
    queryClient.setQueryData(walletQueryKey, (oldWallet) => { /* ... */ return updatedWallet; });
    // ...и помечаем его устаревшим, не запрашивая сейчас
    queryClient.invalidateQueries({ queryKey: walletQueryKey, refetchType: 'none' });
  }, [queryClient]);

  useEffect(() => {
    const unsubscribe = subscribe(handleBalanceUpdate);
    return unsubscribe; // отписка, когда компонент исчезает
  }, [subscribe, handleBalanceUpdate]);
}

Функция вместо значения в setQueryData

setQueryData(key, (oldData) => newData) получает текущие данные из кеша и возвращает новые. Это надёжнее, чем прочитать данные, поменять их и записать обратно: между чтением и записью кеш мог измениться.

Обратите внимание: функция не меняет oldData, а создаёт новый объект через { ...oldData }. Это обязательно. Если изменить старый объект на месте, библиотека и React не заметят изменения, и экран не обновится.

refetchType: 'none' для кошелька

Кошелёк уже поправлен по данным события. Перезапрашивать его прямо сейчас незачем. Но событие могло принести не все поля, поэтому кеш помечается устаревшим: при следующем обращении к кошельку библиотека всё равно сходит на сервер за полной версией. Редкая, но разумная настройка.

Обсудить: запрос сразу после ручной правки

В блоке (2) после правки баланса в кеше пользователя для того же ключа вызывается invalidateQueries, причём без refetchType: 'none'. Значит, запрос уйдёт немедленно, и его ответ заменит то, что мы только что записали.

Если сервер к этому моменту уже знает новый баланс, ничего страшного: просто лишний запрос. Если не успел, баланс на экране на мгновение «откатится» к старому, а потом снова обновится. Почему здесь иначе, чем с кошельком, по коду не понять. Возможно, при первой активности у пользователя меняются и другие поля, и их нужно подтянуть. Тогда это стоит пояснить комментарием. Похожие блоки, написанные по-разному без объяснения, — частый признак случайности, а не замысла.

Вывод
