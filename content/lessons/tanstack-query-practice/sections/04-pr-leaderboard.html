Разбор 2. useLeaderboard: хороший пример

Хук загружает таблицу лидеров турнира. Здесь в основном удачные решения, которые стоит перенять, и одно место для обсуждения.

const EMPTY_ENTRIES: LeaderboardEntry[] = [];          // ← (1)

export const useLeaderboard = ({ mechanicId, isExtended = false, enabled }) => {
  const isEnabled = (enabled ?? true) && Boolean(mechanicId); // ← (2)
  const request = { filters: { mechanicId: mechanicId ?? 0 }, isExtended };

  const query = useQuery({
    queryKey: LEADERBOARD_QUERY_KEYS.leaderboard(mechanicId, isExtended),
    queryFn: ({ signal }) => leaderboardRequest(request, signal), // ← (3)
    enabled: isEnabled,
    staleTime: 60 * 1000,
    refetchOnMount: 'always',                          // ← (4)
  });

  return {
    ...query,                                          // ← (5)
    entries: query.data?.data?.entries ?? EMPTY_ENTRIES,
    entriesTotal: query.data?.data?.entriesTotal ?? 0,
    playerRank: query.data?.data?.playerRank ?? null,
  };
};

(1) Пустой массив вынесен из хука

Пока данных нет, хук возвращает пустой массив. Если написать ?? [] прямо в хуке, на каждом рендере будет создаваться новый массив. Для React два пустых массива — разные значения ([] === [] даёт false).

Компонент, у которого entries стоит в зависимостях useEffect или useMemo, будет перезапускать их на каждый рендер. А если внутри такого эффекта вызывается setState, получится бесконечный цикл перерисовок. Константа вне хука создаётся один раз и всегда одна и та же.

В исходном разборе сказано, что новый массив сам по себе даёт бесконечный ре-рендер. Это преувеличение: бесконечный цикл будет, только если эффект ещё и меняет состояние. Но лишние перезапуски будут в любом случае.

(2) Запрос не уйдёт без id

Boolean(mechanicId) в enabled гарантирует, что запрос с пустым id не отправится. Опцию enabled снаружи хук тоже уважает: можно выключить загрузку, например, пока закрыта вкладка с турниром.

(3) signal: отмена запроса

Библиотека передаёт в queryFn объект с полем signal — это AbortSignal. Если запрос стал не нужен (пользователь ушёл со страницы), библиотека «дёргает» сигнал, и настоящий HTTP-запрос обрывается. Для этого сигнал нужно передать дальше, в fetch(url, { signal }) или в axios. Здесь его передали.

(4) refetchOnMount: 'always'

При staleTime в одну минуту обычное значение true может показать таблицу из кеша, которой почти минута. Для рейтинга, где места меняются постоянно, это много. 'always' перезапрашивает данные при каждом открытии, даже свежие. Старая таблица при этом видна, пока грузится новая.

(5) Обсудить: отдавать весь query наружу?

...query выкладывает все поля библиотеки (isFetching, fetchStatus, dataUpdatedAt и ещё десятки) вперемешку с полями предметной области (entries, playerRank). Это удобно: компонент получит всё, что может понадобиться. Но граница размывается: хук перестаёт быть «таблицей лидеров» и становится «обёрткой над useQuery». Если потом поменять библиотеку, придётся переписать все компоненты.

Однозначного ответа нет. Для маленького проекта спред нормален. Для большого лучше явно перечислить нужные поля: isLoading, error, refetch.
