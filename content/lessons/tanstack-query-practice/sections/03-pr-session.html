Разбор 1. useSession: два запроса в одном хуке

Хук возвращает текущего пользователя. Внутри два запроса: данные пользователя и его избранные игры.

export const useSession = () => {
  const userQuery = useQuery({
    queryKey: queryKeys.auth.me(),
    queryFn: async () => {
      try {
        const response = await fetchCurrentSession();
        return normalizeSessionResponse(response.data);
      } catch (error) {
        const status = error?.response?.status;
        if (status === 401 || status === 403) {
          SessionManager.clearToken(); // не залогинен — это не ошибка, а «пользователя нет»
          return null;
        }
        logger.error('[useSession] Failed to fetch user data', { error });
        throw error;
      }
    },
    retry: false,
    refetchOnWindowFocus: false,
    staleTime: 5 * 60 * 1000,
  });

  const favoritesQuery = useQuery({
    queryKey: ['favorites', userQuery.data?.id],        // ← (2)
    queryFn: async () => {
      try {
        const response = await fetchSavedItems();
        return response.data;
      } catch (error) {
        logger.error('[useSession] Failed to fetch favorites', { error });
        return { total: 0, items: [] };                 // ← (3)
      }
    },
    enabled: !!userQuery.data?.id,
    staleTime: 5 * 60 * 1000,
    gcTime: 30 * 60 * 1000,
    refetchOnMount: true,                               // ← (4)
    refetchOnWindowFocus: false,
  });

  return useMemo(() => ({ userId: userQuery.data?.id || null /* ...и ещё 7 полей */ }), [/* ... */]);
};

Что хорошо

Ответы 401 и 403 обработаны осознанно: «не авторизован» превращается в null, а не в ошибку. Компонент просто увидит, что пользователя нет, и покажет кнопку входа. retry: false тоже к месту: повторять запрос без токена бессмысленно. Избранное ждёт id через enabled.

Что не так

  1. Лишний запрос у всех. useSession() вызывают в шапке, в меню, на странице профиля. И каждый раз вместе с пользователем подключается запрос избранного, даже если компоненту оно не нужно. Пока данные свежие, сеть он не нагрузит, но это лишняя работа и лишние перерисовки.
  2. Ключ набран руками. Первый запрос берёт ключ из фабрики, а второй — нет. Обновить избранное из другого места можно только повторив строку 'favorites' вручную.
  3. Ошибка проглатывается. Любой сбой превращается в пустой список. Пользователь увидит «у вас нет избранного», хотя на самом деле его просто не удалось загрузить. И библиотека не повторит запрос: для неё он успешен.
  4. Опция, которая ничего не делает. refetchOnMount: true — значение по умолчанию. Строка выглядит как осознанная настройка, и читатель тратит время, пытаясь понять, зачем она.

Как исправить

Добавляем ключ в фабрику и выносим избранное в отдельный хук. Его подключат только те компоненты, которым избранное действительно нужно.

// queryKeys.ts
favorites: {
  all: () => ['favorites'] as const,
  byUser: (userId: string) => ['favorites', userId] as const,
},

// useSavedItems.ts — новый хук
export const useSavedItems = (userId: string | null) => {
  const query = useQuery({
    queryKey: queryKeys.favorites.byUser(userId ?? ''),
    queryFn: async () => (await fetchSavedItems()).data, // ошибка уходит наружу
    enabled: !!userId,
    staleTime: 5 * 60 * 1000,
    gcTime: 30 * 60 * 1000,
  });
  return { favorites: query.data, isLoading: query.isLoading, error: query.error };
};

// в компоненте, где нужно избранное
const { userId } = useSession();
const { favorites, error } = useSavedItems(userId);

Из useSession запрос избранного просто удаляется. Пустая строка в byUser(userId ?? '') нужна только для типов: пока userId нет, enabled равен false, и запрос с таким ключом не уйдёт.

Правило

Держите запросы в одном хуке, если почти всем, кто его вызывает, нужны оба результата. Если второй нужен только части компонентов, выносите его в отдельный хук: пусть компонент сам решает, подключать его или нет.
