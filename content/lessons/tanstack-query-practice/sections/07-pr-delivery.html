Как получать свежие данные: запрос, опрос, SSE, WebSocket

Есть четыре способа узнать, что на сервере что-то изменилось. Они идут от простого «спросил один раз» до «сервер сам сообщает об изменениях».

1. Обычный запрос

Клиент спрашивает, сервер отвечает, соединение закрывается. Именно так работает useQuery по умолчанию.

Плюсы: проще некуда, работает через обычный HTTP, TanStack Query умеет кешировать, повторять и отменять такие запросы.

Минусы: данные устаревают молча. Чтобы узнать новое, нужен внешний повод: фокус окна, новое открытие страницы, ручное обновление.

Когда хватает: профиль, каталог, история заказов — всё, что пользователь готов увидеть «почти свежим».

2. Опрос по таймеру (polling)

Тот же обычный запрос, только повторяется каждые N секунд, независимо от того, изменилось что-то или нет.

Плюсы: в TanStack Query это одна строка refetchInterval. Работает через ту же инфраструктуру, что и обычные запросы.

Минусы: большинство запросов пустые, они тратят трафик, батарею и ресурсы сервера. А задержка может достигать целого интервала: если баланс изменился сразу после опроса, вы узнаете об этом только через N секунд.

Когда хватает: изменения редкие и задержка не критична. Статус долгой задачи, курс валют раз в минуту.

3. SSE (Server-Sent Events)

Клиент открывает одно соединение, и оно остаётся открытым. Сервер пишет в него события, когда они случаются. Опрашивать не нужно.

Плюсы: настоящие уведомления без опроса, задержка минимальная. Это обычный HTTP с простым текстовым форматом. В браузере есть готовый класс EventSource, который сам переподключается при обрыве.

Минусы: только от сервера к клиенту; чтобы отправить данные, нужен обычный запрос. Некоторые старые прокси копят потоковый ответ и отдают его пачкой, и события приходят с опозданием. Из общих знаний: EventSource не умеет добавлять свои заголовки (например, Authorization), поэтому авторизацию обычно передают через cookie.

Пример из курса: хук useLiveBalanceSync из разбора 3 получает баланс по SSE и записывает его в кеш без единого запроса.

// как связать SSE с TanStack Query, упрощённо
useEffect(() => {
  const source = new EventSource('/api/events');
  source.addEventListener('balance_changed', () => {
    queryClient.invalidateQueries({ queryKey: ['balance'] }); // или setQueryData с данными события
  });
  return () => source.close();
}, [queryClient]);

4. WebSocket

Тоже одно долгое соединение, но двустороннее: и клиент, и сервер могут писать в любой момент, независимо друг от друга.

Плюсы: полноценная связь в обе стороны, мало накладных расходов на каждое сообщение.

Минусы: свой протокол (ws://, wss://) и свои требования к серверам и балансировщикам. Переподключение, паузы между попытками и повторную отправку потерянных сообщений нужно писать самим: готового, как у EventSource, в браузере нет. Если нужно только «сообщи, когда что-то изменилось», это избыточно.

Когда действительно нужен: чат, совместное редактирование документа, онлайн-игра, аукцион — там, где обе стороны постоянно что-то отправляют.

Начинайте с простого. Обычного запроса с refetchOnWindowFocus хватает большинству экранов. Опрос добавляйте, когда нужно следить за изменениями. SSE — когда опрос становится слишком частым. WebSocket — когда клиенту тоже нужно постоянно отправлять данные.
