Отмена устаревших запросов

Свяжем всё вместе в модуле поиска. Он не знает про DOM: получает текст из поля и сообщает новое состояние через колбэк onState. Рисовать по этому состоянию будет слой интерфейса.

export type State =
  | { kind: 'idle' }
  | { kind: 'loading'; query: string }
  | { kind: 'results'; query: string; items: CountryCard[] }
  | { kind: 'empty'; query: string }
  | { kind: 'error'; query: string; reason: ErrorKind };

export function createSearch(onState: (s: State) => void, delay = 300) {
  let controller: AbortController | null = null;
  let lastQuery = '';

  async function run(query: string): Promise<void> {
    controller?.abort();
    const own = new AbortController();
    controller = own;
    onState({ kind: 'loading', query });
    try {
      const items = (await searchCountries(query, own.signal)).map(mapCountryResponse);
      onState(items.length ? { kind: 'results', query, items } : { kind: 'empty', query });
    } catch (err) {
      const reason = classifyError(err);
      if (reason === 'aborted') return;           // свою отмену не показываем
      onState({ kind: 'error', query, reason });
    }
  }
  const debouncedRun = debounce(run, delay);

  return {
    input(value: string): void {
      controller?.abort();                         // на КАЖДЫЙ ввод
      controller = null;
      lastQuery = value.trim();
      if (!lastQuery) {
        debouncedRun.cancel();
        onState({ kind: 'idle' });
        return;
      }
      debouncedRun(lastQuery);
    },
    retry: (): Promise<void> => run(lastQuery),
  };
}

Почему abort стоит в input, а не только в run

Условие отдельно оценивает это в 15 баллов. Разберём по времени, задержка debounce 300 мс:

ВремяСобытиеAbort только в runAbort в input
0набрали «sp», через 300 мс ушёл запрос Aзапрос A в полёте
500дописали «spain»A живёт, debounce ждётA отменён сразу
600пришёл ответ Aна экране страны по «sp» под текстом «spain»ничего не происходит
800ушёл запрос B по «spain»A уже отрисованB в полёте

Пока debounce ждёт паузу, старый запрос успевает ответить. Поэтому гасим его в момент ввода. Вызов abort() в run тоже оставлен: он нужен для «Повторить», которую можно нажать, пока предыдущая попытка ещё летит.

Зачем локальная переменная own

Каждый запуск получает свой контроллер и передаёт в fetch именно его сигнал. Отменённый запрос попадает в catch с AbortError и выходит, не трогая состояние. Значит, после await не нужно проверять «а мой ли это ещё запрос»: устаревший запрос просто не дойдёт до onState.

Чем плох флаг «актуальный ли ответ»

Можно хранить номер последнего запроса и игнорировать ответы с меньшим номером. Экран будет верным, но:

  • запрос продолжает идти: тратит трафик и соединение браузера, а сервер отрабатывает его зря;
  • в Network старые запросы не помечаются как отменённые, а это пункт чек-листа;
  • проверку легко забыть в одной из веток (например, в catch), и устаревшая ошибка перекроет свежие результаты.

Условие прямо запрещает такой костыль без настоящей отмены. Этот список — готовый ответ на первый пункт DESIGN.md.
