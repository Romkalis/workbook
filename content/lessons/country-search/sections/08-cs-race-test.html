Тест на гонку запросов

Это отдельный коммит за 10 баллов. Тест должен воспроизвести плохой сценарий: ранний запрос отвечает позже позднего. И главное требование: мок fetch слушает переданный signal и отклоняет промис при abort(). Без этого тест пройдёт и у решения с флагом, то есть ничего не докажет.

const tick = () => new Promise((r) => setTimeout(r, 5));

test('поздний ответ на "sp" не перезаписывает "spain"', async () => {
  const pending: Record<string, () => void> = {};
  const aborted: string[] = [];

  vi.stubGlobal('fetch', (url: string, init: RequestInit) =>
    new Promise((resolve, reject) => {
      const q = decodeURIComponent(url.split('/').pop()!);
      init.signal!.addEventListener('abort', () => {
        aborted.push(q);
        reject(init.signal!.reason);               // ведём себя как настоящий fetch
      });
      pending[q] = () => resolve(Response.json([{ name: q }]));
    }));

  const states: State[] = [];
  const search = createSearch((s) => states.push(s), 0);

  search.input('sp');    await tick();           // запрос "sp" в полёте
  search.input('spain'); await tick();           // "sp" отменён, "spain" в полёте

  pending['spain']();                            // поздний отвечает первым
  pending['sp']();                               // ранний — после
  await tick();

  expect(aborted).toEqual(['sp']);
  expect(states.at(-1)).toMatchObject({ kind: 'results', items: [{ name: 'spain' }] });
  expect(states.some((s) => s.kind === 'error')).toBe(false);
});

Задержка debounce здесь 0, чтобы не возиться с таймерами. Три проверки закрывают три требования: старый запрос действительно отменён, итоговое состояние — от последнего запроса, отмена не показана как ошибка. Эквивалентный тест на node:test запущен и проходит.

Убедитесь, что тест умеет падать: временно уберите controller?.abort() из input и run. Тест должен покраснеть. Тест, который не падает на сломанном коде, бесполезен.
