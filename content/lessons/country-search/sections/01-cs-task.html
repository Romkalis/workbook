О чём задание

Country Search — живой поиск стран через публичный API countries.dev: пользователь печатает, приложение само отправляет запросы и показывает карточки. Вёрстка здесь вторична. Задание проверяет, умеете ли вы справиться с гонкой устаревших ответов.

Представьте: вы набрали sp, запрос ушёл. Потом дописали до spain, ушёл второй запрос. Сеть не обещает, что ответы придут в том же порядке. Если ответ на sp задержался, он придёт последним и перерисует экран: в поле написано «spain», а в списке все страны, где встречается «sp». Пользователь видит неверный результат, хотя каждый запрос по отдельности отработал правильно.

Лечение, которого требует задание, — настоящая отмена старого запроса через AbortController, а не флаг «этот ответ уже неактуален». Об этом подробно в разделе про отмену.

Что отвечает API

GET https://countries.dev/name/{query} не требует ключа и отдаёт заголовок access-control-allow-origin: *, поэтому к нему можно обращаться прямо из браузера (что такое CORS). Проверено запросами 15.11.2026:

ЗапросСтатусТело
/name/spain200массив объектов: name, flags.svg, capital, region, population, area, borders, languages[], currencies[]
/name/zzzz404текст Country not found, не JSON

Поля бывают не у всех стран: например, у «United States Minor Outlying Islands» нет capital. Типизируйте такие поля как необязательные. И ещё: условие просит в детальном виде показать «описание», но поля с описанием в ответе нет. Честно покажите то, что есть (субрегион, самоназвание, часовые пояса), и упомяните это в DESIGN.md.

План работы

  1. Настроить TypeScript, ESLint, Prettier, Husky и тестовый раннер.
  2. Для каждой обязательной функции: коммит с падающими тестами, затем коммит с реализацией.
  3. Отдельным коммитом — тест на гонку.
  4. Интерфейс: состояния, карточки, детальный вид, «Повторить».
  5. DESIGN.md, деплой, PR, чек-лист.
