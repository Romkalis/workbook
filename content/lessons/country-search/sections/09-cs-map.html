mapCountryResponse

Ответ API большой и «сырой», а карточке нужны шесть полей. Чистая функция (результат зависит только от аргумента, побочных эффектов нет) превращает одно в другое. Интерфейс тогда не зависит от формы ответа: если API поменяется, правится одна функция.

export interface RawCountry {
  name: string;
  flags?: { svg?: string; png?: string };
  capital?: string;
  region?: string;
  population?: number;
  languages?: { name: string }[];
  // area, borders, currencies, subregion — для детального вида
}

export interface CountryCard {
  name: string; flagUrl: string; capital: string;
  region: string; population: number; languages: string[];
}

export function mapCountryResponse(raw: RawCountry): CountryCard {
  return {
    name: raw.name,
    flagUrl: raw.flags?.svg ?? raw.flags?.png ?? '',
    capital: raw.capital ?? '—',
    region: raw.region ?? '—',
    population: raw.population ?? 0,
    languages: (raw.languages ?? []).map((l) => l.name),
  };
}

?. и ?? спасают от стран без столицы или языков. Тестируйте на заготовленных JSON: сохраните реальный ответ /name/spain в tests/fixtures/spain.json и сделайте второй, урезанный, без capital и languages.

В старых материалах про restcountries.com v3.1 name был объектом (name.common), а languages — словарём. У countries.dev name — строка, capital — строка, languages и currencies — массивы объектов. Код из старых решений без правок работать не будет.

Сложность для DESIGN.md

Обозначим L — число языков страны. Копирование полей — O(1), map по языкам — O(L). Итого O(L) по времени и памяти на одну страну. Для всего ответа из N стран — O(N·L). L на практике единицы, так что фактически линейно по числу стран. Если вы форматируете население через toLocaleString, это O(число цифр), то есть тоже константа.
