TDD и порядок коммитов

Проверяющий открывает вкладку Commits в PR и смотрит порядок. Нарушение стоит −50 баллов, так что спланируйте коммиты заранее. Что такое TDD и принципы FIRST, разобрано в Тестировании JavaScript.

№КоммитТесты
1init: setup typescript, eslint, prettier, husky, vitestнет, проходит пустой набор
2–3test: add debounce tests → feat: implement debounceкрасные → зелёные
4–5test: add searchCountries tests → feat: implement searchCountries and HttpErrorкрасные → зелёные
6–7test: add mapCountryResponse tests → feat: implement mapCountryResponseкрасные → зелёные
8–9test: add error classification tests → feat: implement classifyErrorкрасные → зелёные
10test: add request race testотдельный коммит, после базовой логики
11+feat: render ..., docs: add DESIGN.mdзелёные

Типы сообщений взяты из конвенции RS School. Красный коммит должен компилироваться: создайте файл функции с заглушкой (throw new Error('not implemented')), иначе тест упадёт на импорте, а не на проверке.

Чтобы закоммитить красный тест, хук pre-commit не должен запускать тесты. Если вы всё-таки получили отказ, проверьте .husky/pre-commit, а не обходите его флагом --no-verify.
