Различаем ошибки

Четвёртая обязательная «функция» — логика различения ошибок. Вынесите её в отдельную чистую функцию: так её легко протестировать, а catch в поиске остаётся коротким.

export type ErrorKind = 'aborted' | 'timeout' | 'http' | 'network';

export function classifyError(err: unknown): ErrorKind {
  if (err instanceof DOMException && err.name === 'AbortError') return 'aborted';
  if (err instanceof DOMException && err.name === 'TimeoutError') return 'timeout';
  if (err instanceof HttpError) return 'http';
  return 'network';
}

В catch TypeScript типизирует ошибку как unknown (при strict), поэтому сравнивать поля без проверки типа нельзя. instanceof сужает тип, и после него err.name доступен. Случай 404 сюда не попадает вовсе: searchCountries уже превратила его в пустой массив.

test.each([
  [new DOMException('', 'AbortError'), 'aborted'],
  [new DOMException('', 'TimeoutError'), 'timeout'],
  [new HttpError(500), 'http'],
  [new TypeError('Failed to fetch'), 'network'],
])('%s → %s', (err, kind) => {
  expect(classifyError(err)).toBe(kind);
});

Частая ошибка — проверять err.name === 'AbortError' и молча выходить, считая таймаут тоже «отменой». Тогда при зависшем сервере пользователь видит вечную загрузку или пустой экран. Таймаут — настоящая ошибка, за её отдельное распознавание дают баллы.
