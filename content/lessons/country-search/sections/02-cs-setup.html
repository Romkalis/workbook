Настройка проекта

Бандлер не нужен: TypeScript компилируется через tsc в ES-модули, а index.html подключает результат через <script type="module">. В tsconfig.json достаточно "module": "ES2022", "target": "ES2022", "strict": true, "lib": ["ES2022", "DOM"] и "outDir": "dist". Подробнее про опции — в TypeScript Basic.

Без бандлера браузер сам грузит модули по путям из import. Поэтому в исходниках пишите импорт с расширением .js: import { debounce } from './debounce.js'. TypeScript поймёт, что речь о debounce.ts, а в браузере путь будет верным.

Скрипты и хуки

"scripts": {
  "build": "tsc",
  "lint": "eslint .",
  "format": "prettier --write .",
  "test": "vitest run --passWithNoTests"
}

Флаг --passWithNoTests закрывает требование про самый первый коммит: тестов ещё нет, а npm test должен пройти. В Jest аналогичный флаг называется так же.

Хук HuskyЧто запускаетПочему именно так
pre-commitnpx lint-stagedТесты здесь запускать нельзя: первый шаг TDD — коммит с падающими тестами, и хук бы его заблокировал.
pre-pushnpm testКрасный коммит нельзя отправить один, только вместе с зелёным. Так пара «тесты → реализация» уходит одним push.

Как устроены ESLint, Prettier, lint-staged и Husky, разобрано в уроке Линтеры, форматтеры и Husky.

Структура файлов

Логика не должна знать о DOM: её тестируют без браузера. Удобно разложить так (из общих знаний, условие структуру не задаёт):

src/
  lib/debounce.ts      debounce
  lib/http-error.ts    HttpError
  lib/api.ts           searchCountries
  lib/map-country.ts   mapCountryResponse, типы
  lib/errors.ts        classifyError
  lib/search.ts        createSearch: отмена, состояния
  ui/render.ts         DOM: карточки, состояния, детальный вид
  main.ts              точка входа
tests/                 *.test.ts
