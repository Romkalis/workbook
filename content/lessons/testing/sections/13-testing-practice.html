Как проверить качество решения?

Каждый сценарий запускается отдельно и без сети. При намеренной мутации входа соответствующий тест падает. При удалении проверки верхней границы падает случай 101. Отклонение Promise действительно ожидается через await. Названия объясняют поведение, а ожидаемые значения не повторяют вычисления функции.

Следующий шаг: проверить настоящую связь

Из общих знаний: отдельно поднимите локальный тестовый HTTP-сервер с фиксированным ответом и обратитесь к нему настоящим клиентом. Проверьте URL, статус, разбор JSON и реакцию на ошибку. Остановите сервер после теста. Это упражнение на интеграцию; приведённые выше подмены fetchMovie его не заменяют.

Для E2E сценария задайте путь: открыть каталог → ввести запрос → увидеть результат → очистить запрос. Укажите, используется ли настоящий тестовый backend или подмена. Проверьте состояние загрузки, ошибку, повторную попытку и доступность с клавиатуры.

Задача 23. Интеграционный тест с настоящим HTTP-сервером ★★★ с подвохом

Напишите клиент fetchProducts(baseUrl): делает GET {baseUrl}/api/products, при статусе не 2xx бросает Error с кодом в тексте, иначе возвращает JSON. Протестируйте его с настоящим локальным сервером на node:http: успешный ответ, ответ 500 и проверку, что клиент запросил правильный путь. Сервер поднимайте в before на свободном порту и закрывайте в after.

Зачем: подмены проверяют реакцию кода на задуманный вами ответ, но не совместимость с настоящим HTTP: путь, статус, заголовки, разбор JSON. Интеграционный тест закрывает этот разрыв, оставаясь быстрым и без интернета.

Подсказка

server.listen(0) даёт свободный порт, узнать его можно через server.address().port. Как устроен http.createServer, разобрано в уроке про Node.js.

Решение и разбор
// client.mjs
export async function fetchProducts(baseUrl) {
  const res = await fetch(`${baseUrl}/api/products`);
  if (!res.ok) throw new Error(`Сервер ответил ${res.status}`);
  return res.json();
}
// client.test.mjs
import { describe, it, before, after } from 'node:test';
import assert from 'node:assert/strict';
import http from 'node:http';
import { fetchProducts } from './client.mjs';

describe('fetchProducts с настоящим сервером', () => {
  let server;
  let baseUrl;
  let status = 200;
  const requested = [];

  before(async () => {
    server = http.createServer((req, res) => {
      requested.push(req.url);
      res.writeHead(status, { 'Content-Type': 'application/json' });
      res.end(JSON.stringify(status === 200 ? [{ id: 1, title: 'Чистый код' }] : { error: 'boom' }));
    });
    await new Promise((resolve) => server.listen(0, resolve));
    baseUrl = `http://localhost:${server.address().port}`;
  });

  after(() => new Promise((resolve) => server.close(resolve)));

  it('получает товары и запрашивает правильный путь', async () => {
    status = 200;
    assert.deepEqual(await fetchProducts(baseUrl), [{ id: 1, title: 'Чистый код' }]);
    assert.equal(requested.at(-1), '/api/products');
  });

  it('ответ 500 превращается в ошибку с кодом', async () => {
    status = 500;
    await assert.rejects(() => fetchProducts(baseUrl), /500/);
  });
});

Порт 0 просит систему выдать любой свободный порт: тесты не конфликтуют с запущенным dev-сервером и друг с другом. after закрывает сервер, иначе процесс теста не завершится. Мутант с неверным путём и без проверки статуса ловят оба теста. Это ровно то, что не поймала бы подмена fetch, возвращающая нужный ответ на любой адрес. Сам сервер здесь тоже подмена (не ваш настоящий бэкенд), но HTTP настоящий. Совместимость с вашим API проверяют тестами на стороне сервера, как в уроке Express на TypeScript.
