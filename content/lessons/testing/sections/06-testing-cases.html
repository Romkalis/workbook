Как выбирать сценарии, а не случайные числа

Из общих знаний: разделите входы на группы, которые должны обрабатываться одинаково. Затем возьмите представителей и границы. Для допустимой скидки 0…100 группы — корректные конечные числа, числа ниже и выше диапазона и нечисловые значения.

Классы эквивалентности и граничные значения

ГруппаПримерыОжидание
Границы диапазона0 и 100Принять
Внутри10Применить скидку
Снаружи−1 и 101Отклонить
Нечисловые / неконечные"10", NaN, InfinityОтклонить по контракту
Структура данныхПустая корзина, один товарКорректный результат и отсутствие мутации

Не нужно проверять все числа между 0 и 100. Нужно выбрать случаи, различающие правдоподобные ошибки: например, условие percent > 0 вместо percent >= 0 обнаружит проверка нулевой границы.

Задача 7. Границы допустимого количества ★★☆ практика

Функция isValidQuantity(n, stock) разрешает целые числа от 1 до остатка включительно. Составьте таблицу классов (внутри, границы, снаружи, нечисловые) и напишите тесты по ней параметризацией через for.

// qty.mjs
export function isValidQuantity(n, stock) {
  return Number.isInteger(n) && n >= 1 && n <= stock;
}

Зачем: каждое значение в таблице проверяет конкретную правдоподобную ошибку: < вместо <=, забытую проверку целого числа, ноль. Случайные числа «из середины» таких ошибок не находят.

Решение и разбор
// qty.test.mjs
import { test } from 'node:test';
import assert from 'node:assert/strict';
import { isValidQuantity } from './qty.mjs';

const STOCK = 5;

for (const n of [1, 3, 5]) {
  test(`допустимо: ${n} при остатке ${STOCK}`, () => {
    assert.equal(isValidQuantity(n, STOCK), true);
  });
}

for (const n of [0, 6, -1, 2.5, NaN, Infinity, '2']) {
  test(`недопустимо: ${typeof n} ${String(n)}`, () => {
    assert.equal(isValidQuantity(n, STOCK), false);
  });
}

1 и 5 — границы внутри диапазона, 0 и 6 — сразу за ними. Мутант с < stock отклонит 5 и упадёт на тесте «допустимо: 5». Строка '2' проверяет, что функция не приводит типы: в форме значение приходит строкой, и превращать его в число — работа другого слоя. В названии теста typeof: без него 2 и '2' выглядели бы в отчёте одинаково.

Несколько случаев одного правила

import test from 'node:test';
import assert from 'node:assert/strict';

function validPercent(value) {
  return Number.isFinite(value) && value >= 0 && value <= 100;
}
for (const value of [0, 10, 100]) {
  test(`допустимая скидка ${value}`, () => {
    assert.equal(validPercent(value), true);
  });
}
for (const value of [-1, 101, NaN, Infinity, '10']) {
  test(`недопустимая скидка ${typeof value}: ${String(value)}`, () => {
    assert.equal(validPercent(value), false);
  });
}

Ожидаемый результат здесь задан требованиями. Если вычислить его той же формулой, что и внутри функции, одинаковая ошибка может оказаться и в коде, и в проверке. Для регрессии сначала воспроизведите конкретный найденный дефект, затем добавьте проверку ожидаемого поведения.

Задача 8. Таблица для промокода ★☆☆ разминка

Промокод допустим, если состоит из 4–10 заглавных латинских букв и цифр. Напишите isPromoFormat(code) и проверьте её таблицей: по три допустимых и пять недопустимых примеров с комментарием, какую ошибку ловит каждый.

Зачем: таблица с комментарием «что ловит» превращает тесты в спецификацию. Через месяц понятно, зачем здесь 'SALE 10' и можно ли его удалить.

Решение и разбор
// promo.mjs
export function isPromoFormat(code) {
  return /^[A-Z0-9]{4,10}$/.test(code);
}
// promo.test.mjs
import { test } from 'node:test';
import assert from 'node:assert/strict';
import { isPromoFormat } from './promo.mjs';

const valid = [
  'SALE', // нижняя граница длины
  'SALE10',
  'ABCDEFGH10', // верхняя граница длины
];
const invalid = [
  'SAL', // короче 4
  'ABCDEFGHIJK', // длиннее 10
  'sale10', // строчные
  'SALE 10', // пробел внутри
  'SALE10\n', // перенос строки в конце: ловит регулярку без $ или с multiline
];

for (const code of valid) test(`допустим ${JSON.stringify(code)}`, () => assert.equal(isPromoFormat(code), true));
for (const code of invalid) test(`недопустим ${JSON.stringify(code)}`, () => assert.equal(isPromoFormat(code), false));

JSON.stringify в названии показывает невидимые символы: "SALE10\n" вместо загадочного пустого места. Обе границы длины проверены с двух сторон: 4 и 3, 10 и 11. Комментарий к каждому значению — дешёвая документация: видно, что пробел и строчные проверяются намеренно.
