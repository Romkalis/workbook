Как выбирать сценарии, а не случайные числа

Из общих знаний: разделите входы на группы, которые должны обрабатываться одинаково. Затем возьмите представителей и границы. Для допустимой скидки 0…100 группы — корректные конечные числа, числа ниже и выше диапазона и нечисловые значения.

Классы эквивалентности и граничные значения

ГруппаПримерыОжидание
Границы диапазона0 и 100Принять
Внутри10Применить скидку
Снаружи−1 и 101Отклонить

Структура данныхПустая корзина, один товарКорректный результат и отсутствие мутации

Не нужно проверять все числа между 0 и 100. Нужно выбрать случаи, различающие правдоподобные ошибки: например, условие percent > 0 вместо percent >= 0 обнаружит проверка нулевой границы.

Несколько случаев одного правила

import test from 'node:test';
import assert from 'node:assert/strict';

function validPercent(value) {
  return Number.isFinite(value) && value >= 0 && value <= 100;
}
for (const value of [0, 10, 100]) {
  test(`допустимая скидка ${value}`, () => {
    assert.equal(validPercent(value), true);
  });
}
for (const value of [-1, 101, NaN, Infinity, '10']) {
  test(`недопустимая скидка ${typeof value}: ${String(value)}`, () => {
    assert.equal(validPercent(value), false);
  });
}

Ожидаемый результат здесь задан требованиями. Если вычислить его той же формулой, что и внутри функции, одинаковая ошибка может оказаться и в коде, и в проверке. Для регрессии сначала воспроизведите конкретный найденный дефект, затем добавьте проверку ожидаемого поведения.
