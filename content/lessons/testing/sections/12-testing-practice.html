Практика: соберите маленький набор проверок

Возьмите исправленную applyDiscount из урока Code Review и сохраните в отдельном учебном файле вместе с импортами test и assert. Сначала запишите ожидаемые значения на бумаге, затем добавляйте тесты.

Задания

  • Цена 100, скидка 10 → цена 90; исходная корзина остаётся прежней.
  • Пустая корзина → пустой результат; скидки 0 и 100 разрешены.
  • −1, 101, NaN, Infinity и строка "10" → RangeError.
  • Результирующий товар — другой объект, но имя товара сохранено.
  • Для loadTitle из раздела асинхронности проверьте пустую строку title. Сейчас она разрешена: если это неверно по новым требованиям, сначала добавьте падающий тест и измените контракт.
Как проверить качество решения?

Каждый сценарий запускается отдельно и без сети. При намеренной мутации входа соответствующий тест падает. При удалении проверки верхней границы падает случай 101. Отклонение Promise действительно ожидается через await. Названия объясняют поведение, а ожидаемые значения не повторяют вычисления функции.

Следующий шаг: проверить настоящую связь

Из общих знаний: отдельно поднимите локальный тестовый HTTP-сервер с фиксированным ответом и обратитесь к нему настоящим клиентом. Проверьте URL, статус, разбор JSON и реакцию на ошибку. Остановите сервер после теста. Это упражнение на интеграцию; приведённые выше подмены fetchMovie его не заменяют.

Для E2E сценария задайте путь: открыть каталог → ввести запрос → увидеть результат → очистить запрос. Укажите, используется ли настоящий тестовый backend или подмена. Проверьте состояние загрузки, ошибку, повторную попытку и доступность с клавиатуры.
