Подмены: stub, spy, mock и fake

Из общих знаний: тестовая подмена заменяет зависимость, чтобы управлять условиями или наблюдать взаимодействие. Термины у библиотек пересекаются, поэтому важнее объяснить, что именно заменено и что проверяется.

Stub
Возвращает заранее выбранные данные или ошибку.
Spy
Записывает вызовы: аргументы и число обращений; иногда оборачивает настоящую функцию.
Mock
Подмена с проверяемыми ожиданиями взаимодействия; в runner этим словом часто называют и более общие функции-подмены.
Fake
Упрощённая работающая реализация, например хранилище в памяти вместо базы.

Передайте зависимость явно

Вместо настоящей отправки письма передадим функцию send. Это делает тест быстрым и позволяет проверить публично значимый эффект: кому отправлено уведомление. Почтовый сервер этот тест не проверяет.

import test from 'node:test';
import assert from 'node:assert/strict';

async function notify(email, send) {
  await send({ to: email, subject: 'Заказ принят' });
  return 'sent';
}
test('отправляет одно подтверждение нужному получателю', async () => {
  const calls = [];
  const send = async message => { calls.push(message); };
  const result = await notify('student@example.com', send);
  assert.equal(result, 'sent');
  assert.deepEqual(calls, [
    { to: 'student@example.com', subject: 'Заказ принят' }
  ]);
});

Где подмена перестаёт помогать

У подмен две типичные ошибки. Первая — подменить саму проверяемую функцию. Тогда тест проверяет только то, что подмена вернула заданный вами ответ, а настоящий код не выполняется вовсе. Вторая — проверять каждый внутренний вызов: «сначала вызвали format, потом round». Такой тест упадёт, как только вы перепишете код по-другому, даже если результат остался верным. Подменяйте только внешнее (сеть, время, базу) и проверяйте результат, а не порядок шагов внутри.

Подменяйте внешнюю границу, когда её реальная работа не является целью теста. Взаимодействие проверяйте, когда оно само часть контракта: например, не отправить письмо дважды. Совместимость с настоящим сервисом проверяйте отдельно интеграционным тестом или тестом контракта.
