FIRST: свойства полезных тестов

FIRST — памятка о качестве тестов. Это не отдельный вид тестирования и не команда конкретного фреймворка. Её особенно удобно применять к модульным тестам.

Fast — быстрые
Часто запускаются и быстро дают ответ. Расчёт суммы не должен ждать настоящую сеть.
Independent — независимые
Не требуют, чтобы перед ними прошёл другой тест; каждый готовит свои данные.
Repeatable — повторяемые
Результат не зависит случайно от часов, сети и оставшихся файлов.
Self-validating — самопроверяющиеся
Программа выдаёт успех или ошибку по проверке, человеку не нужно сравнивать логи глазами.
Timely — своевременные
Пишутся тогда, когда помогают формировать поведение и ловить дефект; в TDD — перед реализацией следующего шага.

Одна буква — разные названия

FIRST пересказывают по-разному, и в тестах и статьях встречаются другие названия тех же свойств. Чтобы не запутаться, ориентируйтесь на смысл, а не на слово:

БукваНазванияУзнать по формулировке
FFast, Speed — быстрота«тесты выполняются быстро, их не лень запускать часто»
IIndependent, Independence — независимость«нет зависимости от порядка запуска: тест проходит или падает одинаково в наборе и в одиночку»
RRepeatable, Repeatability — повторяемость«тест не зависит от данных окружения, в котором запущен: машины, часов, сети, файлов»
SSelf-validating, иногда Obviousness — самопроверка, очевидность«не нужна ручная проверка, прошёл тест или нет»
TTimely, Thorough — своевременность, тщательность«тест написан вовремя (в TDD — до кода)» или «проверены не только удачные, но и граничные и ошибочные случаи»

Чаще всего путают I и R. Подсказка: Independence — про другие тесты (порядок, общее состояние), Repeatability — про окружение (на другой машине, завтра, без интернета результат тот же). «Coverage» (покрытие) в FIRST не входит.

Общее состояние и очистка

Из общих знаний: создавайте новый объект для каждого теста. Если меняете глобальные часы, окружение или подменяете модуль, восстанавливайте их после проверки. beforeEach/afterEach помогают с повторяющейся подготовкой и очисткой, но не должны скрывать от читателя важные условия сценария.

В node:test тесты группируют через describe и it (синоним test), а подготовку и очистку пишут в хуках beforeEach и afterEach. Хук выполняется перед каждым и после каждого теста группы, причём afterEach срабатывает и после упавшего теста:

import { describe, it, beforeEach, afterEach } from 'node:test';
import assert from 'node:assert/strict';

describe('корзина', () => {
  let cart;
  beforeEach(() => {
    cart = [{ id: 1, quantity: 1 }]; // у каждого теста свежая корзина
  });
  afterEach(() => {
    // здесь возвращают на место то, что тест менял глобально: часы, process.env
  });

  it('содержит один товар', () => {
    assert.equal(cart.length, 1);
  });
});

Есть и before/after: они выполняются один раз на всю группу. Их используют для дорогой подготовки вроде запуска тестового сервера.

Прохождение только при определённом порядке — признак зависимости. Случайное падение называют flaky: сначала ищите неуправляемое время, гонку, общие данные и нестабильную внешнюю службу. Повторный запуск может помочь расследованию, но сам по себе не исправляет причину.

Не подменяйте проверку логированием

console.log полезен при отладке, но тесту нужно утверждение, которое приводит к ошибке при неверном результате. «Посмотрел вывод — вроде правильно» не даёт автоматической обратной связи.

Задача 4. Свои данные каждому тесту через beforeEach ★★☆ практика

Тесты ниже зависят от порядка: второй ожидает, что первый уже добавил товар. Убедитесь сами: node --test --test-name-pattern="второй" запускает только второй тест, и он падает. Перепишите их с describe и beforeEach так, чтобы каждый тест получал свежую корзину и проходил сам по себе.

// starter.mjs
const cart = new Cart();
test('добавляет товар', () => {
  cart.add({ id: 1, price: 100 });
  assert.equal(cart.count(), 1);
});
test('второй товар увеличивает счётчик', () => {
  cart.add({ id: 2, price: 50 });
  assert.equal(cart.count(), 2);
});
// cart.mjs
export class Cart {
  #items = new Map();
  add(item) {
    this.#items.set(item.id, item);
  }
  remove(id) {
    this.#items.delete(id);
  }
  count() {
    return this.#items.size;
  }
}

Зачем: Independent из FIRST: тест должен падать или проходить одинаково в наборе и в одиночку. Иначе запуск одного теста (--test-name-pattern) даёт ложное падение, а смена порядка — загадочные «мигающие» результаты.

Решение и разбор
// cart.test.mjs
import { describe, it, beforeEach } from 'node:test';
import assert from 'node:assert/strict';
import { Cart } from './cart.mjs';

describe('Cart', () => {
  let cart;

  beforeEach(() => {
    cart = new Cart();
    cart.add({ id: 1, price: 100 });
  });

  it('добавленный товар учитывается', () => {
    assert.equal(cart.count(), 1);
  });

  it('второй товар увеличивает счётчик', () => {
    cart.add({ id: 2, price: 50 });
    assert.equal(cart.count(), 2);
  });

  it('удалённый товар больше не учитывается', () => {
    cart.remove(1);
    assert.equal(cart.count(), 0);
  });
});

beforeEach выполняется перед каждым it, поэтому у каждого теста новая корзина с одним товаром. Теперь каждый тест сам получает условие «в корзине есть товар», а не надеется на соседа. Проверка: node --test --test-name-pattern="второй" теперь проходит, а исходная версия при таком запуске падала (мы проверили: 1 из 1 упал). Обратите внимание на тест удаления в исходном наборе урока: «удалить из пустой корзины и получить 0» проходит и в одиночку. Зависимость от порядка видна не всегда, поэтому свежие данные готовят в каждом тесте заранее, а не после того, как что-то «замигало».

Задача 5. Вернуть окружение на место ★★☆ практика

Функция читает валюту из process.env.CURRENCY. Напишите два теста: с CURRENCY=USD и без переменной (по умолчанию рубли). Тесты должны восстанавливать исходное значение переменной в afterEach, даже если упали.

// money.mjs
export function currencySymbol() {
  return process.env.CURRENCY === 'USD' ? '$' : '₽';
}

Зачем: тест, который поменял глобальное состояние и не вернул его, ломает соседей. Причём не сразу, а «иногда», в зависимости от порядка. afterEach срабатывает и после упавшего теста, а очистка в конце тела теста — нет.

Решение и разбор
// money.test.mjs
import { describe, it, beforeEach, afterEach } from 'node:test';
import assert from 'node:assert/strict';
import { currencySymbol } from './money.mjs';

describe('currencySymbol', () => {
  let saved;
  beforeEach(() => {
    saved = process.env.CURRENCY;
  });
  afterEach(() => {
    if (saved === undefined) delete process.env.CURRENCY;
    else process.env.CURRENCY = saved;
  });

  it('USD → $', () => {
    process.env.CURRENCY = 'USD';
    assert.equal(currencySymbol(), '$');
  });

  it('без переменной → ₽', () => {
    delete process.env.CURRENCY;
    assert.equal(currencySymbol(), '₽');
  });
});

Тонкость: process.env.CURRENCY = undefined запишет строку "undefined", поэтому отсутствие восстанавливаем через delete. Лучшее решение — передавать валюту параметром, как время в задачах выше. Тогда восстанавливать будет нечего. Но с глобальными настройками в чужом коде вы встретитесь, и этот приём пригодится.
