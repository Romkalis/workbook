Jest, Vitest, Testing Library и браузерные инструменты

Из общих знаний и официальной документации: разделяйте runner, библиотеку утверждений, средства работы с UI и браузерную автоматизацию. Иногда один пакет объединяет несколько ролей.

В Jest и Vitest тесты пишутся похоже на примеры выше: test описывает сценарий, expect — ожидание. Главные проверки:

  • toBe — то же самое значение (для объектов — тот же самый объект);
  • toEqual — одинаковое содержимое;
  • toStrictEqual — одинаковое содержимое ещё строже: например, { a: 1 } и { a: 1, b: undefined } для него разные, а для toEqual одинаковые;
  • toThrow — функция выбрасывает ошибку; resolves и rejects — Promise выполнился или отклонился.
test('скидка 10%', () => {
  expect(total(100, 10)).toBe(90);
  expect({ a: 1 }).not.toBe({ a: 1 });   // разные объекты
  expect({ a: 1 }).toEqual({ a: 1 });    // одинаковое содержимое
});

Функцию-подмену в Jest создают через jest.fn(), в Vitest — через vi.fn(). Остальное API похоже, но не совпадает полностью: при переходе сверяйтесь с документацией.

Отложить тест: todo и skip

Иногда понятно, что тест нужен, но писать его сейчас рано. Для этого есть test.todo('название') — заметка-заготовка без тела. Runner покажет её в отчёте отдельной строкой «todo», и она не даст забыть про сценарий. В Jest и Vitest it — второе имя для test, поэтому it.todo работает так же. Методов it.future, test.toBeDone не существует, а toBe и toBeDefined — это проверки внутри expect, а не способ запланировать тест.

test.skip(...) — другое: тест уже написан, но временно не запускается, например пока чинят внешнюю службу. Хуки beforeAll/afterAll к планированию отношения не имеют, они готовят и убирают общее окружение для группы тестов.

import test from 'node:test';
test.todo('скидка для постоянных клиентов'); // в отчёте: # TODO
test.skip('оплата картой', () => { /* не выполнится */ }); // в отчёте: # SKIP

Встроенный runner Node.js 22 поддерживает обе формы; мы проверили отчёт: # todo 1, # skipped 1. Пропущенный тест не должен жить вечно: оставьте рядом причину и задачу, по которой его вернут.

Инструменты для E2E

Сквозной тест управляет настоящим браузером: открывает страницу, кликает, вводит текст, проверяет результат. Это делают специальные инструменты (из общих знаний):

ИнструментЧто это
SeleniumСамый старый и распространённый. Управляет браузером через стандарт WebDriver, есть библиотеки для многих языков
WebdriverIOФреймворк для JavaScript поверх того же протокола WebDriver (и DevTools-протокола)
CypressЗапускает тесты прямо внутри браузера, удобный интерфейс для отладки шагов
PlaywrightОт Microsoft: Chromium, Firefox и WebKit, свой runner и утверждения

Jest, Vitest и node:test — runner'ы для unit- и интеграционных тестов, браузером они не управляют. JUnit — то же самое для Java. Для E2E их не используют.

DOM и настоящий браузер

Testing Library помогает взаимодействовать с DOM так, как это делает пользователь: искать кнопку по роли и доступному имени, вводить текст, проверять видимый результат. Это не самостоятельный runner. Проверки экземпляра компонента и его внутренних методов часто слишком привязаны к реализации.

Playwright и Cypress применяют для браузерных сценариев. Playwright управляет Chromium, Firefox и WebKit и предоставляет runner и утверждения. jsdom — это имитация DOM внутри Node.js: в ней можно кликнуть по кнопке и проверить текст. Но она ничего не рисует, поэтому размеры, положение элементов и прокрутку в ней не проверить. Для этого нужен настоящий браузер.

Для нового упражнения достаточно встроенного Node.js. В существующем проекте сначала используйте принятый набор, а перед установкой сверяйте официальные инструкции и совместимость. Учебник не добавляет Jest или Vitest в свои зависимости.
