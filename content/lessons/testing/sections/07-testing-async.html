Асинхронность: дождитесь результата

Runner должен знать, когда закончилась проверка. Возвращайте Promise из теста или используйте async/await. Иначе тест может завершиться раньше, чем выполнится утверждение; позже возникнет необработанная ошибка или ложный успех.

Успех и отклонение Promise

import test from 'node:test';
import assert from 'node:assert/strict';

async function loadTitle(id, fetchMovie) {
  const movie = await fetchMovie(id);
  if (typeof movie.title !== 'string') {
    throw new TypeError('Ответ не содержит название');
  }
  return movie.title;
}
test('возвращает название загруженного фильма', async () => {
  const fetchMovie = async id => ({ id, title: 'Солярис' });
  const title = await loadTitle(7, fetchMovie);
  assert.equal(title, 'Солярис');
});
test('передаёт ошибку загрузки вызывающему коду', async () => {
  const error = new Error('Нет сети');
  const fetchMovie = async () => { throw error; };
  await assert.rejects(() => loadTitle(7, fetchMovie), error);
});
test('отклоняет ответ без названия', async () => {
  await assert.rejects(() => loadTitle(7, async () => ({})), TypeError);
});

Настоящая сеть здесь не используется: мы проверяем реакцию loadTitle на управляемую зависимость. Ошибку асинхронной функции проверяет rejects, а не throws. Перед await не забывайте, что сама проверка тоже возвращает Promise.

Время и ожидание — из общих знаний

Не делайте фиксированную паузу «на всякий случай»: на быстрой машине она тратит время, на медленной всё равно может оказаться короткой. Ждите конкретное событие или проверяемое состояние. Для debounce и таймеров можно использовать управляемые часы runner, но их API зависит от инструмента; после теста часы нужно восстанавливать.

В браузерных тестах автоматическое ожидание элементов помогает синхронизации, но не исправляет гонки приложения. Если два запроса могут завершиться в обратном порядке, отдельно проверьте, что UI показывает актуальный результат.
