Первый тест: подготовить, выполнить, проверить

AAA означает Arrange, Act, Assert: подготовьте данные, вызовите действие и проверьте наблюдаемый результат. Название теста должно объяснять условие и ожидаемое поведение.

ЧастьЧто в ней происходитЧего в ней быть не должно
Arrange — подготовкаСоздать объекты и входные данные, настроить подмены (stub, mock), задать данные, которые получит проверяемый методПодключений к настоящей базе, сети, сторонним API: в unit-тесте их заменяют подменами
Act — действиеВызвать проверяемый метод с подготовленными параметрами. Обычно одна строкаНескольких разных действий подряд
Assert — проверкаСравнить возвращённый результат с ожидаемым, проверить изменённое состояние или вызовы подменНовых вызовов проверяемого кода
Проверяем итог корзины

Контракт примера: вход — массив уже проверенных товаров с неотрицательными числовыми price и целочисленными quantity. Сумма пустого массива равна 0. Здесь проверяем расчёт, а не валидацию входного JSON.

import test from 'node:test';
import assert from 'node:assert/strict';

function total(items) {
  return items.reduce((sum, item) => sum + item.price * item.quantity, 0);
}

test('два товара: сумма учитывает количество', () => {
  const items = [
    { price: 100, quantity: 2 },
    { price: 50, quantity: 1 }
  ]; // Arrange
  const actual = total(items); // Act
  assert.equal(actual, 250); // Assert
});

test('пустая корзина: итог равен нулю', () => {
  assert.equal(total([]), 0);
});

Если убрать умножение на quantity, первый тест должен упасть. Это полезная мысленная проверка силы утверждения. Для понятных коротких тестов подписывать каждую строку AAA необязательно.

Равенство, структура и исключение

В node:assert/strict equal сравнивает примитивные значения или идентичность объектов. Для структуры массива или объекта используйте deepEqual. Синхронное исключение проверяйте через throws(() => действие()): важно передать функцию, а не вызвать её до проверки.

Вторым аргументом throws можно передать не только класс ошибки, но и регулярное выражение для текста или объект с ожидаемыми полями. Это нужно, когда функция бросает один тип ошибки по разным причинам:

assert.throws(() => parseQuantity('0'), /целое количество/);
assert.throws(() => parseQuantity('0'), { name: 'RangeError', message: 'Нужно целое количество от 1' });
import test from 'node:test';
import assert from 'node:assert/strict';

function parseQuantity(value) {
  const quantity = Number(value);
  if (value.trim() === '' || !Number.isInteger(quantity) || quantity < 1) {
    throw new RangeError('Нужно целое количество от 1');
  }
  return { quantity };
}
test('строка количества превращается в объект', () => {
  assert.deepEqual(parseQuantity('2'), { quantity: 2 });
});
test('нулевое количество отклоняется', () => {
  assert.throws(() => parseQuantity('0'), RangeError);
});

Вход этой функции — строка. Допустимость значений вроде «1e2» или «0x10» зависит от требований: Number понимает их как числа. Если разрешены только десятичные цифры, одного преобразования Number недостаточно.

Задача 6. equal или deepEqual ★☆☆ разминка

Напишите тесты для toCartLine(product, quantity): результат — новый объект строки корзины с нужными полями; это не тот же объект, что товар; сам товар не изменился.

// line.mjs
export function toCartLine(product, quantity) {
  return { id: product.id, title: product.title, price: product.price, quantity };
}

Зачем: equal отвечает «это тот же объект?», а deepEqual — «одинаковое ли содержимое?». В одном тесте нужны оба вопроса: «правильные ли поля» и «не испортили ли исходник».

Решение и разбор
// line.test.mjs
import { test } from 'node:test';
import assert from 'node:assert/strict';
import { toCartLine } from './line.mjs';

const product = () => ({ id: 1, title: 'Чистый код', price: 150000 });

test('строка содержит поля товара и количество', () => {
  assert.deepEqual(toCartLine(product(), 2), { id: 1, title: 'Чистый код', price: 150000, quantity: 2 });
});

test('строка — новый объект, товар не меняется', () => {
  const p = product();
  const line = toCartLine(p, 2);
  assert.notEqual(line, p);
  assert.deepEqual(p, { id: 1, title: 'Чистый код', price: 150000 });
});

Товар создаётся функцией product() для каждого теста: тест-мутант, который портит товар, не должен испортить данные соседнему тесту. Мутант, который дописывает quantity в сам товар и возвращает его, проходит первый тест (содержимое совпадает!) и падает на втором.
