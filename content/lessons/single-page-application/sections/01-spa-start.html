Что такое SPA

В обычном (многостраничном) сайте каждый переход — новый запрос HTML к серверу: браузер выгружает страницу и рисует новую. В одностраничном приложении (Single Page Application) HTML загружается один раз, а дальше JavaScript сам меняет содержимое страницы и адрес, запрашивая с сервера только данные (обычно JSON).

Последние строки таблицы — главное: SPA ускоряет переходы, но забирает у браузера работу, которую он раньше делал бесплатно. Хорошее SPA возвращает её назад: адрес меняется при каждом экране, «Назад» работает, заголовок вкладки обновляется, фокус переносится.

Из чего состоит SPA

  • Роутер — сопоставляет адрес с экраном и реагирует на переходы.
  • Экраны (views) — функции или классы, которые рисуют свою часть страницы и умеют убирать за собой.
  • Состояние — данные, общие для экранов: пользователь, корзина. Устройство стора разобрано в уроке Состояние и отрисовка.
  • Слой данных — API-клиент (урок Данные с сервера в интерфейсе).

Оболочка (шапка, меню, подвал) рисуется один раз, а меняется только область main.

Задача 1. SPA или обычный сайт ★☆☆ разминка

Для каждого проекта решите, нужен ли SPA, и одним предложением объясните почему: блог с десятью статьями; почтовый клиент; лендинг акции; панель администратора магазина; документация библиотеки; онлайн-редактор диаграмм.

Зачем: SPA — не «современный способ делать сайты», а архитектура со своей ценой: тяжёлая первая загрузка, сложное SEO, ручная работа с историей и фокусом. Умение сказать «здесь SPA не нужен» — признак инженерного мышления.

Решение и разбор
// ответы.txt
Блог — не нужен: контент читают, переходов мало, важны SEO и быстрая первая загрузка.
Почтовый клиент — нужен: долгие сессии, частые переходы, общее состояние (папки, черновик).
Лендинг — не нужен: одна страница без переходов, важна скорость первого показа.
Админка — нужна: много экранов с общими данными, SEO не важно, пользователь сидит часами.
Документация — скорее нет, или статическая генерация с «быстрыми переходами» (как у Astro, VitePress).
Редактор диаграмм — нужен: сложное состояние в памяти, страница не должна перезагружаться.

Критерии те же, что в таблице раздела: сколько времени пользователь проводит в приложении, сколько общего состояния у экранов и насколько важны поисковики и первая загрузка. Для документации есть промежуточный путь — генератор статических страниц, которые после загрузки ведут себя как SPA. Это из общих знаний, в материалах модуля такого нет.
