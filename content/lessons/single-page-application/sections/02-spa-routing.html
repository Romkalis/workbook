Маршрутизация: hash и History API

Адрес в SPA — это часть состояния: по нему пользователь делится ссылкой, добавляет закладку, возвращается назад. Есть два способа менять адрес без перезагрузки.

Hash-роутинг

Часть адреса после # браузер не отправляет на сервер и при её смене не перезагружает страницу. Смена вызывает событие hashchange:

window.addEventListener('hashchange', () => render(location.hash.slice(1) || '/'));
// ссылки: <a href="#/products/42">

Плюс — не нужна настройка сервера: любой адрес приходит на тот же index.html. Поэтому hash-роутинг удобен для GitHub Pages и учебных проектов. Минусы — адреса с # выглядят непривычно, и сервер не видит путь (нельзя отрендерить страницу заранее).

Задача 2. Hash-роутер для GitHub Pages ★☆☆ разминка

Напишите createHashRouter(render): вызывает render(path) при старте и на каждый hashchange, где path — часть после # (пустой hash → /). Метод navigate(path) меняет location.hash. Возвращает также destroy().

Зачем: для учебного проекта на GitHub Pages hash-роутинг — честный выбор: сервер ничего не знает о маршрутах, и прямой заход на любой экран работает без настроек. Полезно увидеть, насколько он проще History API.

Решение и разбор
export function createHashRouter(render: (path: string) => void) {
  const current = () => location.hash.slice(1) || '/';
  const onChange = () => render(current());
  window.addEventListener('hashchange', onChange);
  onChange();
  return {
    navigate(path: string) {
      location.hash = path;
    },
    destroy() {
      window.removeEventListener('hashchange', onChange);
    },
  };
}

navigate не вызывает render сам: смена location.hash вызывает hashchange, и отрисовка пройдёт по тому же пути, что и «Назад». В отличие от pushState, здесь событие срабатывает и при программной смене. Присвоение того же значения hash событие не вызывает, так что повторный клик на текущий экран ничего не сломает. Ссылки при hash-роутинге пишут как href="#/products/42", и перехватывать клики не нужно.

History API

history.pushState(state, '', url) меняет адрес и добавляет запись в историю без перезагрузки. history.replaceState меняет текущую запись, не добавляя новую. Кнопки «Назад» и «Вперёд» вызывают событие popstate, а сам pushState — нет: после него роутер должен отрисовать экран сам.

export function createHistoryRouter(render: (path: string) => void) {
  const navigate = (path: string) => {
    history.pushState(null, '', path);
    render(path);
  };
  const onPop = () => render(location.pathname);
  window.addEventListener('popstate', onPop);
  render(location.pathname);
  return { navigate, destroy: () => window.removeEventListener('popstate', onPop) };
}

Адреса становятся обычными (/products/42), но появляется требование к серверу — раздел ниже.

Задача 3. Свой роутер на History API ★★★ с подвохом

Соберите createRouter({ routes, root }) из прошлых задач. Маршрут — { path, view }, где view(params) возвращает объект экрана с mount(root) и необязательным unmount(). Требования: navigate(url) делает pushState и отрисовку; кнопка «Назад» (popstate) перерисовывает экран; переход на тот же адрес не создаёт новую запись истории; перед новым экраном вызывается unmount старого; start() рисует текущий адрес.

// match.ts
export function matchRoute(pattern: string, path: string): Record<string, string> | null {
  const p = pattern.split('/').filter(Boolean), s = path.split('/').filter(Boolean);
  if (p.length !== s.length) return null;
  const r: Record<string, string> = {};
  for (let i = 0; i < p.length; i++) { if (p[i]!.startsWith(':')) r[p[i]!.slice(1)] = decodeURIComponent(s[i]!); else if (p[i] !== s[i]) return null; }
  return r;
}

Зачем: роутер связывает все идеи урока: адрес как состояние, история, жизненный цикл экранов. Написав его один раз, вы поймёте, что делают React Router и Vue Router, и сможете читать их документацию как описание знакомых решений.

Решение и разбор
import { matchRoute } from './match.js';

export interface Screen {
  mount(root: HTMLElement): void;
  unmount?(): void;
}
export interface RouteDef {
  path: string;
  view: (params: Record<string, string>) => Screen;
}

export function createRouter({ routes, root }: { routes: RouteDef[]; root: HTMLElement }) {
  let current: Screen | null = null;

  const render = () => {
    const path = location.pathname;
    let screen: Screen | null = null;
    for (const route of routes) {
      const params = route.path === '*' ? null : matchRoute(route.path, path);
      if (params) {
        screen = route.view(params);
        break;
      }
    }
    screen ??= routes.find((r) => r.path === '*')?.view({}) ?? { mount: (el) => el.replaceChildren('Страница не найдена') };
    current?.unmount?.();
    current = screen;
    screen.mount(root);
  };

  const navigate = (url: string) => {
    const next = new URL(url, location.href);
    if (next.href === location.href) return;
    history.pushState(null, '', next);
    render();
  };

  return {
    navigate,
    start() {
      window.addEventListener('popstate', render);
      render();
    },
    stop() {
      window.removeEventListener('popstate', render);
      current?.unmount?.();
      current = null;
    },
  };
}

Один путь отрисовки render для трёх случаев: старт, navigate и «Назад». Он всегда читает адрес из location, так что разойтись адрес и экран не могут. Сравнение с текущим адресом не даёт засорить историю: десять кликов по «Главной» не потребуют десяти нажатий «Назад». Если маршрута * нет, рисуется простая заглушка, но лучше требовать его явно, как в задаче про таблицу маршрутов.

Задача 4. Защита маршрута: вход и несохранённые изменения ★★★ с подвохом

Добавьте в роутер «охранников»: функция guard(to) вызывается перед переходом и возвращает true (продолжить), false (остаться) или строку (перейти на другой адрес вместо запрошенного). Напишите runGuards(guards, to), возвращающую итоговое решение, и два охранника: requireAuth(isLoggedIn) — для путей /account… без входа отправляет на /login?next=…; confirmLeave(isDirty, confirm) — при несохранённых изменениях спрашивает подтверждение.

Зачем: проверка входа на клиенте — удобство, а не защита (данные всё равно защищает сервер). Но без неё пользователь видит пустой экран и ошибки 401. Параметр next возвращает его туда, куда он шёл, после входа. А «Вы уверены?» спасает заполненную форму от случайного клика.

Решение и разбор
export type GuardResult = boolean | string;
export type Guard = (to: string) => GuardResult;

export function runGuards(guards: readonly Guard[], to: string): GuardResult {
  for (const guard of guards) {
    const result = guard(to);
    if (result !== true) return result;
  }
  return true;
}

export const requireAuth =
  (isLoggedIn: () => boolean): Guard =>
  (to) =>
    to.startsWith('/account') && !isLoggedIn() ? `/login?next=${encodeURIComponent(to)}` : true;

export const confirmLeave =
  (isDirty: () => boolean, confirm: (message: string) => boolean): Guard =>
  () =>
    !isDirty() || confirm('Есть несохранённые изменения. Уйти со страницы?');

Охранники выполняются по порядку, и первый «не true» останавливает цепочку. Это цепочка обязанностей из урока Design Patterns. next кодируется, иначе ? и & из исходного адреса сломают строку запроса страницы входа. После входа значение next стоит проверить: оно должно начинаться с /, иначе это открытый редирект на чужой сайт. Для закрытия вкладки нужен ещё обработчик beforeunload: роутер его не видит.

Параметры пути

Маршрут описывают шаблоном: /products/:id совпадает с /products/42, и id равен '42'. Шаблон превращают в регулярное выражение с именованными группами или сравнивают по сегментам. Значения из адреса — строки и пользовательский ввод: id надо проверить, прежде чем запрашивать по нему данные. Параметры фильтров и сортировки живут в строке запроса (?sort=price), их удобно читать через URLSearchParams.

Задача 5. Сопоставить путь с шаблоном ★☆☆ разминка

Напишите matchRoute(pattern, path): для "/products/:id" и "/products/42" возвращает { id: "42" }, при несовпадении — null. Сравнивайте по сегментам, конечный слеш игнорируйте, значения параметров декодируйте (%20 → пробел).

Зачем: это сердце любого роутера. Разбор по сегментам проще и понятнее регулярных выражений, и из него сразу видно, почему /products/42/reviews не совпадает с /products/:id: у них разное число частей.

Решение и разбор
export function matchRoute(pattern: string, path: string): Record<string, string> | null {
  const split = (s: string) => s.split('/').filter(Boolean);
  const p = split(pattern);
  const s = split(path);
  if (p.length !== s.length) return null;
  const params: Record<string, string> = {};
  for (let i = 0; i < p.length; i++) {
    const part = p[i]!;
    const value = s[i]!;
    if (part.startsWith(':')) {
      try {
        params[part.slice(1)] = decodeURIComponent(value);
      } catch {
        return null;
      }
    } else if (part !== value) return null;
  }
  return params;
}

filter(Boolean) убирает пустые сегменты: и ведущий слеш, и конечный. Поэтому /products/42/ совпадает так же, как /products/42. Корень / даёт пустой массив и совпадает только с шаблоном /. Некорректная кодировка вроде %E0 считается несовпадением, а не падением приложения. Параметр — всегда строка: превратить "42" в число и проверить — задача экрана.

Задача 6. Таблица маршрутов и страница 404 ★★☆ практика

Напишите resolve(routes, url), где routes — массив { path, view }. Возвращает { view, params, query } первого совпавшего маршрута, где query — объект из строки запроса. Если ничего не совпало, возвращается маршрут с path: "*". Его наличие обязательно: без него — ошибка при создании.

// match.ts
export function matchRoute(pattern: string, path: string): Record<string, string> | null {
  const p = pattern.split('/').filter(Boolean), s = path.split('/').filter(Boolean);
  if (p.length !== s.length) return null;
  const r: Record<string, string> = {};
  for (let i = 0; i < p.length; i++) { if (p[i]!.startsWith(':')) r[p[i]!.slice(1)] = decodeURIComponent(s[i]!); else if (p[i] !== s[i]) return null; }
  return r;
}

Зачем: порядок маршрутов важен: /products/new должен стоять раньше /products/:id, иначе «new» станет id. А обязательный маршрут «не найдено» — это решение принять заранее, что пользователь увидит на неизвестном адресе, вместо пустого экрана.

Решение и разбор
import { matchRoute } from './match.js';

export interface Route<V> {
  path: string;
  view: V;
}

export function createResolver<V>(routes: readonly Route<V>[]) {
  const notFound = routes.find((r) => r.path === '*');
  if (!notFound) throw new Error('Нужен маршрут "*" для страницы 404');
  return (url: string) => {
    const { pathname, searchParams } = new URL(url, 'http://local');
    const query = Object.fromEntries(searchParams);
    for (const route of routes) {
      if (route.path === '*') continue;
      const params = matchRoute(route.path, pathname);
      if (params) return { view: route.view, params, query };
    }
    return { view: notFound.view, params: {}, query };
  };
}

Проверка «есть ли 404» вынесена в момент создания: ошибка конфигурации всплывёт при запуске, а не когда пользователь наберёт кривой адрес. new URL(url, 'http://local') разбирает и путь, и строку запроса, даже если передан только /products?sort=price: база нужна лишь для относительных адресов. Маршрут * пропускается в цикле, где бы он ни стоял в массиве.

Перехват ссылок

В SPA ссылки остаются настоящими <a href="/products/42">: так работают «открыть в новой вкладке», копирование адреса и экранные читалки. Роутер перехватывает клик делегированием на document и вызывает navigate, но только когда это действительно внутренний переход:

  • левая кнопка мыши без Ctrl, Cmd, Shift, Alt (с ними пользователь хочет новую вкладку или окно);
  • нет target="_blank" и атрибута download;
  • ссылка ведёт на тот же источник (origin).

Кнопка <button> с обработчиком вместо ссылки ломает всё перечисленное, поэтому для переходов используют ссылки, а кнопки — для действий.

Задача 7. Перехват ссылок ★★☆ практика

Напишите interceptLinks(root, navigate): один обработчик click на root перехватывает клики по внутренним ссылкам и вызывает navigate(path + search + hash) вместо перехода. Не перехватывать: клик не левой кнопкой, с Ctrl/Cmd/Shift/Alt, ссылку с target="_blank" или download, ссылку на другой источник, уже отменённое событие. Возвращает функцию отписки.

Зачем: каждый неучтённый случай ломает привычное поведение браузера: «открыть в новой вкладке» вдруг открывает в этой, ссылка на чужой сайт пытается отрисоваться роутером. Перехват должен быть максимально скромным: забирать только то, что точно наше.

Решение и разбор
export function interceptLinks(root: HTMLElement | Document, navigate: (url: string) => void): () => void {
  const onClick = (event: Event) => {
    const e = event as MouseEvent;
    if (e.defaultPrevented || e.button !== 0 || e.metaKey || e.ctrlKey || e.shiftKey || e.altKey) return;
    const link = (e.target as Element | null)?.closest?.('a[href]');
    if (!(link instanceof HTMLAnchorElement)) return;
    if (link.target && link.target !== '_self') return;
    if (link.hasAttribute('download')) return;
    const url = new URL(link.href);
    if (url.origin !== location.origin) return;
    e.preventDefault();
    navigate(url.pathname + url.search + url.hash);
  };
  root.addEventListener('click', onClick);
  return () => root.removeEventListener('click', onClick);
}

closest('a[href]') находит ссылку, даже если кликнули по иконке внутри неё: это делегирование из урока События и формы. link.href (свойство, а не атрибут) уже содержит абсолютный адрес, поэтому относительные ссылки сравниваются с origin правильно. Проверка defaultPrevented уважает другие обработчики: если кто-то уже отменил переход, роутер не должен его совершать.
