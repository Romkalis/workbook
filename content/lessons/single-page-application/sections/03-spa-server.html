Сервер для SPA с History API

Пользователь открыл /products/42 из закладки — браузер запросил этот путь у сервера. Файла products/42 на сервере нет, и без настройки придёт 404. Решение — fallback: на любой неизвестный путь отдавать index.html, а дальше роутер на клиенте разберётся. Как это настраивается:

  • Vite в режиме разработки делает это сам;
  • Netlify — файл _redirects со строкой /* /index.html 200;
  • nginx — try_files $uri /index.html;;
  • Express — после статики маршрут app.get('/{*path}', (req, res) => res.sendFile(...index.html)) (Express 5).

GitHub Pages такой настройки не умеет: для него выбирают hash-роутинг или трюк с копией index.html под именем 404.html (из общих знаний). Важно: API-маршруты (/api/...) не должны попадать под fallback, иначе вместо ошибки 404 клиент получит HTML и упадёт на разборе JSON.
