Скорость и удобство

Ленивая загрузка экранов

Если весь код приложения в одном файле, пользователь качает админку, чтобы посмотреть главную. Динамический import('./views/admin.js') возвращает промис модуля, и сборщик (Vite, Webpack) выносит такой модуль в отдельный файл, который загрузится при первом переходе. Загруженный модуль кешируется: второй import того же файла не скачивает его снова.

Задача 10. Ленивая загрузка экрана с кешем ★★☆ практика

Напишите lazy(loader), где loader — функция вида () => import('./views/admin.js'), возвращающая модуль с экспортом default. lazy возвращает функцию, которая отдаёт промис экрана. Модуль загружается один раз, даже при двух одновременных вызовах. Если загрузка упала (сеть), следующий вызов пробует снова.

Зачем: динамический import сам кеширует успешные загрузки, но обёртка нужна, чтобы задать поведение явно и тестируемо, а ещё чтобы между вызовами можно было показать индикатор загрузки. Повтор после ошибки — то, о чём часто забывают: один обрыв связи ломает раздел до перезагрузки страницы.

Решение и разбор
export function lazy<T>(loader: () => Promise<{ default: T }>): () => Promise<T> {
  let pending: Promise<T> | null = null;
  return () => {
    pending ??= loader()
      .then((m) => m.default)
      .catch((err: unknown) => {
        pending = null;
        throw err;
      });
    return pending;
  };
}

Как и в задаче про декоратор кеша в уроке Design Patterns, хранится промис, а не результат: два одновременных перехода разделят одну загрузку. При ошибке промис сбрасывается, и следующий вызов вызовет loader снова. В роутере это выглядит как { path: '/admin', view: lazy(() => import('./views/admin.js')) }, а Vite при сборке вынесет admin.js в отдельный файл.

Доступность переходов

При обычном переходе браузер сообщает читалке о новой странице и ставит фокус в начало. В SPA этого не происходит, и незрячий пользователь не узнает, что экран сменился. Минимум для каждого перехода:

  • обновить document.title;
  • перенести фокус на заголовок h1 нового экрана (с tabindex="-1", чтобы на него можно было сфокусироваться программно);
  • при переходе вперёд прокрутить в начало, при «Назад» — восстановить прокрутку (браузер делает это сам, если history.scrollRestoration равно 'auto' и содержимое отрисовано синхронно).

Задача 11. Заголовок вкладки и фокус после перехода ★★☆ практика

Напишите afterNavigate(root, title), которую роутер вызывает после отрисовки экрана: ставит document.title в формате «Название — Магазин», находит в root первый h1, делает его фокусируемым (tabindex="-1") и переносит на него фокус. Если h1 нет, фокус переносится на сам root.

Зачем: без этого незрячий пользователь нажимает ссылку и не слышит ничего: страница не перезагрузилась, фокус остался на ссылке, которой уже нет. Две строки кода возвращают поведение, которое браузер даёт обычным сайтам бесплатно.

Решение и разбор
export function afterNavigate(root: HTMLElement, title: string, site = 'Магазин'): void {
  document.title = `${title} — ${site}`;
  const target = root.querySelector('h1') ?? root;
  if (!target.hasAttribute('tabindex')) target.setAttribute('tabindex', '-1');
  target.focus();
}

tabindex="-1" позволяет сфокусировать элемент программно, но не добавляет его в порядок обхода клавишей Tab. Заголовок не станет лишней остановкой при навигации. Фокус на h1 заставляет читалку произнести название нового экрана. Видимую рамку фокуса на заголовке обычно убирают стилем h1:focus:not(:focus-visible) { outline: none }, чтобы она не мешала тем, кто пользуется мышью.

Создание разметки на JS

Без фреймворка разметку собирают через document.createElement или <template>. Удобна маленькая функция-помощник el(tag, props, ...children), которая создаёт элемент, ставит свойства и добавляет детей; её вариант есть в дополнительных материалах модуля. Данные вставляются как текст, а не через innerHTML — см. урок DOM и Web Security.
