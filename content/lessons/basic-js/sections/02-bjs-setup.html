Подготовка и запуск тестов

Репозиторий устроен так же, как basic-js-ds: форк, клон своего форка, npm install, npm run test. Не отправляйте pull request в исходный репозиторий, сдаётся ссылка на ваш форк.

  1. Сделайте форк AlreadyBored/basic-js и склонируйте свой форк.
  2. В папке проекта выполните npm install, затем npm run test.
  3. Чтобы не тонуть в отчёте на 21 задачу, запускайте один файл: node --test test/count-cats.test.js.
README и package.json расходятся в версии Node.js

В README написано, что рекомендуется Node.js 16. Но в package.json стоит "engines": { "node": ">=22" }, а тесты запускаются встроенным раннером node --test. Верьте package.json: ставьте Node.js 22 или новее. Совет про Node 16 остался от старой версии задания (проверено 9 ноября 2026 года).

Что значат pending, pass и fail

Пока в функции стоит заглушка throw new NotImplementedError('Not implemented'), её тесты помечаются как pending (в отчёте в формате TAP — простом текстовом формате результатов тестов — это todo). Удалили заглушку — тесты начинают проверяться по-настоящему и становятся pass или fail. Внизу отчёта есть сводка # pass, # fail, # todo. Ограничение — 30 секунд на тест: превысить его можно, по сути, только бесконечным циклом или бесконечной рекурсией.

Читайте тесты: там самое важное

README описывает задачу в общих словах, а тесты содержат крайние случаи. Например, только из тестов видно, что dateSample получает строку из одних пробелов, getEmailDomain — адрес с несколькими @, а repeater — null в качестве добавки. Прежде чем писать код, откройте файл теста и выпишите все примеры вызовов. Это уже готовый план проверки.
