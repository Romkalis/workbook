Проверка входных данных

Почти в каждой задаче есть фраза «in case of wrong type return false» или «throw an Error». Значит, функция должна сначала убедиться, что получила то, что ожидала, и только потом считать. Такую проверку называют валидацией: если вход неправильный, функция сразу возвращает ответ «неверно» и дальше не идёт. Это ранний выход (guard clause): плохие случаи отсекаются в первых строках, и основной код не обрастает условиями.

typeof и его сюрпризы

Оператор typeof возвращает строку с названием типа. Для строк, чисел и булевых значений он работает как ожидается. Для массивов и null — нет.

console.log(typeof '1', typeof 1); // string number
console.log(typeof [1]); // object — массив тоже объект
console.log(Array.isArray([1])); // true — так проверяют массив
console.log(typeof null); // object — историческая ошибка языка

Поэтому массив проверяют через Array.isArray, а не через typeof. Это нужно в dream-team и transform-array.

Строка, похожая на число

В carbon-dating активность приходит строкой, например '3.142'. Её надо превратить в число и отбраковать мусор. Два стандартных способа ведут себя по-разному, и у каждого своя ловушка:

console.log(parseFloat('3abc')); // 3 — читает начало и молча отбрасывает хвост
console.log(Number('3abc')); // NaN — строгий: вся строка должна быть числом
console.log(Number(' ')); // 0 — пустая строка и пробелы превращаются в 0!
console.log(parseFloat(' ')); // NaN

Обратите внимание: Number(' ') даёт 0, хотя никакого числа там нет. В тестах carbon-dating есть именно такие входы: '', ' ', ' \n\t\r'. Каждый способ пропускает свой вид мусора, поэтому полагаться на один без дополнительной проверки нельзя. Проверка на NaN делается через Number.isNaN(x): сравнение x === NaN всегда ложно.

Кроме типа проверяют смысл. Активность образца не может быть нулевой, отрицательной или больше современной (константа MODERN_ACTIVITY = 15 в файле задачи): такой образец был бы «из будущего». README называет это inadequate value.

Поддельная дата в what-season

README предупреждает о «вражеском разведчике», который притворяется датой. В тестах это объект, которому подменили прототип и метку Symbol.toStringTag. Прототип — объект, у которого экземпляр берёт методы: у всех дат это Date.prototype. Symbol.toStringTag — особое свойство, которое задаёт подпись в строке вида [object Date]. Посмотрим, какие проверки он обманывает.

const fake = { [Symbol.toStringTag]: 'Date' };
Object.setPrototypeOf(fake, Date.prototype);

console.log(fake instanceof Date); // true — обманули
console.log(Object.prototype.toString.call(fake)); // [object Date] — обманули

try {
  Date.prototype.getTime.call(fake);
} catch (error) {
  console.log(error.constructor.name); // TypeError — а вот это не подделать
}

Внутренний слот — скрытое поле объекта, которое видит только движок. У настоящей даты в нём лежит число миллисекунд. Свойства и методы объекта можно подменить, а слот — нет. Отдельно проверьте второй случай из README: дата настоящая, но недействительная. new Date('завтра').getTime() вернёт NaN, а не ошибку.

Что вернуть, если аргумента нет вовсе?

Это отдельный случай, и он не ошибка: README требует вернуть строку 'Unable to determine the time of year!'. Проверять его надо первым, до попытки работать с датой. Иначе вызов метода на undefined бросит TypeError, и функция ответит «Invalid date!» не по делу.

Отбор строк в dream-team

В массив участников подмешаны числа, null, true, а у имён бывают пробелы в начале: ' William Alston '. Значит, порядок такой: оставить только строки, убрать пробелы по краям (trim), взять первую букву, привести к одному регистру и только потом сортировать. Если отсортировать до приведения регистра, строчная буква окажется после всех заглавных: ['b', 'A', 'C'].sort() даёт ['A', 'C', 'b'], потому что sort без функции сравнения сравнивает коды символов.
