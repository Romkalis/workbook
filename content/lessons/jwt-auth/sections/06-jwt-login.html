Регистрация

// routes/auth.js
const router = require('express').Router();
const jwt = require('jsonwebtoken');
const User = require('../models/User');

router.post('/register', async (req, res) => {
  try {
    const { email, password } = req.body;
    const user = await User.create({ email, password }); // хук pre('save') захеширует пароль
    res.status(201).json({ id: user._id, email: user.email });
  } catch (err) {
    res.status(400).json({ message: err.message });
  }
});

Токен здесь ещё не создаётся. Мы просто сохраняем пользователя. Обратите внимание: в ответе нет пароля, даже хешированного.

Задача 7. Регистрация: 201, 400 и 409 ★★☆ практика

Напишите createApp({ secret }) с маршрутом POST /api/auth/register (пользователи в Map внутри приложения). Правила:

  • email — строка с @, приводится к нижнему регистру; пароль — от 8 символов. Иначе 400;
  • занятый email — 409;
  • успех — 201 и { id, email }, без хеша.

Зачем: в уроке любая ошибка регистрации превращается в 400 с текстом исключения MongoDB. Клиенту так не понять, что делать: исправить поле или войти в существующий аккаунт. Разные коды дают интерфейсу возможность ответить правильно.

Решение и разбор
// app.ts
import bcrypt from 'bcryptjs';
import express from 'express';

export interface User {
  id: string;
  email: string;
  passwordHash: string;
}

export function createApp(_opts: { secret: string }) {
  const users = new Map<string, User>(); // ключ — email
  const app = express();
  app.use(express.json());

  app.post('/api/auth/register', async (req, res) => {
    const { email, password } = (req.body ?? {}) as Record<string, unknown>;
    if (typeof email !== 'string' || !email.includes('@')) return res.status(400).json({ message: 'Неверный email' });
    if (typeof password !== 'string' || password.length < 8) {
      return res.status(400).json({ message: 'Пароль: минимум 8 символов' });
    }
    const normalized = email.trim().toLowerCase();
    if (users.has(normalized)) return res.status(409).json({ message: 'Email уже зарегистрирован' });
    const user: User = { id: String(users.size + 1), email: normalized, passwordHash: await bcrypt.hash(password, 4) };
    users.set(normalized, user);
    res.status(201).json({ id: user.id, email: user.email });
  });
  return app;
}

Нормализация email обязательна: без неё Anna@Example.com и anna@example.com — два разных аккаунта, и человек не сможет войти. В MongoDB ту же роль играют lowercase: true в схеме и уникальный индекс. Индекс надёжнее проверки has: два одновременных запроса могли бы оба пройти проверку. Ответ строится белым списком полей, поэтому хеш не утечёт, даже если в модели появятся новые поля. Стоимость bcrypt 4 — только для скорости тестов.

Вход — здесь появляется токен

router.post('/login', async (req, res) => {
  try {
    const { email, password } = req.body;

    const user = await User.findOne({ email });
    if (!user) return res.status(401).json({ message: 'Неверный email или пароль' });

    const isMatch = await user.comparePassword(password);
    if (!isMatch) return res.status(401).json({ message: 'Неверный email или пароль' });

    const token = jwt.sign(
      { id: user._id },                          // payload: что положить в токен
      process.env.JWT_SECRET,                    // секрет для подписи
      { expiresIn: process.env.JWT_EXPIRES_IN }, // срок жизни
    );
    res.json({ token });
  } catch (err) {
    res.status(500).json({ message: 'Ошибка сервера' });
  }
});

module.exports = router;

Почему сообщение одинаковое и для «нет такого email», и для «неверный пароль»? Если бы они различались, по ответу можно было бы узнать, какие email зарегистрированы.

В исходном материале у маршрута входа нет try/catch. В Express 4 ошибка внутри async-обработчика (например, упала база) не попадёт в обработчик ошибок, и запрос просто повиснет. Express 5 такие ошибки ловит сам, но try/catch работает в обеих версиях.

Задача 8. Вход: одинаковый ответ на обе ошибки ★★☆ практика

Добавьте POST /api/auth/login. При успехе — 200 и { token }, где в payload лежит sub (id пользователя) и срок жизни один час. Неизвестный email и неверный пароль — одинаковый ответ 401 с одним и тем же текстом. Чтобы тест мог создать пользователя, приложение принимает начальный список: createApp({ secret, users }).

Зачем: разные сообщения («нет такого email» и «неверный пароль») позволяют перебором узнать, кто зарегистрирован на сайте. Поле sub (subject, «о ком токен») — стандартное имя из спецификации JWT. Другие библиотеки и сервисы понимают его без договорённостей.

Решение и разбор
// app.ts
import bcrypt from 'bcryptjs';
import express from 'express';
import jwt from 'jsonwebtoken';

export interface User {
  id: string;
  email: string;
  passwordHash: string;
}

export function createApp({ secret, users }: { secret: string; users: User[] }) {
  const app = express();
  app.use(express.json());
  const fail = { message: 'Неверный email или пароль' };

  app.post('/api/auth/login', async (req, res) => {
    const { email, password } = (req.body ?? {}) as Record<string, unknown>;
    if (typeof email !== 'string' || typeof password !== 'string') return res.status(400).json({ message: 'Нужны email и пароль' });
    const user = users.find((u) => u.email === email.trim().toLowerCase());
    if (!user || !(await bcrypt.compare(password, user.passwordHash))) return res.status(401).json(fail);
    const token = jwt.sign({ sub: user.id }, secret, { algorithm: 'HS256', expiresIn: '1h' });
    res.json({ token });
  });
  return app;
}

expiresIn: '1h' библиотека превращает в поле exp = iat + 3600, и тест проверяет именно эту разницу. Отсутствующие поля — 400, а не 401: это ошибка формы запроса, а не неудачная попытка входа. Остаётся одна утечка, через время ответа: для неизвестного email bcrypt не вызывается, и ответ приходит заметно быстрее. Её закрывает следующая задача.

Задача 9. Утечка через время ответа ★★★ с подвохом

Даже с одинаковым текстом ответа вход выдаёт, есть ли пользователь: без него bcrypt не вызывается, и ответ приходит в десятки раз быстрее. Перепишите проверку так, чтобы сравнение пароля выполнялось всегда. Напишите функцию authenticate(users, email, password, compare), где compare передаётся параметром. Так в тесте можно посчитать вызовы.

Зачем: это пример того, что безопасность — свойство поведения, а не текста ответа. Задача тренирует ещё и тестируемость: если зависимость передаётся параметром, тест проверяет «сколько раз вызвали сравнение» без замеров времени, которые в CI нестабильны.

Подсказка

Заранее посчитайте хеш какого-нибудь пароля с той же стоимостью. Если пользователь не найден, сравнивайте с ним, а результат игнорируйте.

Решение и разбор
import bcrypt from 'bcryptjs';

export interface User {
  id: string;
  email: string;
  passwordHash: string;
}
type Compare = (plain: string, hash: string) => Promise<boolean>;

// Хеш с той же стоимостью, что и у настоящих паролей: время проверки одинаковое
const DUMMY_HASH = bcrypt.hashSync('dummy-password', 10);

export async function authenticate(
  users: readonly User[],
  email: string,
  password: string,
  compare: Compare = bcrypt.compare,
): Promise<User | null> {
  const user = users.find((u) => u.email === email);
  const ok = await compare(password, user?.passwordHash ?? DUMMY_HASH);
  return user && ok ? user : null;
}

Обратите внимание на user && ok. Даже если кто-то угадает пароль, от которого посчитан DUMMY_HASH, без пользователя функция вернёт null. Стоимость хеша-заглушки должна совпадать с настоящей, иначе время снова будет различаться. Защиту дополняют ограничением числа попыток входа (rate limiting). Это из общих знаний, в материалах модуля этого нет.

Что делает jwt.sign

  1. Кодирует header {"alg":"HS256","typ":"JWT"} в base64url.
  2. Кодирует payload { id, iat, exp } в base64url. iat и exp библиотека добавит сама из expiresIn.
  3. Склеивает их через точку.
  4. Вычисляет подпись алгоритмом HMAC-SHA256 от этой строки с ключом JWT_SECRET.
  5. Добавляет подпись третьей частью.

Если кто-то заменит id в payload на чужой, но не знает секрета, он не сможет пересчитать подпись. Мы проверили: такой токен jwt.verify отклоняет с ошибкой invalid signature.
