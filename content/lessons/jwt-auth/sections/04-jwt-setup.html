Подготовка проекта

npm install express mongoose bcrypt jsonwebtoken dotenv cookie-parser
ПакетЗачем
expressСервер и маршруты
mongooseРабота с MongoDB через модели
bcryptХеширование паролей. К JWT не относится, но всегда идёт рядом
jsonwebtokenСоздание и проверка токенов
dotenvЧитает секреты из файла .env, чтобы они не лежали в коде
cookie-parserНужен, только если хранить токен в cookie (раздел «Где хранить токен»)

Пакет bcrypt собирается из кода на C++, и на некоторых системах установка падает. Тогда ставьте bcryptjs: он написан на чистом JavaScript, медленнее, но методы те же (hash, compare). Примеры этого урока мы проверяли именно на нём.

Файл .env в корне проекта:

JWT_SECRET=длинная-случайная-строка-не-короче-32-символов
JWT_EXPIRES_IN=1d
MONGO_URI=mongodb://localhost:27017/myapp

Секрет должен быть длинным и случайным. Получить такой можно командой node -e "console.log(require('crypto').randomBytes(32).toString('hex'))".

Не отправляйте .env в git

Добавьте строку .env в .gitignore. Кто знает JWT_SECRET, тот может выпустить токен от имени любого пользователя.

Задача 4. Сервер не стартует без секрета ★☆☆ разминка

Напишите loadConfig(env), которая читает JWT_SECRET, JWT_EXPIRES_IN (по умолчанию "1h") и PORT (по умолчанию 3000). Если секрета нет или он короче 32 символов, бросьте ошибку с понятным текстом. Вызывайте её один раз при старте, а не в каждом обработчике.

Зачем: без проверки jwt.sign(payload, undefined) упадёт только при первом входе пользователя. А короткий секрет вроде "secret" подбирается перебором за минуты. Fail fast: сервер с неверной настройкой не должен даже запуститься.

Решение и разбор
export interface Config {
  jwtSecret: string;
  jwtExpiresIn: string;
  port: number;
}

export function loadConfig(env: Record<string, string | undefined> = process.env): Config {
  const secret = env.JWT_SECRET;
  if (!secret || secret.length < 32) {
    throw new Error('JWT_SECRET не задан или короче 32 символов: проверьте файл .env');
  }
  const port = Number(env.PORT ?? 3000);
  if (!Number.isInteger(port) || port <= 0) throw new Error('PORT должен быть положительным целым');
  return { jwtSecret: secret, jwtExpiresIn: env.JWT_EXPIRES_IN ?? '1h', port };
}

Параметр env со значением по умолчанию process.env — небольшое внедрение зависимости: в тестах можно передать любой объект и не трогать настоящее окружение. Дальше по коду передаётся готовый Config, а не process.env. Все поля проверены и имеют правильные типы, и в одном месте видно, какие настройки нужны приложению.
