Из чего состоит JWT

Токен — это одна строка из трёх частей, разделённых точками:

eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9                                  ← header
.eyJpZCI6IjY2NGYyYSIsImlhdCI6MTc5MzY4ODY3MywiZXhwIjoxNzkzNzc1MDczfQ   ← payload
.L3Vp…                                                                ← signature

Здесь токен разбит на строки для наглядности, на деле это одна строка без пробелов.

  1. Header (заголовок) — служебные данные: каким алгоритмом подписан токен. Например, {"alg":"HS256","typ":"JWT"}.
  2. Payload (полезная нагрузка) — то, что сервер положил в токен. Например, {"id":"664f2a","iat":1793688673,"exp":1793775073}. Поле iat — когда выдан, exp — когда истекает (в секундах с 1970 года).
  3. Signature (подпись) — строка, которую сервер вычислил из первых двух частей и своего секретного ключа.

Первые две части — это обычный JSON, записанный в кодировке base64url. Кодировка — не шифр: её может раскодировать кто угодно. Проверьте сами в Node.js:

const payload = token.split('.')[1];
console.log(Buffer.from(payload, 'base64url').toString());
// {"id":"664f2a","iat":1793688673,"exp":1793775073}

Подпись — не шифрование

Это главное, что нужно понять про JWT. Данные в токене не спрятаны, их видит любой, у кого есть токен. Защищены они от другого — от изменения.

Представьте открытку с печатью. Текст на ней читает каждый почтальон. Но если кто-то исправит текст, печать перестанет совпадать, и это сразу будет видно.

Отсюда два правила:

  • не кладите в токен пароли и другие секреты — их прочитают;
  • доверять данным из токена можно, только если сервер проверил подпись.

Фраза «я шифрую id пользователя в JWT» поэтому неточна: id не шифруют, а подписывают. Зашифрованные JWT тоже существуют (стандарт JWE), но в учебных и большинстве рабочих проектов токены только подписывают.
