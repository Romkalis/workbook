Модель пользователя и хеш пароля

// models/User.js
const mongoose = require('mongoose');
const bcrypt = require('bcrypt');

const userSchema = new mongoose.Schema({
  email: { type: String, required: true, unique: true },
  password: { type: String, required: true }, // здесь будет хеш, а не сам пароль
});

// Перед сохранением хешируем пароль, если он новый или изменился
userSchema.pre('save', async function () {
  if (!this.isModified('password')) return;
  this.password = await bcrypt.hash(this.password, 10);
});

// Проверка пароля при входе
userSchema.methods.comparePassword = function (candidate) {
  return bcrypt.compare(candidate, this.password);
};

module.exports = mongoose.model('User', userSchema);

Что такое хеш

Пароль никогда не хранится как есть. bcrypt.hash превращает "1234" в строку вида $2b$10$N9qo8uLOickgx2ZMRZoMy… длиной 60 символов. Обратно из неё пароль получить нельзя.

Как же тогда проверить пароль при входе? Не расшифровкой, а сравнением: введённый пароль хешируется заново тем же способом, и результаты сравниваются. Это делает bcrypt.compare. Число 10 — «стоимость» хеширования: чем больше, тем медленнее подбирать пароли перебором.

Даже если базу украдут, злоумышленник получит хеши, а не пароли.

Почему function, а не стрелка

Внутри хука this — это документ, который сохраняется. У стрелочной функции своего this нет, поэтому здесь нужна обычная function.

this.isModified('password') защищает от двойного хеширования: если пользователь поменял только email, пароль уже хранится как хеш, и хешировать его снова нельзя, иначе войти больше не получится.

Отличие от исходного материала

В исходнике хук написан как async function (next) с вызовами next(). Для асинхронной функции next не нужен: Mongoose сам ждёт, пока завершится Promise. Мы проверили оба варианта. В mongoose 8 работают оба. В mongoose 9 в хук больше не передаётся next, и код из исходника падает с ошибкой «next is not a function». Вариант без next работает в обеих версиях.
