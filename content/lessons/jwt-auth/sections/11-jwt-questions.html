Вопросы для самопроверки

Можно ли прочитать id пользователя из JWT без секрета?

Да. Payload только закодирован в base64url, а не зашифрован. Секрет нужен, чтобы создать или проверить подпись, а не чтобы прочитать данные.

Почему подделанный токен не пройдёт проверку?

Подпись считается от header, payload и секрета. Изменив payload, нужно пересчитать подпись, а без секрета это невозможно. jwt.verify сравнит подписи и выбросит ошибку.

Почему пароли хранят как хеш?

Из хеша нельзя получить пароль обратно. Если базу украдут, пароли пользователей останутся неизвестны. При входе введённый пароль хешируют заново и сравнивают.

Зачем в хуке pre('save') проверка isModified('password')?

Без неё при любом сохранении документа уже готовый хеш захешируется ещё раз, и пользователь больше не сможет войти.

Почему сложно разлогинить пользователя с JWT досрочно?

Сервер не хранит выданные токены, а значит, не может «забыть» один из них. Помогают короткий срок жизни, чёрный список или смена секрета для всех сразу.

Чем httpOnly cookie безопаснее localStorage и чем она рискованнее?

Скрипты страницы не могут прочитать httpOnly cookie, поэтому XSS не украдёт токен. Но браузер отправляет cookie сам, поэтому нужна защита от CSRF, например sameSite.

Словарь

Аутентификация
Проверка, кто вы: вход по паролю.
Авторизация
Проверка, что вам можно: доступ к профилю только после входа.
JWT
Подписанная строка с данными, по которой сервер узнаёт пользователя.
Payload
Часть токена с данными: id, время выдачи, срок.
Хеш
Результат необратимого преобразования строки. Одинаковый пароль даёт совпадение при проверке, а обратно пароль не восстановить.
Middleware
Функция Express, которая выполняется до обработчика маршрута.
XSS
Атака, при которой на страницу внедряют чужой JavaScript.
CSRF
Атака, при которой чужой сайт заставляет браузер отправить запрос с вашими cookie.
