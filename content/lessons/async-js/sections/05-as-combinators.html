Несколько промисов сразу

Четыре статических метода собирают массив промисов в один. Подробный разбор с реализацией — в уроке core-js-promises.

МетодВыполнится, когдаОтклонится, когда
Promise.allвыполнились все: массив значений в исходном порядкеотклонился первый
Promise.allSettledзавершились все: массив `{ status, value \reason }`никогда
Promise.raceпервый завершился успешнопервый завершился с ошибкой
Promise.anyпервый выполнилсяотклонились все: AggregateError

Типичное применение: all — загрузить данные для экрана параллельно; allSettled — разослать уведомления, неудачи не мешают остальным; race — ограничить время ожидания; any — взять ответ с самого быстрого зеркала.

Promise.all при первой ошибке отклоняется сразу, но остальные операции не отменяются: запросы продолжат выполняться, просто их результаты никто не получит. Отмена — отдельная задача, её решает AbortController.

Задача 10. Отчёт о рассылке ★★☆ практика

Напишите sendAll(emails, send): отправляет письма параллельно и возвращает { sent: string[]; failed: { email: string; reason: string }[] }. Неудачная отправка не должна мешать остальным, а порядок в списках — как во входном массиве.

Зачем: Promise.all здесь не подходит: первая ошибка отклонит всё, и вы не узнаете, кому письмо ушло. allSettled создан для «сделай всё и расскажи, что получилось».

Решение и разбор
export async function sendAll(emails: readonly string[], send: (email: string) => Promise<void>) {
  const results = await Promise.allSettled(emails.map((e) => send(e)));
  const report = { sent: [] as string[], failed: [] as { email: string; reason: string }[] };
  results.forEach((r, i) => {
    const email = emails[i]!;
    if (r.status === 'fulfilled') report.sent.push(email);
    else report.failed.push({ email, reason: r.reason instanceof Error ? r.reason.message : String(r.reason) });
  });
  return report;
}

Результаты allSettled идут в порядке входного массива, а не в порядке завершения. Поэтому индекс i надёжно связывает результат с адресом. Проверка r.status сужает тип: у fulfilled есть value, у rejected — reason. Если адресов тысячи, одновременная отправка всех может упереться в лимиты почтового сервиса. Ограничение параллельности разбирается в задаче ниже.

Задача 11. Тайм-аут без забытых таймеров ★★★ с подвохом

Напишите withTimeout(promise, ms): результат промиса, если он успел за ms, иначе отклонение TimeoutError (свой класс). После завершения таймер должен быть очищен: в тесте проверяется, что таймеров не осталось.

Зачем: наивный Promise.race([p, failAfter(ms)]) работает, но таймер остаётся висеть. В Node.js это держит процесс живым после окончания работы, а в браузере тысячи таких вызовов копят мусор. Уборка за собой — признак аккуратного асинхронного кода.

Решение и разбор
export class TimeoutError extends Error {
  constructor(ms: number) {
    super(`Не уложились в ${ms} мс`);
    this.name = 'TimeoutError';
  }
}

export function withTimeout<T>(promise: Promise<T>, ms: number): Promise<T> {
  let timer: ReturnType<typeof setTimeout> | undefined;
  const timeout = new Promise<never>((_, reject) => {
    timer = setTimeout(() => reject(new TimeoutError(ms)), ms);
  });
  return Promise.race([promise, timeout]).finally(() => clearTimeout(timer));
}

finally срабатывает при любом исходе гонки и убирает таймер. Операция при тайм-ауте не отменяется: мы только перестаём её ждать. Чтобы остановить сам запрос, нужен AbortSignal (раздел про отмену). Отдельный класс ошибки позволяет вызывающему коду различать «долго» и «сломалось»: err instanceof TimeoutError.

Задача 12. Самое быстрое зеркало ★★☆ практика

Файл лежит на нескольких зеркалах. Напишите fromFastest(urls, download): возвращает первый успешный результат. Если все зеркала недоступны, отклоняется ошибкой "Все зеркала недоступны: 3" (число — сколько было попыток).

Зачем: race вернул бы первый завершившийся результат, даже если это быстрая ошибка с мёртвого зеркала. any игнорирует ошибки, пока есть надежда на успех. Разница в одном слове, а поведение противоположное.

Решение и разбор
export async function fromFastest<T>(urls: readonly string[], download: (url: string) => Promise<T>): Promise<T> {
  try {
    return await Promise.any(urls.map((url) => download(url)));
  } catch (err) {
    if (err instanceof AggregateError) throw new Error(`Все зеркала недоступны: ${err.errors.length}`, { cause: err });
    throw err;
  }
}

Здесь return await внутри try обязателен. Без await функция вернула бы промис, не дождавшись его, и catch не увидел бы AggregateError. Это ловушка из раздела про async/await. AggregateError.errors — массив всех причин. Он сохранён в cause, чтобы в логах было видно, что случилось с каждым зеркалом.
