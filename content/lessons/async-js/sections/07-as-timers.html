Таймеры: setTimeout и setInterval

setTimeout(fn, ms) вызывает функцию один раз не раньше чем через ms миллисекунд. setInterval(fn, ms) — повторно. Оба возвращают идентификатор для отмены: clearTimeout(id) и clearInterval(id).

Задержка — это минимум, а не точное время. Колбэк попадёт в очередь по истечении задержки и выполнится, когда освободится поток. Если в это время работает тяжёлый код, таймер опоздает. Браузер ещё и ограничивает таймеры: вложенные глубже пяти уровней получают задержку не меньше 4 мс, а в фоновых вкладках — до секунды и больше.

Рекурсивный setTimeout вместо setInterval

setInterval запускает функцию по расписанию, даже если предыдущий запуск ещё не закончился, например опрос сервера, который отвечает медленнее интервала. Рекурсивный setTimeout планирует следующий запуск только после завершения текущего. Так гарантируется пауза между запусками и можно менять задержку на ходу, например увеличивать её при ошибках.

export function poll(task: () => Promise<boolean>, ms: number): () => void {
  let timer: ReturnType<typeof setTimeout> | undefined;
  let stopped = false;
  const tick = async () => {
    const done = await task();
    if (!done && !stopped) timer = setTimeout(tick, ms);
  };
  timer = setTimeout(tick, ms);
  return () => {
    stopped = true;
    clearTimeout(timer);
  };
}

Тип ReturnType<typeof setTimeout> подходит и для браузера (число), и для Node (объект Timeout).

Задача 17. Debounce для поиска ★★☆ практика

Напишите debounce(fn, ms): обёртка вызывает fn только после того, как вызовы прекратились на ms миллисекунд, с аргументами последнего вызова. Добавьте обёртке метод cancel().

Зачем: поиск по мере ввода без debounce отправляет запрос на каждую букву. Десять букв — десять запросов, и ответы могут прийти не по порядку. Debounce — классическое применение clearTimeout.

Решение и разбор
export function debounce<A extends unknown[]>(fn: (...args: A) => void, ms: number) {
  let timer: ReturnType<typeof setTimeout> | undefined;
  const debounced = (...args: A) => {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), ms);
  };
  debounced.cancel = () => clearTimeout(timer);
  return debounced;
}

Каждый новый вызов отменяет запланированный и ставит новый таймер. Сработает только последний. clearTimeout(undefined) безопасен, поэтому проверка «был ли таймер» не нужна. cancel пригодится при удалении компонента со страницы: иначе запрос уйдёт уже после того, как пользователь ушёл. Родственник debounce — throttle: он вызывает функцию не чаще раза в ms, но не ждёт тишины.

Задача 18. Повтор с растущей паузой ★★★ с подвохом

Напишите retry(fn, { attempts, baseMs }): вызывает fn, при ошибке ждёт и пробует снова. Паузы растут вдвое: baseMs, 2·baseMs, 4·baseMs… Всего не больше attempts попыток, после последней неудачи отклоняется последней ошибкой. Ошибки с полем retry: false не повторяются.

Зачем: сетевые сбои часто временные, и один повтор спасает пользователя от экрана ошибки. Растущая пауза (exponential backoff) не добивает перегруженный сервер. А «не повторять 400 Bad Request» — понимание, что неверный запрос не станет верным от повтора.

Решение и разбор
const sleep = (ms: number) => new Promise((r) => setTimeout(r, ms));

export async function retry<T>(fn: () => Promise<T>, { attempts, baseMs }: { attempts: number; baseMs: number }): Promise<T> {
  let lastError: unknown;
  for (let i = 0; i < attempts; i++) {
    try {
      return await fn();
    } catch (err) {
      lastError = err;
      const permanent = typeof err === 'object' && err !== null && 'retry' in err && err.retry === false;
      if (permanent || i === attempts - 1) break;
      await sleep(baseMs * 2 ** i);
    }
  }
  throw lastError;
}

Цикл с await sleep — это и есть рекурсивный таймер из раздела, только записанный линейно. Следующая попытка не начнётся, пока не закончилась предыдущая. После последней попытки пауза не нужна, отсюда проверка i === attempts - 1. В рабочих системах к паузе добавляют случайный разброс (jitter), чтобы тысячи клиентов не повторяли запрос одновременно (из общих знаний).
