async/await

async-функция всегда возвращает промис. await приостанавливает выполнение этой функции до завершения промиса и возвращает его значение или бросает его ошибку. Остальной код страницы в это время работает.

import { delay } from './delay.js';

export async function sequential(): Promise<number> {
  const a = await delay(30, 1);
  const b = await delay(30, 2); // начнётся только после a: всего ~60 мс
  return a + b;
}

export async function parallel(): Promise<number> {
  const [a, b] = await Promise.all([delay(30, 1), delay(30, 2)]); // ~30 мс
  return a + b;
}

async/await — синтаксис поверх промисов, а не новый механизм. await x работает как .then, а try...catch вокруг await — как .catch. Зато код читается сверху вниз, как синхронный.

Ловушки

  • Лишняя последовательность. Два независимых await подряд ждут друг друга. Если второй запрос не зависит от первого, запустите оба и дождитесь через Promise.all.
  • await в forEach. forEach не ждёт промисы, которые вернул колбэк: цикл закончится сразу, а операции продолжатся «в фоне», и их ошибки никто не поймает. Для последовательной обработки нужен for...of с await, для параллельной — Promise.all(items.map(...)).
  • return без await внутри try. return fetchData() в try вернёт промис, не дожидаясь его. Если он отклонится, catch этой функции его не поймает. Пишите return await fetchData(), когда ошибку нужно обработать здесь.
  • Забытый await. const user = getUser() даст промис вместо пользователя. TypeScript обычно ловит это на первом обращении к полю.

Задача 13. Цепочку — в async/await ★☆☆ разминка

Перепишите функцию на async/await с try...catch. Поведение не должно измениться: при ошибке возвращается "нет данных".

export function cartTotal(load: () => Promise<{ price: number; qty: number }[]>): Promise<string> {
  return load()
    .then((items) => items.reduce((sum, i) => sum + i.price * i.qty, 0))
    .then((total) => `${total} ₽`)
    .catch(() => 'нет данных');
}

Зачем: async/await — тот же механизм промисов, но код читается сверху вниз. Переписать одну и ту же функцию в обе стороны — лучший способ убедиться, что это действительно одно и то же.

Решение и разбор
export async function cartTotal(load: () => Promise<{ price: number; qty: number }[]>): Promise<string> {
  try {
    const items = await load();
    const total = items.reduce((sum, i) => sum + i.price * i.qty, 0);
    return `${total} ₽`;
  } catch {
    return 'нет данных';
  }
}

Каждый then стал строкой после await, а catch цепочки — блоком catch. Синхронные шаги (reduce, сборка строки) больше не нужно заворачивать в then. Сигнатура не изменилась: async-функция по-прежнему возвращает Promise<string>.

Задача 14. Экран профиля без лишнего ожидания ★★☆ практика

Для экрана нужен пользователь, а затем по его id — заказы и уведомления. Заказы и уведомления друг от друга не зависят. Напишите loadProfile(id, api) так, чтобы они запрашивались одновременно, а общее время было «пользователь + самый долгий из двух».

Зачем: три await подряд — самый частый способ сделать экран вдвое медленнее без единой ошибки в коде. Нужно уметь видеть граф зависимостей: что ждёт чего, а что можно запускать вместе.

Решение и разбор
export interface Api {
  user(id: string): Promise<{ id: string; name: string }>;
  orders(userId: string): Promise<string[]>;
  notifications(userId: string): Promise<string[]>;
}

export async function loadProfile(id: string, api: Api) {
  const user = await api.user(id);
  const [orders, notifications] = await Promise.all([api.orders(user.id), api.notifications(user.id)]);
  return { user, orders, notifications };
}

Первый await оправдан: без пользователя нечего запрашивать. Два следующих запроса стартуют в одной строке, а Promise.all ждёт оба. Если бы и пользователь не был нужен для запросов (например, всё идёт по одному id), все три запустились бы сразу. Тест проверяет не время, а факт: второй запрос стартовал, пока первый ещё не завершился.

Задача 15. Почему не дождались ★★☆ практика

Функция должна загрузить файлы по очереди и вернуть список в порядке входного массива. Сейчас она возвращает пустой массив. Исправьте.

export async function uploadAll(files: string[], upload: (f: string) => Promise<string>): Promise<string[]> {
  const done: string[] = [];
  files.forEach(async (f) => {
    done.push(await upload(f));
  });
  return done;
}

Зачем: forEach вызывает async-колбэк, получает промис и выбрасывает его. Цикл заканчивается мгновенно, а загрузки идут «в фоне», их ошибки теряются. Это одна из самых частых ошибок в асинхронном коде.

Решение и разбор
export async function uploadAll(files: string[], upload: (f: string) => Promise<string>): Promise<string[]> {
  const done: string[] = [];
  for (const f of files) {
    done.push(await upload(f));
  }
  return done;
}

for...of с await внутри приостанавливает функцию на каждом шаге: следующая загрузка начнётся после предыдущей. Если порядок загрузки не важен, быстрее await Promise.all(files.map(upload)): результаты всё равно будут в порядке входного массива. Последовательный вариант нужен, когда сервер не любит параллельные запросы или следующий шаг зависит от предыдущего.

Задача 16. Не больше N запросов одновременно ★★★ с подвохом

Напишите mapLimit(items, limit, fn): обрабатывает все элементы, но одновременно выполняется не больше limit вызовов fn. Результат — в порядке входного массива. При первой ошибке функция отклоняется.

Зачем: это золотая середина между «по одному» (медленно) и «все сразу» (сервер ответит 429 Too Many Requests или упадёт). Задача тренирует главное в асинхронности: держать в голове, что сейчас выполняется и что будет дальше.

Подсказка

Запустите limit «работников». Каждый в цикле берёт следующий индекс из общего счётчика и обрабатывает его, пока элементы не кончатся. Дождитесь всех работников через Promise.all.

Решение и разбор
export async function mapLimit<T, R>(items: readonly T[], limit: number, fn: (item: T, index: number) => Promise<R>): Promise<R[]> {
  const results = new Array<R>(items.length);
  let next = 0;
  async function worker(): Promise<void> {
    while (next < items.length) {
      const i = next++;
      results[i] = await fn(items[i]!, i);
    }
  }
  const workers = Array.from({ length: Math.min(limit, items.length) }, () => worker());
  await Promise.all(workers);
  return results;
}

Счётчик next общий для всех работников. Гонки здесь нет: JavaScript однопоточный, и next++ выполняется целиком между двумя await. Индекс сохраняется в i до await, поэтому результат ложится на своё место, даже если элементы завершаются не по порядку. При ошибке Promise.all отклонится сразу, но уже запущенные вызовы доработают: отмена — отдельная задача.
