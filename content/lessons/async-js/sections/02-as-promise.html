Промис: обещание результата

Промис — объект, который представляет результат, которого ещё нет. У него три состояния: pending (ожидание), fulfilled (выполнен со значением) и rejected (отклонён с причиной). Перейти из ожидания можно один раз, дальше состояние не меняется. Выполненный или отклонённый промис называют settled (завершённым).

export function delay<T>(ms: number, value: T): Promise<T> {
  return new Promise((resolve) => {
    setTimeout(() => resolve(value), ms);
  });
}

Функция, переданная в new Promise, называется executor. Она выполняется сразу и синхронно, в момент создания промиса. Асинхронной становится только реакция на результат. Внутри executor вызывают resolve(значение) или reject(ошибка). Повторные вызовы игнорируются: это и есть гарантия «результат один раз».

Если executor бросит исключение, промис станет отклонённым с этой ошибкой. Но исключение внутри колбэка setTimeout в executor промис уже не поймает: колбэк выполнится позже, вне executor. Там нужно явно вызвать reject.

Обернуть колбэчный API

Старый API с колбэком «ошибка первым аргументом» превращается в промис по шаблону. В Node для этого есть готовая util.promisify, но написать обёртку руками полезно один раз:

type NodeCallback<T> = (err: Error | null, value?: T) => void;

export function promisify<A extends unknown[], T>(fn: (...args: [...A, NodeCallback<T>]) => void) {
  return (...args: A): Promise<T> =>
    new Promise((resolve, reject) => {
      fn(...args, (err, value) => (err ? reject(err) : resolve(value as T)));
    });
}

Задача 3. Пауза и тайм-аут как промисы ★☆☆ разминка

Напишите delay(ms), которая выполняется через ms миллисекунд, и failAfter(ms, message), которая через ms отклоняется с Error(message).

Зачем: это два кирпичика для следующих задач: повторов, тайм-аутов и тестов. Заодно тренируется главный шаблон: обернуть колбэчный API (здесь setTimeout) в new Promise.

Решение и разбор
export const delay = (ms: number): Promise<void> => new Promise((resolve) => setTimeout(resolve, ms));

export const failAfter = (ms: number, message: string): Promise<never> =>
  new Promise((_, reject) => setTimeout(() => reject(new Error(message)), ms));

setTimeout(resolve, ms) передаёт resolve напрямую: лишняя стрелка не нужна. Тип Promise<never> честно говорит, что успешного значения не будет никогда. Такой промис можно отдать в Promise.race рядом с любым другим, и тип результата не испортится. В тесте используются поддельные таймеры Vitest: время двигается вручную, тест идёт мгновенно.

Задача 4. Ошибка, которую не поймал промис ★★☆ практика

Функция должна отклоняться при неверном JSON, но вместо этого роняет программу непойманным исключением. Найдите причину и исправьте.

export function parseLater(text: string): Promise<unknown> {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve(JSON.parse(text));
    }, 10);
  });
}

Зачем: правило «исключение в executor отклоняет промис» работает только для синхронной части executor. Колбэк таймера выполняется позже, и его исключение уходит в глобальный обработчик. Ошибка проявляется только на плохих данных, то есть на проде.

Решение и разбор
export function parseLater(text: string): Promise<unknown> {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      try {
        resolve(JSON.parse(text));
      } catch (err) {
        reject(err);
      }
    }, 10);
  });
}

Ещё лучше — вынести асинхронность в отдельный промис и разбирать уже в цепочке: delay(10).then(() => JSON.parse(text)). Исключение внутри then автоматически отклоняет цепочку. Правило на будущее: в new Promise оборачивают только колбэчный API, а логику пишут в then или после await.

Задача 5. Промис из старого API ★★☆ практика

Старый модуль хранилища работает на колбэках «ошибка первым аргументом»: storage.get(key, cb) и storage.set(key, value, cb). Напишите createAsyncStorage(storage) с методами get(key): Promise<string | null> и set(key, value): Promise<void>, а затем функцию increment(store, key), которая читает число, увеличивает его на 1 и записывает.

// legacy.ts
type Cb<T> = (err: Error | null, value?: T) => void;
export interface LegacyStorage {
  get(key: string, cb: Cb<string | null>): void;
  set(key: string, value: string, cb: Cb<void>): void;
}
export function createLegacy(fail = false): LegacyStorage {
  const data = new Map<string, string>();
  return {
    get: (k, cb) => setTimeout(() => (fail ? cb(new Error('диск')) : cb(null, data.get(k) ?? null))),
    set: (k, v, cb) => setTimeout(() => { data.set(k, v); cb(null); }),
  };
}

Зачем: так в проекте сосуществуют старый и новый код: адаптер на границе, а дальше всё пишется на промисах. Функция increment показывает, ради чего это делается: два последовательных шага читаются как обычный код.

Решение и разбор
import type { LegacyStorage } from './legacy.js';

export function createAsyncStorage(storage: LegacyStorage) {
  return {
    get: (key: string) =>
      new Promise<string | null>((resolve, reject) => {
        storage.get(key, (err, value) => (err ? reject(err) : resolve(value ?? null)));
      }),
    set: (key: string, value: string) =>
      new Promise<void>((resolve, reject) => {
        storage.set(key, value, (err) => (err ? reject(err) : resolve()));
      }),
  };
}

export async function increment(store: ReturnType<typeof createAsyncStorage>, key: string): Promise<number> {
  const next = Number((await store.get(key)) ?? 0) + 1;
  await store.set(key, String(next));
  return next;
}

Ошибка колбэка превращается в reject, и дальше её ловит обычный try/catch или .catch. Тип ReturnType<typeof createAsyncStorage> берёт форму объекта из функции, отдельный интерфейс не нужен. Предупреждение на будущее: increment не атомарна. Два одновременных вызова прочитают одно и то же число, и одно увеличение потеряется. В базах данных для этого есть атомарные операции.
