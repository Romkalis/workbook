Разбор и форматирование

1. dateToTimestamp — строка в timestamp

'01 Jan 1970 00:00:00 UTC' => 0
'04 Dec 1995 00:12:00 UTC' => 818035920000

Date.parse возвращает timestamp, не создавая объект. Формат '04 Dec 1995 00:12:00 UTC' не входит в стандарт ISO, но все движки его понимают (его выводит toUTCString()).

function dateToTimestamp(date) {
  return Date.parse(date);
}

В условии написано «number of seconds», но пример и тесты ждут миллисекунды — верьте тестам. Для дат до 1970 года timestamp отрицательный: '01 Jan 1900' даёт −2208988800000.

2. getTime — время hh:mm:ss

Date(2023, 5, 1, 8, 20, 55) => '08:20:55'

Дата создана в местном времени — значит, и часы берём местные. Каждую часть дополняем нулём слева до двух символов.

function getTime(date) {
  const pad = (n) => String(n).padStart(2, '0');
  return [date.getHours(), date.getMinutes(), date.getSeconds()]
    .map(pad)
    .join(':');
}

Короче — date.toTimeString().slice(0, 8), но такой код опирается на формат строки, который в стандарте описан нестрого. Явная сборка читается однозначно.

3. getDayName — название дня недели

'01 Jan 1970 00:00:00 UTC' => 'Thursday'
'25 Jun 2030 20:20:35 UTC' => 'Tuesday'

Строки с UTC, а время бывает и вечерним — значит, день недели нужен по UTC. Названия отдаёт Intl через toLocaleDateString с опциями.

function getDayName(date) {
  return new Date(date).toLocaleDateString('en-US', {
    weekday: 'long',
    timeZone: 'UTC',
  });
}

Без timeZone: 'UTC' функция использовала бы пояс компьютера, и '25 Jun 2030 20:20:35 UTC' в Токио стала бы средой. Массив ['Sunday', 'Monday', ...][date.getUTCDay()] тоже работает, а Intl заодно умеет любой язык: 'ru-RU' даст «четверг».

8. formatDate — дата в формате США

'2024-02-01T15:00:00.000Z' => '2/1/2024, 3:00:00 PM'

Формат M/D/YYYY, h:mm:ss AM/PM — ровно то, что выдаёт локаль en-US. Дата в UTC (Z), значит и форматируем в UTC.

function formatDate(date) {
  return new Date(date).toLocaleString('en-US', { timeZone: 'UTC' });
}

Проверено в Node.js 22: перед PM обычный пробел. В других версиях ICU (библиотеки, на которой работает Intl) там бывает узкий неразрывный пробел U+202F, и строковое сравнение падает при визуально одинаковом тексте (из общих знаний). Если тест «не сходится в одном пробеле» — дело в этом.
