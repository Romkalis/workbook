Network: анализ запросов Теория: Network features reference → Load; Clear; Inspect details

Запрос — обращение страницы за ресурсом или данными, ответ — результат со статусом, заголовками и телом. URL — адрес ресурса. Заголовки передают служебные сведения, тело — содержимое. Сначала выберите строку запроса, затем смотрите её подробности: фильтры меняют только список, а не поведение сети.

Вкладка Network записывает все запросы, которые делает страница: HTML, стили, скрипты, картинки, шрифты, fetch и XHR. Это ответ на вопросы «что загрузилось», «что ушло на сервер», «что вернул сервер» и «что тормозит».

Запись идёт только при открытом DevTools

Network не умеет показывать то, что произошло до его открытия. Чтобы увидеть запросы загрузки страницы, откройте DevTools, перейдите на вкладку Network и только потом перезагрузите страницу (F5).

Таблица запросов

Основные колонки по умолчанию: Name (имя ресурса), Status (код ответа: 200 успех, 304 не изменилось, 404 не найдено, 5xx ошибка сервера), Type (document, stylesheet, script, fetch, png...), Initiator (кто инициировал запрос: ссылка на файл и строку кода), Size (размер), Time (длительность) и Waterfall (график по времени). Правая кнопка по заголовку колонок позволяет добавить другие, например Method, Domain, Protocol.

Над таблицей две временных шкалы. Overview — общий обзор, на нём можно выделить мышью интересный фрагмент. А вертикальные линии на водопаде отмечают события страницы: синяя — DOMContentLoaded (HTML разобран, DOM построен), красная — load (загружены все ресурсы, включая картинки).

Красным в таблице подсвечиваются неудачные запросы (статус 4xx, 5xx, отменённые). На демо-странице это missing.png с кодом 404. Очистить журнал можно кнопкой Clear (значок «запрет») или командой в меню; опция Keep log (раньше Preserve log) сохраняет записи между перезагрузками, что нужно при отладке редиректов и отправки форм.

Фильтры

Фильтры включаются значком воронки (filter toggle). Их несколько уровней, и они комбинируются:

  • Строка фильтра: подстрока имени или URL. Регулярное выражение в слешах (/\.(png|jpg)$/). Исключение через минус: -main.css.
  • Property-фильтры вида свойство:значение: domain:, method:, status-code:, mime-type:, larger-than: (в байтах, можно 100k), scheme: и другие. Подсказки выпадают при вводе.
  • Кнопки типов: All, Fetch/XHR, Doc, CSS, JS, Font, Img, Media и далее. С зажатым Ctrl (Cmd) выбирается несколько типов.
  • Invert — инверсия фильтра, More filters — дополнительные (скрыть data URL и расширения, показать только запросы третьих сторон и т. п.).

Если нужно найти запрос не по имени, а по тому, что внутри заголовков или тела ответа, откройте вкладку Search (Ctrl+F / Cmd+F внутри Network): она ищет по содержимому всех записанных запросов.

Сведения об отдельном запросе

Клик по строке открывает панель подробностей. В ней вкладки:

Эксперименты с сетью

  • Throttling (выпадающий список «No throttling») имитирует медленный интернет: Fast 4G, Slow 4G, 3G и другие. Режим Offline полностью выключает сеть и позволяет проверить, как приложение ведёт себя без связи.
  • Disable cache отключает кэш браузера, пока DevTools открыт. Включайте его, когда сомневаетесь, что вы смотрите свежую версию файла.
  • Правая кнопка на перезагрузке → Empty cache and hard reload очищает кэш для этой страницы и грузит всё заново.
  • Request blocking: командное меню → «block» → добавьте шаблон URL, и такие запросы будут отклоняться. Хороший способ проверить, как страница живёт без шрифта, скрипта или картинки.
  • Screenshots включает ленту кадров загрузки над таблицей: видно, как страница появлялась на экране.
  • Правая кнопка по запросу → Copy даёт копию запроса как cURL, fetch и т. п. А Save all as HAR сохраняет весь журнал в файл для отправки коллегам.
