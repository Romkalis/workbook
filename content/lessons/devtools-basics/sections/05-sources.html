Sources: структура приложения и отладка Теория: Sources overview → Files; Pause your code with breakpoints → Event listener breakpoints

Брейкпоинт, или точка остановки, приостанавливает JavaScript на выбранной строке. После остановки Scope показывает доступные переменные, Call Stack — цепочку вызовов. Продолжить выполнение и пройти один шаг — разные действия: сначала предскажите следующую строку, потом нажмите нужную кнопку.

Вкладка Sources состоит из трёх зон: слева навигатор файлов, по центру редактор, справа отладчик (панели Breakpoints, Scope, Call Stack и другие). В узких окнах отладчик уезжает вниз.

Дерево файлов (Page)

Вкладка Page в навигаторе показывает всё, что страница загрузила, структурой «верхний уровень → источник (origin) → файлы». Если на странице есть iframe, у него будет своё поддерево. Сторонние скрипты (аналитика, расширения) лежат в своих папках, и это хороший способ понять, откуда на странице чужой код. Открыть файл по имени можно через Ctrl+P (Cmd+P).

Рядом есть ещё три вкладки навигатора. В программе модуля они прямо не названы, но пригодятся:

  • Workspace привязывает папку проекта на диске, и тогда правки в DevTools сохраняются в ваши файлы;
  • Overrides сохраняет выбранные загруженные ресурсы в локальную папку и при следующих запросах подставляет их вместо ответов сайта;
  • Snippets — сохранённые скрипты, которые запускаются кнопкой Run или командой ! в командном меню.

Для Local Overrides выберите папку, подтвердите доступ DevTools, затем в Network нажмите правой кнопкой на нужный запрос и выберите пункт сохранения или переопределения ответа (например, Override content). DevTools сохранит его копию в выбранной папке. После этого можно локально менять HTML, CSS, JavaScript, заголовки или тело ответа API и перезагружать страницу: Chrome покажет локальный вариант вместо ответа сервера. Это позволяет проверить исправление, макет или ответ API, не дожидаясь изменений на сервере; сами изменения видны только в вашем браузере и не отправляются на сервер.

Редактор

Редактор позволяет менять код. CSS обновляется на странице сразу. JavaScript нужно сохранить через Ctrl+S (Cmd+S), причём применяется только новое тело функций: если вы переписали код верхнего уровня, он не выполнится заново. Все правки живут до перезагрузки, если не подключён Workspace.

Брейкпоинты: останавливаем код

Брейкпоинт говорит отладчику «встань здесь». Код замирает на строке, и вы можете разглядывать значения переменных, стек вызовов и шагать дальше. Основные типы:

ТипКак поставитьКогда нужен
Line-of-codeКлик по номеру строки в редактореЗнаете, где искать
ConditionalПравый клик по номеру → Add conditional breakpointОстановка только при условии (i === 99)
LogpointПравый клик → Add logpointВывести значение в консоль без правки кода
Event listenerПанель Event Listener Breakpoints → категория (например Mouse → click)Не знаете, какой код реагирует на событие
DOM changeElements → правый клик по узлу → Break onКто-то меняет или удаляет узел
XHR / fetchПанель XHR/fetch Breakpoints, фильтр по подстроке URLОстановиться в момент запроса
ExceptionКнопка Pause on exceptionsОстановиться на месте исключения

Включите флажок рядом с DOM-событием в панели Event Listener Breakpoints — например, Mouse → click. Когда на странице произойдёт это событие и браузер начнёт выполнять обработчик, отладчик поставит код на паузу. В Call Stack и редакторе можно увидеть, какой обработчик сработал, и пройти его по шагам. Это именно остановка выполнения, а не запись события в журнал.

Брейкпоинт срабатывает перед выполнением отмеченной строки. Если в панели есть неудобные брейкпоинты, их можно временно отключить кнопкой Deactivate breakpoints, не удаляя.

Шагаем по коду

Когда код остановился, в панели отладчика появляются кнопки управления:

  • Resume (F8) — продолжить до следующего брейкпоинта;
  • Step over (F10) — выполнить строку целиком, не заходя в вызванные функции;
  • Step into (F11) — зайти внутрь функции, вызванной в строке;
  • Step out (Shift+F11) — дойти до конца текущей функции и выйти.

На паузе информативны три панели: Scope (переменные в текущей области видимости, Local, Closure, Global), Watch (ваши выражения, которые пересчитываются на каждом шаге) и Call Stack (цепочка функций, которая привела в эту точку, клик переключает контекст). Кроме того, значения переменных подсказываются прямо в редакторе рядом с кодом, а на паузе работает и Console: выражения вычисляются в контексте остановленной функции.

Ищем баг: почему 5 + 1 = 51

Классический пример из статьи про отладку. Калькулятор складывает значения двух полей, но вместо 6 показывает 51. В Console мы ничего не увидим, ошибок нет, код «работает». Ставим брейкпоинт на первой строке функции сложения, нажимаем «Сложить» и шагаем:

Исправление: привести значения к числам, Number(...) или parseInt(..., 10). Проверить исправление, не перезагружая страницу, можно так: остановиться на паузе, поправить код в редакторе, сохранить Ctrl+S и продолжить. Начиная с Chrome 105 можно править функцию, остановленную прямо на паузе.

Чужой код и ignore list

Шагая через Step into, легко забраться в код библиотек или фреймворка. Чтобы этого избежать, включают «Focus on your code» (с Chrome 106): сторонние скрипты попадают в ignore list, а отладчик их пропускает. Настраивается в Settings → Ignore List.

Что запомнить

Все изменения в DevTools — локальные. Они меняют только вашу вкладку в вашем браузере и пропадают при перезагрузке. Чтобы они стали частью проекта, нужно перенести их в исходники либо подключить Workspace.
