Оформление Pull Request по правилам школы

Для News API откройте PR из news-api в main своего fork и оставьте его неслитым. Действующие Pull Request Requirements RS School требуют пять частей: ссылку на задачу, изображение результата, публичный deploy, даты сдачи и дедлайна, самооценку. Скриншот перетащите в описание PR — GitHub вставит изображение.

Авторская заготовка Markdown ниже из общих знаний применяет эти требования к News API. Замените заполнители; в Score укажите реальный результат, в чек-листе — баллы за каждый пункт из карты критериев. Не отмечайте непроверенное как выполненное.

1. Task: ССЫЛКА_НА_УСЛОВИЕ
2. Screenshot:
   ВСТАВЬТЕ_ИЗОБРАЖЕНИЕ_ЧЕРЕЗ_GITHUB
3. Deployment: ПУБЛИЧНЫЙ_URL
4. Done ДД.ММ.ГГГГ / deadline ДД.ММ.ГГГГ
5. Score: ФАКТИЧЕСКИЕ_БАЛЛЫ / 200

Самопроверка:
- [ ] PR: __ / 20
- [ ] История коммитов: __ / 20
- [ ] Миграция TS (пять групп по 10): __ / 50
- [ ] ESLint: __ / 10
- [ ] Отсутствие any: __ / 10
- [ ] strict и noImplicitAny: __ / 20
- [ ] Webpack: __ / 10
- [ ] Адаптивность: __ / 10
- [ ] Улучшения дизайна: __ / 20

Улучшения дизайна: ПЕРЕЧИСЛИТЕ
Где использованы обязательные типы: ФАЙЛЫ_И_МЕТОДЫ
Проверки: КОМАНДЫ_И_РЕЗУЛЬТАТЫ
Недочёты и штрафы: ПЕРЕЧИСЛИТЕ_ИЛИ_УКАЖИТЕ_ОТСУТСТВИЕ

По правилам школы в PR не должно быть закомментированного кода, лишних файлов, node_modules и случайно добавленного результата генерации. Публикацию dist выполняйте отдельно от исходников по выбранному способу deploy.

Старая ссылка из задания на pull-request-review-process возвращала 404; выше приведена доступная страница требований. Дополнительные поля о дизайне и проверках помогают проверить именно News API. Перед отправкой убедитесь, что ссылки открываются у другого человека.
