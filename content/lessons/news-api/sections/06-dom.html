Этап 5. Переносим представления и события DOM

После переноса загрузчика дойдите до мест, где программа работает с документом. querySelector может вернуть null, содержимое template нужно проверить, а event.target не обязан быть HTMLElement. Именно здесь массовые утверждения as и оператор ! чаще всего скрывают реальный сбой.

Проверки вместо обещаний компилятору

  1. Для обязательного контейнера проверьте результат поиска и выдайте понятную ошибку, если элемента нет. Для необязательного элемента выберите безопасное отсутствие действия.
  2. При делегировании сначала проверьте target через instanceof Element, затем найдите ближайший элемент с нужным data-атрибутом. Проверьте, что он относится к вашему контейнеру.
  3. Прочитайте dataset и учтите undefined до передачи id источника в контроллер.
  4. Для template проверьте HTMLTemplateElement, для картинки — HTMLImageElement. Типовая подсказка querySelector сама не проверяет разметку во время выполнения.
  5. У колбэка обозначьте входные данные и результат. Методу отрисовки, который ничего не возвращает, подходит void; методу, который строит узел, нужен тип этого узла.

Используйте textContent для внешнего текста. Не вставляйте непроверенные заголовки и описания через innerHTML. Для ссылок и изображений отдельно продумайте допустимые протоколы URL, заглушку при отсутствии картинки и поведение при ошибке её загрузки. Это рекомендации из общих знаний по безопасной работе с DOM.

Состояния, которые легко пропустить

  • Загрузка: видно, что запрос ещё выполняется.
  • Пустой ответ: сообщение вместо пустого непонятного блока.
  • Сбой: понятное сообщение и возможность повторить действие.
  • Быстрая смена источника: старый ответ не должен затереть выбранный позже. Можно сравнивать номер запроса или отменять предыдущий через AbortController.

Готово, когда: источники и новости отрисовываются, клики работают, отсутствие полей и сетевой сбой не ломают страницу. Никаких ts-ignore, массовых non-null assertions и отключения строгих правил ради зелёного отчёта.
