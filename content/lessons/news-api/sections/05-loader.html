Этап 4. Типизируем загрузчик и контроллер

Начните перенос с типов и небольших модулей без DOM, затем двигайтесь к загрузчику, контроллеру, представлениям и точке входа. Переименовывайте файлы небольшими группами, сразу исправляя импорты и проверяя сборку. Для каждого метода определите параметры, результат и владельца данных.

Ответ сервера начинается с unknown

Аннотация или утверждение типа не проверяют JSON. Полученный результат сначала считайте unknown, затем проверьте необходимые поля и только после этого передавайте в интерфейс. Пример ниже проверяет минимальную модель из предыдущего раздела и принимает дополнительные поля.

function parseArticle(value: unknown): Article {
  if (
    typeof value !== "object" || value === null ||
    !("title" in value) || typeof value.title !== "string" ||
    !("url" in value) || typeof value.url !== "string" ||
    !("description" in value) ||
    (typeof value.description !== "string" && value.description !== null)
  ) {
    throw new Error("Некорректная статья");
  }
  return {
    title: value.title,
    url: value.url,
    description: value.description,
  };
}

function parseArticlesResponse(value: unknown): Article[] {
  if (
    typeof value !== "object" || value === null ||
    !("status" in value) || value.status !== "ok" ||
    !("articles" in value) || !Array.isArray(value.articles)
  ) {
    throw new Error("Некорректный ответ с новостями");
  }
  const items: unknown[] = value.articles;
  return items.map(parseArticle);
}

const articles = parseArticlesResponse({
  status: "ok",
  articles: [{ title: "Новость", url: "https://example.org/", description: null }],
});
console.log(articles[0]?.title);

Это минимальная проверка успешного конверта. В приложении отдельно разберите status error, проверьте code и message и покажите понятную ошибку. Если добавляете urlToImage, author или publishedAt, расширьте и модель, и проверку. Не превращайте отсутствующее поле в заведомо допустимое без решения о поведении интерфейса.

Generic связывает проверку и результат

Параметр T должен передавать реальную связь типов. В этом примере тип результата определяется переданным парсером. В отличие от слепого утверждения JSON как T, функция действительно вызывает проверку.

type Decoder<T> = (value: unknown) => T;

class NewsLoader {
  public constructor(private readonly baseUrl: string) {}

  public async get<T>(path: string, decode: Decoder<T>): Promise<T> {
    const response = await fetch(new URL(path, this.baseUrl));
    if (!response.ok) {
      throw new Error(`HTTP ${response.status}`);
    }
    const raw: unknown = await response.json();
    return decode(raw);
  }
}

async function loadArticles(loader: NewsLoader): Promise<Article[]> {
  return loader.get("mocks/everything", parseArticlesResponse);
}

// Проверка без сети: подставляем контролируемый ответ.
const originalFetch = globalThis.fetch;
globalThis.fetch = async () => new Response(JSON.stringify({
  status: "ok", articles: [],
}));
loadArticles(new NewsLoader("https://example.org/"))
  .then((items) => console.log(items.length))
  .finally(() => { globalThis.fetch = originalFetch; });

Подмена fetch в конце нужна только для самостоятельного запуска учебного примера, в приложение её переносить не следует. Для реального API стройте параметры через URLSearchParams в отдельном месте и согласуйте путь с сервером. Начальный слеш в path заменяет путь baseUrl; относительный путь сохраняет его при корректном завершающем слеше базы.

private закрывает доступ к полю в проверке TypeScript, public показывает внешний метод класса. Это не защита API-ключа в браузере. Подробнее: модификаторы доступа и generics.

Готово, когда: успешный ответ и сбой проходят по понятным веткам, обработчики получают правильные типы, а в catch ошибка сужается из unknown через instanceof Error или другую проверку.
