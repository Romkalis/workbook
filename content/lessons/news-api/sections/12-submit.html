Этап 9. Deploy и сдача на cross-check

Публикуем production-сборку

Основной способ по условию — gh-pages. Публикуйте содержимое выходного каталога сборки, а не исходный TypeScript. Если сайт открывается по пути с именем репозитория, проверьте пути JS, CSS и изображений: запросы к корню домена могут приводить к 404.

Если gh-pages использовать невозможно, разрешён Netlify Drop. Загрузите собранный каталог и задайте имя по шаблону GitHub-account-name-task-name, например octocat-news-api. После публикации проверьте сетевые запросы, картинки, ссылки и обновление страницы. Убедитесь, что проверяющий увидит рабочий режим, а не отладочную подмену fetch.

Финальная сдача

До дедлайна отправьте именно ссылку на открытый Pull Request в RS App → Cross-Check: Submit. Ссылка только на deploy или на репозиторий не заменяет PR. Затем выполните назначенные взаимопроверки по правилам школы. Дедлайн не указан в присланном тексте: возьмите его из своего расписания.

Как понять, что работа закончена?

Все прикладные JS-файлы перенесены, типы и линтер проходят без подавлений, сборка опубликована и работает с API, адаптивность и footer проверены, улучшения описаны, PR открыт в свой main и ссылка отправлена в RS App. Встроенный тест ниже помогает проверить понимание, но не сдаёт задание за вас.
