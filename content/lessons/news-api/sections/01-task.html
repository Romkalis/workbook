Что нужно сделать и с чего начать

Вам дано работающее JavaScript-приложение с новостями. Задача — сделать публичный fork, перенести приложение на TypeScript, сохранить его поведение, улучшить оформление и опубликовать результат. Не создавайте новый проект на React или Next.js: в этом задании нужно разобраться в исходном приложении и его сборке Webpack.

Этот урок — маршрут выполнения присланного задания. Он не заменяет актуальную карточку задания в вашем потоке. План и упражнения — авторские дополнения из общих знаний; обязательные условия и баллы ниже взяты из присланного текста.

Какие уроки держать под рукой

  • TypeScript Basic — если пока трудно читать типы, функции и классы.
  • Модули и import type — для зависимостей между файлами.
  • Проверка unknown — для ответа сервера.
  • Webpack и ESLint — готовый разбор настройки инструментов.
  • Классы и прототипы и основы ООП — чтобы понять устройство исходника.
  • Chrome DevTools — чтобы проверить запросы и найти ошибки выполнения.

Маршрут с проверками результата

  1. Создать fork и ветку, запустить JS-версию. Результат: известен исходный сценарий работы.
  2. Подключить TypeScript, Webpack и ESLint. Результат: проверяется и собирается первый TS-файл.
  3. Описать контракты данных. Результат: источники, статьи и ошибки имеют разные типы.
  4. Перенести загрузчик и контроллер. Результат: данные проходят через типизированные методы.
  5. Перенести представления и события DOM. Результат: приложение снова работает целиком.
  6. Проверить обязательные конструкции. Результат: для каждой есть полезное применение.
  7. Улучшить дизайн и адаптивность. Результат: интерфейс работает от 320 до 1920 px.
  8. Пройти проверки и опубликовать сборку. Результат: доступен работающий deploy.
  9. Оформить открытый PR и отправить ссылку. Результат: работа готова к cross-check.

После каждого этапа делайте небольшой осмысленный коммит. Не откладывайте весь перенос на один финальный коммит: история должна показывать ход разработки.
