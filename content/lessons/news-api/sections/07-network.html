API, proxy и mocks: как не застрять на сети

В присланном условии указано ограничение прямого обращения к News API вне localhost и предложен учебный proxy. Выбирайте базовый URL в одном месте: локальная и опубликованная версии могут требовать разных настроек.

Разработка на статических ответах

По условию у proxy есть пути /mocks/sources и /mocks/everything со статическими данными для экономии лимита запросов. Начните с них: получите ответ, сравните его с моделью, отладьте отрисовку. Не ожидайте, что статический mock будет фильтровать новости так же, как живой endpoint.

Доступность proxy в этой работе подтвердить не удалось. Пути mocks взяты из присланного задания; формат параметров живых запросов и требования к ключу нужно проверить перед подключением. Не угадывайте, нужен ли префикс /v2: прямой News API и учебный proxy могут иметь разные маршруты.

Что смотреть в Network

  1. Проверьте полный URL и параметры запроса, затем HTTP-статус.
  2. Откройте тело ответа: даже после успешного HTTP-запроса приложение должно распознать ошибку на уровне данных.
  3. Различайте неверный ключ, исчерпанный лимит, ошибочный маршрут, CORS и недоступный сервер. Изменение интерфейса TypeScript их не исправит.
  4. Для CORS проверьте сервер и разрешённый origin. Режим no-cors не даёт читаемый JSON и не решает задачу.
  5. Перед сдачей переключитесь на рабочие endpoints и повторите сценарий уже на deploy. Одних mocks недостаточно, чтобы подтвердить выбор источника.

API-ключ, помещённый в клиентскую сборку через переменную окружения, остаётся доступен посетителю. Не коммитьте личный ключ; способ предоставления доступа проверяющему согласуйте с актуальным условием курса. Это пояснение из общих знаний, а не дополнительный критерий задания.
