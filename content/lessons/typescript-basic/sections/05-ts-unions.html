Union, narrowing и пересечения

Сужение типа (narrowing) — уточнение после проверки. Например, в ветке typeof id === "string" переменная id уже не string | number, а string. Discriminant, или дискриминант, — поле с разными фиксированными значениями, по которому можно различить варианты объекта.

Union A | B разрешает значение одного из вариантов. Intersection A & B требует одновременно выполнить оба контракта. Символы похожи на логические операции, но работают с типами, а не исполняемыми выражениями.

Сужение типа проверками

function formatId(id: string | number): string {
  if (typeof id === "string") return id.trim().toUpperCase();
  return id.toFixed(0);
}
console.log(formatId(" rs "), formatId(42)); // RS 42
function first(value: string | string[]): string {
  return Array.isArray(value) ? (value[0] ?? "") : value;
}
console.log(first(["TS"]));

Пока переменная может быть и строкой, и числом, TypeScript разрешит только то, что умеют оба типа. Например, toUpperCase() есть только у строк, поэтому вызвать его сразу нельзя. После проверки typeof value === "string" компилятор знает: внутри этой ветки точно строка. Другие средства: instanceof для классов, in для свойств и Array.isArray для массивов. Учитывайте, что typeof null === "object". Проверка truthy отбрасывает также пустую строку и ноль; если надо исключить только отсутствие, проверяйте null/undefined явно.

Размеченное объединение: состояние без противоречий

type LoadResult =
  | { status: "loading" }
  | { status: "success"; data: string[] }
  | { status: "error"; message: string };
function render(result: LoadResult): string {
  switch (result.status) {
    case "loading": return "Загрузка";
    case "success": return result.data.join(", ");
    case "error": return result.message;
    default: {
      const unreachable: never = result;
      return unreachable;
    }
  }
}
console.log(render({ status: "success", data: ["TS"] }));

Общее поле status — дискриминант. В ветке success гарантированно есть data, а в error — message. Если добавить новый вариант и забыть обработку, присваивание в never обнаружит пропуск. Это надёжнее объекта с тремя необязательными полями, который разрешает бессмысленные сочетания.

Пересечение контрактов

type Identified = { id: number };
type Titled = { title: string };
type Lesson = Identified & Titled;
const lesson: Lesson = { id: 1, title: "TypeScript" };
type Impossible = { id: string } & { id: number };
console.log(lesson.title);
if (false) {
  // @ts-expect-error: id должен быть одновременно string и number (never)
  const impossible: Impossible = { id: 1 };
}

Пересечение не означает «выбрать правое свойство при конфликте». Несовместимые требования к одному полю могут дать never. При interface extends несовместимое переопределение обычно обнаруживается уже в объявлении интерфейса.
