Union, narrowing и пересечения

Сужение типа (narrowing) — уточнение после проверки. Например, в ветке typeof id === "string" переменная id уже не string | number, а string. Discriminant, или дискриминант, — поле с разными фиксированными значениями, по которому можно различить варианты объекта.

Union A | B разрешает значение одного из вариантов. Intersection A & B требует одновременно выполнить оба контракта. Символы похожи на логические операции, но работают с типами, а не исполняемыми выражениями.

Сужение типа проверками

function formatId(id: string | number): string {
  if (typeof id === "string") return id.trim().toUpperCase();
  return id.toFixed(0);
}
console.log(formatId(" rs "), formatId(42)); // RS 42
function first(value: string | string[]): string {
  return Array.isArray(value) ? (value[0] ?? "") : value;
}
console.log(first(["TS"]));

Пока переменная может быть и строкой, и числом, TypeScript разрешит только то, что умеют оба типа. Например, toUpperCase() есть только у строк, поэтому вызвать его сразу нельзя. После проверки typeof value === "string" компилятор знает: внутри этой ветки точно строка. Другие средства: instanceof для классов, in для свойств и Array.isArray для массивов. Учитывайте, что typeof null === "object". Проверка truthy отбрасывает также пустую строку и ноль; если надо исключить только отсутствие, проверяйте null/undefined явно.

Задача 12. Количество из строки или числа ★☆☆ разминка

Количество товара приходит то числом (из кода), то строкой (из поля ввода). Напишите parseQuantity(input: string | number): number: строку обрезает от пробелов и переводит в число; результат должен быть целым и не меньше 1, иначе функция бросает RangeError.

Зачем: union на входе — нормальная ситуация на границе программы. Задача функции — превратить «то или это» в одно надёжное значение, чтобы дальше по коду об этом не думать.

Подсказка

Сначала typeof input === 'string' — внутри ветки доступен trim(). Проверку целого числа делает Number.isInteger.

Решение и разбор
export function parseQuantity(input: string | number): number {
  const value = typeof input === 'string' ? Number(input.trim()) : input;
  if (!Number.isInteger(value) || value < 1) {
    throw new RangeError(`Количество должно быть целым числом от 1, получено: ${String(input)}`);
  }
  return value;
}

В ветке typeof input === 'string' тип сужен до string, и trim() разрешён. В другой ветке остаётся number. Дальше одна проверка покрывает всё сразу: Number("abc") даёт NaN, а Number.isInteger(NaN) — false. Пустая строка превращается в 0 и тоже отсекается условием < 1.

Задача 13. Теги в любом виде ★★☆ практика

Теги товара хранятся по-разному: строкой "new, sale", массивом или их нет совсем. Напишите normalizeTags(tags: string | string[] | undefined): string[]: всегда массив, без пробелов по краям и без пустых строк.

Зачем: приведение «разношёрстных» данных к одной форме в одном месте — основной приём защиты от хаоса. Остальной код работает только с string[] и не проверяет три случая заново.

Решение и разбор
export function normalizeTags(tags: string | string[] | undefined): string[] {
  if (tags === undefined) return [];
  const list = Array.isArray(tags) ? tags : tags.split(',');
  return list.map((t) => t.trim()).filter((t) => t !== '');
}

Три проверки сужают тип по очереди: после === undefined остаётся string | string[], а Array.isArray разделяет массив и строку. Для массива typeof не подходит: он вернёт "object". Чистка (trim, фильтр пустых) идёт после приведения к массиву, поэтому написана один раз для обоих случаев.

Размеченное объединение: состояние без противоречий

type LoadResult =
  | { status: "loading" }
  | { status: "success"; data: string[] }
  | { status: "error"; message: string };
function render(result: LoadResult): string {
  switch (result.status) {
    case "loading": return "Загрузка";
    case "success": return result.data.join(", ");
    case "error": return result.message;
    default: {
      const unreachable: never = result;
      return unreachable;
    }
  }
}
console.log(render({ status: "success", data: ["TS"] }));

Общее поле status — дискриминант. В ветке success гарантированно есть data, а в error — message. Если добавить новый вариант и забыть обработку, присваивание в never обнаружит пропуск. Это надёжнее объекта с тремя необязательными полями, который разрешает бессмысленные сочетания.

Задача 14. Состояние загрузки каталога ★★☆ практика

Опишите тип CatalogState размеченным объединением: idle, loading, success с массивом товаров, error с сообщением. Напишите statusText(state): «Нажмите "Загрузить"», «Загрузка…», «Найдено N товаров», «Ошибка: …». В default добавьте проверку полноты через never.

Зачем: три отдельных поля isLoading, error, data разрешают бессмыслицу: загрузка и ошибка одновременно. Размеченное объединение описывает только возможные состояния, а never гарантирует, что новое состояние не забудут отрисовать.

Решение и разбор
export type CatalogState =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'success'; products: { title: string }[] }
  | { status: 'error'; message: string };

export function statusText(state: CatalogState): string {
  switch (state.status) {
    case 'idle':
      return 'Нажмите "Загрузить"';
    case 'loading':
      return 'Загрузка…';
    case 'success':
      return `Найдено ${state.products.length} товаров`;
    case 'error':
      return `Ошибка: ${state.message}`;
    default: {
      const unreachable: never = state;
      return unreachable;
    }
  }
}

В ветке 'success' компилятор знает, что есть products, а в 'error' — message, без единой проверки на undefined. Строка const unreachable: never = state компилируется, только если все варианты обработаны выше. Это «сигнализация» на будущее, следующая задача её проверит.

Задача 15. Новое состояние — и сработала сигнализация ★★★ с подвохом

Добавьте в CatalogState из прошлой задачи вариант { status: 'empty' } (ничего не найдено). Не трогая statusText, запустите проверку типов и прочитайте ошибку. Затем обработайте новый вариант.

Зачем: в реальном проекте состояние добавляет один человек, а switch лежит в пяти файлах у других. Проверка через never превращает «забыли обработать» из бага на проде в ошибку компиляции.

Подсказка

Ошибка будет в строке const unreachable: never = state: в неё «просочился» необработанный вариант.

Решение и разбор
export type CatalogState =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'empty' }
  | { status: 'success'; products: { title: string }[] }
  | { status: 'error'; message: string };

export function statusText(state: CatalogState): string {
  switch (state.status) {
    case 'idle':
      return 'Нажмите "Загрузить"';
    case 'loading':
      return 'Загрузка…';
    case 'empty':
      return 'Ничего не найдено';
    case 'success':
      return `Найдено ${state.products.length} товаров`;
    case 'error':
      return `Ошибка: ${state.message}`;
    default: {
      const unreachable: never = state;
      return unreachable;
    }
  }
}

До исправления компилятор сообщает примерно: Type '{ status: "empty"; }' is not assignable to type 'never'. В тексте ошибки прямо назван пропущенный вариант. Почему отдельное состояние empty, а не success с пустым массивом: у пустого результата свой интерфейс (сообщение, кнопка «Сбросить фильтры»), и явный вариант не даст его забыть.

Пересечение контрактов

type Identified = { id: number };
type Titled = { title: string };
type Lesson = Identified & Titled;
const lesson: Lesson = { id: 1, title: "TypeScript" };
type Impossible = { id: string } & { id: number };
console.log(lesson.title);
if (false) {
  // @ts-expect-error: id должен быть одновременно string и number (never)
  const impossible: Impossible = { id: 1 };
}

Пересечение не означает «выбрать правое свойство при конфликте». Несовместимые требования к одному полю могут дать never. При interface extends несовместимое переопределение обычно обнаруживается уже в объявлении интерфейса.

Задача 16. Отметка времени через пересечение ★☆☆ разминка

Опишите type Timestamps = { createdAt: string; updatedAt: string } и type StoredProduct = Product & Timestamps. Напишите toStored(p: Product, now: string): StoredProduct, которая проставляет обе даты.

Зачем: пересечение собирает тип из независимых «кусков»: отметки времени нужны и товару, и заказу, и пользователю. Описав их один раз, вы не копируете поля по всем сущностям.

Решение и разбор
type Product = { id: number; title: string; price: number };
type Timestamps = { createdAt: string; updatedAt: string };
export type StoredProduct = Product & Timestamps;

export function toStored(p: Product, now: string): StoredProduct {
  return { ...p, createdAt: now, updatedAt: now };
}

Значение типа A & B должно удовлетворять обоим контрактам сразу, поэтому в объекте есть все поля. Время передаётся параметром now, а не берётся внутри через new Date(): так функция чистая и её легко тестировать (зависимость от часов вынесена наружу).
