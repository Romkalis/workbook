Generics и keyof: сохраняем связь типов

В identity буква T — место для конкретного типа. При вызове identity(42) компилятор подставляет числовой тип и сохраняет его в результате. Запись K extends keyof T читается как «K должен быть одним из ключей T», а T[K] — «тип значения по этому ключу».

Generic — параметр типа. Он нужен, когда несколько мест сигнатуры должны зависеть от одного выбранного типа. Замена всех типов на any эту связь теряет.

Функция и контейнер с параметром типа

function identity<T>(value: T): T { return value; }
interface Box<T> { value: T }
const box: Box<string> = { value: "TypeScript" };
const count = identity(42); // тип выведен из аргумента
const title = identity<string>(box.value); // тип задан явно
function first<T>(items: readonly T[]): T | undefined { return items[0]; }
console.log(count, title.toUpperCase(), first<number>([]));

В identity<T> один и тот же T описывает вход и выход. Компилятор чаще всего выводит его сам. Сигнатура first учитывает пустой массив: обещание просто T было бы неверным. Внутри generic-функции нельзя считать, что у любого T есть length.

Ограничение extends

function lengthOf<T extends { length: number }>(value: T): number {
  return value.length;
}
console.log(lengthOf("TS"), lengthOf([1, 2, 3]));
if (false) {
  // @ts-expect-error: у числа нет свойства length
  lengthOf(42);
}

extends здесь задаёт минимальный контракт, а не наследование класса. Если нужно только прочитать length и нигде не сохранить T, достаточно параметра { length: number }. Generic полезен, когда связь типов реально используется.

keyof и доступ к типу свойства

function get<T, K extends keyof T>(object: T, key: K): T[K] {
  return object[key];
}
const student = { name: "Маша", score: 95 };
type StudentKey = keyof typeof student; // "name" | "score"
const key: StudentKey = "score";
console.log(get(student, key).toFixed(0), get(student, "name").toUpperCase());
if (false) {
  // @ts-expect-error: такого ключа нет
  get(student, "age");
}

typeof student в позиции типа получает тип переменной, keyof — объединение ключей этого типа, T[K] — тип выбранного свойства. В JS-выражении typeof по-прежнему возвращает строку. У числовой индексной сигнатуры keyof будет number; у строковой — string | number, потому что числовые ключи JS-объекта преобразуются в строки.

Готовые преобразования типов

Дополнение из общих знаний, сверяемое со справочником TypeScript: Partial<T> делает свойства необязательными, Required<T> — обязательными, Readonly<T> — доступными только для чтения. Pick<T, K> оставляет выбранные ключи, Omit<T, K> исключает их. Это изменения типов, не преобразования объектов во время выполнения.

interface Profile { id: number; name: string; bio?: string }
const patch: Partial<Profile> = { name: "Анна" };
const card: Pick<Profile, "id" | "name"> = { id: 1, name: "Маша" };
console.log({ ...card, ...patch });
