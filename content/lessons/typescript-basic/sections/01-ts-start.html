TypeScript и JavaScript: что меняется

Компилятор TypeScript — программа tsc: она проверяет код и может получить из .ts JavaScript-файлы .js. Тип описывает допустимые значения, аннотация — явная запись вроде : number, контракт — договорённость об аргументах и результате. «Во время выполнения» означает, что JavaScript уже запущен, а большая часть TS-записей удалена.

TypeScript помогает проверить договорённости о данных до запуска программы. Если функция ждёт число, редактор укажет на переданную строку. При этом арифметика, объекты, прототипы и обработка событий остаются JavaScript. Чтобы учиться по этому уроку, уже нужно понимать переменные, функции, массивы и классы JS.

Работайте в два прохода: сначала прочитайте пример и предскажите результат, затем запустите его и объясните типы. В уроке есть намеренные ошибки: строки с @ts-expect-error должны отклоняться компилятором. Директива нужна только для проверки учебных примеров; исправлять ею прикладной код не следует.

Типы до запуска, значения во время выполнения

function double(value: number): number {
  return value * 2;
}
console.log(double(21)); // 42
if (false) {
  // @ts-expect-error: строка не является числом
  double("21");
}

В записи value: number после двоеточия описан параметр, а после скобок — результат функции. Эти аннотации исчезнут из выпущенного JS. Если проверку обойти и передать строку, поведение определит JavaScript, а не аннотация. TypeScript не добавляет автоматическую проверку ответа сервера. Большинство типов стирается, но обычные классы и enum создают код выполнения.

Первый запуск и настройки

Самый короткий путь — открыть TypeScript Playground, включить Strict и сравнить вкладки TypeScript и JavaScript. Для отдельного учебного проекта установите локальный компилятор. Команды ниже выполняются в новой папке, где установлен Node.js; src/index.ts содержит первый пример.

npm init -y
npm install --save-dev typescript
npx tsc --init
npx tsc --project tsconfig.json
node dist/index.js
Какая версия поставится

Сейчас эта команда ставит TypeScript 7 — компилятор, переписанный на Go: tsc в нём работает как раньше. Но ts-loader для Webpack и typescript-eslint пока требуют TypeScript 5.x. Если они нужны в проекте, ставьте typescript@5.9 (подробности — в уроке TypeScript Advanced).

Замените созданный конфиг следующим минимальным вариантом. Здесь target задаёт уровень выходного JS, module — формат модулей, outDir — папку результата. Это вариант для небольших упражнений в Node.js, а настройки приложения с бандлером могут отличаться.

{
  "compilerOptions": {
    "target": "ES2020",
    "module": "CommonJS",
    "strict": true,
    "noEmitOnError": true,
    "rootDir": "src",
    "outDir": "dist"
  },
  "include": ["src/**/*.ts"]
}

strict включает семейство строгих проверок, в том числе noImplicitAny и strictNullChecks. noEmitOnError запрещает выпуск JS при ошибках; без этой опции диагностика и выпуск кода — разные процессы. tsc --noEmit только проверяет типы. Не передавайте имя файла вместе с ожиданием, что автоматически применится ваш tsconfig: используйте --project.

Практический совет из общих знаний: сохраните конфигурацию, исходники и lock-файл зависимостей вместе. Так другой студент сможет повторить запуск с той же версией компилятора.

Создайте отдельную папку для упражнения, откройте в ней терминал, затем выполните команды установки. Перед сборкой создайте папку src, файл src/index.ts с первым примером и tsconfig.json из блока ниже. Команды npx tsc и node dist/index.js выполняйте только после создания этих файлов. В Playground включите strict и выберите target ES2020: это важно для примера с bigint.
