Модули и namespaces

Модуль — файл со своей областью имён и явно указанными зависимостями. Export делает объявление доступным другим модулям, import подключает его. Различайте тип, нужный компилятору, и значение, которое должно существовать при выполнении: import type подключает только первое.

Модуль ограничивает область видимости файла и явно объявляет зависимости. Для современного прикладного кода используйте стандартные import/export; правильный способ запуска зависит от Node.js, браузера или бандлера.

Именованный экспорт, default и import type

Создайте два файла рядом. В примере путь .js в исходном TS предназначен для выходного файла после компиляции. Файлы проверены вместе и выполнены после компиляции в CommonJS; при выборе нативного ESM дополнительно согласуйте module, moduleResolution и package.json с окружением.

// model.ts
export interface Lesson { title: string }
export const prefix = "Урок: ";
export default function format(lesson: Lesson): string {
  return prefix + lesson.title;
}

// main.ts
import format, { prefix } from "./model.js";
import type { Lesson } from "./model.js";
const lesson: Lesson = { title: "TypeScript" };
console.log(format(lesson), prefix.length);

Именованный импорт использует фигурные скобки и имя экспорта; default можно локально назвать иначе. import type явно отделяет типы и исчезает из выпущенного кода. Интерфейс нельзя передать в instanceof: во время выполнения его нет. export type аналогично экспортирует только тип. Если в файле нет ни одного import или export, TypeScript по умолчанию может считать его обычным скриптом, у которого все переменные общие с другими такими файлами. Тогда две переменные count в разных файлах дадут ошибку «уже объявлена». Пустой export {} в начале файла явно делает его модулем со своими переменными.

Namespace не заменяет модульную систему

namespace Geometry {
  export interface Point { x: number; y: number }
  export function length(point: Point): number {
    return Math.hypot(point.x, point.y);
  }
}
console.log(Geometry.length({ x: 3, y: 4 })); // 5

Namespace группирует имена, а его экспортированные члены доступны через имя контейнера. Namespace с исполняемыми членами обычно создаёт JS-объект. Этот механизм встречается в старом коде и декларациях типов; он не описывает загрузку файлов так, как ES-модули. Оборачивать каждый модуль ещё и в namespace обычно избыточно. Файлы .d.ts описывают существующий JS или API и сами реализацию не создают.
