any, unknown, never и void

Разделяйте две ситуации: неизвестно, что пришло снаружи (unknown), и значение вообще невозможно получить на данном пути (never). Void описывает результат, который вызывающий код не использует. Ни один из этих типов не является командой преобразовать реальные данные.

Доверять данным или проверять их

any отключает значимую проверку операций: можно обращаться к несуществующим полям и передавать значение дальше почти куда угодно. Ошибка обнаружится лишь при выполнении. unknown тоже принимает любое значение, но не позволяет пользоваться им до проверки. Для непроверенных внешних данных это удобная отправная точка.

function readTitle(value: unknown): string {
  if (typeof value === "object" && value !== null && "title" in value) {
    if (typeof value.title === "string") return value.title;
  }
  throw new Error("Ожидался объект со строковым title");
}
const raw: unknown = JSON.parse('{"title":"Учебник"}');
console.log(readTitle(raw));
try { readTitle({ title: 5 }); }
catch { console.log("Некорректные данные отклонены"); }

JSON.parse обычно возвращает any. Явно сохранив результат как unknown, мы обязуемся проверить форму.

Предикат типа оформляет такую проверку в переиспользуемую функцию. Вместо boolean в результате пишут value is Student: «если функция вернула true, значение — Student». После вызова в if компилятор сужает тип так же, как после typeof:

interface Student { name: string; score: number }

function isStudent(value: unknown): value is Student {
  return (
    typeof value === "object" && value !== null &&
    "name" in value && typeof value.name === "string" &&
    "score" in value && typeof value.score === "number"
  );
}

const data: unknown = JSON.parse('[{"name":"Маша","score":95},{"name":"Лев"}]');
if (Array.isArray(data)) {
  const students = data.filter(isStudent); // Student[]
  console.log(students.length); // 1
}

Предикат удобен и в filter: результат сразу получает тип Student[]. Но компилятор не проверяет тело предиката: если забыть проверить score, функция всё равно «пообещает» Student, и ошибка всплывёт позже. Поэтому предикат пишут один раз, внимательно и с тестами на неверные данные.

Задача 17. Разбор товара из unknown ★★☆ практика

Напишите parseProduct(value: unknown): Product, где Product = { id: number; title: string; price: number }. Если форма не подходит, бросьте Error. Не используйте any, as и !. Затем вынесите проверку в предикат isProduct(value): value is Product и перепишите parseProduct через него.

Зачем: данные из JSON.parse, fetch и localStorage — это unknown, что бы ни было написано в типах. Функция-разбор на входе — единственное место, где «чужое» становится «своим». Предикат делает такую проверку переиспользуемой, например в filter.

Подсказка

Порядок проверок: объект и не null → есть ли поля (in) → тип каждого поля. Цене стоит проверить и Number.isFinite.

Решение и разбор
export type Product = { id: number; title: string; price: number };

export function isProduct(value: unknown): value is Product {
  return (
    typeof value === 'object' &&
    value !== null &&
    'id' in value && typeof value.id === 'number' &&
    'title' in value && typeof value.title === 'string' &&
    'price' in value && typeof value.price === 'number' && Number.isFinite(value.price)
  );
}

export function parseProduct(value: unknown): Product {
  if (!isProduct(value)) throw new Error('Неверный формат товара');
  return value;
}

const raw: unknown = JSON.parse('[{"id":1,"title":"A","price":100},{"id":"2"}]');
const valid = Array.isArray(raw) ? raw.filter(isProduct) : []; // Product[]
console.log(valid.length); // 1

После 'id' in value TypeScript разрешает читать value.id (тип unknown), а typeof сужает его дальше. Предикат value is Product сообщает компилятору: если функция вернула true, значение — Product. Компилятор верит предикату на слово: забудете проверить price — тип соврёт. Поэтому предикат пишут один раз, аккуратно и с тестами. Бонус: raw.filter(isProduct) возвращает уже Product[].

Невозможный результат и игнорируемый результат

never не содержит ни одного значения: функция всегда бросает исключение или не заканчивает выполнение, либо ветка логически недостижима. void в контракте колбэка означает, что вызывающий код не использует результат. undefined — конкретное значение, это другая идея.

function fail(message: string): never { throw new Error(message); }
const items: string[] = [];
const save: (text: string) => void = text => items.push(text);
save("TS");
console.log(items.length); // 1
try { fail("Нет урока"); } catch { console.log("Ошибка обработана"); }

push возвращает число, но функция подходит колбэку с результатом void: контракт позволяет проигнорировать число. Из этого не следует, что функция с явной аннотацией function f(): void может возвращать любое значение.

Задача 18. Помощник assertNever и тип колбэка ★☆☆ разминка

1) Вынесите проверку полноты в функцию assertNever(value: never): never, которая бросает ошибку с текстом значения. 2) Опишите тип колбэка OnQuantityChange: принимает id товара и новое количество, результат вызывающий код не использует.

Зачем: одна и та же конструкция в каждом switch — повод сделать функцию. А тип колбэка с void честно говорит: «верни что хочешь, я это не читаю». Это расширяет круг подходящих обработчиков.

Решение и разбор
export function assertNever(value: never): never {
  throw new Error(`Необработанный вариант: ${JSON.stringify(value)}`);
}

export type OnQuantityChange = (productId: number, quantity: number) => void;

const log: number[] = [];
export const onChange: OnQuantityChange = (id, qty) => log.push(id * 100 + qty); // push возвращает число — это нормально

type Status = 'idle' | 'done';
export function label(status: Status): string {
  switch (status) {
    case 'idle': return 'ждём';
    case 'done': return 'готово';
    default: return assertNever(status);
  }
}

never в параметре работает как сигнализация из прошлых задач, а never в результате говорит: функция не возвращается, она только бросает. Почему она всё-таки бросает, раз до неё «нельзя дойти»: данные из сети могут нарушить типы, и тогда лучше громкая ошибка, чем молчаливый undefined. Обработчик с push возвращает число, но тип с void его принимает: результат просто игнорируется.
