Примитивы, массивы и кортежи

Примитив — простое значение вроде строки, числа или boolean, в отличие от объекта с полями. Union, или объединение, записывают через вертикальную черту: string | null разрешает строку либо null. Кортеж — массив с заранее заданным смыслом и типом каждой позиции.

Аннотация задаёт множество допустимых значений. Пишите string, number, boolean со строчной буквы: String, Number, Boolean относятся к объектным обёрткам. Отдельных типов int и float нет.

Семь видов примитивных значений

let title: string = "Учебник";
let progress: number = 0.5;
let finished: boolean = false;
const big: bigint = 12n;
const key: symbol = Symbol("lesson");
let missing: undefined = undefined;
let empty: null = null;
console.log(title, progress, finished, big, typeof key, missing, empty);
if (false) {
  // @ts-expect-error: boolean не принимает строку
  finished = "false";
}

bigint — целые произвольной точности, symbol — уникальные идентификаторы. Для литералов bigint нужен подходящий target, здесь ES2020. null и undefined при строгой проверке не подставляются произвольно вместо строки или числа. Если отсутствие допустимо, добавьте его явно через объединение: string | null.

Задача 4. Товар из примитивов ★☆☆ разминка

Объявите переменные для одного товара с явными типами: название, цена в копейках, есть ли на складе, скидка в процентах, которой может не быть. Напишите функцию finalPrice(price, discount): без скидки возвращает цену, со скидкой — цену минус процент, округлённую до целых копеек.

Зачем: «значения может не быть» — отдельный случай, и он должен быть виден в типе. Иначе кто-то передаст 0 там, где имелось в виду «скидки нет», или забудет обработать null.

Подсказка

Тип скидки: number | null. Проверяйте именно === null: скидка 0% — это число, а не отсутствие.

Решение и разбор
export const title: string = 'Каркассон';
export const price: number = 249000;
export const inStock: boolean = true;
export const discount: number | null = null;

export function finalPrice(price: number, discount: number | null): number {
  if (discount === null) return price;
  return Math.round(price * (1 - discount / 100));
}

При strict TypeScript не позволит передать null туда, где ждут number, поэтому отсутствие записано явно через union. Проверка === null, а не if (!discount): последняя спутала бы «скидки нет» и «скидка 0». Строго говоря, с нулём результат совпадёт, но привычка различать «нет значения» и «пустое значение» спасёт в других местах. Типы string, number, boolean пишутся со строчной буквы.

Массив — повторяющиеся элементы, кортеж — известные позиции

const scores: number[] = [80, 95];
const names: Array<string> = ["Анна", "Лев"];
const pair: [string, number] = ["Анна", 95];
const point: readonly [number, number] = [10, 20];
console.log(scores.map(n => n + 1), names.join(", "), pair[1], point[0]);
if (false) {
  // @ts-expect-error: массив принимает только числа
  scores.push("100");
  // @ts-expect-error: readonly запрещает запись через point
  point[0] = 5;
}

number[] и Array<number> равнозначны. В кортеже [string, number] первый элемент — строка, второй — число; порядок важен. readonly запрещает запись только на этапе проверки: редактор подчеркнёт scores[0] = 5. После компиляции типов не остаётся, и в работающей программе массив можно изменить, как обычно. Ещё одна ловушка: для массива number[] TypeScript считает, что scores[100] — это number, хотя на деле там undefined. Флаг noUncheckedIndexedAccess в tsconfig исправляет это: тип становится number | undefined, и компилятор заставит проверить значение.

Когда нужен кортеж вместо массива?

Когда позиции имеют разный смысл и известный порядок: например, координаты или пара «имя, балл». Для списка учеников нужен массив объектов.

Задача 5. Диапазон цен кортежем ★☆☆ разминка

Напишите priceRange(prices: number[]): возвращает кортеж [минимум, максимум] или null, если массив пуст. Аннотируйте результат.

Зачем: кортеж нужен, когда позиции имеют смысл: первая — минимум, вторая — максимум. Тип number[] позволил бы вернуть массив из трёх или нуля элементов, и вызывающий код не знал бы, что получил.

Подсказка

Math.min(...prices) для пустого массива вернёт Infinity, поэтому пустой случай обработайте первым.

Решение и разбор
export function priceRange(prices: number[]): [number, number] | null {
  if (prices.length === 0) return null;
  return [Math.min(...prices), Math.max(...prices)];
}

Тип [number, number] | null говорит всё: либо ровно два числа в известном порядке, либо явное «нечего показать». Деструктуризация const [min, max] = range после проверки на null даст два number. Почему null, а не [0, 0]: ноль — реальная цена, и подменять им «нет данных» значит соврать интерфейсу.

Задача 6. Обещание не менять массив ★★☆ практика

Напишите total(prices), которая складывает цены. Параметр сделайте readonly number[]. Внутри функции напишите строку prices.push(0) с // @ts-expect-error, чтобы убедиться: запись запрещена.

Зачем: readonly в параметре — обещание вызывающему: «я не испорчу твой массив». Многие баги — это функция, которая «по пути» отсортировала или дополнила чужие данные. Такой тип ещё и принимает обычные массивы, так что ограничение ничего не стоит.

Решение и разбор
export function total(prices: readonly number[]): number {
  if (false) {
    // @ts-expect-error: readonly-массив нельзя менять
    prices.push(0);
  }
  return prices.reduce((sum, p) => sum + p, 0);
}

const mutable = [100, 200];
console.log(total(mutable)); // обычный массив подходит

Методы, которые меняют массив (push, sort, splice), у readonly number[] отсутствуют, а map, filter, reduce остаются. Если сортировка всё же нужна, придётся сделать копию [...prices].sort(), и это правильно. Обратное не работает: в функцию, которая ждёт number[], readonly-массив передать нельзя, ведь она вправе его менять.
