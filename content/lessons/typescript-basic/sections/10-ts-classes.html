Классы в TypeScript

Здесь implements означает «класс обязан реализовать перечисленные операции», а extends — «класс наследует реализацию». Public, protected и private управляют доступом при проверке TypeScript. Поле с # — отдельный механизм JavaScript, работающий и при выполнении.

Класс остаётся JavaScript-конструктором с прототипом. TypeScript добавляет описание полей, доступность членов и проверку контрактов. Класс существует как значение для new и как тип его экземпляров.

Поля, конструктор, implements и static

interface Describable { describe(): string }
class Lesson implements Describable {
  static category = "Обучение";
  readonly id: number;
  public title: string;
  private visits = 0;
  constructor(id: number, title: string) {
    this.id = id;
    this.title = title;
  }
  describe(): string {
    this.visits += 1;
    return `${this.title}: ${this.visits}`;
  }
}
const lesson = new Lesson(1, "TS");
console.log(Lesson.category, lesson.describe());

implements проверяет форму экземпляра, но не создаёт методы и не наследует реализацию. Типы параметров метода всё равно нужно объявить. static относится к самому классу, а не экземпляру. При strictPropertyInitialization поле должно быть инициализировано сразу или в конструкторе; optional-поле или тип с undefined явно допускает отсутствие.

Задача 30. Класс корзины ★★☆ практика

Опишите интерфейс CartApi с методами add(id, price), remove(id), total() и count() (общее количество штук). Реализуйте class Cart implements CartApi с приватным хранилищем строк. Повторное добавление увеличивает количество. Покажите, что снаружи нельзя добраться до хранилища.

Зачем: приватное состояние — это гарантия инварианта: количество не станет нулём или отрицательным, потому что менять его можно только через методы класса. implements фиксирует публичный контракт: его можно реализовать иначе (например, с localStorage), не меняя код, который пользуется корзиной.

Решение и разбор
export interface CartApi {
  add(id: number, price: number): void;
  remove(id: number): void;
  total(): number;
  count(): number;
}

export class Cart implements CartApi {
  #lines = new Map<number, { price: number; quantity: number }>();

  add(id: number, price: number): void {
    const line = this.#lines.get(id);
    if (line) line.quantity += 1;
    else this.#lines.set(id, { price, quantity: 1 });
  }

  remove(id: number): void {
    this.#lines.delete(id);
  }

  total(): number {
    let sum = 0;
    for (const { price, quantity } of this.#lines.values()) sum += price * quantity;
    return sum;
  }

  count(): number {
    let n = 0;
    for (const { quantity } of this.#lines.values()) n += quantity;
    return n;
  }
}

if (false) {
  const cart = new Cart();
  // @ts-expect-error: снаружи хранилища не видно ни под каким именем
  cart.lines;
}
// Даже во время работы: Object.keys(new Cart()) → [], поле #lines не перечисляется и не читается извне.

Выбрано поле #lines, а не private lines: # защищает и во время выполнения, а private только при проверке типов. Map по id даёт поиск за O(1) и сам решает вопрос «повторное добавление». Методы total и count вычисляют значения, а не хранят их: хранимую сумму пришлось бы пересчитывать при каждом изменении, и рано или поздно её забудут обновить.

public, protected, private и абстрактные классы

abstract class Material {
  constructor(protected title: string) {}
  abstract read(): string;
  get label(): string { return this.title; }
}
class Article extends Material {
  #opened = 0;
  override read(): string {
    this.#opened += 1;
    return `${this.title}: ${this.#opened}`;
  }
}
const article = new Article("TypeScript");
console.log(article.label, article.read());

public доступен снаружи (это значение по умолчанию), protected — в классе и наследниках, private — внутри объявившего класса. TS-модификатор private проверяется компилятором; JS-поле #opened обеспечивает приватность и при выполнении. protected title в параметре конструктора — сокращённое объявление и присваивание поля.

Абстрактный класс нельзя непосредственно создать через new; наследник реализует абстрактные члены. extends наследует реализацию, а implements только проверяет контракт. В собственном конструкторе наследника перед обращением к this вызывают super. override явно помечает переопределение; флаг noImplicitOverride требует такие отметки. Геттер читают как свойство.

Интерфейс и абстрактный класс взаимозаменяемы?

Не полностью. Интерфейс стирается и не хранит реализацию. Абстрактный класс может содержать реализацию и состояние и участвует в цепочке наследования.

Задача 31. Скидки: абстрактный класс и наследники ★★★ с подвохом

Опишите abstract class Discount с абстрактным методом amount(total: number): number и обычным методом apply(total), который возвращает итог, не меньше нуля. Реализуйте PercentDiscount (процент) и FixedDiscount (сумма в копейках). Пометьте переопределения override.

Зачем: общее правило «итог не уходит в минус» живёт в одном месте, в базовом классе, а наследники отвечают только за «сколько скидка». Новый вид скидки — новый маленький класс без копирования проверки.

Решение и разбор
export abstract class Discount {
  abstract amount(total: number): number;

  apply(total: number): number {
    return Math.max(0, total - this.amount(total));
  }
}

export class PercentDiscount extends Discount {
  constructor(private readonly percent: number) {
    super();
  }
  override amount(total: number): number {
    return Math.round((total * this.percent) / 100);
  }
}

export class FixedDiscount extends Discount {
  constructor(private readonly kopecks: number) {
    super();
  }
  override amount(): number {
    return this.kopecks;
  }
}

if (false) {
  // @ts-expect-error: абстрактный класс нельзя создать
  new Discount();
}

Это паттерн «шаблонный метод»: apply задаёт алгоритм, наследники подставляют шаг. constructor(private readonly percent: number) одновременно объявляет и заполняет поле. Наследник вызывает super() до обращения к this. FixedDiscount.amount объявлен без параметра, и это допустимо: меньше параметров, как с колбэками. Округление стоит в одном месте, в процентной скидке, потому что только она даёт дробные копейки.
