Классы в TypeScript

Здесь implements означает «класс обязан реализовать перечисленные операции», а extends — «класс наследует реализацию». Public, protected и private управляют доступом при проверке TypeScript. Поле с # — отдельный механизм JavaScript, работающий и при выполнении.

Класс остаётся JavaScript-конструктором с прототипом. TypeScript добавляет описание полей, доступность членов и проверку контрактов. Класс существует как значение для new и как тип его экземпляров.

Поля, конструктор, implements и static

interface Describable { describe(): string }
class Lesson implements Describable {
  static category = "Обучение";
  readonly id: number;
  public title: string;
  private visits = 0;
  constructor(id: number, title: string) {
    this.id = id;
    this.title = title;
  }
  describe(): string {
    this.visits += 1;
    return `${this.title}: ${this.visits}`;
  }
}
const lesson = new Lesson(1, "TS");
console.log(Lesson.category, lesson.describe());

implements проверяет форму экземпляра, но не создаёт методы и не наследует реализацию. Типы параметров метода всё равно нужно объявить. static относится к самому классу, а не экземпляру. При strictPropertyInitialization поле должно быть инициализировано сразу или в конструкторе; optional-поле или тип с undefined явно допускает отсутствие.

public, protected, private и абстрактные классы

abstract class Material {
  constructor(protected title: string) {}
  abstract read(): string;
  get label(): string { return this.title; }
}
class Article extends Material {
  #opened = 0;
  override read(): string {
    this.#opened += 1;
    return `${this.title}: ${this.#opened}`;
  }
}
const article = new Article("TypeScript");
console.log(article.label, article.read());

public доступен снаружи (это значение по умолчанию), protected — в классе и наследниках, private — внутри объявившего класса. TS-модификатор private проверяется компилятором; JS-поле #opened обеспечивает приватность и при выполнении. protected title в параметре конструктора — сокращённое объявление и присваивание поля.

Абстрактный класс нельзя непосредственно создать через new; наследник реализует абстрактные члены. extends наследует реализацию, а implements только проверяет контракт. В собственном конструкторе наследника перед обращением к this вызывают super. override явно помечает переопределение; флаг noImplicitOverride требует такие отметки. Геттер читают как свойство.

Интерфейс и абстрактный класс взаимозаменяемы?

Не полностью. Интерфейс стирается и не хранит реализацию. Абстрактный класс может содержать реализацию и состояние и участвует в цепочке наследования.
