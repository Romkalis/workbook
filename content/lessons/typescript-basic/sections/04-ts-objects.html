Объекты, interface и type

Структурная совместимость означает проверку полей, а не только имён типов: если функция требует id и name, объект с такими полями может подойти, даже если его объявили отдельно. Знак ? делает поле необязательным; readonly запрещает запись через соответствующую типизированную ссылку.

Объектный тип описывает доступные свойства и методы. Совместимость в TypeScript в основном структурная: важно наличие нужных членов, а не имя объявления.

Обязательные, optional и readonly свойства

interface Student {
  readonly id: number;
  name: string;
  nickname?: string;
}
function label(student: Student): string {
  return student.nickname ?? student.name;
}
const student = { id: 1, name: "Маша", group: "RS" };
console.log(label(student)); // Маша
if (false) {
  // @ts-expect-error: у свежего литерала проверяются лишние свойства
  label({ id: 1, name: "Маша", group: "RS" });
}

nickname? можно не передавать; при чтении получится string | undefined. Оператор ?? выбирает запасное значение только при null или undefined. readonly id запрещает менять id через ссылку типа Student. Лишние поля у уже существующей переменной не мешают совместимости, а у свежего объектного литерала проверяются строже. Тип не удаляет лишние поля из реального объекта.

Как выбрать interface или type

interface Named { name: string }
interface Named { active: boolean } // слияние объявлений
interface Member extends Named { id: number }
type Identifier = string | number;
type WithScore = Member & { score: number };
const member: WithScore = { name: "Маша", active: true, id: 1, score: 95 };
console.log(member.name, member.score);

interface удобно расширять через extends; повторные объявления одного имени объединяются. type даёт имя любому типу, включая union, кортеж и функцию; повторно объявить его с тем же именем нельзя. Оба подходят для объектов, методов и generics. Не выбирайте по мифу «type для примитивов, interface для всего остального»: выбирайте нужные возможности и стиль проекта.

Индексная сигнатура и словарь

interface Counts { [name: string]: number }
const counts: Counts = { html: 2, typescript: 4 };
const statusLabels: Record<"draft" | "done", string> = {
  draft: "Черновик", done: "Готово"
};
console.log(counts.typescript, statusLabels.done);

Индексная сигнатура допускает строковые ключи с одинаковым типом значений. Она не гарантирует, что любой ключ существует. Record<K, V> полезен для словаря с известным набором ключей: в примере пропуск done станет ошибкой. object означает непримитивное значение, а не объект с любыми полями; пустой тип {} при strictNullChecks допускает почти любое значение, кроме null и undefined.
