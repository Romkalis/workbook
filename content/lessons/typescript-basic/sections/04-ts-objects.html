Объекты, interface и type

Структурная совместимость означает проверку полей, а не только имён типов: если функция требует id и name, объект с такими полями может подойти, даже если его объявили отдельно. Знак ? делает поле необязательным; readonly запрещает запись через соответствующую типизированную ссылку.

Объектный тип описывает доступные свойства и методы. Совместимость в TypeScript в основном структурная: важно наличие нужных членов, а не имя объявления.

Обязательные, optional и readonly свойства

interface Student {
  readonly id: number;
  name: string;
  nickname?: string;
}
function label(student: Student): string {
  return student.nickname ?? student.name;
}
const student = { id: 1, name: "Маша", group: "RS" };
console.log(label(student)); // Маша
if (false) {
  // @ts-expect-error: у свежего литерала проверяются лишние свойства
  label({ id: 1, name: "Маша", group: "RS" });
}

nickname? можно не передавать; при чтении получится string | undefined. Оператор ?? выбирает запасное значение только при null или undefined. readonly id запрещает менять id через ссылку типа Student. Лишние поля у уже существующей переменной не мешают совместимости, а у свежего объектного литерала проверяются строже. Тип не удаляет лишние поля из реального объекта.

Задача 9. Интерфейс товара ★☆☆ разминка

Объявите interface Product: id только для чтения (число), название, цена, необязательное описание. Напишите productSubtitle(p): возвращает описание, а если его нет — "Без описания". Строкой с @ts-expect-error покажите, что id поменять нельзя.

Зачем: readonly фиксирует решение «идентификатор не меняется», и это решение проверяет компилятор, а не память команды. Необязательное поле честно говорит, что описания может не быть, и заставляет обработать этот случай.

Решение и разбор
export interface Product {
  readonly id: number;
  title: string;
  price: number;
  description?: string;
}

export function productSubtitle(p: Product): string {
  return p.description ?? 'Без описания';
}

const book: Product = { id: 1, title: 'Чистый код', price: 150000 };
if (false) {
  // @ts-expect-error: id только для чтения
  book.id = 2;
}

Поле description? при чтении имеет тип string | undefined, и ?? подставляет запасной текст только для null/undefined. С || пустая строка "" тоже превратилась бы в «Без описания». Иногда это и нужно, но решать надо осознанно.

Как выбрать interface или type

interface Named { name: string }
interface Named { active: boolean } // слияние объявлений
interface Member extends Named { id: number }
type Identifier = string | number;
type WithScore = Member & { score: number };
const member: WithScore = { name: "Маша", active: true, id: 1, score: 95 };
console.log(member.name, member.score);

interface удобно расширять через extends; повторные объявления одного имени объединяются. type даёт имя любому типу, включая union, кортеж и функцию; повторно объявить его с тем же именем нельзя. Оба подходят для объектов, методов и generics. Не выбирайте по мифу «type для примитивов, interface для всего остального»: выбирайте нужные возможности и стиль проекта.

Задача 10. Строка корзины: extends и & ★★☆ практика

На основе Product из прошлой задачи опишите строку корзины CartItem (товар плюс quantity) через interface ... extends. Опишите ProductId как string | number (можно ли это сделать через interface?). Затем опишите DiscountedProduct через пересечение & с полем discount. Напишите lineTotal(item: CartItem).

Зачем: типы строятся из других типов, а не копируются. Если завтра у товара появится поле category, оно автоматически окажется и в строке корзины.

Решение и разбор
interface Product {
  readonly id: number;
  title: string;
  price: number;
}

export interface CartItem extends Product {
  quantity: number;
}

export type ProductId = string | number; // union можно назвать только через type

export type DiscountedProduct = Product & { discount: number };

export function lineTotal(item: CartItem): number {
  return item.price * item.quantity;
}

extends и & здесь дают одинаковый результат, выбор — вопрос стиля и возможностей. Interface удобно расширять и читать в ошибках. Union вроде string | number через interface не описать: interface всегда описывает объект. Не копируйте поля Product в CartItem руками: два описания одного и того же рано или поздно разъедутся.

Индексная сигнатура и словарь

interface Counts { [name: string]: number }
const counts: Counts = { html: 2, typescript: 4 };
const statusLabels: Record<"draft" | "done", string> = {
  draft: "Черновик", done: "Готово"
};
console.log(counts.typescript, statusLabels.done);

Индексная сигнатура допускает строковые ключи с одинаковым типом значений. Она не гарантирует, что любой ключ существует. Record<K, V> полезен для словаря с известным набором ключей: в примере пропуск done станет ошибкой. object означает непримитивное значение, а не объект с любыми полями; пустой тип {} при strictNullChecks допускает почти любое значение, кроме null и undefined.

Задача 11. Счётчик по категориям и подписи ★★☆ практика

1) Напишите countByCategory(products), которая возвращает словарь «категория → количество товаров» (Record<string, number>). 2) Объявите type Category = 'books' | 'games' и константу CATEGORY_LABELS: Record<Category, string> с русскими подписями. Убедитесь, что без одной из подписей код не компилируется.

Зачем: словарь с произвольными ключами и словарь с известными ключами — разные контракты. Во втором случае компилятор не даст забыть подпись для новой категории, а это частый баг в интерфейсе («undefined» вместо названия).

Подсказка

Если ключа ещё нет в словаре, counts[key] вернёт undefined, поэтому пишите (counts[key] ?? 0) + 1.

Решение и разбор
type Category = 'books' | 'games';

export function countByCategory(products: { category: string }[]): Record<string, number> {
  const counts: Record<string, number> = {};
  for (const p of products) counts[p.category] = (counts[p.category] ?? 0) + 1;
  return counts;
}

export const CATEGORY_LABELS: Record<Category, string> = {
  books: 'Книги',
  games: 'Настольные игры',
};

if (false) {
  // @ts-expect-error: нет подписи для games
  const broken: Record<Category, string> = { books: 'Книги' };
}

Record<string, number> не обещает, что ключ существует: TypeScript без флага noUncheckedIndexedAccess считает counts['x'] числом, хотя там undefined. Поэтому ?? 0 обязателен по смыслу, даже если компилятор не требует. Record<Category, string> требует все ключи union: добавите 'toys' в Category — получите ошибку ровно там, где забыли подпись.
