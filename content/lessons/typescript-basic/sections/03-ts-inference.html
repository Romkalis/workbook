Вывод типов и литеральные типы

Вывод типа можно увидеть, наведя курсор на переменную в редакторе. «Расширение литерала» означает переход от одного значения, например типа "read", к более широкому string, разрешающему другие строки. Колбэк — функция, которую передают другой функции для вызова позже или во время обработки элементов.

Type inference означает, что компилятор восстанавливает тип по значению и контексту. Аннотация полезна на границе функции или структуры данных; дублировать очевидный тип каждого числа обычно не нужно.

Почему let и const выводятся по-разному

let mode = "read"; // string: переменную можно переназначить
const fixed = "read"; // литеральный тип "read"
const settings = { mode: "read" }; // mode: string
settings.mode = "write";
type Mode = "read" | "write";
function describe(mode: Mode): string {
  return mode === "read" ? "Чтение" : "Запись";
}
console.log(describe(fixed), settings.mode);
if (false) {
  // @ts-expect-error: произвольная строка шире Mode
  describe(mode);
}

Литеральный тип разрешает одно значение, например "read" или 200. Union литералов описывает ограниченный набор состояний. const запрещает переназначить переменную, но свойства её объекта могут изменяться, поэтому settings.mode расширяется до string.

Задача 7. Почему "asc" не подошёл ★☆☆ разминка

Код ниже не компилируется. Объясните почему и исправьте двумя способами: через const и через аннотацию переменной.

type SortOrder = 'asc' | 'desc';
function sortPrices(prices: number[], order: SortOrder): number[] {
  return [...prices].sort((a, b) => (order === 'asc' ? a - b : b - a));
}
let order = 'asc';
sortPrices([3, 1, 2], order); // ошибка

Зачем: расширение литералов встречается каждый день: значение из let или поля объекта «теряет» точный тип. Понимая причину, вы чините это за секунду, а не через as.

Решение и разбор
type SortOrder = 'asc' | 'desc';
export function sortPrices(prices: number[], order: SortOrder): number[] {
  return [...prices].sort((a, b) => (order === 'asc' ? a - b : b - a));
}

// способ 1: const сохраняет литерал 'asc'
const fixedOrder = 'asc';
sortPrices([3, 1, 2], fixedOrder);

// способ 2: аннотация разрешает менять, но только на допустимые значения
let order: SortOrder = 'asc';
order = 'desc';
sortPrices([3, 1, 2], order);

let order = 'asc' выводится как string: переменную можно переназначить на любую строку, поэтому TypeScript расширяет тип. string шире SortOrder, и вызов отклоняется. Если значение не меняется, берите const. Если меняется (переключатель сортировки), аннотируйте SortOrder: тогда опечатка order = 'dsc' тоже будет ошибкой. Решение order as SortOrder хуже: оно пропустит и 'dsc'.

Контекстная типизация

const lengths = ["type", "interface"].map(word => word.length);
const values = [1, "two"]; // (string | number)[]
console.log(lengths, values);
// word получил string из типа массива, а результат map — number[]

В колбэке не нужно снова писать тип word: его даёт сигнатура map. Если вывести желаемое ограничение нельзя, укажите его: let result: string | undefined. При чтении чужого кода начните с параметров и возвращаемого типа, затем проследите ветвления и посмотрите подсказку редактора в каждой ветке.

Задача 8. Уберите лишние аннотации ★☆☆ разминка

В коде ниже аннотирован каждый шаг. Оставьте аннотации только там, где они задают контракт (параметры и результат экспортируемой функции), остальные уберите. Код должен по-прежнему проходить strict.

export function expensiveTitles(products: { title: string; price: number }[]): string[] {
  const limit: number = 100000;
  const expensive: { title: string; price: number }[] = products.filter(
    (p: { title: string; price: number }): boolean => p.price > limit,
  );
  const titles: string[] = expensive.map((p: { title: string; price: number }): string => p.title);
  return titles;
}

Зачем: лишние аннотации — это шум, который надо поддерживать: поменяли тип товара — правьте пять мест. Вывод типов надёжен внутри функции, а явный тип нужен на границе, где он работает как документация и защита.

Решение и разбор
export function expensiveTitles(products: { title: string; price: number }[]): string[] {
  const limit = 100000;
  return products.filter((p) => p.price > limit).map((p) => p.title);
}

limit выводится как number, p в колбэке получает тип из массива (контекстная типизация), результаты filter и map выводятся сами. Остались только параметр и результат: их видит тот, кто вызывает функцию. Наведите курсор на p в редакторе: тип тот же, что был написан вручную.
