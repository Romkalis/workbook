as, non-null assertion, as const и satisfies

Утверждение типа — просьба компилятору считать значение известным автору типом. Оно не проверяет данные. Сравните три задачи: Number(value) преобразует значение, typeof value проверяет его во время выполнения, а value as number лишь меняет представление для проверки типов.

Эти конструкции похожи внешне, но решают разные задачи. Различайте проверку контракта и просьбу поверить программисту.

Утверждение as не проверяет значение

const raw: unknown = "42";
const asserted = raw as number;
const converted = Number(raw);
console.log(typeof asserted, typeof converted); // string number

as number не преобразовало строку в число. Для преобразования нужен Number, а для безопасности ещё и проверка результата, например Number.isFinite. Утверждения разрешаются при достаточном пересечении типов; двойное as unknown as T позволяет обойти ограничение и часто скрывает ошибку. Предпочитайте сужение проверкой, если форма данных заранее неизвестна.

Оператор !: ответственность на авторе

function size(value: string | null): number {
  if (value === null) return 0;
  return value.length;
}
const maybe: string | null = "TS";
console.log(maybe!.length, size(null)); // 2 0

! после выражения (input!.value) — это обещание компилятору: «здесь точно не null». TypeScript поверит на слово и ничего не проверит. Если обещание окажется ложным, программа упадёт при запуске, как в обычном JavaScript. Для DOM безопаснее проверить результат querySelector и при необходимости instanceof HTMLInputElement. value?.length безопасно возвращает undefined при отсутствии значения; это исполняемая операция, в отличие от утверждения !. Префиксный !value — обычное логическое отрицание JS.

as const сохраняет литералы

const options = { mode: "read", size: 2 } as const;
const directions = ["up", "down"] as const;
type Direction = typeof directions[number]; // "up" | "down"
const direction: Direction = "up";
console.log(options.mode, direction);
if (false) {
  // @ts-expect-error: свойство стало readonly
  options.size = 3;
}

Без as const запись const roles = ["admin", "user"] получает тип string[]: просто какие-то строки. С as const тип становится readonly ["admin", "user"]: TypeScript запоминает точные значения и запрещает менять массив. Как и readonly, это работает только при проверке типов. Заморозить объект в работающей программе может только Object.freeze.

satisfies проверяет совместимость

type Channels = "success" | "error";
const colors = {
  success: [0, 128, 0],
  error: "red"
} satisfies Record<Channels, string | [number, number, number]>;
console.log(colors.error.toUpperCase(), colors.success[1]);

При аннотации : Record<...> чтение каждого значения дало бы широкий union. satisfies проверяет контракт, сохраняя полезную конкретику выражения: error остаётся строкой, success — кортежем. Контекст может влиять на вывод, поэтому это не обещание «тип никогда не меняется». Оператор появился в TS 4.9; в видео 2021 года его не будет.
