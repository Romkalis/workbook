Функции: параметры, колбэки и перегрузки

Сигнатура — описание параметров и результата функции. Optional-параметр можно пропустить, default задаёт значение по умолчанию, rest собирает дополнительные аргументы. Перегрузки — несколько разрешённых способов вызова одной функции, а не несколько выполняемых тел.

Сигнатура показывает вход и выход. Проверяйте типы параметров, обязательность аргументов и все пути возврата. Аннотируйте публичный результат, если хотите защитить контракт от случайного изменения реализации.

Optional, default и rest

function greet(name: string, prefix = "Привет", suffix?: string): string {
  return `${prefix}, ${name}${suffix ?? "!"}`;
}
function sum(...values: number[]): number {
  return values.reduce((total, value) => total + value, 0);
}
type Transform = (value: number) => number;
const square: Transform = value => value * value;
console.log(greet("Маша"), sum(1, 2, 3), square(4));

Optional-параметр имеет внутри функции тип с undefined; необязательные параметры ставят после обязательных. Значение по умолчанию срабатывает при пропуске или undefined, но не при null. Rest собирает остаток аргументов в массив. В типе функции стрелка отделяет тип результата, а в обычном объявлении для этого используется двоеточие.

Задача 19. Параметры по умолчанию и rest ★☆☆ разминка

Напишите formatMoney(kopecks, currency = '₽', showKopecks?): если showKopecks не false, показывает два знака после точки. И sumAll(...amounts), которая складывает любое число сумм.

Зачем: значения по умолчанию избавляют вызывающий код от повторения одного и того же ('₽' в сотне мест), а rest-параметр делает вызов естественным: sumAll(a, b, c) вместо создания массива.

Решение и разбор
export function formatMoney(kopecks: number, currency = '₽', showKopecks?: boolean): string {
  const rubles = kopecks / 100;
  const text = showKopecks === false ? Math.round(rubles).toString() : rubles.toFixed(2);
  return `${text} ${currency}`;
}

export function sumAll(...amounts: number[]): number {
  return amounts.reduce((sum, a) => sum + a, 0);
}

Тип currency выводится из значения по умолчанию (string), аннотация не нужна. showKopecks? внутри функции имеет тип boolean | undefined, поэтому сравниваем с false явно: «не передали» означает «показывать». Необязательные параметры идут после обязательных, иначе их нельзя было бы пропустить.

Контракт колбэка и this

Не добавляйте index? в тип колбэка «на всякий случай»: это обещает, что вызывающая сторона вправе не передать index. Если индекс всегда передаётся, пишите number; обработчик, которому он не нужен, просто объявит меньше параметров. Специальный первый параметр this описывает контекст вызова и стирается из JS.

function show(this: { title: string }, prefix: string): string {
  return prefix + this.title;
}
console.log(show.call({ title: "TypeScript" }, "Урок: "));
async function loadCount(): Promise<number> { return 3; }
void loadCount().then(count => console.log(count));

Результат async-функции всегда обёрнут в Promise. Здесь Promise<number> описывает число после успешного ожидания, а не значение, доступное синхронно.

Задача 20. Колбэк и асинхронная загрузка ★★☆ практика

1) Напишите renderList(products, render), где render: (p: Product, index: number) => string, возвращает массив строк. Передайте обработчик, которому индекс не нужен. 2) Напишите async function loadProducts(): Promise<Product[]>, которая возвращает два товара после await задержки 10 мс.

Зачем: в типе колбэка параметры описывают то, что вы передаёте, а не то, что обработчик обязан принять. Поэтому индекс в типе обязательный, а обработчику можно его не объявлять. Promise<T> в результате честно говорит: данных сейчас нет, они будут позже.

Решение и разбор
type Product = { id: number; title: string };

export function renderList(products: Product[], render: (p: Product, index: number) => string): string[] {
  return products.map((p, i) => render(p, i));
}

const titles = renderList([{ id: 1, title: 'A' }], (p) => p.title); // индекс не объявлен — это нормально
console.log(titles);

const wait = (ms: number) => new Promise<void>((resolve) => setTimeout(resolve, ms));

export async function loadProducts(): Promise<Product[]> {
  await wait(10);
  return [{ id: 1, title: 'Чистый код' }, { id: 2, title: 'Каркассон' }];
}

Функция с меньшим числом параметров подходит туда, где ждут больше: лишние аргументы она просто проигнорирует (так работает и JavaScript). А вот index?: number в типе был бы ложью: renderList индекс передаёт всегда. У loadProducts результат аннотирован Promise<Product[]>: вызывающий код обязан сделать await, и попытка взять .length у промиса будет ошибкой.

Когда нужны перегрузки

function convert(value: string): number;
function convert(value: number): string;
function convert(value: string | number): number | string {
  return typeof value === "string" ? Number(value) : String(value);
}
const parsed = convert("42"); // number
const printed = convert(42); // string
console.log(parsed.toFixed(0), printed.toUpperCase());

Перегрузки сохраняют зависимость результата от аргумента. Сигнатура реализации должна обслужить все перегрузки, но снаружи сама по себе недоступна. Если зависимость не нужна, одна сигнатура с union проще. Перегрузка не создаёт несколько JS-функций: тело остаётся одно.

Задача 21. Поиск по одному id и по списку ★★★ с подвохом

Напишите findProducts с перегрузками: по одному id: number возвращает Product | undefined, по массиву ids: number[] возвращает Product[]. Проверьте, что результат первого вызова нельзя использовать как массив.

Зачем: перегрузки нужны, когда тип результата зависит от типа аргумента. С одной сигнатурой (ids: number | number[]): Product | Product[] | undefined каждому вызывающему пришлось бы самому разбираться, что вернулось.

Решение и разбор
type Product = { id: number; title: string };
const PRODUCTS: Product[] = [{ id: 1, title: 'A' }, { id: 2, title: 'B' }];

export function findProducts(id: number): Product | undefined;
export function findProducts(ids: number[]): Product[];
export function findProducts(arg: number | number[]): Product | undefined | Product[] {
  if (Array.isArray(arg)) return PRODUCTS.filter((p) => arg.includes(p.id));
  return PRODUCTS.find((p) => p.id === arg);
}

const one = findProducts(1); // Product | undefined
const many = findProducts([1, 2]); // Product[]
console.log(one?.title, many.length);
if (false) {
  // @ts-expect-error: у одного товара нет length
  findProducts(1).length;
}

Снаружи видны только две верхние сигнатуры. Нижняя (реализация) должна принимать и возвращать всё, что обещают перегрузки, но вызвать её напрямую нельзя. Тело одно: внутри всё равно нужен Array.isArray. Перед тем как писать перегрузки, подумайте, не проще ли две функции findById и findByIds: часто проще, и тогда это лучшее решение.
