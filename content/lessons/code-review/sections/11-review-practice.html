Тренировка на примере скидки

  • Напишите по одному замечанию о мутации и неверной скидке: вход, фактический результат, нарушение контракта, ожидаемое поведение.
  • Отметьте важность каждого замечания. Переименование cart в items обсудите отдельно как вопрос смысла имени.
  • После исправления проверьте пустую корзину, проценты 0 и 100, отрицательное значение и NaN, сохранность входных объектов.
Как оценить своё ревью?

Автор может воспроизвести каждую найденную ошибку. Видно, почему она мешает требованию. Замечания относятся к коду, а не к способностям автора. Пожелания отделены от обязательных правок. В итоговом сообщении указаны реальные границы проверки.

Порядок школьной работы

В задании Code Review используется Movie App Code Review. По прочитанному README порядок такой:

  1. Ознакомиться с приложением и его поведением.
  2. В личном приватном школьном репозитории создать ветку code-review от main или master и разместить там код проверяемого приложения.
  3. Открыть PR из этой ветки в основную ветку своего репозитория.
  4. Проводить ревью непосредственно в PR, привязывая замечания к строкам и участкам кода.
  5. Передать ссылку на доступный проверяющему PR через RS App в нужное поле задания.

README прямо указывает, что сливать учебный PR не требуется. Перед работой перечитайте актуальное задание своего набора. Таблицу MentorEvaluationCriteria.md открыть и разобрать не удалось, поэтому здесь не приводятся неподтверждённые баллы и обязательное число замечаний. Исходники Movie App в рамках конспекта не разбирались: найденные выше ошибки относятся к авторскому примеру, а не к этому репозиторию.

Перед тестом в RS App

Объясните, зачем нужно ревью, чем оно отличается от автоматических проверок, как автор готовит PR и почему проверяющий начинает с задачи. Сформулируйте обязательное замечание, вопрос и nit. После учебного теста ниже переходите к школьному Code Review в RS App по расписанию набора.
