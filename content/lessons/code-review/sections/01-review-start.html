Зачем нужно ревью

Code review — проверка изменения другим разработчиком перед включением в общую кодовую базу. Автор уже написал и проверил решение, а рецензент смотрит на него свежим взглядом: соответствует ли оно задаче, понятны ли последствия, не усложняет ли поддержку.

Представьте поиск фильмов. На обычном запросе всё работает, но пустой ввод отправляет лишний запрос, ошибка сети оставляет бесконечный индикатор, а медленный старый ответ затирает новый. Эти случаи можно заметить, читая поток данных и проверяя сценарии, даже если форматирование идеально.

Чему посвящён урок

  • Подготовить понятный Pull Request (PR), то есть предложение включить изменение из одной ветки в другую.
  • Читать diff — разницу версий — вместе с контекстом.
  • Искать ошибки поведения, сложности и поддержки.
  • Писать конкретные замечания и отвечать на них без споров о личности.
  • Провести учебное ревью Movie App по заданию RS School.
Разделение ответственности

Автор отвечает за решение и собственную проверку. Рецензент помогает найти риски и улучшить понятность. Линтер и тесты дают автоматическую обратную связь, а человек проверяет смысл и соответствие требованиям. Одобрение не доказывает отсутствие ошибок.

План модуля RS School отводит около четырёх часов. Примеры и упражнения здесь авторские; практические дополнения из общих знаний помечены отдельно.
