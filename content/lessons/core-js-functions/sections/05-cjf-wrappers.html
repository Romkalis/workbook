Обёртки и генератор

8. logger — лог начала и конца вызова

const cosLogger = logger(Math.cos, console.log);
cosLogger(Math.PI) => -1
лог: cos(3.141592653589793) starts
     cos(3.141592653589793) ends

Тест проверяет три вещи: формат строк, порядок (запись starts уже есть в момент вызова исходной функции) и то, что результат возвращается без изменений. Аргументы печатаются через JSON.stringify: массив ['expected', 'test', 1] должен выглядеть как ["expected","test",1].

function logger(func, logFunc) {
  return (...args) => {
    const call = `${func.name}(${args.map((a) => JSON.stringify(a)).join(',')})`;
    logFunc(`${call} starts`);
    const result = func(...args);
    logFunc(`${call} ends`);
    return result;
  };
}

Это декоратор: функция с тем же интерфейсом, которая добавляет поведение. Имя берётся из func.name — у Math.cos это cos. Если исходная функция бросит ошибку, строка ends не напишется; для настоящего логгера стоило бы обернуть вызов в try...finally, но условие этого не требует.

9. partialUsingArguments — частичное применение

const fn = (x1, x2, x3, x4) => x1 + x2 + x3 + x4;
partialUsingArguments(fn, 'a')('b', 'c', 'd') => 'abcd'
partialUsingArguments(fn, 'a', 'b', 'c', 'd')() => 'abcd'

Частичное применение фиксирует первые аргументы и возвращает функцию, которая ждёт остальные. Rest-параметры собирают обе порции, spread передаёт их вместе.

function partialUsingArguments(fn, ...args1) {
  return (...args2) => fn(...args1, ...args2);
}

Название задачи намекает на старый объект arguments, но airbnb запрещает его правилом prefer-rest-params, так что rest-параметры — единственный вариант, который пройдёт линтер. То же умеет встроенный fn.bind(null, ...args). Отличие от каррирования: каррированная функция принимает аргументы строго по одному, f(a)(b)(c).

10. getIdGeneratorFunction — генератор id

const getId4 = getIdGenerator(4); getId4() => 4; getId4() => 5
function getIdGeneratorFunction(startFrom) {
  let next = startFrom;
  return () => {
    const id = next;
    next += 1;
    return id;
  };
}

Счётчик next живёт в замыкании, у каждого генератора свой. Снаружи до него не добраться иначе, чем вызовом функции: это простейшая инкапсуляция без классов. Ту же задачу решает генератор function* с бесконечным циклом и yield, но тогда пришлось бы вызывать .next().value, а тест ждёт обычную функцию.
