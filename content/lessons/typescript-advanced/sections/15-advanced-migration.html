Миграция JS → TS и ESLint

Переименование .js в .ts — только начало. Практический план из общих знаний: сначала восстановите рабочий запуск исходного приложения, затем добавьте инструменты, опишите границы данных, переведите модули небольшими шагами и проверяйте поведение после каждого шага. Ошибки компилятора помогают найти ранее неявные договорённости, но не заменяют функциональную проверку.

Начните с границ, а не с утверждений as

  1. Зафиксируйте исходные сценарии и результат сборки.
  2. Настройте tsconfig, loader и typecheck, сохранив рабочий запуск.
  3. Опишите DTO ответа, параметры запросов, результаты и ошибки отдельно от UI-модели.
  4. Принимайте внешние значения как unknown и проверяйте перед использованием.
  5. Типизируйте функции и классы; сохраняйте естественный вывод очевидных локальных значений.
  6. В DOM учитывайте null у querySelector и реальный вид элемента; проверяйте instanceof до специфичных операций.
  7. Уберите подавления и небезопасные утверждения, проверьте сборку и пользовательские сценарии.

ESLint: выбираем формат по версии

ESLint проверяет код по правилам; tsc проверяет типовые связи. Оба формата ниже включают recommended и запрет явного any. Выберите один вариант по версии инструментов в своём проекте; устанавливать обе конфигурации одновременно не нужно.

Новый формат: eslint.config.mjs

Для показанного отдельного проекта установите инструменты. Конфигурация ниже проверена с ESLint 10 и typescript-eslint 8; она не заменяет конфиг уже существующего проекта автоматически.

npm install --save-dev eslint@10 @eslint/js@10 typescript-eslint@8

Создайте eslint.config.mjs:

import js from "@eslint/js";
import { defineConfig } from "eslint/config";
import tseslint from "typescript-eslint";
export default defineConfig(
  { ignores: ["dist/**"] },
  {
    files: ["src/**/*.ts"],
    extends: [js.configs.recommended, tseslint.configs.recommended],
    languageOptions: { globals: { console: "readonly" } },
    rules: { "@typescript-eslint/no-explicit-any": "error" }
  }
);

Это дополнение из официального typescript-eslint Quickstart. Базовые рекомендованные правила и запрет явно написанного any включены явно. Lint анализирует соглашения и подозрительные конструкции, а tsc проверяет типовые связи: запускайте оба. Опция noImplicitAny сообщает об ошибке, когда тип не указан и компилятор не смог вывести достаточно точный тип вместо any. Но она не запрещает написанный вручную any — поэтому отдельное правило важно.

Для этого примера задайте в scripts файла package.json команду "lint": "eslint src" и запускайте npm run lint. Объект files выбирает TS-файлы. Здесь разрешён только console; для браузерного приложения добавьте используемые глобальные имена в languageOptions.globals, например document и fetch, либо подключите набор browser из пакета globals.

Старый формат: .eslintrc.json

Рабочий учебный вариант для ESLint 8.57.1 и typescript-eslint 8: установите parser и plugin отдельно. Команды установки относятся к отдельному проекту, где уже есть package.json; TypeScript 5.9 указан для воспроизводимости проверки.

npm install --save-dev eslint@8.57.1 @typescript-eslint/parser@8 @typescript-eslint/eslint-plugin@8 typescript@5.9

Создайте .eslintrc.json в корне проекта. Это JSON: ключи и строки заключаются в двойные кавычки, import и export здесь не используются.

{
  "root": true,
  "env": { "browser": true, "es2022": true },
  "parser": "@typescript-eslint/parser",
  "parserOptions": { "ecmaVersion": "latest", "sourceType": "module" },
  "plugins": ["@typescript-eslint"],
  "extends": ["eslint:recommended", "plugin:@typescript-eslint/recommended"],
  "ignorePatterns": ["dist/**"],
  "rules": { "@typescript-eslint/no-explicit-any": "error" }
}

root останавливает поиск родительских конфигураций; env задаёт глобальные имена окружения; parser читает TS; plugins подключает правила; extends включает готовые наборы; ignorePatterns исключает сборку. Вместо ignorePatterns можно использовать отдельный .eslintignore. Источники: Legacy ESLint Setup и справочник старого формата.

В ESLint 8 задайте npm-скрипт "lint": "eslint src --ext .ts". Параметр --ext нужен, чтобы захватить TS-файлы. Для проверки без npm-скрипта выполните:

npx eslint src --ext .ts

Если существующий проект уже использует ESLint 9 с совместимыми плагинами, legacy включается переменной окружения. Команда для macOS/Linux:

ESLINT_USE_FLAT_CONFIG=false npx eslint src --ext .ts

В Windows задайте ту же переменную средствами своего терминала перед запуском ESLint. В версии 10 переменная не вернёт поддержку legacy: нужен flat config. Не устанавливайте ESLint без ограничения версии, если намеренно воспроизводите старую настройку.

Проверьте выбранный вариант на корректном TS-файле, затем временно добавьте явный any: lint должен завершиться с ошибкой no-explicit-any. Удалите ошибку и запустите проверки снова. Оба примера конфигураций проверены этим способом; это не проверка типов с помощью tsc.

При переносе существующего проекта перенесите extends в импортированные конфигурации, env — в languageOptions.globals, а исключения .eslintignore — в ignores. Flat config не читает .eslintignore автоматически. Сверьте пути files и ignores с руководством миграции, затем удалите старые файлы настроек и проверьте lint. В уроке News API есть пошаговый список.

Даже запрет явно написанного any не гарантирует безопасный результат стороннего вызова: сохраняйте недоверенные данные как unknown и проверяйте.

В flat config: ignores исключает результат сборки, files выбирает TS-исходники, extends подключает готовые наборы правил, languageOptions разрешает глобальный console, rules задаёт явный запрет any. После установки инструментов и создания файла выполните npm run lint из папки проекта.
