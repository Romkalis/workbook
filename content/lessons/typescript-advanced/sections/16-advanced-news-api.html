Практика RS School: News API

Обязательная практика — News API и [St2] TS Advanced в RS-App → Auto Test. Задание требует миграции приложения, Webpack и ESLint, использования enum, interface/type, generics, union, модификаторов доступа и utility types. Any запрещён, strict и noImplicitAny обязательны.

В задании указаны адаптивность 320–1920 px, оформление footer, Chrome, требования к PR/коммитам и публикации. Для репозитория и сроков следуйте документу и правилам текущего потока. Встроенный тест учебника не заменяет ни проект, ни Auto Test.

Модель ответа и состояния

enum Status { Loading = "loading", Ready = "ready", Error = "error" }
interface Article { id: string; title: string; description: string | null }
type State<T> =
  | { status: Status.Loading }
  | { status: Status.Ready; data: readonly T[] }
  | { status: Status.Error; message: string };
type Card = Readonly<Pick<Article, "id" | "title">>;
type Patch = Partial<Pick<Article, "title" | "description">>;
class Model<T> {
  private state: State<T> = { status: Status.Loading };
  public setData(data: readonly T[]): void { this.state = { status: Status.Ready, data }; }
  public read(): State<T> { return this.state; }
}
const model = new Model<Card>();
model.setData([{ id: "a1", title: "TS" }]);
const patch: Patch = { title: "TypeScript" };
console.log(model.read().status, patch.title);

Это внутренняя модель приложения: мы заранее выбрали удобные поля и названия. Она не является точной копией ответа News API: собственный id формируется на границе приложения. Отдельный DTO должен соответствовать проверенному ответу. Применение utility types должно иметь смысл; простое объявление неиспользуемого типа не демонстрирует решённую задачу.

План самопроверки проекта

  • Приложение запускается, сборка и ESLint завершаются без ошибок.
  • Контракты данных и функций согласованы, any и неявные пробелы не скрыты утверждениями.
  • Состояния загрузки, пустого результата и ошибки показываются осмысленно.
  • API-ответ проверяется до передачи в модель; null и отсутствующие поля обработаны.
  • Выбор источника и загрузка новостей работают после миграции.
  • Применены требуемые языковые конструкции; причины их выбора можно объяснить.
  • Макет проверен на границах ширины задания, оформление и материалы PR сверены с ним.

Совет из общих знаний: для локальной проверки сохраните примеры ответов сервера — с данными, с пустым списком и с ошибкой. Такие заранее подготовленные данные называют фикстурами. Generic-функция загрузки должна получать валидатор, если обещает подтверждённый T. Наличие интерфейса DTO не делает сетевой JSON доверенным.

В документе задания есть промежуточный сервер (proxy) и адреса, возвращающие заранее подготовленные данные вместо реальных новостей (mock-endpoints) для разработки. Их текущая доступность и условия API здесь не проверялись: используйте актуальные указания задания и не встраивайте личный ключ в учебные примеры. Реальная миграция отдельного News API-приложения в рамках добавления этого урока не выполнялась.
