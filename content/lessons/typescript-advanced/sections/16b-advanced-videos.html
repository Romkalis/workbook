Что показывают видео и статьи модуля

Программа модуля советует плейлист «Webpack & TypeScript Setup» (7 коротких видео), ролик об утилитных типах и две статьи freeCodeCamp. Они разобраны по расшифровкам и тексту; ниже — что в них полезно и что устарело.

Плейлист «Webpack & TypeScript Setup»

В плейлисте автор канала Net Ninja собирает проект без фреймворков: TypeScript в папке src, готовые файлы в public, Webpack склеивает всё в один bundle.js. По шагам:

  1. Зачем Webpack. Это сборщик (bundler): он берёт исходники, прогоняет через загрузчики (TypeScript → JavaScript, SASS → CSS) и выдаёт файлы, готовые для браузера. Подробнее о сборщиках — в уроке «Модули в JavaScript».
  2. Установка. tsc --init создаёт tsconfig.json, затем ставятся dev-зависимости: webpack (ядро), webpack-cli (команды в терминале), ts-loader (учит Webpack компилировать TypeScript) и локальный typescript.
  3. Конфиг. Файл webpack.config.js экспортирует объект через module.exports (его читает Node.js). Главное: entry — точка входа, output — имя и абсолютный путь итогового файла (через path.resolve(__dirname, 'public')), правило module.rules с регулярным выражением /\.ts$/ — «файлы, которые оканчиваются на .ts, отдавать ts-loader».
  4. Dev-сервер пересобирает проект при сохранении и держит результат в памяти, а не на диске.
  5. Модули. Код делится на файлы через import и export; чтобы Webpack находил import './forms' без расширения, нужен resolve.extensions: ['.ts', '.js'].
  6. Source maps связывают собранный bundle.js с исходными .ts: ошибки в консоли и точки останова в DevTools показывают ваш TypeScript, а не склеенный код. В tsconfig включают sourceMap, в конфиге Webpack — devtool.
  7. Режим mode: 'development' или 'production' убирает предупреждение и включает оптимизации для выбранного режима (в production — минификация).

Плейлист записан для Webpack 4, поэтому две вещи сейчас делаются иначе. Команда webpack-dev-server заменена на webpack serve, а папка для раздачи указывается не через output.publicPath, как в видео, а через devServer.static. Актуальный конфиг, проверенный с Webpack 5.112, webpack-cli 7.3, webpack-dev-server 6.1, ts-loader 9.6 и TypeScript 5.9:

const path = require('node:path');

module.exports = {
  mode: 'development',
  entry: './src/index.ts',
  devtool: 'eval-source-map',
  module: {
    rules: [{ test: /\.ts$/, use: 'ts-loader', include: path.resolve(__dirname, 'src') }],
  },
  resolve: { extensions: ['.ts', '.js'] },
  output: { filename: 'bundle.js', path: path.resolve(__dirname, 'public') },
  devServer: { static: path.resolve(__dirname, 'public'), port: 8085 },
};

Результат проверки: npx webpack собрал public/bundle.js с встроенными картами исходников; npx webpack serve поднял сервер, и bundle.js отдавался по адресу localhost:8085. Без строки resolve сборка упала с ошибкой «Can't resolve './forms'» — ровно как в видео. Полная настройка проекта для News API — в разделе «Сборка TypeScript с Webpack».

TypeScript 7 и ts-loader

Сейчас npm install typescript ставит TypeScript 7 — новую версию компилятора, переписанную на Go. Команда tsc в ней работает как раньше (проверено: ошибка типа в файле нашлась). Но часть инструментов, которые подключаются к компилятору изнутри, её ещё не поддерживает. С TypeScript 7.0.2 ts-loader 9.6 упал с ошибкой «Cannot read properties of undefined (reading 'fileExists')», а typescript-eslint 8.72 требует TypeScript ниже 6.1 и не установился поверх версии 7. Если проект собирается Webpack с ts-loader или проверяется typescript-eslint, фиксируйте версию: npm install --save-dev typescript@5.9. При установке TypeScript и typescript-eslint одной командой npm сам выбирает совместимую 5.9.3.

Видео «Utility Types — Advanced TypeScript»

В ролике утилитные типы разобраны на примере звездолётов. Полезные примеры, которых нет в разделах урока выше:

  • Partial для функции частичного обновления: updateStarship(id: number, starship: Partial<Starship>) позволяет передать только name.
  • Exclude и Extract на напитках: из 'coffee' | 'tea' | 'orange juice' | 'lemonade' исключаем то, что Джейн не пьёт, и TypeScript не даст «налить» ей кофе. Extract с вариантом 'mojito', которого нет в меню, просто его отбросит.
  • NonNullable работает так, как ожидается, только при strictNullChecks: автор показывает, что без этого флага null и undefined можно присвоить любому типу. В режиме strict флаг включён (урок «TypeScript: основы»).
  • InstanceType по-настоящему нужен с миксинами (урок о паттернах): класс, возвращённый функцией Deletable(User), хранится в переменной, а переменную нельзя использовать как тип. Тип её экземпляров получают так: InstanceType<typeof DeletableUser>.
  • ThisType — маркер, задающий тип this внутри методов объекта; работает только при включённом noImplicitThis (входит в strict).

Пример с напитками проверен компилятором TypeScript 5.9: строка const janeDrink: Exclude<Drinks, 'coffee' | 'orange juice'> = 'coffee' дала ошибку «Type '"coffee"' is not assignable», а значение 'tea' прошло.

Статьи freeCodeCamp

  • «How to set up a TypeScript project» (2018) — обзор экосистемы для новичка: «какой JavaScript» (ES5, ES2015+, TypeScript), фреймворки, сборщики, CSS-препроцессоры, тесты, форматы модулей и полифиллы; затем установка Node.js, редактора, package.json, TypeScript и React. Статья старая: в ней Parcel и React-шаблоны той поры; общая схема (Node.js → npm → tsconfig → сборка) по-прежнему верна.
  • «How to Add TypeScript to a JavaScript Project» (2020) — четыре стратегии перехода: начать с поддержки TS в существующем приложении, добавить типы к библиотеке, сделать «скелет» на будущее или перевести всё сразу. Затем шаги: установить TypeScript, создать tsconfig.json, первый .ts-файл, поправить package.json, подключить source maps, сборку и линтинг. Та же идея постепенной миграции — в разделе «Миграция JS → TS».

Курс Scrimba «Learn TypeScript» интерактивный: он требует входа на сайт и проходится в браузере, поэтому не пересказан.
