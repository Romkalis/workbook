Литеральные и template literal types

Литеральный тип допускает одно конкретное значение: например, "grid", 42 или true. Объединение "grid" | "list" разрешает только две указанные строки. Шаблонный литеральный тип строит строки из других строковых типов. Он описывает допустимые имена, но не проверяет внешнюю строку автоматически.

Узкие значения и проверка конфигурации

type Mode = "grid" | "list";
const config = { mode: "grid", size: 10 } satisfies { mode: Mode; size: number };
const statuses = ["loading", "ready", "error"] as const;
type Status = typeof statuses[number];
const status: Status = "ready";
console.log(config.mode, status);

Const-переменная не делает все свойства объекта литеральными. As const сохраняет литералы и readonly для литеральной структуры; satisfies проверяет совместимость, сохраняя полезную конкретику вывода. Ни то ни другое не заменяет runtime-валидацию.

Сборка имён и строковые преобразования

type Field = "title" | "author";
type Action = "changed" | "cleared";
type EventName = `${Field}:${Action}`;
type Loud = Uppercase<EventName>;
type Getter = `get${Capitalize<Field>}`;
const event: EventName = "title:changed";
const loud: Loud = "AUTHOR:CLEARED";
const getter: Getter = "getTitle";
console.log(event, loud, getter);
if (false) {
  // @ts-expect-error: поле date не входит в Field
  const wrong: EventName = "date:changed";
}

Union в каждой подстановке создаёт комбинации: здесь два поля и два действия дают четыре строки. Большие наборы быстро разрастаются. Uppercase/Lowercase меняют регистр всего литерала, Capitalize/Uncapitalize — первого символа. Совпадение имени события ещё не связывает его с данными: для этого нужен дополнительный контракт.

Переименование и фильтрация ключей через as

type Getters<T> = {
  [K in keyof T as K extends string ? `get${Capitalize<K>}` : never]: () => T[K]
};
type WithoutId<T> = { [K in keyof T as Exclude<K, "id">]: T[K] };
interface Article { id: string; title: string }
const getters: Getters<Article> = {
  getId: () => "a1", getTitle: () => "TS"
};
const publicFields: WithoutId<Article> = { title: "TS" };
console.log(getters.getTitle(), publicFields.title);

Прочитаем Getters для Article. Ключ "title" проходит проверку K extends string; Capitalize превращает его в "Title", а шаблонная строка добавляет get. Получается метод getTitle: () => string. Для "id" аналогично получается getId. As в этой записи задаёт новое имя ключа, а не утверждает тип значения. Never в позиции ключа убирает его из результата. Ограничение K extends string исключает числовые и символьные ключи, к которым нельзя применить Capitalize. Если преобразование становится труднее читать, чем сам контракт, дайте ему понятное имя или оставьте явное объявление.

Связать имя события с типом данных

type Changes<T> = {
  [K in keyof T as K extends string ? `${K}Changed` : never]: T[K]
};
type Events = Changes<{ title: string; count: number }>;
function send<K extends keyof Events>(name: K, value: Events[K]): string {
  return `${name}: ${String(value)}`;
}
console.log(send("countChanged", 2));
if (false) {
  // @ts-expect-error: countChanged ожидает число
  send("countChanged", "two");
}

В Events ключ countChanged связан с number, а titleChanged — со string. В send параметр K выбирает имя события, и Events[K] получает соответствующий тип данных. Поэтому число 2 подходит для countChanged, а строка "two" — нет.
