Литеральные и template literal types

Литеральный тип допускает одно конкретное значение: например, "grid", 42 или true. Объединение "grid" | "list" разрешает только две указанные строки. Шаблонный литеральный тип строит строки из других строковых типов. Он описывает допустимые имена, но не проверяет внешнюю строку автоматически.

Узкие значения и проверка конфигурации

type Mode = "grid" | "list";
const config = { mode: "grid", size: 10 } satisfies { mode: Mode; size: number };
const statuses = ["loading", "ready", "error"] as const;
type Status = typeof statuses[number];
const status: Status = "ready";
console.log(config.mode, status);

Const-переменная не делает все свойства объекта литеральными. As const сохраняет литералы и readonly для литеральной структуры; satisfies проверяет совместимость, сохраняя полезную конкретику вывода. Ни то ни другое не заменяет runtime-валидацию.

Задача 21. Параметр из адреса — в узкий тип ★☆☆ разминка

Сортировка приходит из адресной строки как string. Объявите массив SORTS = ["new", "popular", "discussed"] as const, получите из него тип Sort и напишите parseSort(raw: string | null): Sort: неизвестное значение превращается в "new".

Зачем: список вариантов и тип живут в одном месте. Добавили вариант в массив — он появился и в типе, и в проверке. Задача ещё и знакомит с частым неудобством: SORTS.includes(raw) не компилируется.

Подсказка

includes у массива readonly ("new" | …)[] принимает только эти литералы. Расширьте массив при проверке: (SORTS as readonly string[]).includes(raw), и оформите это предикатом.

Решение и разбор
export const SORTS = ['new', 'popular', 'discussed'] as const;
export type Sort = (typeof SORTS)[number];

function isSort(value: string): value is Sort {
  return (SORTS as readonly string[]).includes(value);
}

export function parseSort(raw: string | null): Sort {
  return raw !== null && isSort(raw) ? raw : 'new';
}

(typeof SORTS)[number] — «тип любого элемента кортежа», то есть "new" | "popular" | "discussed". Расширение до readonly string[] безопасно: мы только читаем. А предикат возвращает узкий тип обратно. Этот приём пригодится в состоянии в адресной строке: любое значение из URL сначала проверяется, потом используется.

Задача 22. Карта маршрутов через satisfies ★★☆ практика

Опишите объект routes с путями приложения (home: "/", article: "/articles/:id", search: "/search"). Требования: каждый путь начинается с / (опечатку "search" должен поймать компилятор), а тип RouteName = keyof typeof routes состоит из точных имён, а не string.

Зачем: аннотация : Record<string, …> проверила бы значения, но стёрла бы имена ключей, и keyof дал бы string. satisfies проверяет объект, не меняя его выведенный тип. Получаем и контроль, и точность.

Решение и разбор
export const routes = {
  home: '/',
  article: '/articles/:id',
  search: '/search',
} satisfies Record<string, `/${string}`>;

export type RouteName = keyof typeof routes;

export function href(name: RouteName): string {
  return routes[name];
}

if (false) {
  const bad = {
    // @ts-expect-error: путь без слеша
    search: 'search',
  } satisfies Record<string, `/${string}`>;
}

Шаблонный литеральный тип /${string} описывает «любую строку, которая начинается со слеша». Попробуйте заменить satisfies на аннотацию const routes: Record<string, /${string}>: проверка c1 в тесте упадёт, потому что RouteName станет string.

Сборка имён и строковые преобразования

type Field = "title" | "author";
type Action = "changed" | "cleared";
type EventName = `${Field}:${Action}`;
type Loud = Uppercase<EventName>;
type Getter = `get${Capitalize<Field>}`;
const event: EventName = "title:changed";
const loud: Loud = "AUTHOR:CLEARED";
const getter: Getter = "getTitle";
console.log(event, loud, getter);
if (false) {
  // @ts-expect-error: поле date не входит в Field
  const wrong: EventName = "date:changed";
}

Union в каждой подстановке создаёт комбинации: здесь два поля и два действия дают четыре строки. Большие наборы быстро разрастаются. Uppercase/Lowercase меняют регистр всего литерала, Capitalize/Uncapitalize — первого символа. Совпадение имени события ещё не связывает его с данными: для этого нужен дополнительный контракт.

Переименование и фильтрация ключей через as

type Getters<T> = {
  [K in keyof T as K extends string ? `get${Capitalize<K>}` : never]: () => T[K]
};
type WithoutId<T> = { [K in keyof T as Exclude<K, "id">]: T[K] };
interface Article { id: string; title: string }
const getters: Getters<Article> = {
  getId: () => "a1", getTitle: () => "TS"
};
const publicFields: WithoutId<Article> = { title: "TS" };
console.log(getters.getTitle(), publicFields.title);

Прочитаем Getters для Article. Ключ "title" проходит проверку K extends string; Capitalize превращает его в "Title", а шаблонная строка добавляет get. Получается метод getTitle: () => string. Для "id" аналогично получается getId. As в этой записи задаёт новое имя ключа, а не утверждает тип значения. Never в позиции ключа убирает его из результата. Ограничение K extends string исключает числовые и символьные ключи, к которым нельзя применить Capitalize. Если преобразование становится труднее читать, чем сам контракт, дайте ему понятное имя или оставьте явное объявление.

Связать имя события с типом данных

type Changes<T> = {
  [K in keyof T as K extends string ? `${K}Changed` : never]: T[K]
};
type Events = Changes<{ title: string; count: number }>;
function send<K extends keyof Events>(name: K, value: Events[K]): string {
  return `${name}: ${String(value)}`;
}
console.log(send("countChanged", 2));
if (false) {
  // @ts-expect-error: countChanged ожидает число
  send("countChanged", "two");
}

В Events ключ countChanged связан с number, а titleChanged — со string. В send параметр K выбирает имя события, и Events[K] получает соответствующий тип данных. Поэтому число 2 подходит для countChanged, а строка "two" — нет.

Задача 23. Типизированные события ★★★ с подвохом

Напишите createEmitter<Events>() с методами on(name, handler) и emit(name, payload). on возвращает функцию отписки. Тип payload зависит от имени события. Для карты событий { "cart:add": { id: string }; "cart:clear": undefined } вызов emit("cart:add", { id: 1 }) должен быть ошибкой компиляции.

Зачем: события — способ связать части интерфейса, не делая их зависимыми друг от друга (вспомните CustomEvent и паттерн «Наблюдатель»). Без типов имя события — строка, и опечатка или неверные данные обнаруживаются только при клике.

Подсказка

Храните обработчики в Map<keyof Events, Set<(payload: never) => void>>, а снаружи давайте строгую сигнатуру on<K extends keyof Events>(name: K, handler: (payload: Events[K]) => void).

Решение и разбор
type Handler<P> = (payload: P) => void;

export function createEmitter<Events extends Record<string, unknown>>() {
  const handlers = new Map<keyof Events, Set<Handler<never>>>();
  return {
    on<K extends keyof Events>(name: K, handler: Handler<Events[K]>): () => void {
      const set = handlers.get(name) ?? new Set();
      set.add(handler);
      handlers.set(name, set);
      return () => set.delete(handler);
    },
    emit<K extends keyof Events>(name: K, payload: Events[K]): void {
      for (const h of handlers.get(name) ?? []) (h as Handler<Events[K]>)(payload);
    },
  };
}

type CartEvents = { 'cart:add': { id: string }; 'cart:clear': undefined };
const bus = createEmitter<CartEvents>();
bus.on('cart:add', (p) => console.log(p.id));
bus.emit('cart:add', { id: 'a1' });
bus.emit('cart:clear', undefined);
if (false) {
  // @ts-expect-error: id должен быть строкой
  bus.emit('cart:add', { id: 1 });
  // @ts-expect-error: такого события нет
  bus.on('cart:remove', () => {});
}

Хранилище внутри не может знать, какой тип у каждого набора: связь «ключ → тип» существует только в сигнатурах. Поэтому внутри одно приведение, а снаружи всё строго. Тот же приём, что в sortBy. Отписка удаляет функцию из Set. Поэтому для отписки нужна та же ссылка на обработчик, и анонимную стрелку без сохранённой функции отписки уже не снять. Обход for…of по Set безопасен, даже если обработчик отпишется во время вызова.
