tsconfig: проект, файлы и настройки

Файл tsconfig.json сообщает компилятору, какие файлы проверять и с какими правилами. Опция — отдельная настройка, например strict. Исходники — файлы, которые мы пишем; выходные файлы — результат работы компилятора или сборщика. Ниже — конфигурация отдельного браузерного проекта с Webpack, а не замена конфига этого учебника на Next.js.

Конфигурация для учебного Webpack-проекта

{
  "compilerOptions": {
    "target": "ES2020",
    "lib": [
      "ES2020",
      "DOM",
      "DOM.Iterable"
    ],
    "module": "ESNext",
    "moduleResolution": "Bundler",
    "strict": true,
    "noImplicitAny": true,
    "noUncheckedIndexedAccess": true,
    "exactOptionalPropertyTypes": true,
    "noEmitOnError": true,
    "sourceMap": true
  },
  "include": [
    "src/**/*.ts"
  ],
  "exclude": [
    "node_modules",
    "dist"
  ]
}

Include выбирает начальные файлы, exclude исключает их из этого отбора; импортированный файл всё равно может попасть в проект. Files перечисляет файлы явно. Extends позволяет наследовать базовую конфигурацию; относительные пути разрешаются относительно файла, в котором записаны. Настройки массивов не следует считать автоматически объединёнными.

Что за что отвечает

ОпцияСмысл и ограничение
targetВерсия синтаксиса выпускаемого JS. Не добавляет реализации отсутствующих API — полифиллы
libДекларации доступных API; DOM описывает браузерные объекты, но не создаёт их в Node.js
moduleФормат модульного кода: как обрабатываются import и export
moduleResolutionКак компилятор ищет зависимости под выбранное окружение
strict / noImplicitAnyСемейство строгих проверок / запрет неявного any
rootDir / outDirКорневая папка исходников / папка результата; rootDir сам не выбирает файлы для проверки
noEmit / noEmitOnErrorНе выпускать вообще / не выпускать при ошибках
sourceMapСвязь выпущенного JS с исходниками для отладки
declaration / emitDeclarationOnlyВыпуск .d.ts для потребителей библиотеки
types / skipLibCheckКакие пакеты описаний @types подключать / пропуск проверки файлов описаний .d.ts

Не включайте skipLibCheck, чтобы прятать ошибки собственного кода. Дополнительные проверки noUnusedLocals, noUnusedParameters, noImplicitReturns помогают выявлять забытые ветки и лишние объявления, но не являются полным анализом корректности программы.

Как увидеть реальную конфигурацию

Эти команды понадобятся после создания файлов и установки TypeScript в разделе Webpack. Выполняйте их в терминале из папки проекта, где лежит tsconfig.json. Утилита npx запускает локально установленный tsc; --project указывает нужный конфигурационный файл.

npx tsc --project tsconfig.json --showConfig
npx tsc --project tsconfig.json --noEmit
npx tsc --project tsconfig.json --listFilesOnly
npx tsc --project tsconfig.json --explainFiles

ShowConfig полезен при extends, listFilesOnly показывает фактические входные файлы, explainFiles объясняет причину их включения. Передача имени файла напрямую может обойти ожидаемые настройки проекта; проверяйте через --project.
