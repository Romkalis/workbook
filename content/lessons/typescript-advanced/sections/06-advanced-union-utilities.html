Utility types для объединений

Exclude и Extract фильтруют варианты union

type Load =
  | { status: "loading" }
  | { status: "ready"; data: string[] }
  | { status: "error"; message: string };
type Ready = Extract<Load, { status: "ready" }>;
type Finished = Exclude<Load, { status: "loading" }>;
type Value = NonNullable<string | null | undefined>;
const ready: Ready = { status: "ready", data: ["TS"] };
const value: Value = "TS";
const finished: Finished = ready;
console.log(value, finished.status);
if (false) {
  // @ts-expect-error: loading исключён
  const wrong: Finished = { status: "loading" };
}

В Load три варианта состояния. Extract<Load, { status: "ready" }> оставляет только объект с готовыми данными. Exclude<Load, { status: "loading" }> оставляет два остальных варианта: ready и error. Иными словами, Exclude исключает подходящие варианты, а Extract выбирает их. NonNullable исключает null и undefined. Эти типы не проверяют переменную при выполнении: перед преобразованием внешнего значения всё ещё нужен guard.

Почему Omit и Exclude не взаимозаменяемы

Omit работает с ключами объекта, а Exclude — с вариантами union. Exclude<"a" | "b", "a"> даст "b". Если применить Exclude к объекту, передав строковое имя его поля, поле не исчезнет. У Omit над union могут потеряться свойства отдельных вариантов, поскольку операция не обязана распределяться по ним.

Для начала достаточно различать операции: Omit<Article, "id"> исключает поле id, а Exclude<"loading" | "ready", "loading"> исключает вариант "loading". Сложный случай — отдельное преобразование каждого объекта в union — разберём после условных типов.
