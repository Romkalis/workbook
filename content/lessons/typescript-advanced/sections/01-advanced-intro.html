От отдельных типов к надёжному проекту

В TypeScript Basic мы описывали значения и функции. Теперь научимся получать новые типы из существующих, проверять неизвестные данные и настраивать сборку. Цель — не написать самый сложный тип, а сохранить понятные договорённости между частями приложения.

Продвинутые типы не ускоряют JavaScript сами по себе и не проверяют ответ сервера. Они помогают обнаруживать несовместимости до запуска. Для внешних данных нужны исполняемые проверки, а для запуска TS — подходящий процесс преобразования и загрузки модулей.

Что понадобится и что получится

Нужно понимать функции, объекты, interface и type. Напомним два обозначения: string | number — объединение типов (union), а T в generic-функции — параметр типа, который уточняется при вызове. Сначала разберём проверки данных, затем готовые преобразования типов, после — собственные преобразования и сборку проекта. Программа RS School отводит около 8 часов; на самостоятельный проект может понадобиться больше.

Учебные примеры независимы. В TypeScript Playground откройте TS Config и включите strict, noUncheckedIndexedAccess и exactOptionalPropertyTypes, а Target установите в ES2020. Два последних флага понадобятся в разделе о строгих проверках: одного strict для этих примеров недостаточно. Можно также запускать локальный компилятор с такими же настройками. В примерах встретится комментарий // @ts-expect-error. Он значит: «на следующей строке должна быть ошибка типов». Это наглядный способ показать, что TypeScript ловит ошибку: если ошибки вдруг не окажется, компилятор пожалуется уже на сам комментарий. Такие строки обёрнуты в if (false): TypeScript их проверяет, а JavaScript никогда не выполняет. Не используйте эту директиву, чтобы скрыть непонятную ошибку своего проекта.

Авторские примеры используют TypeScript 5.9.3. Большинство возможностей появилось раньше; NoInfer требует TS 5.4 или новее. Для современного инструмента всегда проверяйте требования его версии к Node.js. Источники и границы разбора перечислены в конце.

Четыре слова, которые будут встречаться дальше. Компилятор tsc — программа, проверяющая TypeScript и при необходимости выпускающая JavaScript. «Во время выполнения» (runtime) — когда уже работает JavaScript. Контракт — договорённость о допустимых данных, аргументах и результате функции. DTO — объект данных, которыми приложение обменивается с сервером; его тип описывает ожидаемую форму ответа, но сам ответ нужно проверить.
