Generics: связи, ограничения и значения по умолчанию

Generic, или обобщённое объявление, использует параметр типа вместо одного заранее выбранного типа. Например, функция identity<T>(value: T): T принимает значение и возвращает значение того же типа: для строки T станет строкой, для числа — числом. Один и тот же T связывает вход и результат. Если T нигде не связан с входными данными, компилятор не может узнать форму ответа сервера из одного имени типа.

keyof, тип свойства и ограничение параметра

В get буква T обозначает тип объекта. keyof T — допустимые ключи этого объекта. K extends keyof T требует выбрать один из них. Запись T[K] даёт тип значения по выбранному ключу; она называется индексным доступом к типу (indexed access). Это не чтение реального объекта, а описание результата функции.

function get<T, K extends keyof T>(object: T, key: K): T[K] {
  return object[key];
}
function keepId<T extends { id: string }>(value: T): T { return value; }
const article = keepId({ id: "a1", title: "TS" });
const title = get(article, "title");
console.log(title.toUpperCase());
if (false) {
  // @ts-expect-error: отсутствует id
  keepId({ title: "TS" });
  // @ts-expect-error: неизвестный ключ
  get(article, "author");
}

Ограничение extends задаёт минимальные требования, но сохраняет конкретный T. Возврат просто { id: string } потерял бы сведения о title. Не возвращайте новый объект с одним id под видом произвольного T: у клиента могут быть обязательные дополнительные поля.

Обобщённый контейнер и тип по умолчанию

interface Page<T = string> { items: readonly T[]; total: number }
class Store<T extends { id: string }> {
  constructor(private items: readonly T[]) {}
  find(id: string): T | undefined { return this.items.find(item => item.id === id); }
}
const page: Page = { items: ["TS"], total: 1 };
const store = new Store([{ id: "a1", title: "TS" }]);
console.log(page.items.join(", "), store.find("missing"));

Page без аргумента использует string. У конструктора Store тип выводится из переданных элементов. Не обещайте T там, где поиск может ничего не вернуть. Статические члены принадлежат самому классу, а не экземпляру; использовать в их типах параметр T этого экземпляра нельзя.

Дополнительно: NoInfer и источник типа

Этот приём можно оставить на второй проход. В примере values — разрешённые варианты, fallback — запасное значение. Нужно вывести C только из списка вариантов, а запасное значение проверить по уже полученному типу.

function choose<C extends string>(values: readonly C[], fallback: NoInfer<C>): C {
  return values[0] ?? fallback;
}
console.log(choose(["light", "dark"] as const, "light"));
if (false) {
  // @ts-expect-error: fallback не должен расширять набор вариантов
  choose(["light", "dark"] as const, "auto");
}

Здесь C получается равным "light" | "dark". Обёртка NoInfer<C> не позволяет аргументу fallback добавить в этот набор "auto". Поэтому "light" подходит, а "auto" вызывает ошибку. Это дополнение для TS 5.4+, полезное лишь там, где обычный вывод допускает лишние варианты.
