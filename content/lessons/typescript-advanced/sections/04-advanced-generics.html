Generics: связи, ограничения и значения по умолчанию

Generic, или обобщённое объявление, использует параметр типа вместо одного заранее выбранного типа. Например, функция identity<T>(value: T): T принимает значение и возвращает значение того же типа: для строки T станет строкой, для числа — числом. Один и тот же T связывает вход и результат. Если T нигде не связан с входными данными, компилятор не может узнать форму ответа сервера из одного имени типа.

keyof, тип свойства и ограничение параметра

В get буква T обозначает тип объекта. keyof T — допустимые ключи этого объекта. K extends keyof T требует выбрать один из них. Запись T[K] даёт тип значения по выбранному ключу; она называется индексным доступом к типу (indexed access). Это не чтение реального объекта, а описание результата функции.

function get<T, K extends keyof T>(object: T, key: K): T[K] {
  return object[key];
}
function keepId<T extends { id: string }>(value: T): T { return value; }
const article = keepId({ id: "a1", title: "TS" });
const title = get(article, "title");
console.log(title.toUpperCase());
if (false) {
  // @ts-expect-error: отсутствует id
  keepId({ title: "TS" });
  // @ts-expect-error: неизвестный ключ
  get(article, "author");
}

Ограничение extends задаёт минимальные требования, но сохраняет конкретный T. Возврат просто { id: string } потерял бы сведения о title. Не возвращайте новый объект с одним id под видом произвольного T: у клиента могут быть обязательные дополнительные поля.

Задача 7. Достать одно поле из списка ★☆☆ разминка

Напишите pluck(items, key), которая возвращает массив значений одного поля. Тип результата должен следовать за ключом: для "views" — number[], для "title" — string[]. Несуществующий ключ — ошибка компиляции (покажите строкой с @ts-expect-error).

Зачем: связь «ключ → тип значения» — самая частая работа generics в прикладном коде. Без неё функция вернула бы unknown[] или any[], и каждый вызов пришлось бы приводить вручную.

Решение и разбор
export function pluck<T, K extends keyof T>(items: readonly T[], key: K): T[K][] {
  return items.map((item) => item[key]);
}

const articles = [
  { title: 'TS', views: 10 },
  { title: 'JS', views: 3 },
];
const views: number[] = pluck(articles, 'views');
const titles: string[] = pluck(articles, 'title');
console.log(views, titles);

if (false) {
  // @ts-expect-error: такого поля нет
  pluck(articles, 'author');
}

K extends keyof T ограничивает ключ полями объекта, а T[K] — индексный доступ к типу — говорит, какой у этого поля тип. Параметр readonly T[] принимает и обычные, и неизменяемые массивы. Это обещание: функция массив не меняет.

Задача 8. Сортировка по полю без порчи исходника ★★☆ практика

Напишите sortBy(items, key, dir = "asc"): возвращает новый массив, отсортированный по полю. Сортировать можно только по полям-строкам и полям-числам. Строки сравнивайте через localeCompare, чтобы «ё» и регистр не ломали порядок.

Зачем: Array.prototype.sort меняет массив на месте. Если это массив из состояния или из пропсов, ошибка проявится в другом месте экрана. Ограничение «только строки и числа» выражено в типах: сортировка по полю-объекту не имеет смысла, и пусть это ловит компилятор.

Подсказка

Ключи, у которых значение строка или число: { [P in keyof T]: T[P] extends string | number ? P : never }[keyof T]. Сначала соберите объект «ключ → ключ или never», потом возьмите объединение его значений.

Решение и разбор
type SortableKey<T> = { [P in keyof T]: T[P] extends string | number ? P : never }[keyof T];

export function sortBy<T, K extends SortableKey<T>>(items: readonly T[], key: K, dir: 'asc' | 'desc' = 'asc'): T[] {
  const sign = dir === 'asc' ? 1 : -1;
  return [...items].sort((a, b) => {
    const x = a[key] as string | number;
    const y = b[key] as string | number;
    const diff = typeof x === 'string' && typeof y === 'string' ? x.localeCompare(y, 'ru') : Number(x) - Number(y);
    return diff * sign;
  });
}

const list = [
  { title: 'Ёлка', views: 3, meta: { a: 1 } },
  { title: 'Арбуз', views: 10, meta: { a: 2 } },
];
console.log(sortBy(list, 'title').map((x) => x.title));
if (false) {
  // @ts-expect-error: по объекту сортировать нельзя
  sortBy(list, 'meta');
}

SortableKey<T> — комбинация mapped type и индексного доступа: для каждого ключа записываем сам ключ или never, а [keyof T] собирает значения в union. never из union исчезает. Внутри функции компилятор не может доказать, что a[key] строка или число: связь между K и типом значения слишком сложна для вывода. Поэтому одно as оправдано, но оно спрятано внутри функции, а снаружи API строгий. Копия [...items] обязательна. Мутант без неё ловится тестом, который проверяет, что исходный массив не поменялся.

Обобщённый контейнер и тип по умолчанию

interface Page<T = string> { items: readonly T[]; total: number }
class Store<T extends { id: string }> {
  constructor(private items: readonly T[]) {}
  find(id: string): T | undefined { return this.items.find(item => item.id === id); }
}
const page: Page = { items: ["TS"], total: 1 };
const store = new Store([{ id: "a1", title: "TS" }]);
console.log(page.items.join(", "), store.find("missing"));

Page без аргумента использует string. У конструктора Store тип выводится из переданных элементов. Не обещайте T там, где поиск может ничего не вернуть. Статические члены принадлежат самому классу, а не экземпляру; использовать в их типах параметр T этого экземпляра нельзя.

Задача 9. Страница из любого списка ★★☆ практика

Опишите тип Page<T> с полями items, page, pageSize, total, pages. Напишите paginate(items, page, pageSize = 10): страницы нумеруются с 1, страница за пределами диапазона даёт пустой items, а total и pages остаются правильными.

Зачем: один обобщённый тип описывает страницу статей, товаров и пользователей. Тот же ответ сервер отдаёт в уроке RESTful API. Если форма страницы описана один раз, клиент и сервер не разойдутся в названиях полей.

Решение и разбор
export interface Page<T> {
  items: T[];
  page: number;
  pageSize: number;
  total: number;
  pages: number;
}

export function paginate<T>(items: readonly T[], page: number, pageSize = 10): Page<T> {
  const start = (page - 1) * pageSize;
  return {
    items: items.slice(start, start + pageSize),
    page,
    pageSize,
    total: items.length,
    pages: Math.ceil(items.length / pageSize),
  };
}

Тип T выводится из массива, поэтому paginate(articles, 2) вернёт Page<Article> без явного аргумента. slice за пределами массива возвращает пустой массив, а не бросает ошибку. Пограничный случай «страница 3 из 2» обрабатывается без отдельной ветки. Math.ceil нужен, потому что 21 элемент по 10 — это три страницы, а не 2,1.

Дополнительно: NoInfer и источник типа

Этот приём можно оставить на второй проход. В примере values — разрешённые варианты, fallback — запасное значение. Нужно вывести C только из списка вариантов, а запасное значение проверить по уже полученному типу.

function choose<C extends string>(values: readonly C[], fallback: NoInfer<C>): C {
  return values[0] ?? fallback;
}
console.log(choose(["light", "dark"] as const, "light"));
if (false) {
  // @ts-expect-error: fallback не должен расширять набор вариантов
  choose(["light", "dark"] as const, "auto");
}

Здесь C получается равным "light" | "dark". Обёртка NoInfer<C> не позволяет аргументу fallback добавить в этот набор "auto". Поэтому "light" подходит, а "auto" вызывает ошибку. Это дополнение для TS 5.4+, полезное лишь там, где обычный вывод допускает лишние варианты.

Задача 10. Значение по умолчанию не должно расширять варианты ★★★ с подвохом

Напишите createSelect(options, initial): возвращает объект с текущим значением value и методом set(next). Варианты задаются массивом as const. Вызов createSelect(["new", "popular"] as const, "oldest") должен быть ошибкой компиляции, а set("oldest") — тоже.

Зачем: без NoInfer компилятор выводит тип вариантов из обоих аргументов и «великодушно» добавляет "oldest" в набор. Опечатка в значении по умолчанию проходит молча, а в интерфейсе выбран пункт, которого нет в списке.

Решение и разбор
export function createSelect<O extends string>(options: readonly O[], initial: NoInfer<O>) {
  let value: O = initial;
  return {
    get value(): O {
      return value;
    },
    options,
    set(next: O): void {
      value = next;
    },
  };
}

const sort = createSelect(['new', 'popular'] as const, 'new');
sort.set('popular');

if (false) {
  // @ts-expect-error: "oldest" нет среди вариантов
  createSelect(['new', 'popular'] as const, 'oldest');
  // @ts-expect-error: и установить его нельзя
  sort.set('oldest');
}

Уберите NoInfer и посмотрите на первый @ts-expect-error. Компилятор сообщит, что директива лишняя: O вывелся как "new" | "popular" | "oldest". NoInfer<O> говорит: «тип бери из options, а этот аргумент только проверяй». Геттер value нужен, чтобы снаружи всегда читалось текущее значение, а не копия, сделанная при создании объекта.
