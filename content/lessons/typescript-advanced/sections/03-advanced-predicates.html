Type predicates и проверка неизвестных данных

Предикат типа — функция-проверка с результатом вроде value is NewsItem. Читать его можно так: «если функция вернула true, считай value объектом NewsItem». Сама функция возвращает обычный boolean. Компилятор не доказывает истинность такого обещания: ошибочная реализация сделает типизацию ненадёжной. Проверяйте всё, что тип обещает клиенту.

От unknown к проверенному объекту

Тип unknown означает: значение получено, но его форма пока неизвестна. Проверка isRecord сначала убеждается, что перед нами объект, не null и не массив. Запись Record<string, unknown> позволяет затем читать его строковые поля, не считая их содержимое заранее известным.

interface NewsItem { title: string; url: string; description: string | null }
function isRecord(value: unknown): value is Record<string, unknown> {
  return typeof value === "object" && value !== null && !Array.isArray(value);
}
function isNewsItem(value: unknown): value is NewsItem {
  return isRecord(value)
    && typeof value.title === "string"
    && typeof value.url === "string"
    && (typeof value.description === "string" || value.description === null);
}
const input: unknown[] = [
  { title: "TS", url: "/ts", description: null },
  { title: 42, url: "/bad", description: "текст" },
  null
];
const items = input.filter(isNewsItem);
console.log(items.map(item => item.title.toUpperCase())); // ["TS"]

Метод filter вызывает isNewsItem для каждого элемента. Для первого объекта проверка возвращает true, для второго — false из-за числового title, для null — false уже на первом шаге. В items остаётся один объект, а TypeScript знает тип массива NewsItem[]. Проверка подтверждает форму, но не безопасность ссылки или непустой заголовок: бизнес-правила проверяют отдельно. Типы DTO должны учитывать реальные null и пропуски, а не только удачный ответ сервера.

Функция утверждения: продолжить только с правильными данными

Иногда после неверных данных нужно остановить операцию, а не вернуть false. Для этого подходит assertion function — функция утверждения. Запись asserts value is string означает: «если вызов завершился без исключения, дальше value можно использовать как string».

function assertString(value: unknown): asserts value is string {
  if (typeof value !== "string") throw new Error("Нужна строка");
}
function shout(value: unknown): string {
  assertString(value);
  return value.toUpperCase();
}
try { shout(null); }
catch (error: unknown) {
  console.log(error instanceof Error ? error.message : "Неизвестная ошибка");
}
console.log(shout("ts"));

После успешного возврата assertString значение сужено до string. При нарушении обещания функция обязана прервать обычный путь выполнения, например бросить исключение. Это не то же самое, что as string: утверждение типа не добавляет проверки. fetchJson<T>(), возвращающая json as T, также ничего не валидирует.

Вызов shout(null) бросает Error с сообщением «Нужна строка»; catch перехватывает его. Вызов shout("ts") успешно возвращает «TS». Значение ошибки тоже проверяется: JavaScript позволяет бросить не только объект Error.
