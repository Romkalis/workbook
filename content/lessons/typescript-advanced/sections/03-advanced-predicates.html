Type predicates и проверка неизвестных данных

Предикат типа — функция-проверка с результатом вроде value is NewsItem. Читать его можно так: «если функция вернула true, считай value объектом NewsItem». Сама функция возвращает обычный boolean. Компилятор не доказывает истинность такого обещания: ошибочная реализация сделает типизацию ненадёжной. Проверяйте всё, что тип обещает клиенту.

От unknown к проверенному объекту

Тип unknown означает: значение получено, но его форма пока неизвестна. Проверка isRecord сначала убеждается, что перед нами объект, не null и не массив. Запись Record<string, unknown> позволяет затем читать его строковые поля, не считая их содержимое заранее известным.

interface NewsItem { title: string; url: string; description: string | null }
function isRecord(value: unknown): value is Record<string, unknown> {
  return typeof value === "object" && value !== null && !Array.isArray(value);
}
function isNewsItem(value: unknown): value is NewsItem {
  return isRecord(value)
    && typeof value.title === "string"
    && typeof value.url === "string"
    && (typeof value.description === "string" || value.description === null);
}
const input: unknown[] = [
  { title: "TS", url: "/ts", description: null },
  { title: 42, url: "/bad", description: "текст" },
  null
];
const items = input.filter(isNewsItem);
console.log(items.map(item => item.title.toUpperCase())); // ["TS"]

Метод filter вызывает isNewsItem для каждого элемента. Для первого объекта проверка возвращает true, для второго — false из-за числового title, для null — false уже на первом шаге. В items остаётся один объект, а TypeScript знает тип массива NewsItem[]. Проверка подтверждает форму, но не безопасность ссылки или непустой заголовок: бизнес-правила проверяют отдельно. Типы DTO должны учитывать реальные null и пропуски, а не только удачный ответ сервера.

Задача 4. Предикат для статьи с тегами ★★☆ практика

Напишите предикат isArticle(value: unknown): value is Article для типа ниже и функцию validArticles(input: unknown[]): Article[], которая оставляет только корректные элементы. Теги — массив строк, и каждый элемент тоже нужно проверить.

export interface Article {
  id: string;
  title: string;
  tags: string[];
  views: number;
}

Зачем: предикат — это обещание компилятору: «если я вернул true, это точно Article». Компилятор не проверяет, честно ли тело функции, поэтому забытая проверка тегов превратится в падение на tag.toUpperCase() где-то далеко от места ошибки.

Подсказка

Array.isArray(x) && x.every((t) => typeof t === "string"). Для числа подумайте, хотите ли вы пропускать NaN.

Решение и разбор
export interface Article {
  id: string;
  title: string;
  tags: string[];
  views: number;
}

function isRecord(value: unknown): value is Record<string, unknown> {
  return typeof value === 'object' && value !== null && !Array.isArray(value);
}

export function isArticle(value: unknown): value is Article {
  return (
    isRecord(value) &&
    typeof value.id === 'string' &&
    typeof value.title === 'string' &&
    Array.isArray(value.tags) &&
    value.tags.every((tag) => typeof tag === 'string') &&
    Number.isFinite(value.views)
  );
}

export function validArticles(input: unknown[]): Article[] {
  return input.filter(isArticle);
}

Обратите внимание на input.filter(isArticle): благодаря предикату результат имеет тип Article[], а не unknown[]. С обычной функцией (x) => boolean тип бы не сузился. Number.isFinite отсекает и строки, и NaN: JSON не умеет передавать NaN, но данные могут прийти и не из JSON. Если полей становится много, такие проверки удобнее описывать схемой: этим займётся урок Zod.

Задача 5. Предикат из предиката ★★★ с подвохом

Проверки массивов повторяются: «это массив, и каждый элемент проходит проверку X». Напишите обобщённую функцию isArrayOf, которая принимает предикат элемента и возвращает предикат массива. Должно работать так:

const isStringArray = isArrayOf((x: unknown): x is string => typeof x === 'string');
const data: unknown = ['a', 'b'];
if (isStringArray(data)) data.join(', '); // data: string[]

Зачем: так из маленьких проверенных кирпичиков собираются большие, и каждую проверку пишут один раз. Ровно так устроены библиотеки валидации. Задача тренирует generics: тип элемента T выводится из переданного предиката, и его не нужно указывать руками.

Подсказка

Сигнатура: function isArrayOf<T>(guard: (x: unknown) => x is T): (value: unknown) => value is T[].

Решение и разбор
export function isArrayOf<T>(guard: (x: unknown) => x is T): (value: unknown) => value is T[] {
  return (value: unknown): value is T[] => Array.isArray(value) && value.every(guard);
}

export const isString = (x: unknown): x is string => typeof x === 'string';
export const isStringArray = isArrayOf(isString);

const data: unknown = ['a', 'b'];
if (isStringArray(data)) {
  const joined: string = data.join(', ');
  console.log(joined);
}

Функция возвращает функцию: это замыкание над guard. Тип возвращаемой стрелки тоже предикат, иначе снаружи сужение потеряется. T выводится из типа guard: для isString получается string. Пустой массив проходит проверку, ведь every на пустом массиве возвращает true. Для «массив из строк» это правильно. Если нужен непустой, это отдельное правило.

Функция утверждения: продолжить только с правильными данными

Иногда после неверных данных нужно остановить операцию, а не вернуть false. Для этого подходит assertion function — функция утверждения. Запись asserts value is string означает: «если вызов завершился без исключения, дальше value можно использовать как string».

function assertString(value: unknown): asserts value is string {
  if (typeof value !== "string") throw new Error("Нужна строка");
}
function shout(value: unknown): string {
  assertString(value);
  return value.toUpperCase();
}
try { shout(null); }
catch (error: unknown) {
  console.log(error instanceof Error ? error.message : "Неизвестная ошибка");
}
console.log(shout("ts"));

После успешного возврата assertString значение сужено до string. При нарушении обещания функция обязана прервать обычный путь выполнения, например бросить исключение. Это не то же самое, что as string: утверждение типа не добавляет проверки. fetchJson<T>(), возвращающая json as T, также ничего не валидирует.

Вызов shout(null) бросает Error с сообщением «Нужна строка»; catch перехватывает его. Вызов shout("ts") успешно возвращает «TS». Значение ошибки тоже проверяется: JavaScript позволяет бросить не только объект Error.

Задача 6. Утверждение с адресом ошибки ★★☆ практика

Напишите функцию утверждения assertNewsResponse(value: unknown): asserts value is NewsResponse. При неверных данных она бросает TypeError, и в сообщении указано, какое поле сломано: "articles[1].title: ожидалась строка".

export interface NewsResponse {
  status: 'ok';
  articles: { title: string; url: string }[];
}

Зачем: «данные неверные» не помогает исправить ошибку, а «articles[1].title» сразу показывает, куда смотреть в ответе сервера. Функция утверждения подходит, когда дальше без правильных данных идти бессмысленно: после её вызова код пишется так, будто проверка уже прошла.

Решение и разбор
export interface NewsResponse {
  status: 'ok';
  articles: { title: string; url: string }[];
}

function isRecord(value: unknown): value is Record<string, unknown> {
  return typeof value === 'object' && value !== null && !Array.isArray(value);
}

export function assertNewsResponse(value: unknown): asserts value is NewsResponse {
  if (!isRecord(value)) throw new TypeError('ответ: ожидался объект');
  if (value.status !== 'ok') throw new TypeError('status: ожидалось "ok"');
  if (!Array.isArray(value.articles)) throw new TypeError('articles: ожидался массив');
  value.articles.forEach((item: unknown, i) => {
    if (!isRecord(item)) throw new TypeError(`articles[${i}]: ожидался объект`);
    if (typeof item.title !== 'string') throw new TypeError(`articles[${i}].title: ожидалась строка`);
    if (typeof item.url !== 'string') throw new TypeError(`articles[${i}].url: ожидалась строка`);
  });
}

export function titles(raw: unknown): string[] {
  assertNewsResponse(raw);
  return raw.articles.map((a) => a.title); // raw уже NewsResponse
}

В titles после вызова assertNewsResponse(raw) переменная raw имеет тип NewsResponse, хотя пришла как unknown. Одно ограничение: функцию утверждения нужно объявлять через function или с явной аннотацией типа. Стрелка без аннотации в константе выдаст ошибку TS2775. Предикат или утверждение? Предикат подходит, когда «не то» — нормальный вариант, его можно пропустить или отфильтровать. Утверждение — когда «не то» означает поломку.
