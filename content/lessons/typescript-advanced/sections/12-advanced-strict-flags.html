Строгость: индексный доступ и optional-поля

noUncheckedIndexedAccess: элемент может отсутствовать

Перед запуском включите этот флаг в TS Config Playground. Массив пуст: обращение titles[0] действительно вернёт undefined. Компилятор должен заставить нас учесть это перед вызовом строкового метода.

const titles: string[] = [];
const first = titles[0]; // string | undefined при включённом флаге
console.log(first?.toUpperCase() ?? "Нет уроков");
if (false) {
  // @ts-expect-error: элемент может отсутствовать
  first.toUpperCase();
}

Флаг добавляет undefined для потенциально отсутствующего результата индексного доступа. Это полезно для массивов и словарей. Проверка должна учитывать реальное отсутствие; постфиксный ! лишь подавит сомнение компилятора. Флаг не включается автоматически одним strict.

Задача 24. Код, готовый к noUncheckedIndexedAccess ★★☆ практика

Включите в проекте noUncheckedIndexedAccess. Перепишите функции ниже так, чтобы они компилировались с флагом и правильно работали на пустом массиве и при отсутствующем ключе. Без ! и as.

export function firstTitle(titles: string[]): string {
  return titles[0].toUpperCase();
}
export function priceOf(prices: Record<string, number>, id: string): number {
  return prices[id] * 100;
}

Зачем: без флага titles[0] имеет тип string, хотя на пустом массиве это undefined, и падение случится на .toUpperCase(). Флаг заставляет решить, что делать при отсутствии, в момент написания кода.

Решение и разбор
export function firstTitle(titles: string[]): string {
  const first = titles[0];
  return first === undefined ? 'Без названия' : first.toUpperCase();
}

export function priceOf(prices: Record<string, number>, id: string): number {
  const price = prices[id];
  if (price === undefined) throw new RangeError(`Нет цены для ${id}`);
  return price * 100;
}

Что вернуть при отсутствии — решение не про типы, а про смысл. Для заголовка подходит заглушка. Для цены заглушка опасна: 0 означал бы бесплатный товар, поэтому честнее бросить ошибку. С флагом undefined в prices[id] * 100 — ошибка компиляции, без него — тихий NaN в корзине. Проверено отдельным запуском tsc с флагом.

exactOptionalPropertyTypes: отсутствует или записано undefined?

Для этого примера включите exactOptionalPropertyTypes вместе со strict. Объекты {} и { theme: undefined } различаются: в первом свойства нет, во втором оно есть, но содержит undefined. Это различие видно при проверке "theme" in object.

interface Options { theme?: "light" | "dark" }
const absent: Options = {};
const chosen: Options = { theme: "light" };
console.log("theme" in absent, "theme" in chosen); // false true
if (false) {
  // @ts-expect-error: отсутствие поля и явный undefined различаются
  const wrong: Options = { theme: undefined };
}

С этим флагом theme? допускает отсутствие поля, но не явную запись undefined, если undefined отдельно не указан в типе. Чтение optional-поля всё равно учитывает отсутствие. Флаг также не входит в strict. В проекте News API strict и noImplicitAny требуются заданием; дополнительные флаги выбирайте осознанно.

Задача 25. Собрать объект без лишних undefined ★★★ с подвохом

С включённым exactOptionalPropertyTypes напишите buildQuery(form): из формы { q: string; page: number | null } получается Query = { q?: string; page?: number }. Пустая строка и null означают «поле не задано», и ключа в результате быть не должно, даже со значением undefined.

Зачем: { q: undefined } и {} ведут себя по-разному: "q" in obj, Object.keys, URLSearchParams превратит первый в q=undefined. С флагом компилятор не даст записать undefined в необязательное поле, и разница станет видна.

Решение и разбор
export interface Query {
  q?: string;
  page?: number;
}

export function buildQuery(form: { q: string; page: number | null }): Query {
  const query: Query = {};
  const q = form.q.trim();
  if (q !== '') query.q = q;
  if (form.page !== null) query.page = form.page;
  return query;
}

// С флагом следующая строка — ошибка TS2375:
// const bad: Query = { q: undefined };

Объект собирается постепенно, и ключ появляется только при наличии значения. Короче, но читается хуже: { ...(q && { q }) }. Проверьте мутант { q: q || undefined, … }: без флага он компилируется, а тест «ключа нет» его ловит. Флаг включён в отдельной проверке tsc.
