Строгость: индексный доступ и optional-поля

noUncheckedIndexedAccess: элемент может отсутствовать

Перед запуском включите этот флаг в TS Config Playground. Массив пуст: обращение titles[0] действительно вернёт undefined. Компилятор должен заставить нас учесть это перед вызовом строкового метода.

const titles: string[] = [];
const first = titles[0]; // string | undefined при включённом флаге
console.log(first?.toUpperCase() ?? "Нет уроков");
if (false) {
  // @ts-expect-error: элемент может отсутствовать
  first.toUpperCase();
}

Флаг добавляет undefined для потенциально отсутствующего результата индексного доступа. Это полезно для массивов и словарей. Проверка должна учитывать реальное отсутствие; постфиксный ! лишь подавит сомнение компилятора. Флаг не включается автоматически одним strict.

exactOptionalPropertyTypes: отсутствует или записано undefined?

Для этого примера включите exactOptionalPropertyTypes вместе со strict. Объекты {} и { theme: undefined } различаются: в первом свойства нет, во втором оно есть, но содержит undefined. Это различие видно при проверке "theme" in object.

interface Options { theme?: "light" | "dark" }
const absent: Options = {};
const chosen: Options = { theme: "light" };
console.log("theme" in absent, "theme" in chosen); // false true
if (false) {
  // @ts-expect-error: отсутствие поля и явный undefined различаются
  const wrong: Options = { theme: undefined };
}

С этим флагом theme? допускает отсутствие поля, но не явную запись undefined, если undefined отдельно не указан в типе. Чтение optional-поля всё равно учитывает отсутствие. Флаг также не входит в strict. В проекте News API strict и noImplicitAny требуются заданием; дополнительные флаги выбирайте осознанно.
