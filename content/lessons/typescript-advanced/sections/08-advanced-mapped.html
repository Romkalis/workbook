Mapped types: преобразование каждого свойства

Mapped type, или отображаемый тип, описывает преобразование каждого свойства. Запись [K in keyof T] читается как «для каждого ключа K исходного типа T». Это цикл на уровне типов, а не выполнение JS. Partial и Readonly построены на такой идее.

Изменение readonly и необязательных свойств

У Settings два ключа — title и enabled. Тип Flags заменит типы обоих свойств на boolean. Тип Editable сохранит типы string и boolean, но разрешит запись в title и потребует обязательное enabled.

type Flags<T> = { [K in keyof T]: boolean };
type Editable<T> = { -readonly [K in keyof T]-?: T[K] };
interface Settings { readonly title: string; enabled?: boolean }
const flags: Flags<Settings> = { title: true, enabled: false };
const editable: Editable<Settings> = { title: "TS", enabled: true };
editable.title = "Patterns";
console.log(flags.title, editable.title);

Минус перед readonly или ? снимает модификатор, плюс добавляет; без знака добавление является обычным поведением. Простое отображение по keyof сохраняет существующие модификаторы, если явно не поменять их.

Переименовывать ключи тоже можно. К этому примеру с getTitle и getId перейдём после условных типов и шаблонных строк: сначала разберём все части его записи.

Задача 17. Валидаторы для каждого поля формы ★★☆ практика

Опишите mapped type Validators<T>: для каждого поля функция, которая принимает значение этого поля и возвращает текст ошибки или null. Напишите validate(values, validators), возвращающую объект только с полями, где есть ошибка. Проверьте на форме статьи: заголовок не короче 3 символов, просмотры не отрицательные.

Зачем: форма меняется: добавили поле — компилятор сразу потребует для него валидатор, и тип аргумента в нём будет правильным. Это та же идея, что у Record, но тип значения зависит от ключа.

Решение и разбор
export type Validators<T> = { [K in keyof T]: (value: T[K]) => string | null };
export type Errors<T> = Partial<Record<keyof T, string>>;

export function validate<T extends object>(values: T, validators: Validators<T>): Errors<T> {
  const errors: Errors<T> = {};
  for (const key of Object.keys(validators) as (keyof T)[]) {
    const message = validators[key](values[key]);
    if (message !== null) errors[key] = message;
  }
  return errors;
}

export interface ArticleForm {
  title: string;
  views: number;
}
export const articleValidators: Validators<ArticleForm> = {
  title: (v) => (v.trim().length >= 3 ? null : 'Минимум 3 символа'),
  views: (v) => (v >= 0 ? null : 'Не может быть отрицательным'),
};

В валидаторе title параметр v имеет тип string, а в views — number. Аннотировать не нужно: тип берётся из T[K]. Object.keys всегда возвращает string[], потому что у объекта во время выполнения могут быть и лишние ключи. Приведение к (keyof T)[] здесь безопасно: мы перебираем ключи объекта валидаторов, который сами описали по T.

Задача 18. Черновик: всё можно менять и можно не заполнять ★☆☆ разминка

Напишите mapped type Draft<T>: снимает readonly и делает все поля необязательными. Проверьте на интерфейсе с readonly id и обязательным title: черновик {} допустим, и в него можно записать id.

Зачем: модификаторы -readonly и +? объясняют, как устроены встроенные Partial и Readonly. Когда понятно, что это всего лишь mapped types, свои утилиты перестают пугать.

Решение и разбор
export type Draft<T> = { -readonly [K in keyof T]+?: T[K] };

interface Article {
  readonly id: string;
  title: string;
}
const draft: Draft<Article> = {};
draft.id = 'a1';
console.log(draft);

Плюс у ? можно не писать: добавление — поведение по умолчанию. Минус снимает модификатор. Сравните со встроенными утилитами: Partial<T> — это { [K in keyof T]?: T[K] }, а Readonly<T> — { readonly [K in keyof T]: T[K] }.
