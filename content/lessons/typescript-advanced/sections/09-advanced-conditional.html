Conditional types и infer

Условный тип T extends U ? X : Y читается так: «если значения типа T подходят под требования U, выбери X, иначе выбери Y». Например, string extends string ? "да" : "нет" даст тип "да". Это не if, который проверяет данные при выполнении. В generic-объявлении результат может уточниться только после подстановки аргумента.

infer: дать имя найденной части типа

В ElementOf<T> проверяется, является ли T массивом. Если да, infer Item означает «узнай тип его элемента и назови его Item». Для readonly string[] получим string; для number, который не является массивом, вернётся исходный number.

type ElementOf<T> = T extends readonly (infer Item)[] ? Item : T;
type Item = ElementOf<readonly string[]>;
type Result = ElementOf<number>; // не массив — остаётся number
const item: Item = "TS";
const result: Result = 42;
console.log(item, result);
if (false) {
  // @ts-expect-error: ElementOf извлёк string
  const wrong: Item = 42;
}

Infer даёт имя найденной части типа. Здесь Item становится типом string. Для Result проверка «является ли number массивом» не проходит, поэтому выбирается ветка после двоеточия — исходный number. Запись extends встречается также в ограничении параметра типа, например T extends { id: string }: там она задаёт требования к T, а не выбирает одну из двух веток.

Распределение по union и как его отключить

type Each<T> = T extends string ? "text" : "other";
type Whole<T> = [T] extends [string] ? "text" : "other";
type Distributed = Each<string | number>; // "text" | "other"
type Together = Whole<string | number>; // "other"
const first: Distributed = "text";
const second: Together = "other";
console.log(first, second);
if (false) {
  // @ts-expect-error: union целиком не является строковым типом
  const wrong: Together = "text";
}

Подставим string | number в Each. TypeScript не проверяет объединение целиком, а разбирает его по одному варианту: string даёт "text", number даёт "other", и результаты складываются в "text" | "other". Это называется распределением по объединению (distribution). Оно включается само, когда слева от extends стоит просто T.

В Whole параметр завёрнут в квадратные скобки [T], и распределение выключается. Теперь проверяется всё объединение сразу: «является ли string | number строкой?» — нет, поэтому получаем только "other".

Для распределяемого условия never даёт never, поскольку в нём нет вариантов; для проверки самого never используйте [T] extends [never]. Глубокая рекурсия типов имеет ограничения вычисления: не заменяйте понятную модель бесконечным конструктором типов.

Дополнительно: Omit отдельно для каждого варианта union
type Event = { kind: "click"; x: number } | { kind: "key"; key: string };
type DropKind<T> = T extends unknown ? Omit<T, "kind"> : never;
type Payload = DropKind<Event>; // { x: number } | { key: string }
const payload: Payload = { x: 10 };
console.log(payload);

Теперь можно прочитать DropKind по шагам: T extends unknown запускает распределение, Omit убирает kind у каждого варианта отдельно, затем результаты объединяются. Получаются два варианта данных: координата x либо нажатая клавиша key. Это дополнительный приём для случаев, когда обычный Omit теряет поля отдельных вариантов.
