Сборка TypeScript с Webpack

Проверка типов, преобразование синтаксиса и сборка зависимостей — разные шаги. Tsc проверяет типы и может выпускать JS; Webpack находит модули, связанные импортами, и собирает их в выходной файл — bundle. Ts-loader — подключаемый обработчик файлов .ts, который передаёт их TypeScript в процессе сборки. Babel или SWC могут стирать типы без полной проверки, поэтому отдельный typecheck нельзя забывать.

Отдельный проект и зависимости

Создайте отдельную пустую папку, откройте её в редакторе и терминале. Все пути в следующих шагах считаются от этой папки. npm init создаст package.json — описание проекта; npm install добавит инструменты разработки. Перед созданием файлов src/math.ts и src/index.ts создайте папку src.

В новой папке с установленным Node.js выполните команды ниже. В примере согласованы TypeScript 5.9.3, Webpack 5, webpack-cli 6 и ts-loader 9. Локальные примеры и сборка проверены в Node.js 22.23.2; требования других версий инструментов сверяйте с их документацией.

npm init -y
npm install --save-dev typescript@5.9.3 webpack@5 webpack-cli@6 ts-loader@9

Создайте в корне tsconfig.json и скопируйте конфигурацию из раздела о tsconfig. Создайте webpack.config.cjs; расширение .cjs оставляет конфигурацию CommonJS независимо от поля type в package.json.

const path = require("node:path");
module.exports = {
  mode: "development",
  entry: "./src/index.ts",
  devtool: "source-map",
  module: {
    rules: [{ test: /\.tsx?$/, use: "ts-loader", exclude: /node_modules/ }]
  },
  resolve: { extensions: [".ts", ".tsx", ".js"] },
  output: { filename: "bundle.js", path: path.resolve(__dirname, "dist"), clean: true }
};

Создайте src/math.ts:

export function double(value: number): number {
  return value * 2;
}

Создайте src/index.ts:

import { double } from "./math";
const result: number = double(21);
console.log(`Ответ: ${result}`);

Команды проверки и сборки

Откройте package.json, созданный npm init. Добавьте в него поле scripts из примера; если scripts уже есть, замените или дополните только это поле. Остальные поля package.json сохраняйте:

{
  "scripts": {
    "typecheck": "tsc --project tsconfig.json --noEmit",
    "build": "webpack --config webpack.config.cjs",
    "lint": "eslint src"
  }
}

npm run typecheck
npm run build
node dist/bundle.js

После typecheck ошибки типов отсутствуют; после build появляется папка dist с bundle.js и bundle.js.map. Последняя команда запускает bundle.js в Node и печатает «Ответ: 42». Файл .map — карта исходников (source map): она помогает отладчику сопоставить JavaScript с исходным TypeScript. Для браузера подключите dist/bundle.js обычным тегом <script> в HTML. Наш пример не трогает DOM, поэтому работает и в Node.

Почему в tsconfig нет noEmit? Эта настройка запрещает компилятору создавать JavaScript. А ts-loader внутри Webpack как раз должен получить от TypeScript готовый JS, иначе собирать будет нечего. Команда проверки типов передаёт --noEmit отдельно, только для себя, и на сборку это не влияет.

Режим transpileOnly: true ускоряет преобразование, пропуская полную проверку типов. Если используете его, запускайте typecheck отдельно — в том числе в CI, то есть автоматической проверке проекта при отправке изменений. Изоляционная трансформация одного файла и isolatedModules не доказывают согласованность типов всего проекта. Source maps помогают отладке, но не исправляют ошибки типов.

Для выпуска приложения пользователям (production) выбирайте mode production и отдельно проверяйте политику публикации source maps. Практический совет из общих знаний: сохраняйте package-lock.json — файл с точными версиями установленных зависимостей — вместе с проектом и запускайте проверку типов до публикации, чтобы локальный быстрый режим не стал единственной проверкой.
