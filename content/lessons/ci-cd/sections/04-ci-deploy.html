Выкладка на GitHub Pages

Статический сайт (Vite, статический экспорт Next.js) выкладывается на GitHub Pages двумя официальными действиями: одно загружает папку сборки как артефакт, другое публикует её.

name: Deploy
on:
  push:
    branches: [main]

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-node@v7
        with:
          node-version: 22
          cache: npm
      - run: npm ci
      - run: npm test
      - run: npm run build
      - uses: actions/upload-pages-artifact@v5
        with:
          path: dist
  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v5

В настройках репозитория (Settings → Pages → Source) нужно выбрать «GitHub Actions». concurrency не даёт двум выкладкам идти одновременно, а cancel-in-progress: false позволяет начатой выкладке завершиться. Сайт на Pages живёт по адресу /<имя-репозитория>/, поэтому сборщику нужен базовый путь (base в Vite). Про SPA на Pages и маршрутизацию — урок Single Page Application.

Задача 7. Vite-проект на GitHub Pages ★★☆ практика

Сайт на Vite выкладывается workflow из раздела, но на Pages открывается белый экран: скрипты ищутся по адресу /assets/..., а сайт живёт в /shop-web/. Напишите функцию pagesBase(repository), которая из значения GITHUB_REPOSITORY ("anna/shop-web") делает "/shop-web/", а для репозитория вида anna/anna.github.io — "/". Используйте её в vite.config.ts, а локально база должна оставаться /.

Зачем: это самая частая причина «на компьютере работает, на Pages белый экран». Переменная GITHUB_REPOSITORY, которую CI ставит сам, позволяет не вписывать имя репозитория в конфиг руками. Форк или переименование не сломают сайт.

Решение и разбор
export function pagesBase(repository: string | undefined): string {
  if (!repository) return '/';
  const [owner, name] = repository.split('/');
  if (!owner || !name) return '/';
  return name.toLowerCase() === `${owner.toLowerCase()}.github.io` ? '/' : `/${name}/`;
}

Репозиторий <логин>.github.io — пользовательский сайт, он живёт в корне домена. Остальные — в папке с именем репозитория. Проверка process.env.CI оставляет локальную разработку на /: GitHub Actions всегда ставит CI=true. Если в SPA есть роутер на History API, ему тоже нужна база. В Vite она доступна как import.meta.env.BASE_URL.
