Практика команды

  • Защита ветки (Settings → Rules или Branch protection): в main нельзя пушить напрямую, PR сливается только с зелёными обязательными проверками и одобрением ревьюера.
  • Быстрый конвейер. Если проверка идёт 20 минут, её начинают обходить. Кеш, параллельные задания, paths для пропуска лишних запусков.
  • Один источник правды. Скрипт check в package.json запускают и Husky, и CI, и разработчик (задача из урока Express + TypeScript).
  • Падение — сигнал, а не шум. Нестабильный тест («то падает, то нет») чинят или удаляют, иначе к красному статусу привыкают и пропускают настоящую ошибку.

Задача 9. Запускать только нужные проверки ★★★ с подвохом

В монорепозитории две части: web/ и api/, общий код в shared/. Напишите affected(files): по списку изменённых файлов возвращает { web: boolean, api: boolean }. Изменения в shared/, корневом package.json, package-lock.json или в .github/ затрагивают обе части. Файлы *.md не затрагивают ничего.

Зачем: так устроены «умные» конвейеры больших проектов: на каждый PR не гоняют всё подряд. Задача ещё и про безопасный выбор по умолчанию: изменение, о котором логика ничего не знает (новая папка в корне), должно запускать всё, а не ничего.

Решение и разбор
export function affected(files: readonly string[]): { web: boolean; api: boolean } {
  const result = { web: false, api: false };
  for (const file of files) {
    if (file.endsWith('.md')) continue;
    if (file.startsWith('web/')) result.web = true;
    else if (file.startsWith('api/')) result.api = true;
    else {
      // shared/, lock-файлы, .github/ и всё неизвестное — затрагивают обе части
      result.web = true;
      result.api = true;
    }
  }
  return result;
}

Ветка «всё остальное» объединяет и известные общие места, и неизвестные файлы. Это сознательный выбор безопасного умолчания: лишний запуск стоит минуту, а пропущенная поломка — сломанный main. В GitHub Actions список файлов получают через git diff --name-only origin/main...HEAD или готовым действием, а результат передают следующим заданиям через outputs. Для небольших проектов то же решает встроенный фильтр paths.
