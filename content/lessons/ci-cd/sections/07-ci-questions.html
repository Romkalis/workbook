Вопросы и словарь

Чем Continuous Delivery отличается от Continuous Deployment?

В Delivery выкладку подтверждает человек, в Deployment каждое прошедшее изменение выкладывается автоматически.

Почему в CI пишут npm ci, а не npm install?

npm ci ставит ровно версии из lock-файла, начинает с чистой node_modules и падает при расхождении с package.json.

Что произойдёт со следующими шагами, если шаг завершился с ненулевым кодом?

Они не выполнятся, задание будет отмечено как упавшее.

Почему опасно run: echo "${{ github.event.issue.title }}"?

Текст из события подставляется в скрипт до запуска, и специально составленный заголовок выполнится как команда.

Зачем блок permissions?

Чтобы GITHUB_TOKEN имел только нужные права. Взломанный шаг не сможет записать в репозиторий.

CI
автоматическая проверка каждого изменения при частых слияниях.
Continuous Delivery
каждое изменение готово к выкладке, выкладку подтверждает человек.
Continuous Deployment
каждое прошедшее проверки изменение выкладывается автоматически.
Workflow
YAML-файл GitHub Actions с событиями и заданиями.
Runner
машина, на которой выполняется задание.
Artifact
файл или папка, переданные между заданиями или сохранённые после запуска.
