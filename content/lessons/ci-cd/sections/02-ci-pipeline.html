Конвейер проверок

Pipeline (конвейер) — последовательность шагов, которые проходит каждое изменение. Типичный конвейер фронтенд-проекта:

  1. Установка зависимостей строго по package-lock.json: npm ci.
  2. Линтер и проверка форматирования.
  3. Проверка типов: tsc --noEmit.
  4. Тесты.
  5. Сборка.
  6. Выкладка — только для main и только если всё выше прошло.

Принципы:

  • Fail fast: быстрые проверки раньше медленных. Линтер за 10 секунд не должен ждать тестов на 5 минут.
  • Те же команды, что локально. CI вызывает npm run lint и npm test, а не свою копию команд. Если проверка падает в CI, её можно повторить на своём компьютере.
  • Воспроизводимость. npm ci ставит ровно версии из lock-файла и падает, если package.json с ним не согласован. npm install мог бы молча обновить зависимости.
  • Зелёный main. Если проверка в main упала, её чинят первой: пока main красный, никто не знает, сломал ли он что-то ещё.

Задача 1. Скрипты, которые запустит CI ★☆☆ разминка

Подготовьте package.json проекта на Vite + TypeScript к CI: скрипты lint (ESLint без исправлений), format:check (Prettier только проверяет), typecheck, test (Vitest один раз, без режима наблюдения), build и check, который запускает все проверки по принципу fail fast.

Зачем: CI вызывает скрипты проекта, а не свои команды. Тогда упавшую проверку можно повторить локально одной командой. Две частые ошибки: vitest без run в CI зависает в режиме наблюдения, а prettier --write в CI молча «чинит» файлы на сервере вместо того, чтобы упасть.

Решение и разбор
// package.json
{
  "name": "shop-web",
  "private": true,
  "type": "module",
  "scripts": {
    "dev": "vite",
    "lint": "eslint .",
    "format:check": "prettier --check .",
    "typecheck": "tsc --noEmit",
    "test": "vitest run",
    "build": "vite build",
    "check": "npm run lint && npm run format:check && npm run typecheck && npm test"
  }
}

Порядок в check — от быстрых проверок к медленным: линтер и форматирование за секунды, типы дольше, тесты дольше всего. && останавливает цепочку на первой ошибке. Сборка в check не входит: в CI она отдельным шагом, потому что её результат нужен для выкладки. Vitest сам понимает, что работает в CI (переменная CI=true), и не включает наблюдение, но явный run работает везде одинаково.
