ИнкапсуляцияИсточники: oop-overview, Wikipedia (Encapsulation), TechTarget, MDN

У слова два смысла, и в источниках путаются оба. Первый: объединение данных и методов в одном объекте. Второй: ограничение доступа к части этих данных, чтобы с ними работали только через методы самого объекта. В практическом разговоре под инкапсуляцией чаще всего понимают второе.

Зачем скрывать? Если любой код снаружи может записать в поле что угодно, вы не можете гарантировать, что объект остаётся корректным. Баланс счёта становится отрицательным, таймер получает интервал в минус час. Если же изменения идут через методы, проверки сидят в одном месте, а внутреннее устройство можно переписать, не ломая тех, кто объектом пользуется.

Как скрывать в JavaScript

СпособЗащитаКомментарий
_nameТолько договорённостьПоле технически открыто. Подчёркивание говорит коллегам «не трогай». Встретите в старом коде.
#nameНастоящая приватностьДоступ только из тела класса. Снаружи даже обратиться нельзя, синтаксическая ошибка.
замыканиеНастоящая приватностьДанные в переменных функции-конструктора. Старый приём.
Symbol, WeakMapСлабая / частичнаяРедкие приёмы. Для новой разработки берите #.
 
class Acc { _b = 5; #p = 7; }
const a = new Acc();
a._b;           // 5  — соглашение не защищает
a.p;            // undefined
Object.keys(a); // ['_b'] — приватного поля не видно

Полный пример: таймер

Хорошая инкапсуляция выглядит так: состояние и вспомогательная логика закрыты, наружу торчит маленький понятный интерфейс.

В примере есть static с решёткой: static #MIN, static #MAX и static #validate. Это закрытые члены самого класса, а не экземпляра, они общие для всех таймеров и описаны в подразделе «Статические члены подробнее» раздела про классы. Границы интервала и проверка одинаковы для любого таймера, поэтому хранить их в каждом объекте незачем. Вызываются они через имя класса: Timer.#validate(interval).

class Timer {
  static #MIN = 100;
  static #MAX = 1000;
  #interval; #count = 0; #id = null;

  constructor(interval) {
    this.#interval = Timer.#validate(interval);
  }
  static #validate(ms) {
    if (ms < Timer.#MIN || ms > Timer.#MAX) {
      throw new RangeError(
        `Интервал: от ${Timer.#MIN} до ${Timer.#MAX} мс`);
    }
    return ms;
  }
  start() {
    if (this.#id !== null) return;
    this.#id = setInterval(
      () => { this.#count++; }, this.#interval);
  }
  stop() { clearInterval(this.#id); this.#id = null; }
  reset() { this.#count = 0; }
  get count() { return this.#count; }
}

const t = new Timer(100);
t.start();   // через ~350 мс t.count будет около 3
new Timer(5); // RangeError

Заметьте: нельзя создать таймер с интервалом 5 мс, нельзя обнулить счётчик присваиванием, нельзя запустить таймер дважды (повторный start просто ничего не делает). Все правила в одном классе, и снаружи их не обойти.

Геттер и сеттер на каждое поле это ещё не инкапсуляция

Если у каждого приватного поля есть публичные get и set без проверок, вы просто сделали поля публичными более длинным способом. Открывайте операции, которые имеют смысл для предметной области (withdraw(amount)), а не доступ к внутренностям (setBalance(x)).
