НаследованиеИсточники: oop-overview, Wikipedia (Inheritance), MDN, Eloquent JavaScript

Наследование позволяет создать новый класс на основе существующего. Потомок получает поля и методы родителя и может добавить свои или поменять унаследованные. Так общий код пишется один раз и живёт в базовом классе.

class Person {
  constructor(name, age) {
    this.name = name;
    this.age = age;
  }
  sayHi() { return `Привет, я ${this.name}`; }
}

class Employee extends Person {
  constructor(name, age, salary) {
    super(name, age);   // обязательно до this
    this.salary = salary;
  }
  raise(percent) { this.salary *= 1 + percent / 100; }
  sayHi() {             // переопределение
    return super.sayHi() + ', я сотрудник';
  }
}

class Manager extends Employee {
  constructor(name, age, salary, dept) {
    super(name, age, salary);
    this.dept = dept;
  }
  report() { return `${this.name}: отдел ${this.dept}`; }
}

const m = new Manager('Ира', 40, 5000, 'ИТ');
m.raise(10);
m.sayHi();  // 'Привет, я Ира, я сотрудник'
m.report(); // 'Ира: отдел ИТ'

Три механики, которые нужно знать

  • extends устанавливает связь «потомок → родитель».
  • super(...) в конструкторе вызывает конструктор родителя. В классе-потомке до этого вызова нельзя трогать this: получите ReferenceError.
  • super.метод() вызывает версию метода из родителя. Так переопределение (override) дополняет поведение, а не стирает его.

Как движок находит метод

Что происходит при m.sayHi(), если m это Manager? Движок смотрит в сам m, затем по цепочке вверх. Поиск останавливается на первом найденном совпадении, поэтому версия из Employee «затеняет» версию из Person. Именно так работает переопределение.

Виды наследования

ВидЧто этоЕсть в JS?
ОдиночноеУ класса один родитель.Да, единственный вариант.
МногоуровневоеЦепочка: A → B → C (как Person → Employee → Manager).Да.
ИерархическоеНесколько потомков одного родителя.Да.
МножественноеУ класса несколько родителей.Нет. Имитируют примесями (mixins).
ГибридноеКомбинация видов выше.Частично, через примеси.

Когда наследование вредит

Наследование соблазнительно: «у этих двух классов совпадает кусок кода, вынесем в родителя». Это классическая ловушка. Хорошая проверка перед extends: можно ли сказать «потомок является родителем» и подставить его везде, где ожидается родитель (принцип подстановки Лисков). Менеджер является сотрудником, а вот «Автомобиль является Двигателем» уже абсурд, хотя код запуска мог бы пригодиться.

  • Хрупкий базовый класс. Правка в родителе может незаметно сломать потомков, потому что они завязаны на его внутренности.
  • Глубокие иерархии. Чтобы понять метод, приходится прыгать по пяти файлам вверх и вниз (эффект «йо-йо»).
  • Ромбовидная проблема. При множественном наследовании неясно, чью версию метода брать, если два родителя унаследовали его от общего предка. Поэтому в JS и в Java множественного наследования классов нет.

Практическое правило: предпочитайте композицию наследованию. Вместо «является» используйте «имеет»: объект держит внутри другие объекты и делегирует им работу.

class Engine {
  start() { return 'двигатель запущен'; }
}
class Car {
  constructor() { this.engine = new Engine(); }
  start() { return this.engine.start(); }
}
new Car().start(); // 'двигатель запущен'

Теперь двигатель можно заменить на электрический, не трогая иерархию классов. С наследованием так не получится.
