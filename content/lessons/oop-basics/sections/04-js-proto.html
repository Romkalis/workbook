Прототипы в JavaScriptИсточники: MDN, Eloquent JavaScript, freeCodeCamp

У каждого объекта в JavaScript есть «запасной» объект — прототип. Когда вы пишете anna.sayHi(), JavaScript сначала ищет sayHi в самой anna. Не нашёл — идёт в её прототип, потом в прототип прототипа, и так до конца цепочки (там стоит null). Поэтому метод не нужно копировать в каждый объект: он лежит в прототипе один раз, а все объекты находят его там. Такой поиск по цепочке называют прототипным делегированием.

Классы работают на тех же прототипах. Методы, которые вы пишете в теле класса, попадают в объект ИмяКласса.prototype, и все экземпляры ищут их там. Но класс — не просто другая запись старой функции-конструктора. У него есть свои правила: его нельзя вызвать без new, код внутри всегда работает в строгом режиме ("use strict"), и только у классов есть приватные поля #поле.

class Person { sayHi() { /* ... */ } }

typeof Person;                          // 'function'
Person.prototype.constructor === Person; // true

const p = new Person();
Object.getPrototypeOf(p) === Person.prototype; // true
Object.hasOwn(p, 'sayHi');   // false: у самого p метода нет
'sayHi' in p;                // true: нашёлся по цепочке

То же самое без class

До ES6 писали так. Читать такой код вы будете часто, в старых проектах и в учебниках, поэтому понимать его нужно.

function Person(name) {
  this.name = name;
}
Person.prototype.sayHi = function () {
  return 'Привет, ' + this.name;
};

function Student(name, year) {
  Person.call(this, name);        // аналог super()
  this.year = year;
}
Student.prototype =
  Object.create(Person.prototype); // наследование
Student.prototype.constructor = Student;
Student.prototype.introduceSelf = function () {
  return `${this.sayHi()}, я на ${this.year} курсе`;
};

const s = new Student('Маша', 2);
s.introduceSelf(); // 'Привет, Маша, я на 2 курсе'
s instanceof Person; // true

Ещё один способ: создать объект и явно сказать, какой у него прототип. Это и есть чистое делегирование без классов:

const proto = {
  greet() { return 'Привет, ' + this.name; }
};
const o = Object.create(proto);
o.name = 'Лена';
o.greet(); // 'Привет, Лена'
Классы в JS не копируют методы

Метод не копируется в каждый экземпляр, он один на всех в прототипе. Это экономит память, а ещё метод можно подменить сразу для всех объектов.

Обратная сторона — «потерянный» this. Внутри метода this — это объект слева от точки при вызове. Если вызвать метод без точки (например, передать его как колбэк), объекта слева нет, и this становится undefined:

class Counter { count = 0; inc() { this.count++; } }
const c = new Counter();
const f = c.inc;   // взяли метод без объекта
f();               // TypeError: Cannot read properties of undefined
setTimeout(c.inc); // this уже не c: в браузере это window, счётчик c не растёт

setTimeout(() => c.inc()); // так работает: вызов снова «через точку»
setTimeout(c.inc.bind(c)); // и так: bind навсегда привязал this к c

Это самая частая ошибка в ООП-коде на JavaScript.
