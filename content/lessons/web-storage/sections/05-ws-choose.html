Что выбрать

  • Настройка интерфейса (тема, язык, свёрнутое меню) — localStorage.
  • Черновик формы, шаг мастера в текущей вкладке — sessionStorage.
  • То, что должен знать сервер (сессия), — cookie, а токен входа — в httponly-cookie, которую ставит сервер.
  • Много данных, объекты, файлы, работа без сети — IndexedDB.
  • Пароли, номера карт и другие секреты — нигде на клиенте. Любой скрипт на странице читает localStorage, sessionStorage, IndexedDB и cookie без httponly. Одна XSS-уязвимость — и всё это у злоумышленника. Подробнее — урок Web Security.

Задача 11. Выберите хранилище ★☆☆ разминка

Для каждого случая выберите хранилище и одним предложением объясните выбор:

  1. Тёмная тема, выбранная пользователем.
  2. Номер шага в мастере оформления заказа, открытом в этой вкладке.
  3. Идентификатор сессии, по которому сервер узнаёт пользователя.
  4. Каталог из 20 000 товаров для работы без сети.
  5. Номер банковской карты, чтобы не вводить его заново.
  6. Флаг «баннер о cookie закрыт».

Зачем: автотест по модулю проверяет именно это: знание различий, применённое к ситуации. Последний пункт — проверка на безопасность, а не на API.

Решение и разбор
// ответы.txt
1. localStorage — настройка интерфейса, нужна между визитами, серверу не нужна.
2. sessionStorage — относится только к этой вкладке, не должен всплыть в соседней.
3. Cookie с httponly, secure и samesite, которую ставит сервер, — её должен получать сервер, а скрипт не должен читать.
4. IndexedDB — большой объём, объекты, поиск по индексам.
5. Нигде на клиенте — карту хранит платёжный провайдер, а приложение держит только его токен.
6. localStorage (или cookie, если сервер должен не рендерить баннер) — простой флаг между визитами.

В шестом пункте оба ответа правильные, и выбор зависит от архитектуры. Если баннер рисует сервер, ему нужен флаг в cookie, иначе баннер мелькнёт и исчезнет. Если баннер рисуется на клиенте, хватает localStorage. Хороший ответ на собеседовании называет условие, при котором меняется выбор.
