Cookie

Cookie придумали для сервера: он ставит её заголовком Set-Cookie, а браузер возвращает с каждым следующим запросом на этот сайт в заголовке Cookie. Так работают сессии и вход. Из JavaScript cookie доступны через document.cookie, у которого странный интерфейс:

document.cookie = 'theme=dark; max-age=31536000; path=/; samesite=lax';
document.cookie = 'lang=ru';
document.cookie; // 'theme=dark; lang=ru' — все cookie одной строкой, без атрибутов

Присваивание не заменяет все cookie, а добавляет или обновляет одну. Чтение возвращает пары имя=значение через ; , и разбирать их приходится вручную. Значения кодируют через encodeURIComponent: пробелы, ; и = иначе сломают строку.

Атрибуты

АтрибутЧто делает
expires=дата / max-age=секундысрок жизни; без них cookie сеансовая и удаляется при закрытии браузера
path=/для каких путей отправлять; по умолчанию — текущий путь

Удалить cookie — записать её с max-age=0. Но с тем же path и domain, иначе браузер посчитает это другой cookie. Значение по умолчанию для samesite в Chrome — lax (из общих знаний: в других браузерах поведение разное, лучше указывать явно).

Задача 7. Записать и удалить cookie ★★☆ практика

Напишите serializeCookie(name, value, options), которая собирает строку для document.cookie: значение кодируется, опции — maxAge (секунды), path (по умолчанию /), sameSite (по умолчанию lax), secure. sameSite: "none" без secure — ошибка. Имя с ;, = или пробелом — ошибка. Добавьте deleteCookie(name, path), которая возвращает строку удаления.

Зачем: одна функция вместо ручной склейки строк в разных местах — меньше шансов забыть path и получить cookie, которую потом не удалить. Правило «none только с secure» браузеры применяют молча: cookie просто не сохранится, и без проверки об этом не узнать.

Решение и разбор
export interface CookieOptions {
  maxAge?: number;
  path?: string;
  sameSite?: 'strict' | 'lax' | 'none';
  secure?: boolean;
}

export function serializeCookie(name: string, value: string, options: CookieOptions = {}): string {
  if (!/^[^\s;=,]+$/.test(name)) throw new TypeError(`Недопустимое имя cookie: "${name}"`);
  const { maxAge, path = '/', sameSite = 'lax', secure = false } = options;
  if (sameSite === 'none' && !secure) throw new TypeError('SameSite=None требует Secure');
  const parts = [`${name}=${encodeURIComponent(value)}`, `path=${path}`, `samesite=${sameSite}`];
  if (maxAge !== undefined) parts.push(`max-age=${Math.floor(maxAge)}`);
  if (secure) parts.push('secure');
  return parts.join('; ');
}

export const deleteCookie = (name: string, path = '/'): string => serializeCookie(name, '', { maxAge: 0, path });

deleteCookie использует ту же функцию с max-age=0 и тем же path. Это и есть причина держать сборку в одном месте. httponly в опциях нет намеренно: из JavaScript его поставить нельзя, браузер такую cookie через document.cookie не примет. Тест проверяет и запись в настоящий document.cookie в jsdom.

Когда cookie, а когда нет

Cookie нужны, когда значение должен видеть сервер: сессия, язык для серверного рендеринга. Каждая cookie едет с каждым запросом, даже за картинкой, поэтому хранить в них данные «для себя» — лишний трафик. Токен входа безопаснее хранить в cookie с httponly: скрипт на странице, даже внедрённый злоумышленником, его не прочитает. Разбор вариантов — в уроке JWT.

Задача 6. Разобрать document.cookie ★☆☆ разминка

Напишите parseCookies(header: string): Record<string, string>. Пары разделены ; , значение может содержать = (например, base64) и закодировано через encodeURIComponent. Пустая строка даёт пустой объект.

Зачем: document.cookie отдаёт одну строку, и стандартного разборщика в браузере нет (новый cookieStore поддерживается не везде). Две ловушки — = внутри значения и кодирование — ломают наивный split('=').

Решение и разбор
export function parseCookies(header: string): Record<string, string> {
  const result: Record<string, string> = {};
  for (const part of header.split(';')) {
    const pair = part.trim();
    if (!pair) continue;
    const eq = pair.indexOf('=');
    const name = eq === -1 ? pair : pair.slice(0, eq);
    const raw = eq === -1 ? '' : pair.slice(eq + 1);
    try {
      result[name] = decodeURIComponent(raw);
    } catch {
      result[name] = raw;
    }
  }
  return result;
}

Делим по первому =: всё после него — значение, даже если там ещё знаки равенства. decodeURIComponent бросает ошибку на некорректной последовательности вроде %E0, а cookie могли поставить другие скрипты без кодирования. Поэтому при ошибке берём строку как есть. Тот же разбор нужен на сервере для заголовка Cookie, и именно это делает пакет cookie-parser из урока JWT.
