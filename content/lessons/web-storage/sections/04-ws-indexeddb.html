IndexedDB

IndexedDB — настоящая база данных в браузере. Она хранит объекты (не только строки), умеет искать по индексам, работает асинхронно и транзакционно. Подходит для больших объёмов: список товаров для работы без сети, черновики с картинками, кеш ответов API.

Открытие базы и версии

Структура базы — какие есть хранилища объектов (object store, аналог таблицы) и индексы — меняется только в обработчике upgradeneeded. Он срабатывает, когда база открывается с номером версии больше текущего, в том числе при первом создании.

export function openDb(name: string): Promise<IDBDatabase> {
  return new Promise((resolve, reject) => {
    const request = indexedDB.open(name, 1);
    request.onupgradeneeded = () => {
      const db = request.result;
      const notes = db.createObjectStore('notes', { keyPath: 'id', autoIncrement: true });
      notes.createIndex('byTag', 'tag');
    };
    request.onsuccess = () => resolve(request.result);
    request.onerror = () => reject(request.error);
  });
}

keyPath: 'id' — ключ берётся из поля объекта, autoIncrement — база сама выдаёт номера. API IndexedDB старше промисов и построен на событиях success и error у объекта-запроса, поэтому его почти всегда оборачивают в промисы. Готовая тонкая обёртка — библиотека idb (из общих знаний).

Задача 8. Промис из IDBRequest ★★☆ практика

Напишите request<T>(req: IDBRequest<T>): Promise<T> и transactionDone(tx): Promise<void>. На их основе напишите countNotes(db), возвращающую число записей в хранилище notes.

// open.ts
export function openNotes(name: string): Promise<IDBDatabase> {
  return new Promise((resolve, reject) => {
    const r = indexedDB.open(name, 1);
    r.onupgradeneeded = () => r.result.createObjectStore('notes', { keyPath: 'id', autoIncrement: true });
    r.onsuccess = () => resolve(r.result);
    r.onerror = () => reject(r.error);
  });
}

Зачем: событийный API IndexedDB неудобно складывать в цепочки. Две маленькие обёртки превращают его в обычный асинхронный код с await, и дальше с базой можно работать как с любым асинхронным сервисом. Это тот же приём, что промисификация колбэков в уроке Async JS.

Решение и разбор
export function request<T>(req: IDBRequest<T>): Promise<T> {
  return new Promise((resolve, reject) => {
    req.onsuccess = () => resolve(req.result);
    req.onerror = () => reject(req.error);
  });
}

export function transactionDone(tx: IDBTransaction): Promise<void> {
  return new Promise((resolve, reject) => {
    tx.oncomplete = () => resolve();
    // в момент error поле tx.error ещё пустое: ошибка лежит в запросе, который её вызвал
    tx.onerror = (event) => reject((event.target as IDBRequest).error ?? tx.error);
    tx.onabort = () => reject(tx.error ?? new Error('Транзакция отменена'));
  });
}

export function countNotes(db: IDBDatabase): Promise<number> {
  return request(db.transaction('notes').objectStore('notes').count());
}

Тест на дубликат ключа поймал тонкость: событие error всплывает от запроса к транзакции, и в этот момент tx.error ещё null, оно заполнится только при abort. Поэтому ошибку берём из event.target, то есть из запроса. Для чтения достаточно дождаться запроса. Для записи надёжнее ждать complete транзакции: только тогда изменения зафиксированы. У abort поле error бывает null, если транзакцию отменили вызовом tx.abort(). Поэтому стоит запасная ошибка: промис не должен отклоняться значением null.

Задача 9. Миграция базы: версия 2 ★★★ с подвохом

В версии 1 у хранилища notes не было индекса. В версии 2 нужен индекс byCreated по полю createdAt, а у старых записей этого поля нет: проставьте им 0. Напишите openV2(name), которая корректно работает и для новой базы, и для базы версии 1 с данными.

Зачем: у пользователей в браузере лежат базы всех версий, которые вы когда-либо выпускали. Миграция по шагам (oldVersion < 1, oldVersion < 2) — способ довести любую из них до текущей схемы. Это та же идея, что миграции на сервере.

Решение и разбор
export function openV2(name: string): Promise<IDBDatabase> {
  return new Promise((resolve, reject) => {
    const req = indexedDB.open(name, 2);
    req.onupgradeneeded = (event) => {
      const db = req.result;
      const tx = req.transaction!;
      if (event.oldVersion < 1) {
        db.createObjectStore('notes', { keyPath: 'id', autoIncrement: true });
      }
      if (event.oldVersion < 2) {
        const store = tx.objectStore('notes');
        store.createIndex('byCreated', 'createdAt');
        const cursorReq = store.openCursor();
        cursorReq.onsuccess = () => {
          const cursor = cursorReq.result;
          if (!cursor) return;
          if (cursor.value.createdAt === undefined) cursor.update({ ...cursor.value, createdAt: 0 });
          cursor.continue();
        };
      }
    };
    req.onsuccess = () => resolve(req.result);
    req.onerror = () => reject(req.error);
  });
}

Шаги проверяются через <, а не через ===: база версии 0 (новая) должна пройти все шаги подряд, а база версии 1 — только второй. В upgradeneeded уже есть открытая транзакция обновления req.transaction, и через неё можно и менять схему, и переписывать данные. Курсор обходит записи по одной: continue() запрашивает следующую, и тот же обработчик onsuccess срабатывает снова. Событие success у открытия наступит только после завершения всей миграции.

Транзакции

Любое чтение и запись идут внутри транзакции: она указывает, с какими хранилищами работаем и в каком режиме (readonly или readwrite). Если внутри транзакции что-то пошло не так, все её изменения откатываются. Важное правило: транзакция закрывается сама, как только в ней не осталось запросов и управление вернулось в цикл событий. Если между запросами сделать await fetch(...), транзакция успеет закрыться, и следующий запрос упадёт с TransactionInactiveError.

const done = (tx: IDBTransaction) =>
  new Promise<void>((resolve, reject) => {
    tx.oncomplete = () => resolve();
    tx.onerror = (event) => reject((event.target as IDBRequest).error); // ошибка запроса
    tx.onabort = () => reject(tx.error);
  });

export async function addNote(db: IDBDatabase, note: { text: string; tag: string }): Promise<void> {
  const tx = db.transaction('notes', 'readwrite');
  tx.objectStore('notes').add(note);
  await done(tx); // ждём завершения транзакции, а не только запроса
}

Ждать стоит complete транзакции: успешный запрос ещё не значит, что данные записаны на диск.

Индексы и поиск

Индекс позволяет искать по полю, которое не является ключом: store.index('byTag').getAll('work') вернёт все заметки с тегом work. Для диапазонов есть IDBKeyRange: IDBKeyRange.bound(a, b) — от a до b, lowerBound, upperBound. Для обхода больших наборов по одному — курсор openCursor().

Задача 10. Репозиторий заметок на IndexedDB ★★☆ практика

Напишите createNotesRepo(name), который открывает базу (хранилище notes, ключ id с автоувеличением, индекс byTag) и возвращает методы add(note): Promise<number> (возвращает id), byTag(tag), remove(id). Код, который пользуется репозиторием, не должен видеть ни одного IDBRequest.

Зачем: это слой доступа к данным: остальное приложение говорит «добавь заметку», а не «открой транзакцию readwrite на хранилище notes». Когда-нибудь заметки переедут на сервер, и поменяется один модуль, а не весь интерфейс.

Решение и разбор
export interface Note {
  id?: number;
  text: string;
  tag: string;
}

const request = <T>(req: IDBRequest<T>) =>
  new Promise<T>((resolve, reject) => {
    req.onsuccess = () => resolve(req.result);
    req.onerror = () => reject(req.error);
  });

function open(name: string): Promise<IDBDatabase> {
  const req = indexedDB.open(name, 1);
  req.onupgradeneeded = () => {
    const store = req.result.createObjectStore('notes', { keyPath: 'id', autoIncrement: true });
    store.createIndex('byTag', 'tag');
  };
  return request(req);
}

export async function createNotesRepo(name: string) {
  const db = await open(name);
  const store = (mode: IDBTransactionMode) => db.transaction('notes', mode).objectStore('notes');
  return {
    add: (note: Omit<Note, 'id'>) => request(store('readwrite').add(note)) as Promise<number>,
    byTag: (tag: string) => request(store('readonly').index('byTag').getAll(tag)) as Promise<Note[]>,
    remove: (id: number) => request(store('readwrite').delete(id)),
  };
}

Каждый метод открывает свою короткую транзакцию. Это проще и безопаснее, чем держать одну долгую: она бы закрылась при первом await чего-то постороннего. request(indexedDB.open(...)) работает, потому что IDBOpenDBRequest — разновидность IDBRequest с теми же событиями. as Promise<number> нужен потому, что add типизирован как возвращающий любой допустимый ключ, а мы знаем, что ключ числовой.
