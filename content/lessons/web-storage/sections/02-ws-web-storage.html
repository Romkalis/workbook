localStorage и sessionStorage

У обоих одинаковый API — пары «ключ — значение», где и ключ, и значение строки:

export function demo(storage: Storage): string[] {
  storage.setItem('theme', 'dark');
  storage.setItem('visits', String(3));
  const out = [storage.getItem('theme') ?? '', String(storage.length)];
  storage.removeItem('theme');
  out.push(String(storage.getItem('theme'))); // 'null' — ключа нет
  storage.clear();
  return out; // ['dark', '2', 'null']
}

getItem для отсутствующего ключа возвращает null, а не undefined. key(i) и length позволяют перебрать все ключи. Можно писать и как в объект (localStorage.theme = 'dark'), но так легко затереть встроенный метод: ключ 'setItem' через свойство сломает хранилище. Пользуйтесь методами.

Только строки: JSON и его ловушки

Всё, что не строка, превращается в строку: setItem('n', 5) сохранит '5', а объект — '[object Object]'. Объекты сохраняют через JSON.stringify и читают через JSON.parse. Прочитанное нужно проверять: значение могли поменять руками в DevTools, его могла записать старая версия вашего кода, а JSON.parse на испорченной строке бросает SyntaxError. Проверка формы и версия формата подробно разобраны в уроке Состояние и отрисовка.

Задача 2. Значение со сроком годности ★★☆ практика

У localStorage нет срока жизни. Напишите setWithTtl(storage, key, value, ttlMs, now) и getWithTtl(storage, key, now): значение хранится вместе со временем истечения, а после истечения getWithTtl удаляет ключ и возвращает null. Время передаётся функцией now, по умолчанию Date.now.

Зачем: кеш ответов API или «не показывать баннер неделю» требуют срока. Такой обёрткой сохраняют то, что можно получить заново, но не хочется дёргать сервер на каждой загрузке. Внедрённое время делает проверку истечения детерминированной.

Решение и разбор
type Now = () => number;
interface Entry<T> {
  value: T;
  expiresAt: number;
}

export function setWithTtl<T>(storage: Storage, key: string, value: T, ttlMs: number, now: Now = Date.now): void {
  const entry: Entry<T> = { value, expiresAt: now() + ttlMs };
  storage.setItem(key, JSON.stringify(entry));
}

export function getWithTtl<T>(storage: Storage, key: string, now: Now = Date.now): T | null {
  const raw = storage.getItem(key);
  if (raw === null) return null;
  try {
    const entry = JSON.parse(raw) as Entry<T>;
    if (typeof entry.expiresAt !== 'number' || now() >= entry.expiresAt) {
      storage.removeItem(key);
      return null;
    }
    return entry.value;
  } catch {
    storage.removeItem(key);
    return null;
  }
}

Хранится момент истечения, а не время записи и срок отдельно: так проверка — одно сравнение, и смена срока в коде не продлевает уже сохранённые записи. Удаление при чтении — «ленивая» уборка. Записи, которые никто не читает, останутся, и для них можно раз при запуске пройти по всем ключам. Испорченная запись тоже удаляется, чтобы не спотыкаться о неё каждый раз.

Квота и ошибки записи

При переполнении setItem бросает QuotaExceededError. В Safari в приватном режиме раньше любая запись бросала эту ошибку (из общих знаний), а в некоторых встроенных браузерах хранилище вообще недоступно. Поэтому запись оборачивают в try...catch: если сохранить не удалось, приложение должно продолжить работу, просто без сохранения.

Ещё один нюанс — синхронность. localStorage читает и пишет в главном потоке. Записать пару ключей — мгновенно, а сериализовать мегабайтный объект на каждое нажатие клавиши — заметная задержка. Для больших данных подходит IndexedDB.

Задача 3. Хранилище, которое не роняет приложение ★☆☆ разминка

Напишите createJsonStore(storage) с методами get(key, fallback) и set(key, value): boolean. get возвращает fallback, если ключа нет или там испорченный JSON. set возвращает false, если запись не удалась (квота, недоступное хранилище), и не бросает ошибку.

Зачем: сохранение — удобство, а не основная функция. Испорченное значение или переполненная квота не должны превращать страницу в белый экран. Обёртка в одном месте — и весь остальной код может не думать о try...catch.

Решение и разбор
export function createJsonStore(storage: Pick<Storage, 'getItem' | 'setItem'>) {
  return {
    get<T>(key: string, fallback: T): T {
      try {
        const raw = storage.getItem(key);
        return raw === null ? fallback : (JSON.parse(raw) as T);
      } catch {
        return fallback;
      }
    },
    set(key: string, value: unknown): boolean {
      try {
        storage.setItem(key, JSON.stringify(value));
        return true;
      } catch {
        return false;
      }
    },
  };
}

get обёрнут целиком, а не только JSON.parse: в некоторых окружениях исключение бросает уже само обращение к getItem. as T здесь — честное допущение «верим, что там то, что мы сами записали». Если данные могли поменяться между версиями приложения, вместо него нужна проверка формы (урок Состояние и отрисовка). Параметр storage позволяет использовать и localStorage, и sessionStorage, и заглушку в тестах.

sessionStorage: данные одной вкладки

sessionStorage живёт столько, сколько открыта вкладка: переживает перезагрузку, но не закрытие. У каждой вкладки своё хранилище, даже у двух вкладок одного сайта. При дублировании вкладки браузер копирует её sessionStorage в новую, дальше они расходятся. Подходит для черновика формы, шага мастера оформления, позиции прокрутки — всего, что относится к текущему «сеансу работы» и не должно появиться в соседней вкладке.

Задача 4. Черновик формы во вкладке ★★☆ практика

Напишите persistDraft(form, storage = sessionStorage): при загрузке восстанавливает значения полей из хранилища, при каждом вводе (input) сохраняет все поля формы, при отправке (submit) очищает черновик. Ключ — draft: плюс id формы. Возвращает функцию отписки.

Зачем: перезагрузка страницы или случайное обновление не должны стирать длинный отзыв. sessionStorage здесь правильнее localStorage: черновик принадлежит этой вкладке, и он не должен всплыть в другой вкладке или через неделю.

Решение и разбор
export function persistDraft(form: HTMLFormElement, storage: Storage = sessionStorage): () => void {
  const key = `draft:${form.id}`;
  const saved = storage.getItem(key);
  if (saved !== null) {
    try {
      const values = JSON.parse(saved) as Record<string, string>;
      for (const [name, value] of Object.entries(values)) {
        const field = form.elements.namedItem(name);
        if (field instanceof HTMLInputElement || field instanceof HTMLTextAreaElement) field.value = value;
      }
    } catch {
      storage.removeItem(key);
    }
  }
  const controller = new AbortController();
  form.addEventListener(
    'input',
    () => {
      const values = Object.fromEntries([...new FormData(form)].filter(([, v]) => typeof v === 'string'));
      storage.setItem(key, JSON.stringify(values));
    },
    { signal: controller.signal },
  );
  form.addEventListener('submit', () => storage.removeItem(key), { signal: controller.signal });
  return () => controller.abort();
}

Обработчик input один на всю форму, и событие всплывает от любого поля: это делегирование из урока События и формы. FormData собирает значения по атрибутам name. Файлы (File) отфильтрованы: в JSON их не сохранить. Поля паролей тоже не стоит сохранять в черновик, и FormData их включает. В рабочем коде их исключают по типу поля. Отписка через AbortController снимает оба обработчика разом.

Событие storage: синхронизация вкладок

Когда одна вкладка меняет localStorage, в остальных вкладках того же источника срабатывает событие storage на window. В самой вкладке, которая сделала запись, оно не срабатывает. В событии есть key, oldValue, newValue и storageArea. При clear() key равен null.

window.addEventListener('storage', (event) => {
  if (event.key === 'cart') renderCart(JSON.parse(event.newValue ?? '[]'));
});

Так корзина обновляется во всех открытых вкладках, а выход из аккаунта в одной вкладке разлогинивает остальные. Для sessionStorage событие тоже существует, но вкладки его почти не разделяют, поэтому на практике полезно только для localStorage.

Задача 1. Своё пространство ключей ★★☆ практика

На одном домене живут несколько приложений, и localStorage.clear() одного стирает данные другого. Напишите namespaced(storage, prefix) с методами get, set, remove, keys() и clear(), которые работают только с ключами вида prefix:ключ.

Зачем: хранилище общее для всего источника, а значит, это глобальное состояние. Префикс — простейшее разделение ответственности. Задача ещё и про перебор: удалять ключи во время обхода по индексу — классическая ошибка.

Подсказка

Сначала соберите список своих ключей через key(i) и length, потом удаляйте. Если удалять внутри цикла по индексам, индексы сдвинутся, и часть ключей пропустится.

Решение и разбор
export function namespaced(storage: Storage, prefix: string) {
  const full = (key: string) => `${prefix}:${key}`;
  const ownKeys = (): string[] => {
    const result: string[] = [];
    for (let i = 0; i < storage.length; i++) {
      const key = storage.key(i);
      if (key !== null && key.startsWith(`${prefix}:`)) result.push(key);
    }
    return result;
  };
  return {
    get: (key: string) => storage.getItem(full(key)),
    set: (key: string, value: string) => storage.setItem(full(key), value),
    remove: (key: string) => storage.removeItem(full(key)),
    keys: () => ownKeys().map((k) => k.slice(prefix.length + 1)),
    clear: () => ownKeys().forEach((k) => storage.removeItem(k)),
  };
}

Сначала собираем, потом удаляем: так перебор не зависит от изменений, которые он сам вносит. Двоеточие в конце префикса важно. Без него префикс shop захватил бы и ключи приложения shop2. Порядок ключей в key(i) стандартом не гарантирован, поэтому в тесте ключи сортируются.

Задача 5. Корзина во всех вкладках ★★☆ практика

Напишите watchKey(key, onChange, target = window): вызывает onChange(value) с разобранным JSON, когда другая вкладка меняет этот ключ в localStorage. Удаление ключа или clear() вызывает onChange(null). Изменения других ключей и sessionStorage игнорируются. Возвращает функцию отписки.

Зачем: пользователь добавил товар в одной вкладке, переключился на другую — и видит старую корзину. Событие storage решает это без сервера. Главное — не забыть, что в своей вкладке оно не приходит, поэтому интерфейс там обновляют обычным путём.

Решение и разбор
export function watchKey<T>(key: string, onChange: (value: T | null) => void, target: Window = window): () => void {
  const handler = (event: StorageEvent) => {
    if (event.storageArea !== localStorage) return;
    if (event.key !== null && event.key !== key) return;
    if (event.newValue === null) return onChange(null);
    try {
      onChange(JSON.parse(event.newValue) as T);
    } catch {
      onChange(null);
    }
  };
  target.addEventListener('storage', handler);
  return () => target.removeEventListener('storage', handler);
}

event.key === null означает clear(): удалены все ключи, и наш тоже. Поэтому такое событие пропускается к обработчику, и newValue у него null. Проверка storageArea отсекает sessionStorage. В тесте событие создаётся вручную через new StorageEvent: так проверяется реакция без второй вкладки.
