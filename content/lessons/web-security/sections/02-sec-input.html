Проверка входных данных

Правило OWASP: проверять на сервере, по белому списку (что разрешено), а не по чёрному (что запрещено). Чёрный список всегда неполон: найдётся кодировка, регистр или символ, о котором вы не подумали.

  • Синтаксис: тип, длина, формат (email, целое от 1 до 100).
  • Семантика: смысл в контексте — дата начала раньше даты конца, количество не больше остатка на складе.
  • Лишние поля отбрасываются или отклоняются: клиент не должен протащить isAdmin: true.

Удобный инструмент — схемы (Zod). Проверка ввода не заменяет экранирование вывода: корректная строка <b>Аня</b> — допустимое имя, но вставлять её в HTML как разметку нельзя.

Задача 1. Белый список полей профиля ★★☆ практика

Напишите validateProfileUpdate(body: unknown) для PATCH /api/me. Разрешены только name (строка 1–50 символов после обрезки пробелов) и bio (строка до 300 символов). Любое другое поле (role, isAdmin, id) — ошибка. Результат: { ok: true, data } или { ok: false, errors: string[] } со всеми ошибками сразу.

Зачем: это защита от API3 из OWASP — mass assignment: обработчик делает Object.assign(user, req.body), и пользователь назначает себе роль администратора. Белый список полей закрывает это раз и навсегда, даже когда в модель добавят новое служебное поле.

Решение и разбор
export type ProfileUpdate = { name?: string; bio?: string };
type Result = { ok: true; data: ProfileUpdate } | { ok: false; errors: string[] };
const ALLOWED = new Set(['name', 'bio']);

export function validateProfileUpdate(body: unknown): Result {
  if (typeof body !== 'object' || body === null || Array.isArray(body)) return { ok: false, errors: ['Ожидался объект'] };
  const errors: string[] = [];
  const data: ProfileUpdate = {};
  for (const key of Object.keys(body)) if (!ALLOWED.has(key)) errors.push(`Поле ${key} менять нельзя`);
  const input = body as Record<string, unknown>;
  if ('name' in input) {
    const name = typeof input.name === 'string' ? input.name.trim() : '';
    if (name.length < 1 || name.length > 50) errors.push('name: от 1 до 50 символов');
    else data.name = name;
  }
  if ('bio' in input) {
    if (typeof input.bio !== 'string' || input.bio.length > 300) errors.push('bio: строка до 300 символов');
    else data.bio = input.bio;
  }
  if (errors.length === 0 && Object.keys(data).length === 0) errors.push('Нечего обновлять');
  return errors.length ? { ok: false, errors } : { ok: true, data };
}

Лишнее поле здесь — ошибка, а не молчаливое удаление. Для API, которым пользуется ваш же фронтенд, это полезнее: опечатка nmae не проглотится незаметно. Результат строится из проверенных полей, а не копированием body. Ошибки собираются все, чтобы форма показала их разом. Та же проверка схемой — z.strictObject в уроке Zod.
