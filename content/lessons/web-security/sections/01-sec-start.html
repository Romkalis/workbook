Как думать о безопасности

Безопасность — не отдельная функция, которую добавляют в конце, а привычка задавать вопрос: «что будет, если сюда придут не те данные или не тот человек». Три правила, на которых держится всё остальное:

  • Не доверяйте клиенту. Всё, что пришло по сети — тело, параметры, заголовки, cookie, — мог сформировать кто угодно, не только ваш фронтенд. Проверка на клиенте — удобство для пользователя, защита — на сервере.
  • Минимум прав. Каждая часть системы получает ровно столько доступа, сколько нужно: токен только для чтения, пользователь видит только свои заказы, ключ API — только от одного сервиса.
  • Защита в несколько слоёв. Каждая мера может отказать: экранирование забыли в одном месте — спасает CSP; украли токен — спасает короткий срок жизни.

Аутентификация и авторизация

Аутентификация — «кто вы»: проверка пароля, токена, сертификата. Ошибка — 401 Unauthorized. Авторизация — «что вам можно»: может ли этот пользователь удалить этот заказ. Ошибка — 403 Forbidden (или 404, если сам факт существования ресурса — секрет). Путать их опасно: «вошёл — значит можно всё» — самая частая уязвимость API.
