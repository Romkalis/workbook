Что такое линтер

Видео модуля о линтерах начинается с определения из Википедии: линтер — инструмент статического анализа кода, который отмечает программные ошибки, баги, стилистические ошибки и подозрительные конструкции. «Статический» значит, что код анализируется без запуска: линтер читает исходный текст, как внимательный ревьюер. Название пошло от программы lint 1978 года для языка C — «вычёсывать катышки» (lint) из кода.

Автор видео разбирает четыре категории того, что находит линтер.

Программные ошибки
В компилируемых языках (Java, Go, Rust) компилятор сам скажет об опечатке в имени переменной. JavaScript не компилируется, и nmae вместо name обнаружится только при запуске нужной строки — может быть, у пользователя. Линтер найдёт это сразу: обращение к необъявленной переменной, вызов несуществующей функции, синтаксические ошибки.
Баги и производительность
Код, который работает, но, скорее всего, не так, как задумано: == с неявным приведением типов, await внутри цикла, условие, которое всегда истинно, недостижимый код после return.
Стиль
Единообразие: как называть переменные, где ставить скобки. Автор видео подчёркивает главную пользу: когда стиль проверяет программа, обсуждение в пул-реквестах переходит к важному — архитектуре, багам, безопасности.
Подозрительные конструкции и безопасность
Например, eval, который выполняет строку как код и открывает дорогу атакам.

Итог видео: линтер делает код читаемее, ловит ошибки до запуска, помогает стандартизации и безопасности, а значит экономит время и уменьшает технический долг — накопленные «потом поправлю», которые замедляют работу.

Линтеры есть почти для всего: ESLint для JavaScript и TypeScript, Stylelint для CSS, markdownlint для Markdown, а в CI (автоматических проверках на сервере при каждом пуше) их часто запускают пачкой (видео упоминает GitHub Super-Linter). В этом уроке речь об ESLint — стандарте для JavaScript; JSHint и JSLint, которые сравнивает одна из дополнительных статей модуля, сегодня почти не используются.
