Практика, вопросы и словарь

Настройка с нуля: все шаги

git init
npm init -y
npm pkg set type=module
npm install -D eslint @eslint/js globals prettier eslint-config-prettier husky lint-staged
# создать eslint.config.js и .prettierrc (см. разделы выше)
npx husky init
echo "npx lint-staged" > .husky/pre-commit
# добавить "lint-staged" и скрипты в package.json
npm pkg set scripts.lint="eslint ." scripts.format="prettier --write ."

Команда npm pkg set меняет package.json без ручного редактирования. Именно эта последовательность проверена при подготовке урока.

Упражнения

  1. Настройте ESLint и Prettier в своём проекте по шагам выше. Запустите npm run lint и разберитесь с каждой ошибкой по справочнику правил.
  2. Включите правила no-console как warn и eqeqeq как error. Чем отличается код выхода, когда есть только предупреждения?
  3. Поменяйте в .prettierrc printWidth на 40 и выполните prettier --write. Посмотрите, как переносятся строки.
  4. Настройте VS Code на форматирование при сохранении.
  5. Подключите Husky и lint-staged. Попробуйте закоммитить файл с необъявленной переменной и убедитесь, что коммит не прошёл.

Вопросы

Нужен ли Prettier, если есть ESLint?

Да. ESLint ищет ошибки и проблемы качества, Prettier полностью отвечает за внешний вид и делает это лучше. Используют оба, а конфликтующие правила ESLint выключают пакетом eslint-config-prettier.

Почему eslint --fix не заменил == на ===?

Такая замена может изменить поведение программы. Автоматически ESLint исправляет только безопасное.

Зачем Husky, если git сам умеет хуки?

Папка .git/hooks не попадает в репозиторий. Husky хранит хуки в .husky, которая коммитится, и включает их у всех через скрипт prepare.

Зачем lint-staged?

Чтобы проверять только файлы этого коммита: быстро и без падений на чужом старом коде. Исправленные файлы он сам возвращает в коммит.

Словарь

Статический анализ
Проверка кода без его запуска.
Линтер
Инструмент статического анализа: ошибки, баги, подозрительные места, соглашения.
Форматтер
Инструмент, который переписывает внешний вид кода по единым правилам.
Правило ESLint
Одна проверка, например no-unused-vars; уровень off, warn или error.
Flat config
Современный формат конфига ESLint: eslint.config.js с массивом настроек.
Стайлгайд
Руководство по стилю кода (Airbnb, Google, Standard).
Git-хук
Скрипт, который git запускает при событии: перед коммитом, перед пушем.
Husky
Инструмент, который хранит git-хуки в проекте и включает их у всей команды.
lint-staged
Запуск команд только для файлов, добавленных в коммит.
Staged-файлы
Изменения, добавленные через git add и готовые к коммиту.
CI
Автоматические проверки на сервере при каждом пуше или пул-реквесте.
