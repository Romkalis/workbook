ESLint

ESLint — расширяемый линтер для JavaScript. Во втором видео модуля говорится о 17 миллионах скачиваний в неделю и использовании в Microsoft, Netflix и Google. Его ставят как dev-зависимость (раздел devDependencies в package.json, подробнее в уроке о Node.js): приложению для работы он не нужен.

Установка

Быстрый путь — мастер (интерактивная программа в терминале), который задаст вопросы (для браузера или Node, есть ли React, TypeScript) и создаст конфиг (Getting Started):

npm init @eslint/config@latest

Или вручную:

npm install -D eslint @eslint/js globals

Файл eslint.config.js

Конфиг в корне проекта (документация). Это массив объектов-настроек, которые применяются по порядку; если два объекта задают одно правило, побеждает последний.

import js from '@eslint/js';
import globals from 'globals';
import { defineConfig } from 'eslint/config';

export default defineConfig([
  { ignores: ['dist/'] },                    // какие папки не проверять
  js.configs.recommended,                    // рекомендуемый набор правил
  {
    files: ['**/*.js'],
    languageOptions: { globals: globals.browser }, // window, document и т. п.
    rules: {
      eqeqeq: 'error',
      'no-console': 'warn',
      'prefer-const': 'error',
    },
  },
]);
  • js.configs.recommended включает правила, которые ловят настоящие ошибки: no-undef, no-unused-vars, no-unreachable и другие.
  • globals.browser сообщает, что в коде можно пользоваться window, document, localStorage. Без этого ESLint решит, что document не объявлен. Для Node.js — globals.node.
  • files — к каким файлам применять объект, ignores — что пропустить. node_modules пропускается всегда.
Старый формат .eslintrc

В видео модуля и статье LogRocket конфиг называется .eslintrc.json (или .eslintrc.js) и выглядит как объект с полями extends, plugins, env. Это прежний формат. С ESLint 9 (апрель 2024) по умолчанию используется «плоский» eslint.config.js, а в ESLint 10 старый формат удалён совсем: проверка показала, что ESLint 10.15 не видит .eslintrc.json даже с переменной ESLINT_USE_FLAT_CONFIG=false и просит создать eslint.config.js. Если в туториале .eslintrc — пользуйтесь им только для понимания, а переносите по руководству по миграции: env: { browser: true } превращается в languageOptions.globals, а extends — в элементы массива.

Запуск и автоисправление

Проверим файл с типичными ошибками:

import { unused } from './utils.js'
let total = 0
const items = [1,2,3]
for (const item of items) { total += item }
if (total == '6') {
    console.log("всё сходится")
}
function greet(name) { return 'Привет, ' + nmae }
greet('Аня')
$ npx eslint .
src/app.js
  1:10  error    'unused' is defined but never used   no-unused-vars
  5:11  error    Expected '===' and instead saw '=='  eqeqeq
  6:5   warning  Unexpected console statement         no-console
  8:16  error    'name' is defined but never used     no-unused-vars
  8:44  error    'nmae' is not defined                no-undef

✖ 5 problems (4 errors, 1 warning)

Каждая строка: позиция (строка:столбец), уровень, сообщение и имя правила. По имени правила ищут объяснение в справочнике правил. Опечатку nmae линтер нашёл, хотя код ни разу не запускался. Команда завершилась с кодом 1 — это важно для автоматизации: Husky и CI по коду выхода понимают, что проверка не прошла.

npx eslint . --fix исправляет то, что можно исправить безопасно. В нашем файле он ничего не поменял: == на === автоматически не заменяется, потому что это может изменить поведение (6 == '6' истинно, 6 === '6' ложно). Неиспользуемые переменные и опечатки исправляет человек. Удобно добавить скрипты в package.json: "lint": "eslint ." и "lint:fix": "eslint . --fix".

Правила и уровни

Каждое правило включается одним из трёх уровней (Configure Rules — документ из теории модуля):

  • "off" или 0 — выключено;
  • "warn" или 1 — предупреждение: показывается, но код выхода не портит;
  • "error" или 2 — ошибка: команда завершится с кодом 1, коммит или сборка в CI не пройдут.

Документация советует: правила, нарушение которых обязательно исправить, — error; warn — для новых правил, которые позже станут ошибками, и для случаев, где правило может ошибаться. У некоторых правил есть настройки, тогда значение — массив: 'prefer-const': ['error', { ignoreReadBeforeAssign: true }].

Отключить правило в одном месте можно комментарием. Пишите причину после --, чтобы следующий человек понял, зачем это:

// eslint-disable-next-line no-console -- отладочный вывод для лекции
console.log(result);

/* eslint eqeqeq: "off" */   // для всего файла

Злоупотреблять этим не стоит: десятки eslint-disable означают, что правило не подходит проекту и его лучше настроить в конфиге.

Готовые наборы правил и стайлгайды

Правил сотни, настраивать каждое долго. Поэтому берут готовый набор и подправляют. Статья Codacy из дополнительных материалов называет популярные стайлгайды (руководства по стилю кода):

  • Airbnb JavaScript Style Guide (2012) — подробный и строгий, долго был самым популярным, в RS School его часто использовали через eslint-config-airbnb-base. Этот пакет долго не поддерживал новый формат конфигов; перед установкой проверяйте совместимость с вашей версией ESLint.
  • Google JavaScript Style Guide — правила стиля и правила языка, используемые в Google.
  • JavaScript Standard Style — готовый набор без настройки: никаких точек с запятой, команда standard --fix.
  • Idiomatic.js — открытое руководство, которое можно адаптировать.

Для TypeScript используют typescript-eslint, для React — eslint-plugin-react и eslint-plugin-react-hooks. Шаблоны Vite и Next.js создают конфиг ESLint сами.
