Кто прав: клиент или сервер

Сумму корзины можно посчитать и в браузере, но цены и скидки решает сервер: клиентский код меняется в DevTools за секунду. Поэтому итог для оплаты всегда берётся из ответа сервера, а клиентский расчёт — разве что предварительная подсказка.

Два стиля обновления интерфейса (из общих знаний). Пессимистичный: показываем «Считаем…», ждём сервер, рисуем результат. Честно и просто. Оптимистичный: сразу рисуем ожидаемый результат, а при ошибке откатываем. Быстрее на вид, но сложнее: нужно хранить прежнее состояние и показать откат так, чтобы пользователь понял, что случилось. Для денег начинайте с пессимистичного.

Задача 13. Оптимистичное «В избранное» с откатом ★★★ с подвохом

Кнопка «В избранное» должна реагировать мгновенно. Напишите toggleFavorite(state, id, save, onState): сразу сообщает новое состояние (id добавлен или убран из множества избранного), затем вызывает асинхронный save(id, isFavorite). При ошибке возвращает прежнее состояние и сообщает текст ошибки.

Зачем: избранное — хороший кандидат для оптимистичного обновления: ошибка редка и безобидна, а задержка клика заметна. Задача показывает, сколько стоит «быстро на вид»: нужно хранить прежнее состояние и честно откатить его при ошибке.

Решение и разбор
// favorite.ts
export interface FavState {
  favorites: ReadonlySet<string>;
  error: string | null;
}

export async function toggleFavorite(
  state: FavState,
  id: string,
  save: (id: string, isFavorite: boolean) => Promise<void>,
  onState: (s: FavState) => void,
): Promise<void> {
  const isFavorite = !state.favorites.has(id);
  const next = new Set(state.favorites);
  if (isFavorite) next.add(id);
  else next.delete(id);
  onState({ favorites: next, error: null });
  try {
    await save(id, isFavorite);
  } catch {
    onState({ favorites: state.favorites, error: 'Не удалось сохранить избранное, попробуйте ещё раз' });
  }
}

Откат возвращает именно state.favorites, прежнее множество. Его не меняли, потому что новое создано копией (new Set(...)), и иммутабельность здесь работает как бесплатная «точка отката». Ограничение: если за время запроса пользователь нажал ещё что-то, откат затрёт и это. Для таких случаев откатывают только своё изменение (убрать/вернуть один id) или ставят действия в очередь.

Последний расчёт побеждает

Нажали «+» три раза быстро — ушло три запроса расчёта. Если ответ на второй придёт последним, на экране останется неверная сумма. Если отменять запрос нельзя или не хочется, помогает номер запроса: каждый новый получает следующий номер, а ответ рисуется, только если его номер последний. Так сделано в main.ts проекта.

Задача 12. POST с JSON ★☆☆ разминка

Напишите postJson(url, body, fetchFn = fetch): отправляет POST с заголовком Content-Type: application/json и телом-JSON, при статусе не 2xx бросает Error с текстом из поля error ответа (используйте readErrorMessage), иначе возвращает разобранный JSON как unknown.

// error-text.ts
export async function readErrorMessage(res: Response): Promise<string> {
  try {
    const body: unknown = await res.json();
    if (typeof body === 'object' && body !== null && 'error' in body && typeof body.error === 'string') return body.error;
  } catch {
    // тело не JSON
  }
  return `Сервер ответил ${res.status}`;
}

Зачем: три обязательные части JSON-запроса (метод, заголовок, тело) легко забыть по одной. Функция, которая собирает их правильно, избавляет от самой частой ошибки «сервер не видит моих данных».

Решение и разбор
// post.ts
import { readErrorMessage } from './error-text.js';

export async function postJson(url: string | URL, body: unknown, fetchFn: typeof fetch = fetch): Promise<unknown> {
  const res = await fetchFn(url, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(body),
  });
  if (!res.ok) throw new Error(await readErrorMessage(res));
  return res.json();
}

Результат — unknown: проверять форму будет вызывающий код, потому что только он знает, что ожидает. Так же устроен getJson с предикатом. Можно объединить две функции в одну request<T>(method, url, body, isT), и в больших клиентах так и делают.

Задача 14. Номер запроса против устаревших ответов ★★☆ практика

Напишите createLatest() — счётчик запросов: begin() возвращает функцию isLatest(), которая истинна, только пока после этого begin не было нового. Используйте его, чтобы из трёх быстрых расчётов корзины на экран попал только последний, даже если ответы пришли в обратном порядке.

Зачем: не каждый запрос можно отменить: старые API, сторонние библиотеки, запросы, которые уже изменили данные на сервере. Номер запроса — универсальная защита отображения, независимая от транспорта.

Решение и разбор
// latest-id.ts
export function createLatest() {
  let current = 0;
  return {
    begin(): () => boolean {
      const id = ++current;
      return () => id === current;
    },
  };
}

Каждый begin захватывает свой номер в замыкании, а сравнивается он с общим счётчиком. Разница с AbortController: запрос не отменяется, сеть и сервер работают зря, зато код не зависит от того, умеет ли запрос отменяться. Для POST, который меняет данные, отмена и вовсе опасна: сервер мог уже выполнить действие. Здесь честнее дождаться ответа и просто его не показать.
