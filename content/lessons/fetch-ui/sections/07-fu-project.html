Задача 17. Каталог целиком: тест от клика до экрана ★★★ с подвохом

Напишите интеграционный тест (jsdom) для связки из готового проекта, но в миниатюре: mountCatalog(root, api) загружает товары и рисует карточки, при ошибке показывает «Повторить», а клик по ней повторяет загрузку. API подменён объектом, который сначала падает, а потом отвечает.

Зачем: модульные тесты проверили клиент, состояния и отрисовку по отдельности. Интеграционный тест проверяет, что они правильно соединены: именно на стыках прячутся ошибки вроде «кнопка повтора вызывает не ту функцию».

Решение и разбор
// catalog.ts
type Product = { id: string; title: string };
type Api = { getProducts(): Promise<Product[]> };

export function mountCatalog(root: HTMLElement, api: Api): Promise<void> {
  async function load(): Promise<void> {
    root.setAttribute('aria-busy', 'true');
    root.replaceChildren(Object.assign(document.createElement('p'), { textContent: 'Загрузка…' }));
    try {
      const products = await api.getProducts();
      root.replaceChildren(...products.map((p) => Object.assign(document.createElement('article'), { textContent: p.title })));
    } catch (error) {
      const retry = Object.assign(document.createElement('button'), { type: 'button', textContent: 'Повторить' });
      retry.addEventListener('click', () => void load());
      root.replaceChildren(Object.assign(document.createElement('p'), { textContent: `Ошибка: ${(error as Error).message}` }), retry);
    } finally {
      root.removeAttribute('aria-busy');
    }
  }
  return load();
}
// catalog.test.ts
// @vitest-environment jsdom
import { expect, it, vi } from 'vitest';
import { mountCatalog } from './catalog.js';

it('ошибка → Повторить → товары', async () => {
  const getProducts = vi
    .fn()
    .mockRejectedValueOnce(new Error('нет сети'))
    .mockResolvedValueOnce([{ id: 'g1', title: 'Каркассон' }]);
  const root = document.createElement('section');

  await mountCatalog(root, { getProducts });
  expect(root.textContent).toContain('Ошибка: нет сети');

  root.querySelector('button')!.click();
  await vi.waitFor(() => expect(root.querySelector('article')?.textContent).toBe('Каркассон'));
  expect(getProducts).toHaveBeenCalledTimes(2);
  expect(root.hasAttribute('aria-busy')).toBe(false);
});

mockRejectedValueOnce и mockResolvedValueOnce задают сценарий ответов по порядку: сначала сбой, потом успех. vi.waitFor повторяет проверку, пока она не пройдёт или не кончится время: клик запускает асинхронную загрузку, и тест ждёт её результата, а не фиксированную паузу. Это ровно правило «ждите событие, а не время».
