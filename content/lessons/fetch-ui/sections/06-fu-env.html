Адрес API: переменные окружения Vite

Адрес API на вашем компьютере и на хостинге разный. Vite подставляет в код переменные с префиксом VITE_ из файлов .env, .env.local и других: import.meta.env.VITE_API_URL. Префикс защищает от случайной утечки: переменные без него в браузерный код не попадают (из документации Vite).

Всё, что попало в браузерный код, видит любой пользователь. Ключи и секреты в VITE_* не кладут — ни в какие. Секрет живёт только на сервере.

Альтернатива CORS при разработке — прокси dev-сервера Vite: в vite.config.ts указывают server.proxy: { '/api': 'http://localhost:3000' }, и фронтенд обращается к /api/... на своём же origin, а Vite пересылает запрос серверу (из документации Vite, в этой работе не запускалось). На хостинге тогда нужна та же схема: общий домен или настройка прокси на сервере.

Задача 16. Адрес API из окружения ★☆☆ разминка

Напишите apiUrl(env): берёт env.VITE_API_URL, по умолчанию — http://localhost:3000; убирает слэш в конце; если значение не начинается с http:// или https://, бросает ошибку с названием переменной. В приложении вызывается как apiUrl(import.meta.env).

Зачем: опечатка в переменной окружения на хостинге («localhost:3000» без схемы) даёт загадочные ошибки запросов. Проверка при старте с понятным текстом экономит час отладки. Параметр env делает функцию тестируемой без настоящего Vite.

Решение и разбор
// env.ts
export function apiUrl(env: Record<string, string | undefined>): string {
  const value = env.VITE_API_URL ?? 'http://localhost:3000';
  if (!/^https?:\/\//.test(value)) {
    throw new Error(`VITE_API_URL должен начинаться с http:// или https://, получено "${value}"`);
  }
  return value.replace(/\/+$/, '');
}

Это та же идея, что loadConfig на сервере: настройки проверяются в одном месте при старте. Помните, что значение VITE_API_URL попадёт в собранный код и будет видно любому пользователю. Для адреса API это нормально, для ключей — нет.
