npm и package.json

npm (node package manager) — менеджер пакетов: он скачивает чужие библиотеки из реестра npmjs.com и следит за их версиями. Альтернативы с теми же идеями — pnpm и yarn.

package.json

Паспорт проекта. Создаётся командой npm init -y (-y — согласиться со всеми вопросами). Основные поля (документация):

{
  "name": "todo-api",
  "version": "1.0.0",
  "type": "module",
  "scripts": {
    "dev": "node --watch --env-file=.env src/server.js",
    "start": "node src/server.js",
    "test": "node --test"
  },
  "dependencies": {
    "express": "^5.3.0",
    "mongoose": "^8.24.9"
  },
  "devDependencies": {
    "eslint": "^9.0.0"
  }
}
  • dependencies — то, что нужно программе для работы (Express, Mongoose). Ставятся: npm install express.
  • devDependencies — только для разработки: линтеры, тесты, сборщики. Ставятся: npm install -D eslint.
  • scripts — команды проекта. Запуск: npm run dev. Для start и test слово run можно опустить: npm start, npm test.

Задача 5. Скрипты проекта ★☆☆ разминка

Создайте package.json для каталога: тип модулей ES, скрипт dev перезапускает src/server.js при изменениях и читает .env, start просто запускает сервер, test запускает встроенный runner. Express — в зависимостях, ESLint — в dev-зависимостях.

Зачем: package.json — инструкция для людей и машин: как запустить, проверить и собрать проект. Новичок в команде набирает npm run dev и не спрашивает, какие флаги нужны.

Решение и разбор
// package.json
{
  "name": "catalog-api",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "scripts": {
    "dev": "node --watch --env-file=.env src/server.js",
    "start": "node src/server.js",
    "test": "node --test"
  },
  "dependencies": {
    "express": "^5.3.0"
  },
  "devDependencies": {
    "eslint": "^9.0.0"
  }
}

start без --env-file намеренно: на хостинге переменные задают в настройках сервиса, а файла .env там нет. "private": true защищает от случайной публикации пакета в npm. Версии лучше не писать руками, а получить командами npm i express и npm i -D eslint.

Версии: что значат ^ и ~

Версии пакетов записывают по правилам семантического версионирования: МАЖОРНАЯ.МИНОРНАЯ.ПАТЧ. Патч — исправления ошибок, минорная — новые возможности без поломок, мажорная — изменения, которые могут сломать ваш код (Express 4 → 5).

  • ^5.3.0 — любая 5.x.x не ниже 5.3.0. Это вариант по умолчанию.
  • ~5.3.0 — только патчи: 5.3.x.
  • 5.3.0 — ровно эта версия.

Задача 6. Проверка диапазона ^ ★★☆ практика

Напишите satisfiesCaret(version, range) для диапазонов вида ^5.3.0 и мажорной версии от 1: версия подходит, если мажорная часть та же, а сама версия не меньше указанной. Добавьте satisfiesTilde для ~5.3.0. Проверьте на 5.3.0, 5.10.1, 6.0.0, 5.2.9.

Зачем: «почему у меня поставилась 5.10, а не 5.3» — частый вопрос. Написав проверку диапазона сами, вы поймёте, что ^ разрешает новые возможности, но не ломающие изменения. Заодно увидите, почему версии сравнивают как числа, а не как строки.

Подсказка

Разбейте версию на три числа: v.split('.').map(Number). Строки сравнивать нельзя: '5.10.1' < '5.3.0' истинно.

Решение и разбор
// semver.mjs
const parse = (v) => v.split('.').map(Number);

function compare(a, b) {
  for (let i = 0; i < 3; i++) if (a[i] !== b[i]) return a[i] - b[i];
  return 0;
}

export function satisfiesCaret(version, range) {
  const v = parse(version);
  const min = parse(range.slice(1));
  return v[0] === min[0] && compare(v, min) >= 0;
}

export function satisfiesTilde(version, range) {
  const v = parse(version);
  const min = parse(range.slice(1));
  return v[0] === min[0] && v[1] === min[1] && compare(v, min) >= 0;
}

compare идёт слева направо и возвращает разницу в первой отличающейся части: мажорная важнее минорной, минорная важнее патча. Сравнение строк дало бы неверный ответ: '1' < '3', поэтому '5.10.1' оказалась бы «меньше» '5.3.0'. Наша функция упрощена: у настоящего ^0.x особые правила, а ещё бывают пре-релизы (5.0.0-beta). В проектах для этого берут пакет semver (из общих знаний).

node_modules и package-lock.json

Пакеты скачиваются в папку node_modules, вместе с их собственными зависимостями — поэтому она бывает огромной. В git её не добавляют (строка в .gitignore): её всегда можно восстановить командой npm install.

Файл package-lock.json записывает точные версии всего дерева пакетов. Его в git добавляют: так у всех разработчиков и на сервере стоят одинаковые версии. На сервере и в CI (автоматической проверке, которая запускается на сервере при каждом пуше в репозиторий) ставят командой npm ci — строго по lock-файлу.

npx

npx запускает команду из пакета: из node_modules/.bin проекта, а если её там нет — скачивает пакет во временную папку. npx eslint . вызывает локальный ESLint. С незнакомыми пакетами осторожнее: npx что-то скачает и выполнит чужой код с вашими правами.
