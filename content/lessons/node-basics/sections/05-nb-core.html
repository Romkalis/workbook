process, .env, файлы, пути и события

process

Глобальный объект process описывает запущенную программу:

  • process.argv — аргументы командной строки. node app.js --port 4000 даёт массив, где первые два элемента — путь к node и к файлу, дальше ваши аргументы.
  • process.env — переменные окружения (следующий подраздел).
  • process.exit(1) — завершить программу. Код 0 означает успех, любой другой — ошибку; по нему скрипты и CI понимают, что что-то пошло не так.
  • process.cwd() — папка, из которой запустили программу (не обязательно папка файла).
  • process.version, process.platform — версия Node.js и система: у нас вывело v22.23.2 darwin.

Переменные окружения и .env

Переменные окружения — настройки, которые передаются программе снаружи, а не пишутся в коде: порт, адрес базы данных, секретные ключи. Один и тот же код запускают на ноутбуке и на сервере с разными значениями. А секреты не попадают в git (документация).

Локально их удобно держать в файле .env в корне проекта:

PORT=4000
MONGO_URI=mongodb://localhost:27017/todo
JWT_SECRET=длинная-случайная-строка

Прочитать его можно двумя способами:

  • Встроенный флаг (Node.js 20.6+): node --env-file=.env app.js.
  • Пакет dotenv, как в уроке о JWT: require('dotenv').config() в самом начале программы.

Проверка: node --env-file=.env -e "console.log(process.env.PORT, typeof process.env.PORT)" вывела 4000 string. Все значения в process.env — строки, числа и логические значения нужно преобразовать: Number(process.env.PORT) || 3000. Файл .env всегда добавляют в .gitignore, а в репозиторий кладут .env.example — файл-образец с названиями переменных без настоящих значений.

Файлы: fs

Модуль fs (file system) работает с файлами. У большинства функций три вида: с колбэком (fs.readFile), синхронный (fs.readFileSync) и на промисах (fs/promises). В новом коде берите промисы, а синхронные — только в коротких скриптах: пока файл читается синхронно, сервер не отвечает никому.

import { readFile, writeFile } from 'node:fs/promises';
import path from 'node:path';

const file = path.join(import.meta.dirname, 'notes.txt');
await writeFile(file, 'первая строка\n', 'utf8');
console.log(await readFile(file, 'utf8')); // первая строка

try {
  await readFile(path.join(import.meta.dirname, 'nope.txt'), 'utf8');
} catch (error) {
  console.log(error.code); // ENOENT — такого файла нет
}

Без второго аргумента 'utf8' readFile вернёт не строку, а Buffer — набор байтов. Ошибки Node.js имеют свойство code: ENOENT (нет файла), EACCES (нет прав), EADDRINUSE (порт занят) — по нему удобно ветвиться, как учил урок об обработке ошибок.

Пути: path

Пути в Windows пишутся через \, в macOS и Linux через /. Модуль path собирает их правильно для любой системы, поэтому строки руками не склеивают:

  • path.join('src', 'routes', 'todos.js') → src/routes/todos.js.
  • path.resolve('public') → абсолютный путь от папки запуска.
  • path.extname('photo.final.jpg') → .jpg; path.basename(file) → имя файла.

Относительные пути в readFile('data.json') считаются от process.cwd(), а не от файла с кодом. Запустили из другой папки — файл «пропал». Надёжнее строить путь от import.meta.dirname или __dirname.

События: EventEmitter

Многие объекты Node.js (сервер, потоки, процесс) сообщают о происходящем через события, как кнопки в браузере. Основа — класс EventEmitter:

const { EventEmitter } = require('node:events');

const shop = new EventEmitter();
shop.on('order', (id) => console.log('новый заказ', id));
shop.emit('order', 42);
console.log('после emit');
// новый заказ 42
// после emit

on подписывается, emit вызывает всех подписчиков — синхронно, сразу. Если у эмиттера случилось событие 'error', а подписчика на него нет, программа упадёт, поэтому на 'error' подписываются всегда.
