Модули: CommonJS и ES-модули

Модуль — файл со своей областью видимости: переменные внутри не видны снаружи, пока их явно не экспортировали. В Node.js две системы модулей. Новый код пишут на ES-модулях, но CommonJS вы встретите в половине туториалов и старых проектов, включая урок о JWT.

CommonJS: require и module.exports

Исторически первая система Node.js (документация):

// math.js
function sum(a, b) {
  return a + b;
}
module.exports = { sum };

// cjs.js
const { sum } = require('./math');
const path = require('node:path');
console.log(sum(2, 3));            // 5
console.log(path.basename(__filename)); // cjs.js

require загружает файл синхронно, выполняет его один раз и кеширует: второй require того же файла вернёт тот же объект. Расширение .js можно не писать. Внутри модуля доступны __filename (полный путь к файлу) и __dirname (папка файла).

Задача 2. Модуль CommonJS и кеш require ★☆☆ разминка

Создайте counter.cjs: внутри переменная count и экспорт функций increment() и value(). В main.cjs подключите модуль дважды под разными именами (a и b), вызовите a.increment() и выведите b.value(). Объясните результат.

Зачем: кеш модулей — основа того, как в Node.js живут «одиночки»: подключение к базе, конфигурация, логгер. Модуль выполняется один раз, и все, кто его подключил, видят одно и то же состояние.

Решение и разбор
// counter.cjs
let count = 0;
module.exports = {
  increment() {
    count += 1;
  },
  value() {
    return count;
  },
};
// main.cjs
const a = require('./counter.cjs');
const b = require('./counter.cjs');

a.increment();
console.log(b.value()); // 1
console.log(a === b); // true

Второй require не выполняет файл заново, а возвращает тот же объект из кеша, поэтому b.value() равно 1, а a === b. Расширение .cjs делает файл CommonJS-модулем независимо от "type" в package.json. В проекте с "type": "module" это единственный способ написать require в файле.

ES-модули: import и export

Стандарт языка, тот же, что в браузере (learn.javascript.ru, документация Node.js):

// math.mjs
export function sum(a, b) {
  return a + b;
}
export default function greet(name) {
  return `Привет, ${name}`;
}

// main.mjs
import greet, { sum } from './math.mjs';
console.log(greet('Аня'), sum(1, 2)); // Привет, Аня 3
console.log(import.meta.dirname);     // папка текущего файла

Node.js считает файл ES-модулем, если у него расширение .mjs или в ближайшем package.json написано "type": "module". Иначе .js — это CommonJS. Отличия, о которые спотыкаются:

  • В ESM путь пишут полностью, с расширением: './math.js', а не './math'.
  • В ESM нет __dirname и __filename. Вместо них import.meta.dirname и import.meta.filename (Node.js 20.11+).
  • В ESM можно писать await на верхнем уровне файла, вне функции.
  • Смешивать require и import в одном файле нельзя.

Встроенные модули принято подключать с префиксом node: — 'node:fs', 'node:path'. Так сразу видно, что это часть Node.js, а не пакет из npm с похожим именем.

Задача 3. Перевод на ES-модули ★☆☆ разминка

Перепишите модуль цен на ES-модули: price.mjs экспортирует по умолчанию formatPrice(kopecks) (строка "1500.00 ₽") и именованную константу CURRENCY = '₽'. В main.mjs импортируйте оба и выведите цену и путь к папке файла.

const CURRENCY = '₽';
function formatPrice(kopecks) {
  return `${(kopecks / 100).toFixed(2)} ${CURRENCY}`;
}
module.exports = { formatPrice, CURRENCY };
console.log(__dirname);

Зачем: новый код в Node.js и весь код в браузере пишут на ES-модулях: одна система модулей для фронтенда и бэкенда, статический анализ импортов, top-level await. Переводить старые файлы придётся часто.

Решение и разбор
// price.mjs
export const CURRENCY = '₽';

export default function formatPrice(kopecks) {
  return `${(kopecks / 100).toFixed(2)} ${CURRENCY}`;
}
// main.mjs
import formatPrice, { CURRENCY } from './price.mjs';

console.log(formatPrice(150000), CURRENCY);
console.log(import.meta.dirname);

Путь пишется полностью, с расширением: './price.mjs'. В ESM нет __dirname, его заменяет import.meta.dirname. Импорт по умолчанию можно назвать как угодно, именованный — только именем экспорта (или через as).

Задача 4. await на верхнем уровне ★★☆ практика

Напишите show-products.mjs: он читает products.json (лежит рядом с файлом) через fs/promises с await прямо на верхнем уровне файла, без обёртки-функции, и печатает число товаров.

// products.json
[
  { "id": 1, "title": "Чистый код", "category": "books", "price": 150000 },
  { "id": 2, "title": "Каркассон", "category": "games", "price": 249000 },
  { "id": 3, "title": "Грокаем алгоритмы", "category": "books", "price": 99000 }
]

Зачем: в скриптах и при старте сервера (прочитать конфиг, подключиться к базе) top-level await избавляет от обёрток async function main() и делает порядок шагов очевидным. Работает только в ES-модулях.

Решение и разбор
// show-products.mjs
import { readFile } from 'node:fs/promises';
import path from 'node:path';

const file = path.join(import.meta.dirname, 'products.json');
const products = JSON.parse(await readFile(file, 'utf8'));
console.log(`Товаров: ${products.length}`);

Путь собран от import.meta.dirname, поэтому скрипт работает из любой папки. В CommonJS такой код был бы синтаксической ошибкой: await вне функции там запрещён.
