Модули: CommonJS и ES-модули

Модуль — файл со своей областью видимости: переменные внутри не видны снаружи, пока их явно не экспортировали. В Node.js две системы модулей. Новый код пишут на ES-модулях, но CommonJS вы встретите в половине туториалов и старых проектов, включая урок о JWT.

CommonJS: require и module.exports

Исторически первая система Node.js (документация):

// math.js
function sum(a, b) {
  return a + b;
}
module.exports = { sum };

// cjs.js
const { sum } = require('./math');
const path = require('node:path');
console.log(sum(2, 3));            // 5
console.log(path.basename(__filename)); // cjs.js

require загружает файл синхронно, выполняет его один раз и кеширует: второй require того же файла вернёт тот же объект. Расширение .js можно не писать. Внутри модуля доступны __filename (полный путь к файлу) и __dirname (папка файла).

ES-модули: import и export

Стандарт языка, тот же, что в браузере (learn.javascript.ru, документация Node.js):

// math.mjs
export function sum(a, b) {
  return a + b;
}
export default function greet(name) {
  return `Привет, ${name}`;
}

// main.mjs
import greet, { sum } from './math.mjs';
console.log(greet('Аня'), sum(1, 2)); // Привет, Аня 3
console.log(import.meta.dirname);     // папка текущего файла

Node.js считает файл ES-модулем, если у него расширение .mjs или в ближайшем package.json написано "type": "module". Иначе .js — это CommonJS. Отличия, о которые спотыкаются:

  • В ESM путь пишут полностью, с расширением: './math.js', а не './math'.
  • В ESM нет __dirname и __filename. Вместо них import.meta.dirname и import.meta.filename (Node.js 20.11+).
  • В ESM можно писать await на верхнем уровне файла, вне функции.
  • Смешивать require и import в одном файле нельзя.

Встроенные модули принято подключать с префиксом node: — 'node:fs', 'node:path'. Так сразу видно, что это часть Node.js, а не пакет из npm с похожим именем.
