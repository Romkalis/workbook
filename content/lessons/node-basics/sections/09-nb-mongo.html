MongoDB и Mongoose

Данные в массиве пропадают при перезапуске. Их хранят в базе данных — отдельной программе, которая надёжно сохраняет данные на диск и быстро ищет их.

MongoDB

MongoDB — документная база данных. Данные в ней похожи на объекты JavaScript:

  • Документ — одна запись, объект вроде { "title": "Купить молоко", "done": false }. У каждого есть уникальный _id типа ObjectId — 24 шестнадцатеричных символа (цифры 0–9 и буквы a–f), например 664f2a1b2c3d4e5f6a7b8c9d.
  • Коллекция — набор документов одного вида (todos, users), аналог таблицы.
  • База — набор коллекций одного приложения.

В отличие от реляционных баз с языком запросов SQL (PostgreSQL, MySQL), где данные лежат в таблицах со строго заданными столбцами, MongoDB не требует заранее описывать структуру таблиц. Свобода опасна: в коллекцию можно случайно записать что угодно. Поэтому структуру задают на уровне приложения через Mongoose.

Где взять базу: поставить MongoDB Community локально, запустить в Docker — программе, которая запускает приложения в изолированных контейнерах (docker run -p 27017:27017 mongo) или создать бесплатный кластер в облаке MongoDB Atlas. Адрес подключения кладут в переменную окружения MONGO_URI.

Mongoose: схема и модель

Mongoose — библиотека, которая добавляет к MongoDB схемы, проверку данных и удобные методы. Установка: npm install mongoose.

const mongoose = require('mongoose');

const todoSchema = new mongoose.Schema(
  {
    title: { type: String, required: true, trim: true, maxlength: 200 },
    done: { type: Boolean, default: false },
  },
  { timestamps: true },
);

const Todo = mongoose.model('Todo', todoSchema);
  • Схема описывает поля: тип, обязательность (required), значение по умолчанию (default), обработку (trim убирает пробелы по краям), ограничения (maxlength, min, enum, unique).
  • timestamps: true сам добавляет поля createdAt и updatedAt.
  • Модель — класс для работы с коллекцией. Из имени 'Todo' Mongoose делает имя коллекции todos.

Проверено без базы: new Todo({ title: ' Купить молоко ' }) дал title «Купить молоко» без пробелов, done: false и готовый _id типа ObjectId. Документ без title не прошёл проверку: ValidationError с видом ошибки required у поля title (документация по валидации).

Подключение и операции

await mongoose.connect(process.env.MONGO_URI);

const todo = await Todo.create({ title: 'Купить молоко' }); // создать
const all = await Todo.find({ done: false });                // найти по условию
const one = await Todo.findById(id);                         // по _id, или null
const updated = await Todo.findByIdAndUpdate(
  id,
  { done: true },
  { new: true, runValidators: true },                        // вернуть новую версию и проверить
);
await Todo.findByIdAndDelete(id);                            // удалить

Все методы асинхронные, поэтому await. Тонкости, на которых спотыкаются:

  • findById не находит документ — возвращает null, а не бросает ошибку. Проверяйте и отвечайте 404.
  • Если id вообще не похож на ObjectId (например, '123'), будет CastError. Проверка заранее: mongoose.isValidObjectId('123') вернул false, а для 24-символьной строки — true.
  • Без { new: true } findByIdAndUpdate возвращает документ до изменения, а без runValidators не проверяет схему.
  • ValidationError — это ошибка данных клиента, отвечать на неё нужно 400, а не 500.

Маршрут с базой вместо массива:

app.get('/api/todos/:id', async (req, res) => {
  if (!mongoose.isValidObjectId(req.params.id)) {
    return res.status(400).json({ error: 'Неверный id' });
  }
  const todo = await Todo.findById(req.params.id);
  if (!todo) return res.status(404).json({ error: 'Задача не найдена' });
  res.json(todo);
});

Этот фрагмент повторяет проверенный выше маршрут, но с запросом к базе; с настоящей MongoDB при подготовке урока он не запускался.

Пароли не хранят как есть

Если в модели есть пароль, его сохраняют только в виде хеша — необратимого отпечатка, по которому можно проверить пароль, но нельзя его восстановить (библиотека bcrypt). Как это делается в хуке модели перед сохранением — в уроке «JWT-авторизация».
