Подготовка и запуск тестов

Форк, клон, установка

  1. Поставьте Node.js 22 LTS или новее. В package.json указано "engines": { "node": ">=22" }: тесты запускаются встроенным раннером node --test, Jest и Mocha не нужны. Если на проверке окажется функция, которой нет в Node 22, сдача может сломаться.
  2. Сделайте форк AlreadyBored/basic-js-ds в свой GitHub (кнопка Fork).
  3. Склонируйте свой форк: git clone https://github.com/<ваш-логин>/basic-js-ds.
  4. cd basic-js-ds, затем npm install. Сторонних зависимостей в проекте нет, команда в основном проверяет версию Node.
  5. npm run test. Это node --test --test-reporter tap: Node найдёт файлы в папке test/ и выведет отчёт в формате TAP.

Как читать отчёт

Заготовки методов бросают NotImplementedError. Обёртка test из lib/ ловит именно эту ошибку и помечает тест как todo с текстом «Pending: …». Поэтому в начале вы увидите много pending и ни одного fail. Как только вы удалили строку throw new NotImplementedError(...), тест начинает проверяться по-настоящему и становится pass или fail.

Внизу отчёта есть сводка: # pass, # fail, # todo. Цель — ноль fail и ноль todo. Чтобы запустить один файл, передайте его путь: node --test test/stack.test.js.

Лимит 30 секунд

Каждый тест должен укладываться в 30 секунд. Превысить лимит можно только бесконечным циклом. Чаще всего это while, в котором забыли сдвинуть указатель (current = current.next). Если отчёт завис, ищите такой цикл.

Читайте тесты, а не только README

README описывает задачу словами, а тесты точно говорят, что считается правильным. Откройте test/queue.test.js и посмотрите, чем сравнивают результат. Там стоит assert.deepStrictEqual, и из-за этого меняется решение очереди (см. ловушку). Ещё из тестов видно, что пустой стек и пустая очередь должны вернуть undefined, а пустое дерево — null из root(), min() и max().
