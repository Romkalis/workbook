Проверка перед сдачей

Чек-лист

  • npm run test: в сводке # fail 0 и # todo 0. Ни одной строки throw new NotImplementedError не осталось.
  • Node 22 или новее. Не используйте возможности, которых нет в Node 22.
  • Экспорт не тронут: module.exports = { Stack } и так далее. Тесты импортируют классы именно по этим именам.
  • Пустые случаи: pop, peek, dequeue → undefined; root, min, max, find → null.
  • Ничего лишнего в консоли: отладочные console.log удалены.
  • Изменения закоммичены и отправлены в ваш форк: git push origin main.

Сдача в RS App

  1. Откройте app.rs.school и войдите.
  2. Перейдите на страницу сдачи задач.
  3. Выберите задание BasicJS Data Structures.
  4. Нажмите кнопку отправки. Проверяющая система сама склонирует ваш форк и прогонит тесты.

Если локально всё зелёное, а в RS App нет, сначала проверьте, что изменения действительно запушены в репозиторий с именем basic-js-ds в вашем аккаунте. Затем сравните версию Node и посмотрите, нет ли в решении долгого или бесконечного цикла.

Если хочется больше практики

Задания, которые не проверяются тестами, но хорошо закрепляют материал (из общих знаний):

  • Добавить в стек и очередь геттер size за O(1) — заведите счётчик.
  • Написать в дереве обход inOrder(), который возвращает отсортированный массив значений.
  • Переписать add рекурсивно и сравнить, что читается проще.
  • Написать removeKFromList рекурсивно: l.next = removeKFromList(l.next, k). Почему на списке из 100 000 узлов эта версия может упасть?
