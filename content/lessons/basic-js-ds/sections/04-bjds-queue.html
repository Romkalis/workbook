Queue: очередь на связном списке

Очередь работает по правилу FIFO: первым пришёл — первым ушёл. Добавляем в хвост, забираем из головы. Задание требует построить очередь на связном списке, а не на массиве: getUnderlyingList() должен вернуть сам список, то есть его первый узел.

Чтобы обе операции были O(1), храним две ссылки: head на первый узел и tail на последний. Без tail для добавления пришлось бы каждый раз идти до конца списка, это O(n).

class Queue {
  #head = null;
  #tail = null;

  getUnderlyingList() {
    return this.#head;
  }

  enqueue(value) {
    const node = { value, next: null };
    if (this.#tail) {
      this.#tail.next = node;
    } else {
      this.#head = node;
    }
    this.#tail = node;
  }

  dequeue() {
    if (!this.#head) return undefined;
    const { value } = this.#head;
    this.#head = this.#head.next;
    if (!this.#head) this.#tail = null;
    return value;
  }
}

module.exports = { Queue };

Строка if (!this.#head) this.#tail = null выглядит лишней, но без неё после опустошения tail продолжит указывать на удалённый узел. Следующий enqueue прицепит новый элемент к нему, а head останется null, и элемент пропадёт.

Ловушка: ListNode и deepStrictEqual

В заготовке и README написано «используйте ListNode из extensions». Но тест сравнивает результат так:

assert.deepStrictEqual(queue.getUnderlyingList(), {
  value: 1,
  next: { value: 2, next: { value: 3, next: null } },
});

deepStrictEqual сравнивает не только поля, но и прототипы объектов. Узел, созданный через new ListNode(1), имеет прототип ListNode.prototype, а литерал { value: 1, next: null } — Object.prototype. Поля совпадают, а тест падает. Проверка в Node.js 22:

const assert = require('node:assert');
class ListNode {
  constructor(x) { this.value = x; this.next = null; }
}
assert.deepEqual(new ListNode(1), { value: 1, next: null });       // проходит
assert.deepStrictEqual(new ListNode(1), { value: 1, next: null }); // AssertionError

Поэтому в решении выше узлы — обычные объекты { value, next: null }. Форма у них та же, что у ListNode, так что требование «очередь на связном списке» выполнено. Тесты я проверял на копии их утверждений (версия репозитория от 28 июня 2026 года, коммит a87c2a8).
