Zod во фронтенде

Две точки применения. Ответы API: z.array(Product).parse(await res.json()) заменяет ручной isProduct из клиента shop-web — короче, и при ошибке в сообщении видно, какое поле какого товара не подошло. Формы: схема плюс z.flattenError дают объект «поле → сообщение», который прямо подходит для функции показа ошибок из урока о формах.

Цена — размер: Zod добавляет в бандл десятки килобайт (из общих знаний; точная цифра зависит от версии и того, что импортировано). Для маленькой страницы это заметно; для приложения с десятком форм и API обычно окупается. У Zod 4 есть облегчённый вариант zod/mini с функциональным синтаксисом (из документации Zod, в этой работе не проверялся).

Задача 18. Проверка ответа API схемой ★★☆ практика

Перепишите getProducts из клиента shop-web на Zod: ответ проверяется z.array(Product), а при несоответствии бросается TypeError, в сообщении которого есть prettifyError, то есть видно, какое поле какого товара не подошло.

Зачем: когда сервер меняет формат, фронтенд должен падать с понятной ошибкой у входа, а не с undefined где-то в отрисовке. Сообщение с путём («at [3].price») экономит полчаса поиска в devtools.

Решение и разбор
// client.ts
import { z } from 'zod';

export const Product = z.object({
  id: z.string(),
  title: z.string(),
  category: z.enum(['books', 'games', 'home']),
  price: z.number().int(),
});
export type Product = z.infer<typeof Product>;

const ProductList = z.array(Product);

export async function getProducts(baseUrl: string, fetchFn: typeof fetch = fetch): Promise<Product[]> {
  const res = await fetchFn(new URL('/api/products', baseUrl));
  if (!res.ok) throw new Error(`Сервер ответил ${res.status}`);
  const result = ProductList.safeParse(await res.json());
  if (!result.success) throw new TypeError(`Неожиданный ответ сервера:\n${z.prettifyError(result.error)}`);
  return result.data;
}

Ручная функция isProduct исчезла, а тип Product теперь выводится из схемы. Если сервер начнёт отдавать новое поле rating, проверка не сломается: z.object его отбросит. Если поле нужно, его добавляют в схему, и тип появится сам. Это мягкая совместимость: сервер может добавлять поля, не ломая клиентов.

Задача 19. Форма отзыва на схеме ★★☆ практика

Соедините схему отзыва, FormData и показ ошибок: handleReviewSubmit(form, onValid) на submit собирает поля, приводит оценку к числу (z.coerce), проверяет схемой и либо вызывает onValid(данные), либо ставит у полей aria-invalid и текст ошибки в #<поле>-error.

Зачем: это та же форма из урока о событиях, но правила теперь описаны декларативно, а не десятком if. И ту же схему можно импортировать на сервер, чтобы проверка была единой.

Решение и разбор
// review-form.ts
import { z } from 'zod';

export const ReviewForm = z.object({
  author: z.string().trim().min(1, 'Укажите имя'),
  rating: z.coerce.number().int().min(1, 'Оценка от 1 до 5').max(5, 'Оценка от 1 до 5'),
  text: z.string().trim().min(10, 'Отзыв — хотя бы 10 символов'),
});
export type ReviewForm = z.infer<typeof ReviewForm>;

export function handleReviewSubmit(form: HTMLFormElement, onValid: (r: ReviewForm) => void): void {
  form.addEventListener('submit', (event) => {
    event.preventDefault();
    const result = ReviewForm.safeParse(Object.fromEntries(new FormData(form)));
    const errors: Partial<Record<string, string[]>> = result.success ? {} : z.flattenError(result.error).fieldErrors;
    for (const field of form.querySelectorAll<HTMLInputElement | HTMLTextAreaElement>('[name]')) {
      const message = errors[field.name]?.[0];
      field.toggleAttribute('aria-invalid', Boolean(message));
      const box = form.querySelector(`#${field.name}-error`);
      if (box) box.textContent = message ?? '';
    }
    if (result.success) onValid(result.data);
  });
}

Object.fromEntries(new FormData(form)) превращает форму в объект строк, это ровно вход для схемы. z.coerce.number() здесь безопасен: поле оценки в форме — select или number с required, а пустая строка всё равно не пройдёт min(1), превратившись в 0. В отличие от фильтров, тут 0 — не «нет значения», а ошибка, и это правильное поведение.
