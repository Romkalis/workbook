Преобразования и свои правила

Строки из адреса и форм

Всё, что приходит из query string и FormData, — строки. z.coerce.number() сначала превращает значение в число (через Number(x)), потом проверяет:

import { z } from 'zod';

export const Query = z.object({
  page: z.coerce.number().int().min(1).default(1),
  maxPrice: z.coerce.number().int().nonnegative().optional(),
});
// Query.parse({ page: '3' }) → { page: 3 }
// Query.parse({}) → { page: 1 }

Ловушка: Number('') равно 0, поэтому z.coerce.number() пропустит пустую строку как ноль. ?maxPrice= превратится в «цена до 0 рублей». Пустые значения сначала превращают в undefined (задача ниже показывает как), и только потом приводят к числу.

Задача 9. Параметры адреса без ловушки пустой строки ★★☆ практика

Схема параметров каталога: page — целое от 1, по умолчанию 1; minPrice, maxPrice — необязательные целые от 0; sort — price-asc или price-desc, необязательный. Пустая строка в любом параметре должна значить «не задано», а не 0 или ошибку. Используйте z.preprocess.

Зачем: форма фильтров отправляет пустые поля как ?maxPrice=. С голым z.coerce.number() это «цена до 0 рублей», и каталог внезапно пуст. Предварительная обработка превращает «пусто» в «нет значения», и дальше работают обычные правила.

Подсказка

z.preprocess(fn, schema) вызывает fn с исходным значением, а результат передаёт в схему.

Решение и разбор
// query.ts
import { z } from 'zod';

const emptyToUndefined = (v: unknown) => (v === '' ? undefined : v);
const optionalInt = (min: number) => z.preprocess(emptyToUndefined, z.coerce.number().int().min(min).optional());

export const CatalogQuery = z.object({
  page: z.preprocess(emptyToUndefined, z.coerce.number().int().min(1).default(1)),
  minPrice: optionalInt(0),
  maxPrice: optionalInt(0),
  sort: z.preprocess(emptyToUndefined, z.enum(['price-asc', 'price-desc']).optional()),
});

export type CatalogQuery = z.infer<typeof CatalogQuery>;

Помощники emptyToUndefined и optionalInt — обычные функции, которые собирают схемы, и это нормальный способ убрать повторение. С ?page=&maxPrice=&sort= получится { page: 1 }, а ?maxPrice=abc по-прежнему ошибка: Number('abc') — NaN, и проверка числа её отклонит.

refine: правило для нескольких полей

Встроенных проверок не хватает, когда правило связывает поля: «пароли совпадают», «адрес обязателен для курьера». .refine(функция, { message, path }) добавляет своё правило; path говорит, у какого поля показать ошибку:

import { z } from 'zod';

export const SignUp = z
  .object({ password: z.string().min(8, 'Минимум 8 символов'), confirm: z.string() })
  .refine((d) => d.password === d.confirm, { message: 'Пароли не совпадают', path: ['confirm'] });

Задача 10. Адрес обязателен для курьера ★★☆ практика

Схема оформления: delivery — courier или pickup; address — необязательная строка. Через refine сделайте адрес обязательным для курьера и покажите ошибку у поля address. Сравните с ручной версией из задачи «Проверка формы заказа».

Зачем: правила «если A, то нужно B» встроенными проверками не выразить. refine с path добавляет такое правило и сообщает об ошибке у нужного поля, так что форма покажет её в правильном месте.

Решение и разбор
// checkout.ts
import { z } from 'zod';

export const Checkout = z
  .object({
    delivery: z.enum(['courier', 'pickup'], { error: 'Выберите способ получения' }),
    address: z.string().trim().optional(),
  })
  .refine((d) => d.delivery !== 'courier' || (d.address !== undefined && d.address !== ''), {
    message: 'Для курьера нужен адрес',
    path: ['address'],
  });

refine выполняется после проверки полей, поэтому внутри d.delivery уже точно один из двух вариантов. Если поля не прошли, refine не запускается, и пользователь сначала увидит базовые ошибки. Альтернатива — размеченное объединение двух схем (следующая задача про discriminatedUnion), тогда адрес будет в типе только у курьера.

transform: превратить после проверки

.transform(fn) меняет проверенное значение: строку "1500.50" в копейки, "a, b" в массив тегов. Тип результата меняется вместе с ним: z.infer покажет тип после преобразования, а z.input — до. Это полезно, когда формат передачи (строка в форме) отличается от формата в программе (число).

Задача 11. Цена из поля ввода в копейки ★★☆ практика

Схема RubleInput: принимает строку вида "1500", "1500,5", "1 500.50" (пробелы и запятая допустимы), проверяет формат «рубли и до двух знаков копеек» и превращает в целое число копеек. Выведите входной и выходной типы.

Зачем: формат передачи (строка в поле) и формат хранения (целые копейки) разные, и преобразование между ними — частый источник ошибок округления. Схема проверяет формат и преобразует в одном месте, а z.input/z.output показывают обе стороны.

Решение и разбор
// money.ts
import { z } from 'zod';

export const RubleInput = z
  .string()
  .transform((s) => s.replace(/\s/g, '').replace(',', '.'))
  .pipe(z.string().regex(/^\d+(\.\d{1,2})?$/, 'Цена: рубли и до двух знаков копеек'))
  .transform((s) => {
    const [rub, kop = ''] = s.split('.');
    return Number(rub) * 100 + Number(kop.padEnd(2, '0'));
  });

export type RubleIn = z.input<typeof RubleInput>; // string
export type RubleOut = z.output<typeof RubleInput>; // number

pipe передаёт результат первого преобразования в следующую схему: сначала нормализуем строку, потом проверяем формат, потом считаем копейки. Копейки собираются из строковых частей, без умножения дробного числа: 4.35 * 100 дал бы 434.99999999999994 (это разбиралось в ревью командного проекта). padEnd(2, '0') превращает «,5» в 50 копеек, а не в 5.

Задача 12. Теги из строки ★☆☆ разминка

Схема TagsInput: строка из поля «теги через запятую» превращается в массив тегов — обрезанных, в нижнем регистре, без пустых и без повторов; тегов не больше 10 (проверка после преобразования).

Зачем: пользователь вводит теги как удобно ему, а программа хранит как удобно ей. Ограничение «не больше 10» имеет смысл только для готового массива, поэтому проверка стоит после преобразования.

Решение и разбор
// tags.ts
import { z } from 'zod';

export const TagsInput = z
  .string()
  .transform((s) => [...new Set(s.split(',').map((t) => t.trim().toLowerCase()).filter(Boolean))])
  .pipe(z.array(z.string()).max(10, 'Не больше 10 тегов'));

new Set убирает повторы, а spread превращает его обратно в массив. filter(Boolean) отбрасывает пустые строки после trim. pipe передаёт уже готовый массив в схему массива с ограничением. Ограничение до преобразования (длина строки) было бы неточным: «a,a,a,…» — длинная строка, но один тег.
