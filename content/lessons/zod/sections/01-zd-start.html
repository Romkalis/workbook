Зачем библиотека схем

В уроке Express на TypeScript тело запроса проверялось предикатом isQuoteBody — двенадцать строк на два поля. В уроке Данные с сервера — такая же проверка товара на фронтенде. У ручных проверок три проблемы:

  • Тип и проверка живут отдельно. Добавили поле в interface, забыли в предикате — компилятор молчит, ведь предикату он верит на слово.
  • Ошибка одна на всё. Предикат говорит «нет», но не говорит, какое поле и почему. Для формы нужен текст у каждого поля.
  • Объём. Проверка вложенных объектов и массивов вручную разрастается и обрастает ошибками.

Zod решает все три: вы описываете схему — объект, который умеет проверять данные, — а тип TypeScript выводится из неё. Схема одна, расхождения невозможны.

import { z } from 'zod';

export const Product = z.object({
  id: z.string(),
  title: z.string().trim().min(1),
  price: z.number().int().nonnegative(),
  category: z.enum(['books', 'games', 'home']),
});

export type Product = z.infer<typeof Product>;
// { id: string; title: string; price: number; category: 'books' | 'games' | 'home' }

Одно имя Product живёт в двух мирах, как в задаче enum → объект as const: значение (схема) и тип. Установка: npm i zod. Урок написан по Zod 4 (проверено на 4.6); в старых статьях встречается Zod 3, отличия отмечены ниже.

Задача 1. Первая схема вместо интерфейса ★☆☆ разминка

Замените интерфейс отзыва схемой Zod и выведите из неё тип: автор — непустая строка после обрезки пробелов, оценка — целое от 1 до 5, текст — от 10 до 2000 символов, дата — строка. Проверьте схемой правильный отзыв и отзыв с оценкой 7.

interface Review {
  author: string;
  rating: number;
  text: string;
  createdAt: string;
}

Зачем: интерфейс описывает данные, но ничего не проверяет. Схема делает и то, и другое, а тип из неё не может разойтись с проверкой: поменяли правило — поменялся тип.

Решение и разбор
// review.ts
import { z } from 'zod';

export const Review = z.object({
  author: z.string().trim().min(1),
  rating: z.number().int().min(1).max(5),
  text: z.string().trim().min(10).max(2000),
  createdAt: z.string(),
});

export type Review = z.infer<typeof Review>;

trim() стоит перед min(1): сначала обрезка, потом проверка длины, поэтому автор из пробелов не пройдёт. Интерфейс удалён совсем. Если оставить его рядом со схемой, через месяц они разойдутся. Для дат Zod 4 умеет z.iso.datetime(), но здесь достаточно строки.
