Visitor — Посетитель

Поведенческий паттерн. Для известных видов материалов нужны новые операции: длительность, экспорт, проверка. Не хочется добавлять каждую такую операцию в классы материалов.

Простыми словами

Инспектор обходит кафе, магазин и аптеку и для каждого типа применяет свою проверку. Чтобы добавить новую проверку, нанимают нового инспектора, а сами заведения не перестраивают. Посетитель позволяет добавлять новые операции над разными классами, не меняя эти классы.

Участники и направление вызовов

Элемент имеет accept(visitor). Конкретные Video и Article вызывают соответствующий метод visitVideo или visitArticle. Visitor содержит операцию над всеми видами элементов. Выбор зависит и от вида элемента, и от конкретного посетителя — это двойная диспетчеризация.

Пример на TypeScript

interface Material { accept<R>(visitor: Visitor<R>): R }
interface Visitor<R> {
  visitVideo(video: Video): R;
  visitArticle(article: Article): R;
}
class Video implements Material {
  constructor(readonly minutes: number) {}
  accept<R>(visitor: Visitor<R>): R { return visitor.visitVideo(this); }
}
class Article implements Material {
  constructor(readonly words: number) {}
  accept<R>(visitor: Visitor<R>): R { return visitor.visitArticle(this); }
}
class DurationVisitor implements Visitor<number> {
  visitVideo(video: Video): number { return video.minutes; }
  visitArticle(article: Article): number { return Math.ceil(article.words / 200); }
}
const materials: Material[] = [new Video(12), new Article(600)];
const duration = new DurationVisitor();
const total = materials.reduce((sum, item) => sum + item.accept(duration), 0);
console.log(total); // 15

Посетитель посчитал 12 минут видео и 3 минуты статьи. Скорость 200 слов/мин — условность примера, а не норматив. Метод accept выбирает нужную операцию явно, без цепочки instanceof. Параметр R описывает результат посетителя: DurationVisitor выбирает number, а другой посетитель может выбрать string, не меняя классы элементов.

Когда применять и что учитывать

Удобен, когда набор видов элементов стабилен, а новые операции появляются часто. Добавить новый Visitor сравнительно легко; новый вид элемента заставит обновить контракт и существующих посетителей. Первичное внедрение требует accept в элементах. Перегрузки TypeScript сами не обеспечивают runtime-выбор по классу. Посетитель и итератор решают разные задачи: один выполняет операцию, другой задаёт обход.

Источник: Visitor — Посетитель. Пример авторский, адаптирован для учебного каталога.

Проследите один элемент Video: accept получает посетителя и вызывает у него visitVideo(this). У Article такой же шаг приводит в visitArticle. Клиент обходит материалы единообразно, а специальные операции для разных видов собраны в посетителе.
