Singleton — Одиночка

Порождающий паттерн. Нужна одна общая точка доступа к экземпляру внутри выбранной области выполнения. Например, счётчик учебных событий должен сохранять одно состояние для всех клиентов.

Простыми словами

В приложении может быть ровно один объект настроек, и все части программы должны видеть один и тот же. Одиночка гарантирует, что экземпляр создаётся один раз, а все, кто его запрашивает, получают именно его.

Участники и направление вызовов

Класс скрывает конструктор и хранит экземпляр в статическом поле. GetInstance либо создаёт объект, либо возвращает сохранённый. Клиенты получают одну и ту же ссылку.

Пример на TypeScript

class Metrics {
  private static instance: Metrics | undefined;
  private constructor() {}
  count = 0;
  static getInstance(): Metrics {
    return this.instance ??= new Metrics();
  }
}
const first = Metrics.getInstance();
const second = Metrics.getInstance();
first.count += 1;
console.log(first === second, second.count); // true 1

Обе переменные указывают на один объект. Private constructor ограничивает создание при проверке TypeScript; он не является защитой от обхода в произвольном JavaScript.

Когда применять и что учитывать

Общее изменяемое состояние усложняет тесты и скрывает зависимости. Часто достаточно создать объект в точке сборки приложения и передавать его явно. Не путайте один экземпляр на область с одним экземпляром во всей распределённой системе. Дополнение из общих знаний: разные процессы, workers и независимые загрузки модулей могут иметь свои экземпляры; состояние конкретного пользователя нельзя бездумно хранить в серверном глобальном объекте.

Источник: Singleton — Одиночка. Пример авторский, адаптирован для учебного каталога.

Сравнение first === second проверяет совпадение ссылок, а не равенство полей. После увеличения first.count меняется тот же объект, который доступен через second. Это полезный способ увидеть общее состояние и одновременно его риск.
