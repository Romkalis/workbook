Для практики: Strategy, DI и полиморфизм

Kata — небольшое упражнение Codewars с заданным интерфейсом и автоматическими тестами. DI означает Dependency Injection, передачу зависимостей снаружи. Дублёр — небольшой заменяющий объект для проверки, который возвращает заранее известные данные вместо обращения к реальному источнику.

Простыми словами

Навигатор строит маршрут пешком, на машине или на транспорте: цель одна, способ подменяется. Стратегия — это подменяемый алгоритм. А внедрение зависимостей (DI) — когда объект не создаёт себе помощников сам, а получает их снаружи, например в конструкторе. Так их легко заменить, в том числе в тестах.

В связанном с модулем наборе Codewars есть Strategy, Dependency Injection и Sortable Shapes, хотя они не входят в список 15 теоретических страниц. Поэтому разберём необходимую основу отдельно. Примеры авторские и не являются готовыми решениями kata.

Strategy — Стратегия: смена алгоритма

Контекст использует один контракт алгоритма, а клиент подставляет нужную реализацию. Например, каталог можно сортировать по имени или длительности. В JS стратегия часто является функцией, и отдельные классы не нужны. В отличие от State стратегия описывает выбранный способ решения, а не жизненный цикл контекста.

type Lesson = { title: string; minutes: number };
type Compare = (a: Lesson, b: Lesson) => number;
class Catalog {
  constructor(private compare: Compare) {}
  ordered(items: readonly Lesson[]): Lesson[] { return [...items].sort(this.compare); }
}
const lessons = [{ title: "TS", minutes: 30 }, { title: "Patterns", minutes: 10 }];
const shortest = new Catalog((a, b) => a.minutes - b.minutes);
const longest = new Catalog((a, b) => b.minutes - a.minutes);
console.log(shortest.ordered(lessons)[0].title); // Patterns
console.log(longest.ordered(lessons)[0].title); // TS

Источник: Strategy. Стратегия позволяет менять алгоритм независимо от клиента; цена — дополнительный контракт и место выбора. Для одного стабильного алгоритма она может быть лишней.

Dependency Injection — внедрение зависимостей

Объект получает нужную зависимость снаружи вместо самостоятельного поиска или создания. Ниже Report не знает, откуда приходят названия уроков. Сборка приложения подставляет источник, тест — небольшой дублёр. Это внедрение через конструктор; DI-контейнер не обязателен.

interface Source { titles(): readonly string[] }
class Report {
  constructor(private source: Source) {}
  render(): string { return this.source.titles().join(", "); }
}
const testSource: Source = { titles: () => ["TS", "Patterns"] };
const report = new Report(testSource);
console.log(report.render()); // TS, Patterns

Основа — статья Мартина Фаулера о DI; она добавлена как первоисточник для практической темы. Если Report сам обращается к глобальному registry.get, это поиск зависимости через Service Locator. DI делает зависимость явной в контракте. Не путайте DI, конкретный способ передачи зависимости, с общим принципом инверсии зависимостей.

Sortable Shapes: полиморфный контракт

Подготовка из общих знаний: разные фигуры могут реализовать метод area. Сортировщик сравнивает площади через общий контракт и не обязан проверять вид фигуры. Для Codewars сначала прочитайте требуемый API: метод, поле и правила сравнения определяются конкретным условием, а не названием паттерна.

Для числовой сортировки в JS нужен компаратор, возвращающий отрицательное число, ноль или положительное число. Сам sort меняет массив; в примере Strategy сначала делается копия. Не используйте boolean вместо числового результата сравнения.
