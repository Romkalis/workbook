Для практики: Strategy, DI и полиморфизм

Kata — небольшое упражнение Codewars с заданным интерфейсом и автоматическими тестами. DI означает Dependency Injection, передачу зависимостей снаружи. Дублёр — небольшой заменяющий объект для проверки, который возвращает заранее известные данные вместо обращения к реальному источнику.

Простыми словами

Навигатор строит маршрут пешком, на машине или на транспорте: цель одна, способ подменяется. Стратегия — это подменяемый алгоритм. А внедрение зависимостей (DI) — когда объект не создаёт себе помощников сам, а получает их снаружи, например в конструкторе. Так их легко заменить, в том числе в тестах.

В связанном с модулем наборе Codewars есть Strategy, Dependency Injection и Sortable Shapes, хотя они не входят в список 15 теоретических страниц. Поэтому разберём необходимую основу отдельно. Примеры авторские и не являются готовыми решениями kata.

Strategy — Стратегия: смена алгоритма

Контекст использует один контракт алгоритма, а клиент подставляет нужную реализацию. Например, каталог можно сортировать по имени или длительности. В JS стратегия часто является функцией, и отдельные классы не нужны. В отличие от State стратегия описывает выбранный способ решения, а не жизненный цикл контекста.

type Lesson = { title: string; minutes: number };
type Compare = (a: Lesson, b: Lesson) => number;
class Catalog {
  constructor(private compare: Compare) {}
  ordered(items: readonly Lesson[]): Lesson[] { return [...items].sort(this.compare); }
}
const lessons = [{ title: "TS", minutes: 30 }, { title: "Patterns", minutes: 10 }];
const shortest = new Catalog((a, b) => a.minutes - b.minutes);
const longest = new Catalog((a, b) => b.minutes - a.minutes);
console.log(shortest.ordered(lessons)[0].title); // Patterns
console.log(longest.ordered(lessons)[0].title); // TS

Источник: Strategy. Стратегия позволяет менять алгоритм независимо от клиента; цена — дополнительный контракт и место выбора. Для одного стабильного алгоритма она может быть лишней.

Задача 16. Стратегии скидок ★☆☆ разминка

Скидка бывает процентной, фиксированной и «третий товар бесплатно». Опишите тип стратегии (items: number[]) => number (возвращает сумму скидки), три стратегии и функцию checkout(items, strategy), которая возвращает итог. Скидка не может сделать сумму отрицательной.

Зачем: алгоритм, который меняется, выносится за интерфейс. Новая акция — новая функция, а checkout остаётся прежним и уже покрыт тестами. В JavaScript стратегия чаще всего — просто функция: класс с одним методом ничего не добавляет.

Решение и разбор
export type Discount = (items: readonly number[]) => number;

export const percent =
  (p: number): Discount =>
  (items) =>
    (items.reduce((a, b) => a + b, 0) * p) / 100;

export const fixed =
  (amount: number): Discount =>
  () =>
    amount;

export const thirdFree: Discount = (items) => {
  const sorted = [...items].sort((a, b) => b - a);
  return sorted.filter((_, i) => i % 3 === 2).reduce((a, b) => a + b, 0);
};

export function checkout(items: readonly number[], strategy: Discount): number {
  const sum = items.reduce((a, b) => a + b, 0);
  return Math.max(0, sum - strategy(items));
}

percent(10) и fixed(500) — фабрики стратегий: параметр акции фиксируется в замыкании. В thirdFree бесплатным становится каждый третий по цене, начиная с дорогих. Так магазин не дарит самый дорогой товар. Это бизнес-правило, и его стоит обсудить, а не угадать. Ограничение «не меньше нуля» стоит в checkout, а не в каждой стратегии: это общий инвариант.

Dependency Injection — внедрение зависимостей

Объект получает нужную зависимость снаружи вместо самостоятельного поиска или создания. Ниже Report не знает, откуда приходят названия уроков. Сборка приложения подставляет источник, тест — небольшой дублёр. Это внедрение через конструктор; DI-контейнер не обязателен.

interface Source { titles(): readonly string[] }
class Report {
  constructor(private source: Source) {}
  render(): string { return this.source.titles().join(", "); }
}
const testSource: Source = { titles: () => ["TS", "Patterns"] };
const report = new Report(testSource);
console.log(report.render()); // TS, Patterns

Основа — статья Мартина Фаулера о DI; она добавлена как первоисточник для практической темы. Если Report сам обращается к глобальному registry.get, это поиск зависимости через Service Locator. DI делает зависимость явной в контракте. Не путайте DI, конкретный способ передачи зависимости, с общим принципом инверсии зависимостей.

Задача 17. Внедрение зависимостей вместо импорта ★★☆ практика

Сервис ниже сам импортирует время и хранилище, поэтому тест «скидка действует до конца дня» зависит от того, когда его запустили. Перепишите в класс PromoService, который получает clock: () => Date и storage через конструктор, и проверьте тестом обе стороны полуночи.

export function isPromoActive(): boolean {
  const until = localStorage.getItem('promoUntil');
  return until !== null && new Date() < new Date(until);
}

Зачем: скрытые зависимости (текущее время, localStorage, сеть) делают код непредсказуемым в тестах. Если передать их снаружи, поведение полностью определяется входными данными, а в тесте время — это просто аргумент.

Решение и разбор
export interface KeyValue {
  getItem(key: string): string | null;
}

export class PromoService {
  constructor(
    private readonly storage: KeyValue,
    private readonly clock: () => Date = () => new Date(),
  ) {}

  isActive(): boolean {
    const until = this.storage.getItem('promoUntil');
    return until !== null && this.clock() < new Date(until);
  }
}

// в приложении: new PromoService(localStorage)

Значение по умолчанию для clock оставляет вызов в приложении коротким, а тест передаёт фиксированное время. Интерфейс KeyValue требует от хранилища только один метод. Подойдут localStorage, Map-обёртка или серверное хранилище. Это и есть принцип инверсии зависимостей: сервис зависит от маленького интерфейса, а не от конкретного глобального объекта.

Sortable Shapes: полиморфный контракт

Подготовка из общих знаний: разные фигуры могут реализовать метод area. Сортировщик сравнивает площади через общий контракт и не обязан проверять вид фигуры. Для Codewars сначала прочитайте требуемый API: метод, поле и правила сравнения определяются конкретным условием, а не названием паттерна.

Для числовой сортировки в JS нужен компаратор, возвращающий отрицательное число, ноль или положительное число. Сам sort меняет массив; в примере Strategy сначала делается копия. Не используйте boolean вместо числового результата сравнения.

Задача 18. Полиморфизм вместо switch ★★☆ практика

Функция ниже считает площадь фигур через switch по типу. Перепишите на классы с общим абстрактным классом Shape и методом area(), добавьте треугольник и функцию sortByArea(shapes), которая не меняет исходный массив и ничего не знает о конкретных фигурах.

function area(s: { type: string; a: number; b?: number }) {
  switch (s.type) {
    case 'square': return s.a * s.a;
    case 'circle': return Math.PI * s.a * s.a;
    case 'rect': return s.a * (s.b ?? 0);
  }
}

Зачем: это суть задачи Sortable Shapes из практики: новая фигура добавляется новым классом, а не правкой switch во всех функциях. Код сортировки опирается только на контракт «у фигуры есть площадь».

Решение и разбор
export abstract class Shape {
  abstract area(): number;
}

export class Square extends Shape {
  constructor(private readonly side: number) {
    super();
  }
  area() {
    return this.side ** 2;
  }
}
export class Circle extends Shape {
  constructor(private readonly radius: number) {
    super();
  }
  area() {
    return Math.PI * this.radius ** 2;
  }
}
export class Rectangle extends Shape {
  constructor(
    private readonly width: number,
    private readonly height: number,
  ) {
    super();
  }
  area() {
    return this.width * this.height;
  }
}
export class Triangle extends Shape {
  constructor(
    private readonly base: number,
    private readonly height: number,
  ) {
    super();
  }
  area() {
    return (this.base * this.height) / 2;
  }
}

export const sortByArea = (shapes: readonly Shape[]): Shape[] => [...shapes].sort((a, b) => a.area() - b.area());

Обратите внимание на исходный switch: у него нет ветки по умолчанию, и для неизвестного типа функция вернёт undefined. С классами такой ошибки нет: фигуру без area() компилятор не даст создать. Размеченный union с switch тоже законный подход, и его поддерживает проверка never. Выбор зависит от того, что чаще меняется. Если добавляются фигуры, удобнее классы. Если добавляются операции (площадь, периметр, отрисовка), удобнее union и посетитель.
