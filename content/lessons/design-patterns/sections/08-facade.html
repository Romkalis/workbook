Facade — Фасад

Структурный паттерн. Для открытия урока клиенту приходится читать хранилище, форматировать заголовок и готовить результат. Хочется дать ему одну понятную операцию.

Простыми словами

Администратор в отеле: вы говорите «организуйте ужин и такси», а он сам договаривается с кухней, рестораном и водителем. Фасад даёт одну простую функцию вместо десятка вызовов сложной системы.

Участники и направление вызовов

Фасад LessonFacade знает последовательность действий подсистемы. Store и Formatter выполняют свои задачи и не обязаны знать о фасаде. Клиент использует open.

Пример на TypeScript

class LessonStore {
  read(id: number): string {
    if (id !== 1) throw new Error("Урок не найден");
    return "TypeScript";
  }
}
class Formatter {
  heading(title: string): string { return `Урок: ${title}`; }
}
class LessonFacade {
  constructor(private store: LessonStore, private formatter: Formatter) {}
  open(id: number): string {
    return this.formatter.heading(this.store.read(id));
  }
}
const facade = new LessonFacade(new LessonStore(), new Formatter());
console.log(facade.open(1)); // Урок: TypeScript

Клиент больше не собирает последовательность сам. Ошибка хранилища по-прежнему возможна: упрощение интерфейса не означает, что операция всегда успешна.

Когда применять и что учитывать

Полезен для частого сценария сложной подсистемы. Он предоставляет более удобный интерфейс, а не обязан сохранять прежний, как Proxy или Decorator. Не сваливайте все операции приложения в один фасад: разделяйте их по сценариям. Доступ к продвинутым возможностям подсистемы при необходимости может остаться отдельным.

Источник: Facade — Фасад. Пример авторский, адаптирован для учебного каталога.

Вызов open скрывает два шага: получить заголовок из LessonStore и оформить его через Formatter. Клиенту нужен итоговый сценарий, а не знание, какой служебный объект вызвать первым.
