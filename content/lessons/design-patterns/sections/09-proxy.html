Proxy — Заместитель

Структурный паттерн. Чтение каталога дорогое; хотим повторно использовать результат, сохранив контракт сервиса. Клиент не должен управлять кэшем вручную.

Простыми словами

Секретарь начальника: с ним говорят так же, как с начальником, но он решает, пускать ли посетителя, может сам ответить на частый вопрос или записать визит в журнал. Заместитель имеет тот же интерфейс, что и настоящий объект, и встаёт перед ним, чтобы проверять, кешировать или откладывать работу.

Участники и направление вызовов

Catalog — общий интерфейс сервиса и заместителя. CachedCatalog проверяет кэш и при необходимости делегирует запрос RealCatalog. Клиент видит тот же метод title.

Пример на TypeScript

interface Catalog { title(id: number): string }
class RealCatalog implements Catalog {
  calls = 0;
  title(id: number): string { this.calls += 1; return `Урок ${id}`; }
}
class CachedCatalog implements Catalog {
  private cache = new Map<number, string>();
  constructor(private source: Catalog) {}
  title(id: number): string {
    const cached = this.cache.get(id);
    if (cached !== undefined) return cached;
    const title = this.source.title(id);
    this.cache.set(id, title);
    return title;
  }
}
const source = new RealCatalog();
const proxy = new CachedCatalog(source);
console.log(proxy.title(1), proxy.title(1), source.calls); // Урок 1 Урок 1 1

Повторный запрос не дошёл до источника: calls равно 1. Здесь заместитель кэширующий; другие варианты контролируют доступ или откладывают создание тяжёлого объекта.

Когда применять и что учитывать

Нужно определить срок актуальности и способ сброса кэша. Пример синхронный и не обрабатывает гонки запросов. Дополнение из общих знаний: встроенный JS Proxy перехватывает операции над объектами и может помочь реализовать заместителя, но паттерн не требует этого API. Проверка доступа на клиенте не заменяет проверку на сервере.

Источник: Proxy — Заместитель. Пример авторский, адаптирован для учебного каталога.

Кэш — сохранённый результат предыдущего обращения. В первый вызов proxy идёт к source и запоминает строку. Во второй возвращает её из Map: поэтому счётчик обращений к source не увеличивается. При изменении исходных данных старый кэш нужно обновить или удалить.
