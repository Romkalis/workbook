Mediator — Посредник

Поведенческий паттерн. В форме поле заголовка влияет на кнопку сохранения. Если элементы начнут напрямую менять друг друга, их будет трудно использовать в другой форме.

Простыми словами

Диспетчерская вышка в аэропорту: самолёты не договариваются друг с другом напрямую, все говорят только с вышкой. Посредник убирает прямые связи между множеством объектов: каждый общается только с ним.

Участники и направление вызовов

Компоненты сообщают о событиях посреднику. FormMediator знает правила взаимодействия и меняет Button. Field знает только контракт Mediator, а не конкретную кнопку.

Пример на TypeScript

interface Mediator { changed(value: string): void }
class Button { enabled = false; }
class Field {
  constructor(private mediator: Mediator) {}
  input(value: string): void { this.mediator.changed(value); }
}
class FormMediator implements Mediator {
  readonly button = new Button();
  readonly title = new Field(this);
  changed(value: string): void {
    this.button.enabled = value.trim().length > 0;
  }
}
const form = new FormMediator();
form.title.input("TS");
console.log(form.button.enabled); // true
form.title.input("  ");
console.log(form.button.enabled); // false

Поле не обращалось к кнопке. Правило «пустой заголовок запрещает сохранение» сосредоточено в посреднике. Объекты имитируют элементы формы без зависимости от DOM.

Когда применять и что учитывать

Подходит, когда много связей между участниками одного сценария. Посредник не просто рассылает события, а определяет реакцию и координирует коллег. Следите, чтобы он не стал огромным объектом, знающим весь продукт. Небольшие независимые формы могут иметь своих посредников.

Источник: Mediator — Посредник. Пример авторский, адаптирован для учебного каталога.

При вводе Field сообщает новое значение посреднику. Посредник проверяет строку и меняет enabled у Button. Сам Field не ищет кнопку и не знает правила её включения: это позволяет использовать поле с другой координацией.
