Builder — Строитель

Порождающий паттерн. Сложный план занятия собирается по шагам. Длинный позиционный конструктор плохо читается, а промежуточный результат ещё не готов к использованию.

Простыми словами

Заказ бургера по шагам: булка, котлета, сыр, соус — а в конце кассир отдаёт готовый бургер. Строитель собирает сложный объект за несколько понятных вызовов вместо одного конструктора с десятью аргументами, в которых легко перепутать порядок.

Участники и направление вызовов

Builder хранит состояние сборки и предоставляет шаги. Build возвращает готовый продукт. Необязательный Director задаёт повторяемый порядок шагов; здесь эту роль играет makeIntro.

Пример на TypeScript

type Plan = { title: string; topics: string[] };
class PlanBuilder {
  private title = "";
  private topics: string[] = [];
  named(title: string): this { this.title = title; return this; }
  add(topic: string): this { this.topics.push(topic); return this; }
  build(): Plan {
    if (!this.title.trim()) throw new Error("Нужен заголовок");
    const plan = { title: this.title, topics: [...this.topics] };
    this.title = "";
    this.topics = [];
    return plan;
  }
}
function makeIntro(builder: PlanBuilder): Plan {
  return builder.named("Паттерны").add("Задача").add("Пример").build();
}
const builder = new PlanBuilder();
const plan = makeIntro(builder);
const next = builder.named("Повторение").add("Тест").build();
console.log(plan.topics.join(", "), next.topics.join(", "));

После первого build получим «Задача, Пример», после второго — «Тест». Массив скопирован, а строитель сброшен: предыдущий продукт не меняется от следующей сборки.

Когда применять и что учитывать

Нужен при действительно многошаговом создании и разных представлениях продукта. Обязательно определите правила повторного использования и момент проверки обязательных полей. Цепочка методов сама по себе не доказывает Builder. Для двух независимых параметров объект настроек проще.

Источник: Builder — Строитель. Пример авторский, адаптирован для учебного каталога.

Цепочка named(...).add(...).build() — последовательные вызовы одного строителя. Возврат this позволяет сразу вызвать следующий шаг. Только build выдаёт готовый Plan; при пустом заголовке он бросает ошибку. Director — необязательный организатор повторяемой последовательности шагов.
