Всплытие и делегирование

Событие идёт вверх

Клик по кнопке внутри карточки внутри списка — это клик и по кнопке, и по карточке, и по списку, и по документу. Событие сначала проходит сверху вниз до цели (погружение, capture), затем поднимается обратно (всплытие, bubbling). Обычные обработчики срабатывают на всплытии: сначала на кнопке, потом на карточке, потом на списке. Большинство событий всплывают; исключения — например, focus и blur (у них есть всплывающие пары focusin/focusout).

Задача 4. Порядок всплытия ★☆☆ разминка

Повесьте обработчики click на кнопку, карточку и список, каждый пишет своё имя в массив log. Кликните по кнопке и убедитесь, что порядок — ['button', 'card', 'list']. Затем добавьте списку обработчик с опцией capture: true и посмотрите, куда он встанет.

Зачем: понимание порядка срабатывания объясняет большинство «странных» багов с событиями: почему меню закрылось раньше, чем сработала кнопка внутри него, почему делегирование вообще работает.

Решение и разбор
// order.ts
export function wire(button: HTMLElement, card: HTMLElement, list: HTMLElement): string[] {
  const log: string[] = [];
  button.addEventListener('click', () => log.push('button'));
  card.addEventListener('click', () => log.push('card'));
  list.addEventListener('click', () => log.push('list'));
  list.addEventListener('click', () => log.push('list-capture'), { capture: true });
  return log;
}

Обработчик с capture: true срабатывает на пути вниз, раньше всех: ['list-capture', 'button', 'card', 'list']. В обычном коде capture нужен редко. Пример полезного применения — перехватить событие раньше дочернего кода, например закрыть всплывающее меню при клике в любом месте страницы.

Делегирование: один обработчик на список

Вешать обработчик на каждую из ста кнопок «В корзину» неудобно: новые карточки после загрузки придётся подписывать отдельно, а при перерисовке — следить за отпиской. Вместо этого один обработчик ставят на общий контейнер и по target выясняют, что нажали:

export type CartAction = { type: 'add' | 'remove'; productId: string };

export function listenCartActions(list: HTMLElement, onAction: (action: CartAction) => void): void {
  list.addEventListener('click', (event) => {
    if (!(event.target instanceof Element)) return;
    const button = event.target.closest<HTMLElement>('[data-action]');
    if (!button || !list.contains(button)) return;
    const card = button.closest<HTMLElement>('[data-id]');
    const action = button.dataset.action;
    if (!card?.dataset.id || (action !== 'add' && action !== 'remove')) return;
    onAction({ type: action, productId: card.dataset.id });
  });
}

Кнопки размечены атрибутом data-action="add", карточка — data-id. Обработчику всё равно, сколько карточек и когда они появились: он работает и для карточек, нарисованных позже. Проверка list.contains(button) отсекает случай, когда closest нашёл подходящего предка выше самого списка.

Обратите внимание на форму функции: она не меняет корзину сама, а сообщает о действии через onAction. DOM-событие переводится в событие предметной области («добавить товар g1»), а что с ним делать — решает другой код. Так обработчик можно проверить, просто собрав переданные действия.

Задача 5. Количество в корзине через делегирование ★★☆ практика

В корзине строки <li data-id> с кнопками data-action="inc", "dec", "remove". Напишите listenCart(list, handlers) с одним обработчиком на список, который вызывает handlers.inc(id), dec(id) или remove(id). Неизвестное действие игнорируется. Строки, добавленные после подписки, тоже должны работать.

Зачем: строки корзины постоянно появляются и исчезают. Обработчик на каждой кнопке пришлось бы вешать заново после каждой перерисовки, а делегирование работает «навсегда». Словарь обработчиков вместо if/else — новое действие добавляется одной строкой.

Решение и разбор
// cart-events.ts
type Handlers = Record<'inc' | 'dec' | 'remove', (id: string) => void>;

function isAction(value: string | undefined): value is keyof Handlers {
  return value === 'inc' || value === 'dec' || value === 'remove';
}

export function listenCart(list: HTMLElement, handlers: Handlers): void {
  list.addEventListener('click', (event) => {
    if (!(event.target instanceof Element)) return;
    const button = event.target.closest<HTMLElement>('[data-action]');
    const row = button?.closest<HTMLElement>('[data-id]');
    if (!button || !row || !list.contains(row)) return;
    const action = button.dataset.action;
    if (isAction(action) && row.dataset.id) handlers[action](row.dataset.id);
  });
}

Предикат isAction превращает строку из разметки в ключ словаря. Без него handlers[action] не скомпилировался бы, и это правильно: в data-action может оказаться что угодно. Функция только переводит клик в вызов, а что такое «увеличить количество», решает код корзины.

stopPropagation — крайняя мера

event.stopPropagation() останавливает всплытие. Выглядит удобно («клик по кнопке не должен закрывать карточку»), но ломает чужой код выше по дереву: аналитику, закрытие меню по клику снаружи, делегирование. Обычно задачу решает проверка цели: в обработчике родителя спросите, откуда пришёл клик (event.target.closest(...)), вместо того чтобы глушить событие у ребёнка.

Задача 6. Закрыть окно по клику на фон ★★☆ практика

Модальное окно — div.backdrop с вложенным div.modal. Клик по фону закрывает окно, клик внутри окна — нет. Решите задачу без stopPropagation.

backdrop.addEventListener('click', close);
modal.addEventListener('click', (e) => e.stopPropagation()); // «чтобы не закрывалось»

Зачем: stopPropagation внутри окна ломает делегирование на document: аналитику, закрытие выпадающих меню, ваши же обработчики. Проверка «клик был именно по фону» решает задачу локально и ничего не ломает вокруг.

Решение и разбор
// backdrop.ts
export function closeOnBackdrop(backdrop: HTMLElement, close: () => void): void {
  backdrop.addEventListener('click', (event) => {
    if (event.target === event.currentTarget) close();
  });
}

Клик по фону: target и currentTarget — один и тот же элемент. Клик внутри окна: target — что-то внутри .modal, проверка не проходит. Событие при этом спокойно всплывает дальше, и все остальные слушатели его получат. Если вы используете <dialog>, приём тот же: клик по его фону приходит с target === dialog (из общих знаний).
