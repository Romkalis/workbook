Действия по умолчанию

У некоторых событий браузер делает что-то сам: ссылка переходит по адресу, форма отправляется с перезагрузкой страницы, пробел прокручивает страницу. event.preventDefault() отменяет это действие (если событие отменяемое, event.cancelable). Самый частый случай — форма: без preventDefault браузер отправит её и перезагрузит страницу, и ваш JavaScript-обработчик просто не успеет показать результат.

preventDefault не останавливает всплытие, а stopPropagation не отменяет действие браузера. Это разные вещи, их часто путают.

Задача 7. Ссылка, которая работает и без JavaScript ★☆☆ разминка

Ссылки фильтров ведут на ?category=books. Напишите обработчик: если JavaScript работает, он отменяет переход, вызывает onFilter(category) и обновляет адрес через history.pushState. Без JavaScript ссылка просто откроет страницу с параметром.

Зачем: это «прогрессивное улучшение»: базовое поведение даёт HTML, а JavaScript делает его быстрее и приятнее. Ссылку можно открыть в новой вкладке, скопировать, и она работает у поисковика.

Решение и разбор
// filter-links.ts
export function enhanceFilterLinks(nav: HTMLElement, onFilter: (category: string) => void): void {
  nav.addEventListener('click', (event) => {
    if (!(event.target instanceof Element)) return;
    const link = event.target.closest<HTMLAnchorElement>('a[href]');
    if (!link || !nav.contains(link)) return;
    const category = new URL(link.href).searchParams.get('category');
    if (category === null) return;
    event.preventDefault();
    history.pushState(null, '', link.href);
    onFilter(category);
  });
}

preventDefault вызывается только когда мы точно обработаем клик сами. Ссылки без category работают как обычно. pushState меняет адрес без перезагрузки, поэтому кнопка «назад» и копирование ссылки по-прежнему работают. Чтобы «назад» перерисовывал фильтр, нужен ещё обработчик popstate; это тема урока о состоянии.
