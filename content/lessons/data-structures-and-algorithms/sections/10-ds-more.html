Хеш-таблица, куча и граф: краткая карта

Эти структуры встречаются в заметке модуля. Здесь достаточно понять назначение и не перепутать их гарантии; подробные реализации можно изучать после основной практики.

Хеш-таблица и Map

Хеш-функция переводит ключ в номер корзины. У разных ключей может совпасть номер — это коллизия. Её решают, например, хранением нескольких записей в корзине или поиском другого свободного места. Важно сравнивать исходные ключи, а не считать равный хеш доказательством равенства.

Из общих знаний: обычно хеш-таблица находит, добавляет и удаляет за O(1): по ключу сразу ясно, в какую корзину смотреть. Но если много ключей попало в одну корзину, её придётся перебирать, и в худшем случае поиск займёт O(n). Хорошие реализации следят за этим и вовремя увеличивают число корзин. Map в JavaScript на практике работает именно так, хотя стандарт требует лишь «в среднем быстрее, чем перебор». Ключи-объекты в Map сравниваются по ссылке: два одинаковых на вид объекта — разные ключи.

function frequencies(values) {
  const counts = new Map();
  for (const value of values) {
    counts.set(value, (counts.get(value) ?? 0) + 1);
  }
  return counts;
}
console.log([...frequencies(['js', 'ts', 'js'])]);
// [['js', 2], ['ts', 1]]

При ожидаемых O(1) операциях Map этот подсчёт занимает ожидаемо O(n) времени и O(k) памяти для k различных значений. Сортировка для подсчёта не требуется.

Коллизии: пробирование и цепочки

Линейное пробирование (открытая адресация): если корзина занята, смотрим следующую, потом ещё одну, по кругу. Все записи лежат прямо в массиве. В примере у всех трёх ключей хеш-функция плохая (длина строки), и ключи занимают соседние ячейки:

function insertProbing(table, key, hash) {
  let i = hash(key) % table.length;
  for (let step = 0; step < table.length; step++) {
    if (table[i] === undefined || table[i] === key) {
      table[i] = key;
      return i;
    }
    i = (i + 1) % table.length;
  }
  throw new Error('Таблица заполнена');
}

const table = new Array(5);
const hash = (s) => s.length;
console.log(['ab', 'cd', 'xyz'].map((k) => insertProbing(table, k, hash)));
// [2, 3, 4]

Занятые ячейки слипаются в кластеры, и поиск в них удлиняется. Если шаг больше единицы и не взаимно прост с размером таблицы, обход может вернуться в исходную ячейку и не увидеть часть свободных мест. Об этом и предупреждает заметка. Удаление тоже не тривиально: пустая дыра оборвёт поиск ключей, стоявших дальше, поэтому на её месте оставляют пометку «удалено».

Цепочки: в каждой корзине лежит список (или дерево) записей. Вставка O(1), а поиск зависит от длины цепочки. Заметка говорит, что цепочки «сильно повышают производительность», но точнее так: они проще и не страдают от кластеров, зато тратят память на узлы и хуже используют кэш процессора. Обе схемы работают быстро, пока таблица не переполнена и хеш-функция распределяет ключи равномерно.

Object или Map — из общих знаний

Обычный объект тоже хранит пары «ключ — значение», но ключи у него только строки и символы: число 1 и строка '1' станут одним ключом. У литерала {} есть прототип, поэтому 'toString' in {} даёт true, хотя вы ничего туда не клали. Map принимает ключи любого типа, помнит порядок вставки, знает свой размер (size) и не содержит лишних ключей. Для словаря с данными пользователя выбирайте Map или Object.create(null).

Двоичная куча и очередь с приоритетом

Куча (min-heap) — дерево, где каждый родитель не больше своих детей. Поэтому самый маленький элемент всегда на вершине, и взять его можно сразу. Остальные лежат не по порядку: куча гарантирует только «родитель ≤ дети».

Дерево заполняется по уровням слева направо без пропусков, поэтому его удобно хранить в обычном массиве. У элемента с индексом i дети лежат на позициях 2i + 1 и 2i + 2. Например, у корня (индекс 0) дети — 1 и 2, у элемента 1 — 3 и 4.

Чтение минимума — O(1), вставка с подъёмом и извлечение минимума с просеиванием — O(log n) в худшем случае, поиск произвольного значения — O(n). В заметке для вставки указано O(1); для обычной двоичной кучи это неверно как общая оценка худшего случая. Приоритетная очередь выдаёт элемент по приоритету, а не по времени прихода.

Слово «куча» значит две разные вещи. Область памяти heap — место, где движок размещает объекты во время выполнения (в отличие от стека вызовов). Структура данных heap — дерево с правилом «родитель ≤ дети». Между ними нет никакой связи, кроме названия.

Max-heap и пирамидальная сортировка

У кучи есть зеркальный вариант — max-heap: каждый родитель не меньше своих детей, и на вершине лежит максимум. Min-heap и max-heap устроены одинаково, отличается только знак сравнения. Обе — полные двоичные деревья. «Двоичное» значит, что у узла не больше двух детей. «Полное» — что все уровни заполнены целиком, кроме, может быть, последнего, а последний заполняется слева направо без дыр. Именно поэтому кучу можно хранить в массиве по формуле 2i + 1 и 2i + 2: пропусков нет.

Частая ошибка — путать кучу с деревом поиска. В BST левый потомок меньше, правый больше, и можно искать любое значение за O(высоты). В куче левый и правый дети никак не упорядочены между собой, а поиск произвольного значения стоит O(n). Зато вершина доступна мгновенно.

class MaxHeap {
  #items = [];
  get size() { return this.#items.length; }
  peek() { return this.#items[0]; } // максимум за O(1)

  push(value) {
    const a = this.#items;
    a.push(value);
    let i = a.length - 1;
    while (i > 0) { // поднимаем, пока родитель меньше
      const parent = Math.floor((i - 1) / 2);
      if (a[parent] >= a[i]) break;
      [a[parent], a[i]] = [a[i], a[parent]];
      i = parent;
    }
  }

  pop() {
    const a = this.#items;
    if (a.length === 0) return undefined;
    const top = a[0];
    const last = a.pop();
    if (a.length > 0) {
      a[0] = last; // последний встаёт на вершину и опускается вниз
      let i = 0;
      while (true) {
        const left = 2 * i + 1;
        const right = 2 * i + 2;
        let big = i;
        if (left < a.length && a[left] > a[big]) big = left;
        if (right < a.length && a[right] > a[big]) big = right;
        if (big === i) break;
        [a[big], a[i]] = [a[i], a[big]];
        i = big;
      }
    }
    return top;
  }
}

const heap = new MaxHeap();
for (const x of [5, 9, 1, 7, 3]) heap.push(x);
console.log(heap.peek()); // 9
const out = [];
while (heap.size > 0) out.push(heap.pop());
console.log(out); // [9, 7, 5, 3, 1]

Последние строки показывают идею пирамидальной сортировки (heap sort): сложить всё в кучу и доставать вершину, пока куча не опустеет. Каждое извлечение стоит O(log n), извлечений n, итого O(n log n) в любом случае, даже в худшем. Здесь для наглядности результат собран в новый массив. Настоящий heap sort работает на месте: строит max-heap прямо во входном массиве и переставляет вершину в конец (из общих знаний). Устойчивой эта сортировка не является.

Граф, BFS и DFS

Граф состоит из вершин и рёбер: например, остановок и маршрутов. Рёбра могут быть направленными и иметь веса. В списке смежности для каждой вершины хранят соседей, в матрице смежности — таблицу V × V. Первая обычно требует O(V + E) памяти, вторая O(V²).

Из общих знаний: BFS идёт слоями с очередью, DFS углубляется с помощью стека или рекурсии. Чтобы не зациклиться, отмечают посещённые вершины. Со списком смежности полный обход занимает O(V + E); старт из одной вершины посещает только достижимую часть. BFS находит кратчайший путь по числу рёбер в невзвешенном графе, но не решает автоматически задачу с произвольными весами.

Ещё одно деление графов — по циклам. В циклическом графе можно выйти из вершины и вернуться в неё по рёбрам. Ациклический направленный граф (DAG) — например, зависимости пакетов в npm или порядок задач в сборке. Для него можно найти топологический порядок: каждая вершина стоит раньше тех, что от неё зависят. Для взвешенных графов кратчайший путь ищут алгоритмом Дейкстры, и внутри него снова пригождается куча (из общих знаний).
