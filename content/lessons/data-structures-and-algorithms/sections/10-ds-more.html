Хеш-таблица, куча и граф: краткая карта

Эти структуры встречаются в заметке модуля. Здесь достаточно понять назначение и не перепутать их гарантии; подробные реализации можно изучать после основной практики.

Хеш-таблица и Map

Хеш-функция переводит ключ в номер корзины. У разных ключей может совпасть номер — это коллизия. Её решают, например, хранением нескольких записей в корзине или поиском другого свободного места. Важно сравнивать исходные ключи, а не считать равный хеш доказательством равенства.

Из общих знаний: обычно хеш-таблица находит, добавляет и удаляет за O(1): по ключу сразу ясно, в какую корзину смотреть. Но если много ключей попало в одну корзину, её придётся перебирать, и в худшем случае поиск займёт O(n). Хорошие реализации следят за этим и вовремя увеличивают число корзин. Map в JavaScript на практике работает именно так, хотя стандарт требует лишь «в среднем быстрее, чем перебор». Ключи-объекты в Map сравниваются по ссылке: два одинаковых на вид объекта — разные ключи.

function frequencies(values) {
  const counts = new Map();
  for (const value of values) {
    counts.set(value, (counts.get(value) ?? 0) + 1);
  }
  return counts;
}
console.log([...frequencies(['js', 'ts', 'js'])]);
// [['js', 2], ['ts', 1]]

При ожидаемых O(1) операциях Map этот подсчёт занимает ожидаемо O(n) времени и O(k) памяти для k различных значений. Сортировка для подсчёта не требуется.

Двоичная куча и очередь с приоритетом

Куча (min-heap) — дерево, где каждый родитель не больше своих детей. Поэтому самый маленький элемент всегда на вершине, и взять его можно сразу. Остальные лежат не по порядку: куча гарантирует только «родитель ≤ дети».

Дерево заполняется по уровням слева направо без пропусков, поэтому его удобно хранить в обычном массиве. У элемента с индексом i дети лежат на позициях 2i + 1 и 2i + 2. Например, у корня (индекс 0) дети — 1 и 2, у элемента 1 — 3 и 4.

Чтение минимума — O(1), вставка с подъёмом и извлечение минимума с просеиванием — O(log n) в худшем случае, поиск произвольного значения — O(n). В заметке для вставки указано O(1); для обычной двоичной кучи это неверно как общая оценка худшего случая. Приоритетная очередь выдаёт элемент по приоритету, а не по времени прихода.

Граф, BFS и DFS

Граф состоит из вершин и рёбер: например, остановок и маршрутов. Рёбра могут быть направленными и иметь веса. В списке смежности для каждой вершины хранят соседей, в матрице смежности — таблицу V × V. Первая обычно требует O(V + E) памяти, вторая O(V²).

Из общих знаний: BFS идёт слоями с очередью, DFS углубляется с помощью стека или рекурсии. Чтобы не зациклиться, отмечают посещённые вершины. Со списком смежности полный обход занимает O(V + E); старт из одной вершины посещает только достижимую часть. BFS находит кратчайший путь по числу рёбер в невзвешенном графе, но не решает автоматически задачу с произвольными весами.
