Массивы: индексы, проходы и границы

Массив хранит последовательность с индексами от 0 до length − 1. Зная индекс, можно сразу обратиться к нужной позиции. Чтобы найти значение без дополнительных сведений, обычно приходится перебирать элементы.

Стоимость основных операций

  • Взять по индексу arr[5] — O(1): позиция вычисляется сразу.
  • Найти значение arr.indexOf(x) — O(n): придётся смотреть элементы по очереди.
  • Добавить в конец push — амортизированно O(1) (что это значит, сказано в разделе про Big O).
  • Вставить или удалить в начале или середине (unshift, splice) — до O(n): все элементы правее приходится сдвигать.

В таблице модуля вставка в середину выглядит как запрещённая операция. Это не так: она разрешена, просто дороже.

Из общих знаний: массив в JavaScript устроен свободнее, чем в учебнике по алгоритмам. В нём могут быть «дыры» ([1, , 3]) и значения разных типов, а стандарт языка не обещает именно такие оценки. Для обычных массивов чисел или объектов они на практике верны.

Ещё одна ловушка: одни методы создают новый массив, а другие меняют старый. slice возвращает копию куска и исходник не трогает. splice и sort меняют сам массив.

Линейный поиск и инвариант цикла

Как убедиться, что такой цикл верен? Найти утверждение, которое правдиво на каждом шаге. Здесь оно такое: «все элементы левее i уже проверены, и искомого среди них нет». Перед первым шагом это верно (левее нуля ничего нет), и каждый шаг это сохраняет. Значит, при совпадении можно сразу вернуть индекс, а если цикл закончился — честно вернуть −1. Такое утверждение называют инвариантом цикла.

function linearSearch(items, target) {
  for (let i = 0; i < items.length; i++) {
    if (items[i] === target) return i;
  }
  return -1;
}
console.log(linearSearch([8, 3, 8], 8)); // 0
console.log(linearSearch([], 8)); // -1

В худшем случае проверим n элементов: Θ(n) времени и O(1) памяти. Проверка i < items.length не обращается к позиции за концом. Для объектов === сравнивает ссылки, а не набор свойств.

Два указателя: убрать лишний перебор

Из общих знаний: найдём пару с заданной суммой в отсортированном по возрастанию массиве чисел. Начнём с краёв. Если сумма мала, сдвигаем левую границу: с прежним левым элементом и любым меньшим правым сумма тоже была бы мала. Если велика — сдвигаем правую.

function findPair(sorted, target) {
  let left = 0;
  let right = sorted.length - 1;
  while (left < right) {
    const sum = sorted[left] + sorted[right];
    if (sum === target) return [left, right];
    if (sum < target) left++;
    else right--;
  }
  return null;
}
console.log(findPair([1, 3, 4, 8], 7)); // [1, 2]

Каждый шаг уменьшает расстояние между указателями: O(n) времени, O(1) памяти. На неотсортированном входе доказательство не работает. Если сначала сортировать, нужно учесть стоимость сортировки и изменение индексов.
