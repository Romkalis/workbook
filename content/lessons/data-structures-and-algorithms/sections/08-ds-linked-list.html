Ссылки и связный список

В односвязном списке каждый узел хранит значение и ссылку next на следующий узел; последний ссылается на null. head указывает на первый узел. В JavaScript это ссылки на объекты, а не адреса, над которыми выполняют арифметику указателей.

Вставка после известного узла

Было A → C. Создадим B со ссылкой на C, затем направим A на B. Порядок важен: если сначала затереть ссылку A на C и не сохранить её, остаток списка можно потерять.

const head = { value: 'A', next: { value: 'C', next: null } };
const inserted = { value: 'B', next: head.next };
head.next = inserted;

function listValues(node) {
  const result = [];
  while (node !== null) {
    result.push(node.value);
    node = node.next;
  }
  return result;
}
console.log(listValues(head)); // ['A', 'B', 'C']
head.next = head.next.next; // удалить B после известного A
console.log(listValues(head)); // ['A', 'C']

Изменить пару ссылок — O(1), если нужный узел уже известен. Найти его по значению или индексу — O(n). Поэтому утверждение «вставка в список всегда O(1)» неполно. Удаление узла односвязного списка в общем случае требует знать его предшественника; добавление в конец без tail требует обхода.

Сбор значений в примере занимает O(n) времени и памяти результата. Дополнительная память самого обхода без результата — O(1). Предполагается, что список не содержит цикла: иначе такой обход не завершится.

Двусвязный список

Узел двусвязного списка дополнительно хранит prev. Можно идти в обе стороны и удалить известный узел без поиска предшественника, но при каждой правке нужно согласованно обновлять обе связи и крайние head/tail. Цена — дополнительная память и больше условий корректности.

Почему массив часто удобнее списка?

Доступ по индексу проще, а вставке в список часто всё равно предшествует поиск. Список полезен, когда алгоритм уже держит ссылки на нужные узлы и часто меняет связи. Выбирайте по операциям задачи, а не по одной строке таблицы сложностей.
