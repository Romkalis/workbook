Сортировки: сравниваем идеи и реализации

Сортировка упорядочивает данные по правилу сравнения. Устойчивый алгоритм сохраняет взаимный порядок элементов с равными ключами. Сортировка на месте использует небольшую дополнительную память; рекурсивный стек при этом тоже надо учитывать.

Пузырьковая сортировка

Сравниваем соседей слева направо и меняем их местами, если они стоят неверно. После первого прохода максимум оказался справа. После каждого следующего прохода неупорядоченная часть сокращается. Если обменов не было, можно закончить раньше.

function bubbleSort(input) {
  const items = [...input];
  for (let end = items.length - 1; end > 0; end--) {
    let swapped = false;
    for (let i = 0; i < end; i++) {
      if (items[i] > items[i + 1]) {
        [items[i], items[i + 1]] = [items[i + 1], items[i]];
        swapped = true;
      }
    }
    if (!swapped) break;
  }
  return items;
}
console.log(bubbleSort([4, 1, 3, 1])); // [1, 1, 3, 4]

С флагом swapped лучший случай Θ(n), худший Θ(n²). В примере сделана копия: память O(n), хотя сами обмены требуют O(1). В версии из заметки RS School раннего выхода нет, поэтому даже отсортированный вход требует Θ(n²).

Сортировка слиянием

Делим массив до отрезков длины 0 или 1, затем сливаем отсортированные половины. При слиянии сравниваем первые ещё не взятые элементы. Берём меньший, а когда одна половина кончилась, дописываем остаток другой.

function mergeSort(input) {
  if (input.length <= 1) return [...input];
  const mid = Math.floor(input.length / 2);
  const left = mergeSort(input.slice(0, mid));
  const right = mergeSort(input.slice(mid));
  const result = [];
  let i = 0;
  let j = 0;
  while (i < left.length && j < right.length) {
    if (left[i] <= right[j]) result.push(left[i++]);
    else result.push(right[j++]);
  }
  while (i < left.length) result.push(left[i++]);
  while (j < right.length) result.push(right[j++]);
  return result;
}
console.log(mergeSort([7, 2, 5, 2])); // [2, 2, 5, 7]

Слияние одного уровня обрабатывает суммарно n элементов, уровней около log₂ n. Получаем Θ(n log n) времени и O(n) пиковой дополнительной памяти; стек имеет глубину O(log n). Суммарно за выполнение выделяется больше памяти, чем одновременно удерживается.

Уточнение к реализации модуля

В заметке слияние использует shift(). В обычной модели массива удаление первого элемента требует сдвига остальных, что портит линейную стоимость слияния. Здесь используются индексы, а при равенстве берётся левый элемент — это сохраняет устойчивость.

Сортировка вставками

Так раскладывают карты в руке: берём следующую карту и сдвигаем её влево, пока слева не окажется карта не больше её. Левая часть массива всё время остаётся отсортированной, а правая ждёт своей очереди.

function insertionSort(items, key) {
  const result = [...items];
  for (let i = 1; i < result.length; i++) {
    const current = result[i];
    let j = i - 1;
    while (j >= 0 && key(result[j]) > key(current)) {
      result[j + 1] = result[j]; // сдвигаем больший вправо
      j--;
    }
    result[j + 1] = current;
  }
  return result;
}
const people = [{ name: 'Аня', age: 20 }, { name: 'Борис', age: 18 }, { name: 'Вера', age: 20 }];
console.log(insertionSort(people, (p) => p.age).map((p) => p.name).join(', '));
// Борис, Аня, Вера

Лучший случай Θ(n): на отсортированном входе внутренний цикл ни разу не сдвигает элементы. Худший Θ(n²): на обратном порядке каждый элемент едет в самое начало. Сравнение строгое (>), поэтому равные не перепрыгивают друг через друга, и сортировка устойчива: Аня и Вера с одинаковым возрастом остались в исходном порядке. Из общих знаний: на маленьких и почти отсортированных массивах вставки работают быстро, поэтому встроенные сортировки часто используют их для коротких кусков.

Быстрая сортировка и встроенный sort

Quick sort выбирает опорный элемент, разделяет значения относительно него и сортирует части. Опорный — не обязательно среднее арифметическое и не обязательно медиана. При удачных разбиениях время O(n log n). Если опорный элемент выбирать случайно, такое время получается в среднем: плохие разбиения бывают, но редко. В худшем случае, когда опорный раз за разом оказывается самым маленьким или самым большим, время O(n²). Память зависит от реализации: версии с новыми массивами не являются сортировками на месте.

Уточнение к реализации модуля

В заметке сказано, что опорным берётся средний элемент, но код берёт первый: p = arr[0]. На уже отсортированном массиве всё уходит в правую часть, разбиение каждый раз отрезает один элемент, и время становится Θ(n²). Глубина рекурсии тоже равна n. В Node.js 22 сортировка массива 0…19 999 этой функцией падала с ошибкой RangeError: Maximum call stack size exceeded. Обычные средства — случайный опорный элемент или медиана из трёх (первый, средний, последний).

// quickSort из заметки, без изменений
const sorted = Array.from({ length: 20000 }, (_, i) => i);
quickSort(sorted); // RangeError: Maximum call stack size exceeded

Из общих знаний: встроенный sort() без функции сравнения сортирует по строковому представлению, поэтому для чисел обычно передают (a, b) => a - b. Стандарт требует устойчивость, но не фиксирует конкретный алгоритм и его сложность. Для сохранения входа сортируйте копию.

const values = [10, 2, 1];
const sorted = [...values].sort((a, b) => a - b);
console.log(sorted); // [1, 2, 10]
console.log(values); // [10, 2, 1]

Устойчивость: кто сохраняет порядок равных

Устойчивость важна, когда сортируют записи, а не голые числа. Пусть список студентов уже отсортирован по имени, и теперь мы сортируем его по баллу. Устойчивая сортировка оставит студентов с равным баллом в алфавитном порядке, неустойчивая может их перемешать.

Bubble, вставки и merge устойчивы, если при равенстве не менять элементы местами (или при слиянии брать левый). Обычный quick sort на месте неустойчив: при разбиении элемент может перепрыгнуть через равный ему. Ниже пример: карты B1 и D1 равны по значению, во входе B стоит раньше D, а после быстрой сортировки (разбиение по схеме Ломуто: опорным берём последний элемент, идём слева направо и переносим всё, что меньше опорного, в начало, а в конце ставим опорный сразу за ними) порядок поменялся.

Встроенный Array.prototype.sort обязан быть устойчивым по стандарту ECMAScript 2019, поэтому на практике это обычно не ваша забота. Помнить об этом нужно, когда пишете сортировку сами.

Как отсортировать связный список

Quick sort и вставки любят прыгать по индексам, а у списка индексов нет: дойти до k-го узла стоит O(k). Сортировке слиянием прыжки не нужны. Ей достаточно разрезать список пополам и потом сливать две цепочки, переставляя ссылки next. Поэтому для связного списка стандартный выбор — merge sort за O(n log n), и ему даже не нужен дополнительный массив.

function sortList(head) {
  if (!head || !head.next) return head;
  // slow идёт по одному узлу, fast — по два: когда fast дойдёт до конца, slow будет в середине
  let slow = head;
  let fast = head.next;
  while (fast && fast.next) {
    slow = slow.next;
    fast = fast.next.next;
  }
  const right = slow.next;
  slow.next = null; // разрезали список на два
  return mergeLists(sortList(head), sortList(right));
}

function mergeLists(a, b) {
  const start = { next: null }; // временный узел-заглушка перед результатом
  let tail = start;
  while (a && b) {
    if (a.value <= b.value) { tail.next = a; a = a.next; }
    else { tail.next = b; b = b.next; }
    tail = tail.next;
  }
  tail.next = a ?? b; // остаток одной из цепочек
  return start.next;
}
// для списка 4 → 1 → 3 → 1 → 2 получится 1 → 1 → 2 → 3 → 4

Время Θ(n log n), как и у массива. Дополнительной памяти под элементы не нужно: узлы не копируются, меняются только ссылки. Остаётся стек рекурсии глубиной O(log n).
