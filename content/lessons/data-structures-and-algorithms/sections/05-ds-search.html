Бинарный поиск: каждый раз вдвое меньше

Если числа уже отсортированы по возрастанию, сравнение со средним элементом исключает половину диапазона. Поиск не сортирует данные сам. Для одного запроса на неотсортированном входе линейный поиск часто дешевле предварительной сортировки.

Замкнутый диапазон [left, right]

В начале возможный ответ находится между 0 и length − 1 включительно. Если середина меньше цели, новая левая граница — mid + 1; иначе правая — mid − 1. Проверенный mid больше не нужен, поэтому диапазон строго уменьшается.

function binarySearch(sorted, target) {
  let left = 0;
  let right = sorted.length - 1;
  while (left <= right) {
    const mid = left + Math.floor((right - left) / 2);
    if (sorted[mid] === target) return mid;
    if (sorted[mid] < target) left = mid + 1;
    else right = mid - 1;
  }
  return -1;
}
console.log(binarySearch([2, 5, 8, 12, 16, 23, 38], 23)); // 5

Худшее время O(log n), лучшее O(1), дополнительная память итеративной версии O(1). При дубликатах вернётся одно из совпадений, не обязательно первое. Рекурсивный вариант потребует O(log n) памяти стека вызовов в худшем случае.

Почему нельзя оставлять left = mid?

При двух соседних позициях округлённая середина может совпасть с left. Если присвоить left = mid, диапазон не изменится и цикл может не завершиться. Новая граница mid + 1 гарантирует продвижение.

Сколько шагов в худшем случае

Каждая проверка середины оставляет не больше половины диапазона. Значит, вопрос «сколько шагов» сводится к другому: сколько раз n можно поделить пополам, пока не останется один элемент, и ещё одна проверка на него. Это ⌊log₂ n⌋ + 1 (скобки ⌊ ⌋ означают округление вниз). Логарифм по основанию 2 отвечает на вопрос «в какую степень надо возвести двойку, чтобы получить n»: 2⁶ = 64, 2⁷ = 128, поэтому log₂ 100 ≈ 6,6.

Удобно запомнить ориентиры: 1000 элементов — не больше 10 шагов, миллион — не больше 20. При росте входа в тысячу раз работа выросла всего на 10 шагов. Это и есть логарифмический рост.

Бинарный поиск на неотсортированном массиве

Алгоритм опирается на одно обещание: всё, что левее середины, меньше её, а всё, что правее, больше. Если массив не отсортирован, обещание ложно, и выброшенная половина может содержать ответ. Функция при этом не сломается и не выдаст ошибку. Она вернёт неверный результат.
