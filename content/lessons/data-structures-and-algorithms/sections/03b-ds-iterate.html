Обход массива: циклы и методы

Почти любая задача на массив начинается с прохода по элементам. В JavaScript для этого есть обычный цикл for, цикл for...of и методы массива: forEach, map, filter, find, some, every, reduce. Все они делают проход за O(n), но отвечают на разные вопросы. Если выбрать метод по вопросу, код становится короче и понятнее.

Методу передают функцию, которую он вызывает для каждого элемента. Такую функцию называют колбэком (callback, «обратный вызов»). Колбэк, который возвращает true или false, называют предикатом: он отвечает на вопрос «подходит ли элемент?».

const scores = [72, 95, 40, 88];
console.log(scores.every((s) => s >= 40)); // true — все не меньше 40
console.log(scores.some((s) => s > 90)); // true — есть хотя бы один выше 90
console.log(scores.filter((s) => s >= 70)); // [72, 95, 88]
console.log(scores.map((s) => s / 100)); // [0.72, 0.95, 0.4, 0.88]
console.log(scores.find((s) => s < 50)); // 40
console.log(scores.reduce((sum, s) => sum + s, 0)); // 295
console.log(scores.forEach((s) => s)); // undefined

Несколько вещей, которые путают чаще всего:

  • every и some — пара. every — «для всех», some — «хотя бы для одного». У пустого массива every вернёт true (нет ни одного нарушителя), а some — false (нет ни одного подходящего). Метода check у массива нет.
  • forEach ничего не возвращает и не умеет останавливаться: return внутри колбэка завершает только текущий вызов. Если нужно прервать проход, берите for...of с break или подходящий метод вроде some/find.
  • map и filter создают новый массив и не меняют исходный. Это O(n) дополнительной памяти.
  • У reduce второй аргумент — начальное значение. Без него на пустом массиве будет ошибка TypeError.

Скрытый вложенный цикл

Метод выглядит как одна строка, но внутри него тоже цикл. Если внутри колбэка вызвать ещё один проход — includes, indexOf, find, — получится цикл в цикле. Для массивов длиной n и m это O(n · m), а при одинаковой длине — O(n²).

const allowed = ['ann', 'bob', 'eva'];
const users = ['bob', 'kim', 'eva'];

// includes перебирает allowed для каждого пользователя: O(n · m)
console.log(users.filter((u) => allowed.includes(u))); // ['bob', 'eva']

// Set проверяет наличие ожидаемо (в среднем) за O(1): всего O(n + m)
const allowedSet = new Set(allowed);
console.log(users.filter((u) => allowedSet.has(u))); // ['bob', 'eva']

На трёх элементах разницы не видно. На десяти тысячах это сто миллионов сравнений против двадцати тысяч операций. На код-ревью такие места ищут в первую очередь.

Set: только уникальные значения

Set — коллекция, в которой каждое значение встречается не больше одного раза. Повторное добавление ничего не меняет. Проверка has, добавление add и удаление delete работают ожидаемо за O(1), так же как у Map. Порядок перебора — порядок первого добавления.

console.log(new Set([1, 2, 2, 3, 1]).size); // 3
console.log([...new Set(['a', 'b', 'a'])]); // ['a', 'b'] — убрали дубликаты

Индексов у Set нет: спросить «третий элемент» нельзя. Из массива, Map и связного списка уникальность сама собой не следует — её пришлось бы проверять вручную. Объекты в Set, как и в Map, сравниваются по ссылке.
