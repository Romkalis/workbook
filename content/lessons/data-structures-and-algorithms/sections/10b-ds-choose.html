Как выбрать структуру под задачу

Структуры в этом уроке не соревнуются, «лучшей вообще» среди них нет. Каждая отвечает на свой вопрос быстро, а на остальные медленно. Поэтому выбор начинается с вопроса: какие операции в задаче будут самыми частыми?

Доступ по ключу: массив, Map или объект

Если ключи — номера 0, 1, 2, … без пропусков, это и есть индексы массива. Массив вычисляет место элемента по номеру сразу, без вычисления хеша и без поиска, это самый прямой доступ. Если же ключи — строки, или числа с пропусками (0, 4, 5, 100), массив становится неудобным. Ему придётся хранить «дыры», а его length будет говорить о самом большом индексе, а не о количестве записей. Для таких ключей берут Map или обычный объект: хеш-таблица находит запись по любому ключу ожидаемо за O(1). «Ожидаемо» значит «в среднем при нормальной хеш-функции»: подробнее в разделе про хеш-таблицу.

const sparse = [];
sparse[100] = 'c';
console.log(sparse.length); // 101 — хотя запись одна

const byId = new Map([[0, 'a'], [4, 'b'], [100, 'c']]);
console.log(byId.get(100)); // 'c'
console.log(byId.size); // 3 — ровно столько, сколько записей

Вложенные данные: объект и дерево

Настройки, JSON-ответ сервера, файловая система, DOM — во всех этих случаях внутри одной записи лежат другие записи. Это дерево: у каждого узла есть дочерние узлы. В JavaScript такое дерево естественно описывается вложенными объектами (или Map), а путь к значению читается по цепочке ключей.

const settings = { theme: { colors: { accent: '#e8340c' } }, editor: { tabSize: 2 } };
console.log(settings.theme.colors.accent); // '#e8340c'
console.log(settings.editor?.font?.size ?? 14); // 14 — свойства нет, берём значение по умолчанию

Плоский массив или Set так не умеют: в них нет вложенности по именам. Обходить такие данные удобно рекурсией: функция обрабатывает узел и вызывает себя для каждого дочернего.

Почему стек — это массив

Для стека нужны две операции на одном конце: положить сверху и снять сверху. У массива JavaScript ровно это делают push и pop, они работают с концом и ничего не сдвигают. Писать связный список для стека в JS не нужно, а Set и Map не подходят: у них нет понятия «верхний элемент», который можно снять.

В классическом стеке доступна только вершина: последний добавленный элемент. Его можно посмотреть (операцию часто называют peek) или снять (pop). До элемента под вершиной можно добраться, только сняв всё, что выше. Массив, конечно, позволяет прочитать stack[0], но тогда вы используете его как массив, а не как стек. Ограничение и есть смысл структуры: оно гарантирует порядок LIFO.

Обратите внимание на последнюю строку. Полный обход — единственная операция, в которой обе структуры гарантированно делают одно и то же количество работы, как бы их ни реализовали. Всё, что связано с номером элемента, у массива быстрее, всё, что связано с началом последовательности, у списка. Из общих знаний: даже при одинаковой оценке O(n) массив на практике обходится быстрее, потому что лежит в памяти подряд и лучше использует кэш процессора — маленькую быструю память, в которую процессор заранее подгружает соседние данные.
