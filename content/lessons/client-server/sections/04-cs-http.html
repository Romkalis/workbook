Протокол HTTP

HTTP (HyperText Transfer Protocol) — прикладной протокол передачи гипертекста. Задумывался для HTML-страниц, а сегодня возит что угодно: JSON (текстовый формат данных, похожий на объект JavaScript: {"login": "octocat"}), картинки, видео, шрифты. MDN в «An overview of HTTP» перечисляет его ключевые свойства, и лекции повторяют их.

Свойства HTTP

  • Простой и читаемый. Сообщения HTTP/1.x — обычный текст, который человек может прочитать и даже набрать руками. В HTTP/2 сообщения упаковываются в двоичные кадры, но смысл (метод, путь, заголовки) остаётся тем же.
  • Клиент-серверный и «тянущий» (pull). Разговор всегда начинает клиент. Сервер не может сам по себе прислать данные браузеру, который ни о чём не спрашивал. Для уведомлений в реальном времени используют обходные пути: периодический опрос, Server-Sent Events, WebSocket (постоянный двусторонний канал) (из общих знаний).
  • Без состояния (stateless). Протокол не помнит предыдущих запросов: каждый обрабатывается так, будто он первый. Поэтому сервер легко масштабировать: балансировщик (программа, которая распределяет входящие запросы между серверами) отправляет запросы на любой из пяти одинаковых серверов, и никому не нужно знать, что было раньше. Состояние (например, «пользователь вошёл») передают явно — куками или токеном в каждом запросе.
  • Расширяемый. Заголовки позволяют добавлять новые возможности, не меняя протокол: кеширование, сжатие, CORS, авторизация появились именно так.
  • Не привязан к транспорту, но требует надёжного. HTTP/1.1 и HTTP/2 работают поверх TCP, HTTP/3 — поверх QUIC.

Как проходит обмен

  1. Клиент открывает TCP-соединение (или переиспользует открытое).
  2. Отправляет HTTP-запрос.
  3. Читает ответ сервера.
  4. Закрывает соединение или оставляет для следующих запросов.

Запрос

GET /search/users?q=rolling HTTP/1.1
Host: api.github.com
User-Agent: Mozilla/5.0 (Macintosh; ...)
Accept: application/json
Accept-Language: ru,en;q=0.8
Accept-Encoding: gzip, br

Первая строка — стартовая: метод (GET), путь с query string, версия протокола. Дальше заголовки в формате Имя: значение, каждый на своей строке. Затем обязательная пустая строка и, если нужно, тело (body). У GET тела обычно нет; у POST, PUT, PATCH в теле лежат данные — JSON, поля формы, файл.

Задача 2. HTTP-запрос как текст ★★☆ практика

Напишите rawRequest({ method, url, headers, body }), которая собирает текст запроса HTTP/1.1: стартовая строка, заголовок Host из адреса, переданные заголовки, для тела — Content-Length в байтах, пустая строка, тело. Строки разделяются \r\n.

Зачем: HTTP/1.1 — это просто текст, и написать его руками — лучший способ понять, что отправляет fetch. Content-Length в символах вместо байтов — реальная ошибка: кириллица занимает два байта в UTF-8, и сервер обрежет тело.

Решение и разбор
export function rawRequest({ method, url, headers = {}, body }: { method: string; url: string; headers?: Record<string, string>; body?: string }): string {
  const u = new URL(url);
  const lines = [`${method} ${u.pathname}${u.search} HTTP/1.1`, `Host: ${u.host}`];
  for (const [name, value] of Object.entries(headers)) lines.push(`${name}: ${value}`);
  if (body !== undefined) lines.push(`Content-Length: ${Buffer.byteLength(body, 'utf8')}`);
  return lines.join('\r\n') + '\r\n\r\n' + (body ?? '');
}

В стартовой строке — только путь и строка запроса, без домена: домен уходит в обязательный в HTTP/1.1 заголовок Host. По нему один сервер обслуживает много сайтов на одном IP. u.host включает порт, если он нестандартный. Пустая строка (\r\n\r\n) отделяет заголовки от тела, и без неё сервер ждал бы продолжения заголовков. Следующая задача отправляет такой текст настоящему серверу.

Ответ

HTTP/1.1 200 OK
Date: Sat, 14 Nov 2026 10:51:24 GMT
Content-Type: application/json; charset=utf-8
Content-Encoding: gzip
Cache-Control: private, max-age=60
Content-Length: 1082

{"total_count":42,"items":[...]}

Стартовая строка ответа: версия, код состояния (200) и его текстовое пояснение (OK). Дальше заголовки ответа, пустая строка и тело.

HTTP руками: telnet и curl

В лекции по HTTP (слайды) показано, что запрос действительно просто текст. Через telnet www.google.com 80 можно открыть TCP-соединение, набрать GET /index.html HTTP/1.1, заголовок Host, нажать Enter дважды и получить в ответ HTML. Telnet сегодня почти не используется и на macOS по умолчанию не установлен; показан он для понимания.

Удобнее curl: он сам собирает запрос. Лектор удивился, что curl не показал заголовки ответа: для этого нужен флаг -i (заголовки и тело) или -I (только заголовки, методом HEAD), а -v показывает и заголовки запроса:

curl -I https://example.com
curl -i https://api.github.com/search/users?q=rolling
curl -v https://example.com -o /dev/null

Команда curl -I https://example.com на момент написания вернула первую строку HTTP/2 200: curl по возможности договаривается с сервером о HTTP/2.

Задача 3. HTTP без fetch: через TCP-сокет ★★☆ практика

Повторите опыт с telnet в коде: напишите sendRaw(host, port, text) на модуле node:net, которая открывает TCP-соединение, отправляет текст запроса и возвращает весь ответ строкой. Затем statusOf(response) — код из первой строки ответа. В тесте запрос уходит на настоящий HTTP-сервер Node, запущенный рядом.

Зачем: это прямое доказательство, что HTTP — текстовый протокол поверх TCP. Сокет ничего не знает о методах и заголовках, он передаёт байты. Всё, что делает fetch, — аккуратно собирает этот текст и разбирает ответ.

Подсказка

Отправьте запрос с заголовком Connection: close: тогда сервер закроет соединение после ответа, и событие end у сокета сообщит, что ответ получен целиком.

Решение и разбор
import net from 'node:net';

export function sendRaw(host: string, port: number, text: string): Promise<string> {
  return new Promise((resolve, reject) => {
    const socket = net.createConnection({ host, port }, () => socket.write(text));
    const chunks: Buffer[] = [];
    socket.on('data', (chunk: Buffer) => chunks.push(chunk));
    socket.on('end', () => resolve(Buffer.concat(chunks).toString('utf8')));
    socket.on('error', reject);
  });
}

export function statusOf(response: string): number {
  const match = /^HTTP\/\d(?:\.\d)? (\d{3})/.exec(response);
  if (!match) throw new Error('Не похоже на HTTP-ответ');
  return Number(match[1]);
}

Куски ответа собираются в массив Buffer и склеиваются в конце: многобайтовый символ может разрезаться между двумя кусками, и склейка строк по кускам его бы испортила. Без Connection: close соединение HTTP/1.1 остаётся открытым (keep-alive), и end не наступит. Тогда конец ответа определяют по Content-Length, как это и делают настоящие клиенты.
