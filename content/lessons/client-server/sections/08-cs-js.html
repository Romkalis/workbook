Запросы из JavaScript

AJAX

Раньше сайты были многостраничными: каждое действие (отправка формы, клик по ссылке) уходило на сервер, и он присылал целую новую страницу. Вторая часть вебинара начинается с AJAX (Asynchronous JavaScript and XML) — подхода, при котором JavaScript отправляет запрос в фоне и обновляет только часть страницы, без перезагрузки. На этом построены одностраничные приложения (SPA). Слово XML осталось в названии исторически: сегодня почти всегда передают JSON.

Минусы, которые называет лектор: без JavaScript ничего не работает; нужно настраивать CORS для запросов на другие домены; поисковики хуже индексируют контент, который появляется только после запросов. Последняя проблема уменьшилась (Google выполняет JS), но для важных для SEO страниц всё равно выбирают рендеринг на сервере (SSR).

XMLHttpRequest

Исторический API для AJAX. Пример со слайдов лекции:

const xhr = new XMLHttpRequest();
xhr.open('GET', '/');
xhr.send();
xhr.onload = function () {
  if (xhr.status !== 200) {
    console.log(`Error: ${xhr.status}: ${xhr.statusText}`);
  } else {
    console.log(`Response: ${xhr.response}`);
  }
};
xhr.onerror = function () {
  console.log('Request failed');
};

Колбэки, много строк, неудобная обработка ошибок. В новом коде XHR не пишут, но встретить его можно в старых проектах и в библиотеке Axios, которая в браузере работает поверх XHR. Одна из причин, по которой его ещё используют, — событие прогресса загрузки файла (xhr.upload.onprogress), которого у fetch до сих пор нет в удобном виде (из общих знаний).

Промисы за пять минут

Сетевой запрос долгий, а JavaScript не должен замирать в ожидании. Поэтому fetch сразу возвращает промис — объект, который сейчас в состоянии pending (ожидание), а потом перейдёт в fulfilled (выполнен, есть значение) или rejected (ошибка). Обработчики вешаются через .then и .catch, и выполняются позже, когда результат готов; код ниже продолжает работать, не дожидаясь.

console.log(1);
fetch('/api/user').then(() => console.log(3));
console.log(2);
// 1, 2, 3

Если из .then вернуть значение, оно станет аргументом следующего .then. Если вернуть промис — следующий .then дождётся его. На этом стоит цепочка fetch(url).then(r => r.json()).then(data => ...): response.json() тоже асинхронный, потому что тело ответа приходит потоком (ReadableStream) и его нужно дочитать.

async/await — синтаксис поверх тех же промисов: await приостанавливает только текущую async-функцию до результата промиса, остальная программа продолжает работать. Лектор пользуется async/await почти всегда; технической разницы с цепочками нет. Подробнее о промисах и цикле событий — на learn.javascript.ru, его советуют в вебинаре.

fetch

fetch(url, options) — современный встроенный API. Второй аргумент необязателен; по умолчанию метод GET.

const response = await fetch('/api/users', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ name: 'Аня' }),
});

Объект Response содержит status, statusText, ok (true для 200–299), headers, url, redirected и методы для чтения тела: json(), text(), blob(), formData(), arrayBuffer(). Тело можно прочитать только один раз. Если вызвать json() на HTML-странице, получите SyntaxError: Unexpected token '<' — лектор показывает это на запросе к google.com.

Главная ловушка: fetch не бросает ошибку на 404 и 500

В вебинаре запрос к GitHub без параметра q вернул 422, а сработал .then, а не .catch. С точки зрения fetch ответ получен, значит, промис выполнен. Отклоняется он только при сетевой ошибке (нет соединения, DNS не нашёл адрес, CORS заблокировал ответ) или отмене. Статус нужно проверять самому:

async function getJson(url) {
  const response = await fetch(url);
  if (!response.ok) {
    throw new Error(`HTTP ${response.status}`);
  }
  return response.json();
}

try {
  const user = await getJson('http://localhost:8001/api/user');
  console.log(user);
} catch (error) {
  console.log('Ошибка:', error.message);
}

Запуск в Node.js 22 против локального сервера: для существующего адреса вывелось { login: 'octocat' }, для несуществующего — Ошибка: HTTP 404. Голый fetch на тот же адрес вернул объект со status = 404 и ok = false, без исключения. Запрос на закрытый порт отклонился с TypeError: fetch failed — это и есть сетевая ошибка.

Пример из вебинара: поиск пользователей GitHub

Лектор пишет функцию поиска через GitHub Search API и выводит логины списком. Версия с async/await и проверкой статуса:

async function searchUsers(query) {
  const url = `https://api.github.com/search/users?q=${encodeURIComponent(query)}`;
  const response = await fetch(url);
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  const { items } = await response.json();
  return items.map((user) => user.login);
}

function renderLoginList(logins) {
  const list = document.createElement('ul');
  for (const login of logins) {
    const item = document.createElement('li');
    item.textContent = login;
    list.append(item);
  }
  document.body.append(list);
}

searchUsers('rolling-scopes').then(renderLoginList).catch(console.error);

Функция searchUsers запущена в Node.js 22 и вернула ['rolling-scopes', 'rolling-scopes-school', 'Rolling-Scopes-School-Team'] первыми тремя результатами (выдача со временем меняется). Запрос без q вернул 422 Validation Failed. Список добавляется в DOM одним append; если списков много, слушатели вебинара справедливо советуют собирать их в DocumentFragment. Без авторизации GitHub разрешает около 10 поисковых запросов в минуту, поэтому при активной отладке можно получить 403 с сообщением о лимите.

Отменить fetch можно: лектор сказал, что нельзя, но AbortController давно поддерживается всеми браузерами. fetch(url, { signal: controller.signal }), затем controller.abort() — и промис отклонится с AbortError. Для тайм-аута есть AbortSignal.timeout(5000).

Библиотеки и инструменты

Слайды лекции называют Axios для фронтенда, got и node-fetch для Node.js. Сегодня в Node.js 18+ fetch встроен, и node-fetch не нужен. Axios по-прежнему популярен за удобства: сам бросает ошибку на 4xx/5xx, сам разбирает JSON, умеет перехватчики (interceptors) для токенов. Аргумент из лекции про то, что fetch в разных браузерах работает по-разному, устарел: он одинаково поддерживается всеми современными браузерами.

Postman — приложение для ручных запросов: выбрать метод, URL, query-параметры, заголовки, тело (raw JSON), посмотреть ответ, статус, время, куки. Запросы сохраняются в коллекции и передаются коллегам; на вкладке Tests можно проверять ответ (например, что статус 200). Postman не браузер, поэтому CORS на него не действует — этим объясняется классическая ситуация «в Postman работает, а в браузере нет». Альтернативы: Insomnia, Bruno, расширение Thunder Client для VS Code, файлы .http в редакторе.

Вкладка Network в DevTools показывает все запросы страницы. Полезное:

  • Фильтр Fetch/XHR оставляет только запросы из JavaScript.
  • Preserve log не очищает список при переходе или редиректе.
  • Disable cache отключает кеш, пока DevTools открыты: видно, как страница грузится у нового посетителя.
  • У запроса: Headers (статус, заголовки запроса и ответа), Payload (тело и query), Preview (отформатированный JSON), Response (сырой текст, по нему удобно искать), Timing (DNS, соединение, ожидание, загрузка).
  • Столбец Protocol (включается правым кликом по заголовку таблицы) показывает http/1.1, h2 или h3.
  • Throttling эмулирует медленную сеть.
