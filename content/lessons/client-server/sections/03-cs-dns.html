URL и DNS: как найти сервер

Из чего состоит URL

URL (Uniform Resource Locator) говорит, по какому протоколу, к какому серверу и за каким ресурсом идти.

https://api.github.com:443/search/users?q=rolling&per_page=5#top
└─┬─┘   └─────┬──────┘ └┬┘└─────┬─────┘ └─────────┬────────┘ └┬┘
схема       хост      порт   путь        строка запроса     фрагмент
  • Схема — протокол: http, https, ws, file.
  • Хост — доменное имя или IP-адрес сервера.
  • Порт — номер «двери» на сервере. Если не указан, берётся стандартный: 80 для HTTP, 443 для HTTPS.
  • Путь — какой ресурс нужен на сервере.
  • Строка запроса (query string) начинается с ?, пары ключ=значение разделяются &. Значения с пробелами и кириллицей нужно кодировать: encodeURIComponent('рыжий кот') или URLSearchParams.
  • Фрагмент после # на сервер не отправляется: это якорь внутри страницы, его читает только браузер.

Схема, хост и порт вместе называются origin (источник). Это понятие понадобится в разделе про CORS.

DNS: имя превращается в адрес

Маршрутизаторы знают только IP-адреса вроде 140.82.121.6. Имена нужны людям: github.com проще запомнить и продиктовать. Превращает имя в адрес DNS (Domain Name System) — распределённая иерархическая система серверов.

Браузер сначала смотрит в свои кеши: собственный, операционной системы и файл hosts. Если ответа нет, запрос уходит к DNS-резолверу (серверу, который ищет адрес за вас) (обычно провайдера, или публичному вроде 1.1.1.1). Резолвер, если сам не знает ответа, идёт по иерархии: корневой сервер подсказывает, кто отвечает за зону .com, тот — кто отвечает за github.com, а авторитетный сервер домена возвращает адрес. Ответ кешируется на время, указанное в записи (TTL), поэтому полный путь проходится редко.

В лекции это сказано так: «если сервер не знает, он идёт выше по иерархии». Это упрощение: на деле резолвер спускается сверху вниз от корня, а не поднимается. Для фронтендера важен итог — первый запрос к новому домену платит за DNS, повторные берут адрес из кеша. Если имя не существует, браузер показывает ошибку вида DNS_PROBE_FINISHED_NXDOMAIN.

Файл hosts

В каждой системе есть файл hosts (на macOS и Linux — /etc/hosts, на Windows — C:\Windows\System32\drivers\etc\hosts), где можно вручную сопоставить имени адрес. Он проверяется раньше DNS. Лектор использует его, чтобы открывать локальный сервер под «красивым» именем вроде local.myapp.com вместо localhost: так локальная версия получает такие же куки и хранилище, как домен проекта. Вредоносные программы раньше подменяли hosts, чтобы отправить человека на поддельный сайт банка.

127.0.0.1   local.myapp.com
