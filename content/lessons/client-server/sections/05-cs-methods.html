Методы HTTP

Метод говорит серверу, что клиент хочет сделать с ресурсом. Стандартных методов девять, на практике постоянно встречаются пять-шесть.

МетодНазначениеТело запросаБезопасныйИдемпотентный
GETПолучить ресурснетдада
HEADКак GET, но только заголовки (узнать размер, дату изменения)нетдада
POSTСоздать ресурс или выполнить действие, отправить данныеданетнет
PUTЗаменить ресурс целиком (или создать по известному адресу)данетда

CONNECT, TRACEТуннель через прокси (сервер-посредник между клиентом и целевым сервером), отладочное эхо———

Безопасный метод не меняет данные на сервере: его можно вызывать сколько угодно, ничего не сломав. Идемпотентный даёт тот же итоговый результат при повторе: удалить пользователя №5 один раз или три раза — в итоге его нет. А три одинаковых POST «создать заказ» создадут три заказа. Поэтому браузер спрашивает «Отправить форму повторно?» при обновлении страницы после POST. Безопасные методы всегда идемпотентны. Термины в лекциях не звучат (вебинар упоминает «идемпотентность» лишь в списке тем на потом), но без них разница между PUT и POST неясна, поэтому они добавлены из общих знаний.

PUT или PATCH

Есть профиль { "name": "Аня", "city": "Минск", "age": 20 }. PUT /users/5 с телом { "name": "Аня", "city": "Гродно" } по смыслу заменяет ресурс целиком, и поле age пропадёт. PATCH /users/5 с телом { "city": "Гродно" } меняет только город. Как именно ведёт себя конкретный API, написано в его документации: не все серверы строго следуют этим правилам.

GET или POST

  • Параметры GET лежат в URL: они видны в истории, логах серверов и попадают в закладки. Пароли и личные данные туда класть нельзя.
  • Длина URL ограничена (браузеры и серверы режут по-разному, ориентир — несколько тысяч символов), поэтому большие данные отправляют в теле POST.
  • Ответы на GET можно кешировать, ответы на POST браузер обычно не кеширует.

HTML-форма как POST-запрос

Самый старый способ отправить POST — обычная форма. Браузер собирает значения полей по их атрибутам name и отправляет запрос на адрес из action методом из method, после чего загружает ответ как новую страницу.

<form action="/login" method="post">
  <input name="email" type="email">
  <input name="password" type="password">
  <button>Войти</button>
</form>

В вебинаре сказано, что так «уже не делают». Это не совсем так: обычные формы без JavaScript снова в моде во фреймворках вроде Remix и Next.js (Server Actions), потому что работают даже до загрузки скриптов. В одностраничных приложениях форму перехватывают: event.preventDefault(), затем fetch с new FormData(form), без перезагрузки.
