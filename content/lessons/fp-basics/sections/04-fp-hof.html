Функции первого класса и функции высшего порядка

В JavaScript функции — граждане первого класса (first-class functions): с функцией можно делать всё то же, что с числом или строкой. Положить в переменную, передать аргументом, вернуть из другой функции, хранить в массиве.

const greet = (name) => `Привет, ${name}`; // функция в переменной
const actions = [greet, (name) => name.toUpperCase()]; // в массиве
actions.map((fn) => fn('Аня')); // ['Привет, Аня', 'АНЯ']

Функция высшего порядка (higher-order function, HOF) — функция, которая принимает другую функцию аргументом или возвращает функцию. Функцию, которую передали аргументом, называют колбэком.

// Принимает функцию и возвращает новую
const twice = (fn) => (x) => fn(fn(x));
const inc = (x) => x + 1;
twice(inc)(5); // 7

Самые частые HOF — методы массивов: map (преобразовать каждый элемент), filter (оставить подходящие), reduce (свернуть в одно значение), some, every, find. Функция, которая возвращает true или false, называется предикатом: filter и every принимают предикаты.

Как устроены map и filter

Две задачи Codewars из модуля просят написать map и filter самостоятельно. Вот чистые версии через reduce:

const map = (arr, fn) =>
  arr.reduce((acc, x, i) => [...acc, fn(x, i, arr)], []);

const filter = (arr, predicate) =>
  arr.reduce((acc, x, i) => (predicate(x, i, arr) ? [...acc, x] : acc), []);

map([1, 2, 3], (x) => x * 2);          // [2, 4, 6]
filter([1, 2, 3, 4], (x) => x % 2 === 0); // [2, 4]

reduce идёт по массиву и каждый раз передаёт в колбэк «накопленное» (acc) и текущий элемент. Что вернёт колбэк, то станет новым acc. Второй аргумент reduce — начальное значение, здесь пустой массив.

Копирование [...acc, x] на каждом шаге делает эти версии O(n²) по времени (см. Big O в уроке «Алгоритмы и структуры данных»). Для учебного примера это неважно, а встроенные map и filter работают за O(n). Внутри своей функции мутировать локальный массив, который никто снаружи не видит, допустимо: чистота оценивается снаружи.

Задача 7. Свой reduce, а из него map и filter ★★☆ практика

Напишите reduce(list, fn, initial) без встроенного Array.prototype.reduce, а затем map и filter — только через свой reduce. Колбэк получает аккумулятор, элемент и индекс. Все функции чистые.

Зачем: reduce — самая общая операция над списком: через неё выражаются map, filter, some, groupBy. Если написать её самому, перестаёт пугать запись arr.reduce((acc, x) => …, {}) в чужом коде.

Решение и разбор
export function reduce<T, A>(list: readonly T[], fn: (acc: A, item: T, index: number) => A, initial: A): A {
  let acc = initial;
  for (let i = 0; i < list.length; i++) acc = fn(acc, list[i]!, i);
  return acc;
}

export const map = <T, R>(list: readonly T[], fn: (item: T, index: number) => R): R[] =>
  reduce<T, R[]>(list, (acc, item, i) => [...acc, fn(item, i)], []);

export const filter = <T>(list: readonly T[], pred: (item: T) => boolean): T[] =>
  reduce<T, T[]>(list, (acc, item) => (pred(item) ? [...acc, item] : acc), []);

Цикл внутри reduce — нормально: чистота касается того, что видно снаружи. Функция не меняет вход и не зависит от внешнего состояния. [...acc, x] на каждом шаге создаёт новый массив, и на больших списках это квадратичная сложность. Встроенный map так не делает. Здесь выбрана наглядность, а в рабочем коде внутри своей функции можно безопасно делать push в локальный массив: снаружи этого не видно.

Замыкание

Когда функция возвращает другую функцию, внутренняя помнит переменные внешней даже после того, как внешняя завершилась. Это называется замыканием (closure). На замыканиях держатся каррирование и мемоизация, поэтому разберём на счётчике:

const createCounter = () => {
  let count = 0;           // живёт в замыкании
  return () => ++count;
};

const counter = createCounter();
counter(); // 1
counter(); // 2
counter(); // 3
createCounter()(); // 1 — у нового счётчика своя переменная

Снаружи до count не добраться, изменить его можно только через возвращённую функцию. Обратите внимание: counter не чистая — одинаковый вызов без аргументов возвращает разное. Замыкание — инструмент, а не гарантия чистоты. Подробнее о замыканиях и областях видимости — в учебнике learn.javascript.ru.

Задача 6. groupBy и countBy ★★☆ практика

Напишите чистые groupBy(list, keyFn) → Record<string, T[]> и countBy(list, keyFn) → Record<string, number>. Сравните с встроенным Object.groupBy: что он возвращает и почему у результата нет прототипа?

Зачем: группировка — частая операция: товары по категориям, заказы по статусу, задачи по колонкам доски. Функция высшего порядка принимает правило группировки параметром, и одна реализация обслуживает все случаи.

Решение и разбор
export function groupBy<T>(list: readonly T[], keyFn: (item: T) => string): Record<string, T[]> {
  const groups: Record<string, T[]> = Object.create(null);
  for (const item of list) (groups[keyFn(item)] ??= []).push(item);
  return groups;
}

export const countBy = <T>(list: readonly T[], keyFn: (item: T) => string): Record<string, number> =>
  Object.fromEntries(Object.entries(groupBy(list, keyFn)).map(([k, items]) => [k, items.length]));

Объект без прототипа (Object.create(null)) — тот же выбор, что у Object.groupBy: ключ "toString" или "__proto__" из данных не столкнётся со свойствами Object.prototype. Object.groupBy и Map.groupBy есть в Node 21+ и современных браузерах, а в Node 20 их нет. Мутация push внутри функции не нарушает чистоту: массивы созданы здесь же, и снаружи их до возврата никто не видел.

Задача 8. Счётчик на замыкании ★☆☆ разминка

Напишите createCounter(step = 1), которая возвращает объект с методами next(), reset() и value(). Значение счётчика недоступно снаружи иначе, чем через методы. Два счётчика независимы.

Зачем: замыкание даёт настоящую приватность без классов: переменную нельзя поменять в обход методов. Это тот же механизм, что у генератора id в задании core-js-functions, и основа паттерна «модуль».

Решение и разбор
export function createCounter(step = 1) {
  let count = 0;
  return {
    next: () => (count += step),
    reset: () => {
      count = 0;
    },
    value: () => count,
  };
}

Переменная count живёт в окружении вызова createCounter, и у каждого вызова оно своё. В отличие от #private-полей класса, здесь нет даже имени поля, к которому можно обратиться. next возвращает новое значение: присваивание count += step — выражение со значением. Счётчик не чистый, у него есть состояние. Замыкание инкапсулирует эффект, а не убирает его.
