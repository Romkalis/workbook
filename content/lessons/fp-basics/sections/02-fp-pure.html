Чистые функции

Функция чистая, если выполняются два условия:

  1. При одинаковых аргументах она всегда возвращает одинаковый результат.
  2. У неё нет побочных эффектов — она ничего не меняет за своими пределами.
// Чистая: результат зависит только от a и b
const add = (a, b) => a + b;
add(2, 3); // 5
add(2, 3); // 5 — и так всегда

// Нечистая: читает и меняет внешнюю переменную
let total = 0;
const addToTotal = (x) => {
  total += x;
  return total;
};
addToTotal(5); // 5
addToTotal(5); // 10 — аргумент тот же, результат другой

Что считается побочным эффектом

Побочный эффект — любое действие функции, которое заметно снаружи, кроме возврата значения. Статья freeCodeCamp из материалов модуля перечисляет:

  • изменение входных аргументов (мутация);
  • console.log;
  • HTTP-запросы (fetch);
  • работу с файловой системой;
  • обращение к DOM.

Сюда же относятся запись в localStorage, изменение глобальных переменных и таймеры. Нарушить первое условие могут и «безобидные» чтения: Math.random() и Date.now() возвращают разное при каждом вызове, поэтому функция, которая их вызывает, нечистая.

Задача 1. Сделайте функцию чистой ★☆☆ разминка

Функция ниже добавляет товар в корзину. Найдите все побочные эффекты и перепишите её чистой: тот же вход — тот же результат, ничего снаружи не меняется. Время добавления передайте параметром.

let lastAdded = '';
export function addToCart(cart: { items: { id: string; at: number }[] }, id: string) {
  cart.items.push({ id, at: Date.now() });
  lastAdded = id;
  console.log('added', id);
  return cart;
}

Зачем: чистую функцию можно проверить одним сравнением, безопасно вызвать дважды и не бояться, что она испортит чужие данные. Эффекты (время, лог, внешняя переменная) никуда не исчезают, но переезжают на край программы, где их видно.

Решение и разбор
export interface Cart {
  readonly items: readonly { id: string; at: number }[];
}

export function addToCart(cart: Cart, id: string, at: number): Cart {
  return { ...cart, items: [...cart.items, { id, at }] };
}

Эффектов было четыре: мутация аргумента (push), чтение текущего времени, запись во внешнюю переменную и вывод в консоль. Время стало параметром, а остальное — заботой вызывающего кода: const next = addToCart(cart, id, Date.now()); log(next). Типы readonly делают обещание «не меняю» проверяемым: cart.items.push внутри теперь не скомпилируется.

Самая частая ловушка: мутация аргумента

const addItem = (cart, item) => {
  cart.push(item); // меняем массив, который нам передали
  return cart;
};

const cart = ['молоко'];
const newCart = addItem(cart, 'хлеб');
console.log(cart);           // ['молоко', 'хлеб'] — исходный тоже изменился!
console.log(cart === newCart); // true — это один и тот же массив

// Чистая версия: возвращаем новый массив
const addItemPure = (cart, item) => [...cart, item];
const cart2 = ['молоко'];
addItemPure(cart2, 'хлеб'); // ['молоко', 'хлеб']
console.log(cart2);          // ['молоко'] — не тронут

Массивы и объекты передаются в функцию по ссылке: функция получает не копию, а адрес того же самого массива. Поэтому push внутри меняет данные вызывающего кода. Подробнее об этом — в следующем разделе.

Задача 2. Сортировка, которая портила данные ★☆☆ разминка

Функция возвращает три самых дорогих товара, но после её вызова каталог на странице переупорядочивается. Исправьте двумя способами: через копию и через неизменяющий метод массива.

export function top3(products: { price: number }[]) {
  return products.sort((a, b) => b.price - a.price).slice(0, 3);
}

Зачем: sort, reverse и splice меняют массив на месте и возвращают его же. Выглядит как функция «получи отсортированное», а на деле переставляет данные всех, у кого есть ссылка на этот массив.

Решение и разбор
export function top3(products: readonly { price: number }[]) {
  return [...products].sort((a, b) => b.price - a.price).slice(0, 3);
}

export function top3Modern(products: readonly { price: number }[]) {
  return products.toSorted((a, b) => b.price - a.price).slice(0, 3);
}

toSorted, toReversed, toSpliced и with появились в ES2023: они возвращают новый массив и не трогают исходный. Есть в Node 20+ и всех современных браузерах. Параметр readonly делает исходную версию с sort ошибкой компиляции: метод sort у readonly-массива просто отсутствует.

Без эффектов программа бесполезна

Программа, которая ничего не выводит и никуда не пишет, никому не нужна. Цель не в том, чтобы убрать эффекты, а в том, чтобы отодвинуть их на края: расчёты — в чистых функциях, а ввод, вывод, сеть и DOM — в тонком слое вокруг них. Приём «передать нечистое параметром» помогает тестировать:

// Нельзя проверить: результат случайный
const rollDice = () => Math.floor(Math.random() * 6) + 1;

// Можно: источник случайности передаётся снаружи
const rollDiceWith = (random) => Math.floor(random() * 6) + 1;
rollDiceWith(() => 0);    // 1
rollDiceWith(() => 0.99); // 6
rollDiceWith(Math.random); // в игре — настоящая случайность
Чистая ли функция const greet = (name) => console.log('Привет, ' + name)?

Нет. Вывод в консоль — побочный эффект, а возвращает она всегда undefined. Чистая версия возвращает строку, а вызывающий код сам решает, выводить её или нет: const greet = (name) => 'Привет, ' + name.
