Иммутабельность

Иммутабельность (неизменяемость) — правило «данные не меняем, а создаём новые». Нужно поменять поле — делаем копию объекта с новым значением, а старый оставляем как был.

Значения и ссылки

В JavaScript два вида данных:

  • Примитивы — числа, строки, булевы значения, null, undefined, symbol, bigint. Они неизменяемы сами по себе: 'abc'.toUpperCase() не меняет строку, а возвращает новую 'ABC'.
  • Объекты, в том числе массивы и функции. Они изменяемы, а переменная хранит не сам объект, а ссылку на него.
const a = { count: 1 };
const b = a;     // скопировалась ссылка, объект один
b.count = 2;
console.log(a.count); // 2

Статья о мутабельности из материалов модуля пишет, что у примитивов «нет свойств и методов». Это неточно: у строк и чисел есть методы ('abc'.toUpperCase()), JS временно оборачивает примитив в объект. Верная формулировка: примитив нельзя изменить. Попытка str[0] = 'z' в обычном скрипте молча ничего не сделает, а в модуле или в 'use strict' бросит TypeError (проверено в Node 22).

const не делает объект неизменяемым

const settings = { theme: 'light' };
settings.theme = 'dark'; // можно!
settings = {};           // TypeError: Assignment to constant variable

const запрещает переприсвоить переменную, но не менять объект, на который она указывает.

Копирование: поверхностное и глубокое

Spread-синтаксис ... «распаковывает» объект или массив в новый: { ...user }, [...list]. Но копия поверхностная: вложенные объекты остаются общими.

const user = { name: 'Ann', address: { city: 'Minsk' } };
const copy = { ...user };
copy.address.city = 'Vilnius';
console.log(user.address.city); // 'Vilnius' — вложенный объект общий!

Правильное обновление вложенного поля — копировать каждый уровень на пути к нему:

const moved = {
  ...user,
  address: { ...user.address, city: 'Kyiv' },
};
// user не тронут, moved — новый объект с новым address

Для полной (глубокой) копии есть встроенная функция structuredClone(user) (из общих знаний: работает в браузерах и Node 17+, но не копирует функции). Статья модуля этого не показывает и вообще не упоминает, что копия через spread поверхностная, — будьте внимательны.

Object.freeze

Object.freeze(obj) запрещает добавлять, удалять и менять свойства объекта. Две детали, которые легко упустить:

  • Заморозка поверхностная: вложенные объекты остаются изменяемыми.
  • Попытка изменить замороженный объект в нестрогом режиме молча игнорируется, а в строгом (ES-модули, классы, 'use strict') бросает TypeError. Статья модуля говорит только про «молча».
const config = Object.freeze({ port: 3000, db: { host: 'localhost' } });
config.port = 80;        // в модуле: TypeError
config.db.host = 'prod'; // сработает: db не заморожен

const deepFreeze = (obj) => {
  Object.values(obj).forEach((value) => {
    if (typeof value === 'object' && value !== null) deepFreeze(value);
  });
  return Object.freeze(obj);
};

Проверка value !== null важна: typeof null возвращает 'object'. В версии из статьи модуля этой проверки нет, и объект с полем, равным null, ломает функцию.

toSorted, toReversed, toSpliced и with появились в ES2023 (из общих знаний), в Node 20+ и современных браузерах они есть.
