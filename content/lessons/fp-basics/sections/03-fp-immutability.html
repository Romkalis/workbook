Иммутабельность

Иммутабельность (неизменяемость) — правило «данные не меняем, а создаём новые». Нужно поменять поле — делаем копию объекта с новым значением, а старый оставляем как был.

Значения и ссылки

В JavaScript два вида данных:

  • Примитивы — числа, строки, булевы значения, null, undefined, symbol, bigint. Они неизменяемы сами по себе: 'abc'.toUpperCase() не меняет строку, а возвращает новую 'ABC'.
  • Объекты, в том числе массивы и функции. Они изменяемы, а переменная хранит не сам объект, а ссылку на него.
const a = { count: 1 };
const b = a;     // скопировалась ссылка, объект один
b.count = 2;
console.log(a.count); // 2

Статья о мутабельности из материалов модуля пишет, что у примитивов «нет свойств и методов». Это неточно: у строк и чисел есть методы ('abc'.toUpperCase()), JS временно оборачивает примитив в объект. Верная формулировка: примитив нельзя изменить. Попытка str[0] = 'z' в обычном скрипте молча ничего не сделает, а в модуле или в 'use strict' бросит TypeError (проверено в Node 22).

const не делает объект неизменяемым

const settings = { theme: 'light' };
settings.theme = 'dark'; // можно!
settings = {};           // TypeError: Assignment to constant variable

const запрещает переприсвоить переменную, но не менять объект, на который она указывает.

Копирование: поверхностное и глубокое

Spread-синтаксис ... «распаковывает» объект или массив в новый: { ...user }, [...list]. Но копия поверхностная: вложенные объекты остаются общими.

const user = { name: 'Ann', address: { city: 'Minsk' } };
const copy = { ...user };
copy.address.city = 'Vilnius';
console.log(user.address.city); // 'Vilnius' — вложенный объект общий!

Правильное обновление вложенного поля — копировать каждый уровень на пути к нему:

const moved = {
  ...user,
  address: { ...user.address, city: 'Kyiv' },
};
// user не тронут, moved — новый объект с новым address

Для полной (глубокой) копии есть встроенная функция structuredClone(user) (из общих знаний: работает в браузерах и Node 17+, но не копирует функции). Статья модуля этого не показывает и вообще не упоминает, что копия через spread поверхностная, — будьте внимательны.

Задача 3. Неизменяемое обновление вложенного объекта ★★☆ практика

Напишите moveUser(state, city): возвращает новое состояние, где у state.user.address.city новое значение. Всё, что не менялось (state.cart, state.user.orders), должно остаться тем же объектом, а не копией.

Зачем: это структурное разделение: копируется только путь до изменённого поля, остальное переиспользуется. Так работают сторы (Redux, Zustand) и почему сравнение по ссылке prev.cart === next.cart позволяет не перерисовывать корзину.

Решение и разбор
export interface State {
  user: { name: string; address: { city: string; street: string }; orders: string[] };
  cart: { id: string }[];
}

export function moveUser(state: State, city: string): State {
  return {
    ...state,
    user: {
      ...state.user,
      address: { ...state.user.address, city },
    },
  };
}

Каждый уровень на пути к полю копируется spread-ом: корень, user, address. Соседние ветки копируются только по ссылке. structuredClone(state) тоже не изменил бы исходный объект, но скопировал бы всё, и сравнение по ссылке сказало бы, что поменялась и корзина. Для глубоких обновлений удобны библиотеки вроде Immer (из общих знаний).

Object.freeze

Object.freeze(obj) запрещает добавлять, удалять и менять свойства объекта. Две детали, которые легко упустить:

  • Заморозка поверхностная: вложенные объекты остаются изменяемыми.
  • Попытка изменить замороженный объект в нестрогом режиме молча игнорируется, а в строгом (ES-модули, классы, 'use strict') бросает TypeError. Статья модуля говорит только про «молча».
const config = Object.freeze({ port: 3000, db: { host: 'localhost' } });
config.port = 80;        // в модуле: TypeError
config.db.host = 'prod'; // сработает: db не заморожен

const deepFreeze = (obj) => {
  Object.values(obj).forEach((value) => {
    if (typeof value === 'object' && value !== null) deepFreeze(value);
  });
  return Object.freeze(obj);
};

Проверка value !== null важна: typeof null возвращает 'object'. В версии из статьи модуля этой проверки нет, и объект с полем, равным null, ломает функцию.

Задача 4. Глубокая заморозка ★★☆ практика

Object.freeze замораживает только верхний уровень. Напишите deepFreeze(obj): замораживает объект и все вложенные объекты и массивы. Объект с циклической ссылкой не должен вызывать бесконечную рекурсию. Возвращает тот же объект с типом DeepReadonly.

Зачем: замороженная конфигурация или справочник гарантируют, что никакой код случайно их не поменяет. В строгом режиме (модули всегда строгие) попытка записи в замороженный объект бросит TypeError, и ошибку будет видно сразу.

Решение и разбор
export type DeepReadonly<T> = T extends (...args: never[]) => unknown ? T : T extends object ? { readonly [K in keyof T]: DeepReadonly<T[K]> } : T;

export function deepFreeze<T>(obj: T): DeepReadonly<T> {
  if (typeof obj === 'object' && obj !== null && !Object.isFrozen(obj)) {
    Object.freeze(obj);
    for (const value of Object.values(obj)) deepFreeze(value);
  }
  return obj as DeepReadonly<T>;
}

Защита от цикла получилась бесплатно: объект замораживается до обхода детей, и при повторной встрече Object.isFrozen вернёт true. Тип DeepReadonly — рекурсивный mapped type из урока TS Advanced. Функции оставлены как есть, иначе тип метода превратился бы в объект. Заморозка — проверка во время работы, а readonly — во время компиляции. Вместе они закрывают и JS-код, и TS-код.

Задача 5. Переставить элемент без мутации ★☆☆ разминка

Напишите moveItem(list, from, to): возвращает новый массив, где элемент с индексом from стоит на позиции to. Используйте неизменяющие методы (toSpliced, with, slice, spread). Индексы вне диапазона — RangeError.

Зачем: перетаскивание карточек на Kanban-доске или в списке задач — ровно эта операция. Если она мутирует массив состояния, сравнение по ссылке не заметит изменения, и экран не перерисуется.

Решение и разбор
export function moveItem<T>(list: readonly T[], from: number, to: number): T[] {
  if (from < 0 || from >= list.length || to < 0 || to >= list.length) {
    throw new RangeError(`Индексы вне диапазона: ${from} → ${to}`);
  }
  const item = list[from]!;
  return list.toSpliced(from, 1).toSpliced(to, 0, item);
}

Два шага: убрать элемент, затем вставить его на новое место. Индекс to относится к массиву после удаления, и это даёт естественное поведение для перетаскивания и вниз, и вверх. toSpliced — неизменяющий брат splice из ES2023. Без него то же делается через [...list] и обычный splice на копии.
