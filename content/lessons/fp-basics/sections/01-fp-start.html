Что такое функциональное программирование

Функциональное программирование (ФП) — способ писать программу как набор небольших функций, которые получают данные и возвращают новые данные, ничего не меняя вокруг себя. Это не отдельный язык и не библиотека: в JavaScript можно писать в функциональном стиле, в объектном и смешивать их. Модуль RS School учит базовым приёмам, которые пригодятся в любом коде.

Сравним два способа посчитать сумму оплаченных заказов.

const orders = [
  { title: 'Книга', price: 20, paid: true },
  { title: 'Ручка', price: 2, paid: false },
  { title: 'Лампа', price: 35, paid: true },
];

// Императивно: говорим КАК — заводим счётчик, идём циклом, меняем счётчик
let total = 0;
for (let i = 0; i < orders.length; i++) {
  if (orders[i].paid) total += orders[i].price;
}

// Декларативно: говорим ЧТО — оплаченные → цены → сумма
const paidTotal = orders
  .filter((order) => order.paid)
  .map((order) => order.price)
  .reduce((sum, price) => sum + price, 0); // 55

Оба варианта дают 55. Во втором нет изменяемых переменных, а каждый шаг читается как предложение. Это и есть главная идея ФП: описывать преобразование данных, а не последовательность команд.

Зачем это нужно

  • Предсказуемость. Функция, которая зависит только от аргументов, ведёт себя одинаково везде. Её не сломает чужой код, поменявший глобальную переменную.
  • Тестируемость. Чтобы проверить такую функцию, не нужны браузер, сеть и моки: передали данные — сравнили результат. Подробнее — в уроке «Тестирование JavaScript».
  • Переиспользование. Маленькие функции легко собирать в новые, как детали конструктора.

Многое из ФП вы уже используете: map, filter, обработчики событий, стрелочные функции. В React оно повсюду: компонент — функция от пропсов, а состояние нельзя менять напрямую.

ФП не отменяет ООП (см. урок «Основы ООП»). На практике побеждает смесь: классы для объектов с долгой жизнью, чистые функции для расчётов и преобразований. Задание Bulls and Cows требует написать игровую логику именно в функциональном стиле.
