Объект Error

Ошибки в JavaScript — обычные объекты. Создаются конструктором Error, со словом new или без него (результат одинаковый):

const error = new Error('Не удалось загрузить', { cause: 'timeout' });

error.name;     // 'Error'
error.message;  // 'Не удалось загрузить'
error.cause;    // 'timeout'
error.stack;    // 'Error: Не удалось загрузить\n    at file:///.../e1.mjs:2:11 ...'
String(error);  // 'Error: Не удалось загрузить'
name
Тип ошибки: 'Error', 'TypeError' и так далее. Берётся из прототипа; у своих классов его нужно задать самому.
message
Описание для человека. Первый аргумент конструктора.
stack
Стек вызовов — список функций, через которые программа пришла к месту ошибки, с файлами и номерами строк. Читается сверху вниз: первая строка «at» — где ошибка создана, ниже — кто вызвал эту функцию. Свойство нестандартное, но есть во всех движках (программах, которые выполняют JavaScript: V8 в Chrome и Node.js, SpiderMonkey в Firefox, JavaScriptCore в Safari). По стеку DevTools показывает кликабельные ссылки на код.
cause
Причина: исходная ошибка, из-за которой возникла эта. Передаётся вторым аргументом { cause }. Появилось в ES2022 и поддерживается всеми современными браузерами.

Метод toString() возвращает строку «name: message». Поэтому в лекции console.log('...' + error) печатает тип и сообщение, но без стека. Чтобы увидеть всё, логируйте сам объект: console.error(error).

Выбросить можно что угодно, но не нужно

Оператор throw принимает любое значение: throw 'строка', throw 404, throw { code: 'NOT_FOUND' }, даже throw null. Проверка в Node.js 22: после throw 'строка' в catch пришла строка, и у неё нет stack (undefined). Без стека непонятно, откуда прилетела проблема, а код, который ждёт error.message, сам упадёт на null. Правило: выбрасывайте только экземпляры Error или его наследников. В слайдах лекции «сервер» эмулируется через throw { statusCode: 404 } — так делать можно только для имитации чужого API, в своём коде нельзя.

Отсюда же совет для catch: не полагайтесь на то, что пойманное значение — Error. В TypeScript переменная в catch по умолчанию имеет тип unknown именно поэтому; проверка error instanceof Error перед чтением message — хорошая привычка.
