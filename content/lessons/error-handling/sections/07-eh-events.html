Глобальные события ошибок

Есть ошибки, которые до вашего catch не дошли, и ресурсы, которые не загрузились. Для них у браузера есть события. Используют их не для «починки», а как последнюю линию: записать в журнал и показать пользователю, что что-то пошло не так.

window.onerror и событие error

Событие error на window срабатывает при любой неперехваченной ошибке JavaScript. Подписаться можно двумя способами. Старый — свойство window.onerror с пятью аргументами:

window.onerror = (message, source, line, column, error) => {
  sendToLog({ message, source, line, column, stack: error?.stack });
  return true; // не показывать ошибку в консоли
};

Новый — addEventListener, где все данные лежат в объекте события: event.message, event.filename, event.lineno, event.colno, event.error. Чтобы подавить вывод в консоль, здесь вызывают event.preventDefault(), а не возвращают true.

window.addEventListener('error', (event) => {
  sendToLog(event.error);
});

Проверено в Chrome: ошибка, выброшенная в setTimeout, вызвала оба обработчика. В onerror пришло сообщение «Uncaught TypeError: из таймера» и объект ошибки, а после return true в консоли ничего не появилось. Лектор объясняет return true как «заткнуть ошибку» — это верно, но глушить ошибки в консоли во время разработки не стоит: вы перестанете их видеть.

«Script error.»

Если ошибка произошла в скрипте с другого домена (например, с CDN — сервиса, который раздаёт библиотеки с серверов по всему миру), браузер из соображений безопасности скрывает подробности: в обработчик приходит только «Script error.» без файла, строки и стека. Чтобы получить детали, скрипт подключают с атрибутом crossorigin="anonymous", а сервер отдаёт его с заголовком Access-Control-Allow-Origin — это тот же механизм CORS, что разобран в уроке о клиенте и сервере.

Ошибки загрузки ресурсов

Событие error бывает и у элементов, которые что-то загружают: <img>, <script>, <link>, <video>, <audio> (MDN: HTMLElement error event). Лектор приводит пример: картинку создают на лету из JavaScript, и если она не загрузилась, нужно что-то показать вместо неё.

const img = document.createElement('img');
img.addEventListener('error', () => {
  img.src = '/img/placeholder.svg';
  img.alt = 'Картинка не загрузилась';
}, { once: true });
img.src = user.avatarUrl;

{ once: true } защищает от бесконечного цикла, если не загрузится и заглушка. В лекции лектор не смог вспомнить, как это сделать; рабочий вариант проверен в Chrome: для несуществующего адреса событие error у картинки сработало.

Важная деталь: ошибка загрузки ресурса не всплывает до window. Обработчик window.addEventListener('error', ...) увидит её, только если подписаться на фазе перехвата (capture) — третьим аргументом true. Событие сначала идёт от window вниз к элементу (перехват), а потом обратно вверх (всплытие); ошибки ресурсов проходят только первый путь. В Chrome такой обработчик получил событие с event.target, равным элементу IMG. А window.onerror ошибки ресурсов не получает совсем.

unhandledrejection

Для промисов без .catch есть отдельное событие:

window.addEventListener('unhandledrejection', (event) => {
  sendToLog(event.reason);
  event.preventDefault(); // убрать «Uncaught (in promise)» из консоли
});

В event.reason — то, с чем отклонился промис. В Chrome Promise.reject(new Error('забытый reject')) вызвал этот обработчик. Событие error на window для отклонённых промисов не срабатывает, поэтому в приложении обычно подписываются на оба.
