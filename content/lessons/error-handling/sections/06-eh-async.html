Ошибки в асинхронном коде

Лекция начинается с того, что ошибку можно «совершить» двумя способами: синхронно (throw) и асинхронно (Promise.reject или любой сбой внутри промиса). Ловятся они по-разному. Синхронный код выполняется строка за строкой прямо сейчас. Асинхронный запускает действие (таймер, запрос), а результат обрабатывает позже, в колбэке — функции, которую передали, чтобы её вызвали потом.

Колбэки: try снаружи не помогает

try {
  setTimeout(() => {
    throw new Error('внутри таймера');
  }, 0);
} catch {
  console.log('сюда не попадём');
}

try выполнился и закончился сразу, как только таймер был запланирован. Колбэк запустится позже, когда try уже давно позади, и ошибка станет неперехваченной. Ловить нужно внутри самого колбэка — в Node.js 22 такой вариант напечатал «пойман внутри: внутри таймера». То же касается обработчиков событий: try вокруг addEventListener бесполезен, try должен быть внутри обработчика.

В старом коде, особенно в Node.js, ошибки передают первым аргументом колбэка. Например, чтение файла в Node.js: fs.readFile(path, (error, data) => { if (error) ... }). Это соглашение «error-first callback»; о нём пишут Kinsta и Гальярди.

Промисы: catch, then и finally

Промис переходит в состояние «отклонён» (rejected), если вызвали reject, Promise.reject(...) или внутри исполнителя (функции, переданной в new Promise(...)) или обработчика .then произошёл throw. Отклонение «падает» по цепочке вниз, пропуская все .then, до ближайшего .catch (глава javascript.info, на русском).

Promise.resolve(1)
  .then(() => { throw new Error('A'); })
  .then(() => console.log('пропущен'))
  .catch((error) => console.log('catch:', error.message))
  .then(() => console.log('цепочка продолжается'));
// catch: A
// цепочка продолжается

После .catch цепочка снова «здорова»: если обработчик ничего не выбросил, следующие .then выполнятся. Поэтому .catch ставят в конце, чтобы поймать всё, или в середине, если ошибку конкретного шага можно исправить и продолжить. .finally работает как в try: вызывается всегда и не получает ни результата, ни ошибки.

Второй аргумент then

У .then есть второй параметр — обработчик ошибки: .then(onSuccess, onError). Лектор упоминает, что встречает его редко. Подвох: onError не ловит ошибку, выброшенную в onSuccess того же .then. Проверено в Node.js 22: обработчик успеха выбросил ошибку, второй аргумент не вызвался, ошибка стала неперехваченной. .then(...).catch(...) такую ошибку поймает.

async/await

Внутри async-функции await превращает отклонённый промис в обычный throw в этой строке, и работает привычный try...catch (глава javascript.info):

async function loadUser(id) {
  try {
    const response = await fetch(`/api/users/${id}`);
    if (!response.ok) throw new HttpError(response.status);
    return await response.json();
  } catch (error) {
    if (error instanceof HttpError && error.status === 404) return null;
    throw error;
  }
}

Помните урок о клиенте и сервере: fetch не отклоняется на 404 и 500, статус проверяется вручную. Ошибка, не пойманная внутри async-функции, не исчезает: функция возвращает отклонённый промис, и его нужно обработать снаружи — через await в try или через .catch.

Лектор показывает частую ловушку: убрал await перед вызовом — и try перестал ловить. Вариант той же ошибки, который легко не заметить, — return без await:

async function noAwait() {
  try { return load(); }          // промис возвращается как есть
  catch { return 'поймано'; }
}
async function withAwait() {
  try { return await load(); }    // дожидаемся внутри try
  catch { return 'поймано'; }
}

Если load() отклоняется, withAwait() вернул 'поймано', а noAwait() упал наружу с ошибкой «сеть»: к моменту отказа функция уже вышла из try. Внутри try пишите return await.

Promise.all и родственники

Эти методы запускают несколько промисов сразу и объединяют результаты; подробности на learn.javascript.ru: Promise API.

МетодЕсли промисы отклоняются
Promise.allОтклоняется с первой ошибкой, остальные результаты теряются (сами запросы при этом не отменяются)
Promise.allSettledНикогда не отклоняется; возвращает массив { status: 'fulfilled', value } или { status: 'rejected', reason }
Promise.anyЖдёт первый успех; если отклонены все — AggregateError со всеми ошибками в errors
Promise.raceПовторяет исход первого завершившегося, будь то успех или ошибка

Проверка: Promise.all([ok, fail('x'), fail('y')]) отклонился с x; allSettled вернул fulfilled,rejected; Promise.any из двух отказов дал AggregateError с ['x', 'y']. Если нужно показать на странице всё, что загрузилось, даже когда часть запросов упала, выбирайте allSettled.

Потренироваться на всех четырёх комбинаторах можно в задании core-js-promises — разбор решений в уроке «Core JS Promises».

Необработанные отклонения

Промис, отклонение которого никто не обработал, вызывает в консоли «Uncaught (in promise)». Лектор замечает, что такая ошибка часто не роняет всё приложение, как синхронная: просто какие-то данные тихо не появятся. Это хуже, потому что незаметно. В браузере такие случаи ловит событие unhandledrejection (следующий раздел), в Node.js — process.on('unhandledRejection'); начиная с Node.js 15 необработанное отклонение по умолчанию завершает процесс (из общих знаний).
