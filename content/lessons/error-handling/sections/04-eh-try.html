throw и try...catch...finally

throw

throw прерывает выполнение текущей функции. Дальше движок поднимается по стеку вызовов — к функции, которая вызвала эту, потом к её вызывающей и так далее — пока не найдёт подходящий catch. Если не нашёл, ошибка становится неперехваченной (uncaught): в консоли появляется красное «Uncaught TypeError...», текущий скрипт или обработчик события останавливается.

function divide(a, b) {
  if (b === 0) {
    throw new RangeError('Делить на ноль нельзя');
  }
  return a / b;
}

Выбрасывать ошибку стоит, когда функция не может выполнить своё обещание и не должна молча вернуть мусор. Это лучше, чем вернуть null и надеяться, что вызывающий проверит.

try...catch

try...catch выполняет код в блоке try. Если там (или в функциях, которые он вызывает) выброшена ошибка, выполнение try обрывается и управление переходит в catch, куда передаётся выброшенное значение. Если ошибки не было, catch пропускается.

try {
  const settings = JSON.parse(localStorage.getItem('settings'));
  applySettings(settings);
} catch (error) {
  console.error('Настройки повреждены, берём стандартные', error);
  applySettings(DEFAULT_SETTINGS);
}

Если объект ошибки не нужен, скобки можно опустить: try { ... } catch { ... }. Это возможно с ES2019; лектор упоминает, что «раньше было обязательно».

Переменная error видна только внутри catch, а переменные, объявленные внутри try через let и const, — только внутри try. Нужный результат объявляйте снаружи.

finally

Блок finally выполняется всегда: после успешного try, после catch и даже если внутри был return или ошибка выброшена дальше. Его используют для «уборки»: спрятать индикатор загрузки, закрыть файл, снять блокировку кнопки.

button.disabled = true;
try {
  await sendForm(data);
  showMessage('Отправлено');
} catch (error) {
  showMessage('Не получилось, попробуйте ещё раз');
} finally {
  button.disabled = false;
}

Две проверенные в Node.js 22 тонкости. Функция try { return 'try' } finally { console.log(...) } сначала напечатала сообщение из finally, а потом вернула 'try'. А если в finally тоже есть return, он перекрывает результат try: функция вернула 'finally'. Так же return в finally «съедает» выброшенную ошибку, поэтому return в finally не пишут.

Ловить только то, что умеете обработать

Пустой catch — главная ошибка новичков. Он прячет не только ожидаемую проблему, но и любой баг рядом: опечатку в имени функции вы будете искать часами. Правило из главы javascript.info (на русском): catch должен обрабатывать только те ошибки, которые он знает, и пробрасывать остальные.

try {
  user = parseUser(json);
} catch (error) {
  if (error instanceof SyntaxError) {
    showMessage('Сервер прислал повреждённые данные');
  } else {
    throw error; // не наш случай — пусть ловят выше
  }
}

Проверять тип через instanceof надёжнее, чем через error.name === '...' или текст сообщения: тексты отличаются в разных браузерах.

Когда try не нужен

  • Ожидаемые ситуации лучше проверять заранее: пустое поле формы — это if, а не исключение.
  • Не оборачивайте каждую строку в отдельный try. Обычно достаточно ловить ошибки на границах: обработчик клика, загрузка данных, точка входа приложения (раздел об архитектуре).
  • try...catch работает синхронно: он не поймает ошибку, которая произойдёт позже, в колбэке таймера или события. Об этом — раздел про асинхронный код.
