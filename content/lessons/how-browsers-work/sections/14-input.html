Ввод и compositor Chrome «Inside look» часть 4

Действие по умолчанию — то, что браузер делает сам, например прокручивает страницу или переходит по ссылке. Обработчик — ваша функция, вызванная при событии. Hit test — поиск элемента в указанной точке. Эти задачи различаются: определить цель события ещё не значит выполнить пользовательский код.

Для браузера «ввод» это любой жест: прокрутка колёсиком, касание, наведение мыши, клик, нажатие клавиши. Первым событие получает browser process, но знает он только тип и координаты. Дальше он пересылает их в renderer, а тот находит цель и вызывает обработчики.

Non-fast scrollable region

Для некоторых участков прокрутки браузеру может понадобиться решение основного потока: не отменит ли обработчик действие? Такие области в описанной архитектуре называют non-fast scrollable region — областями, где прокрутку нельзя полностью выполнить быстрым путём композитора. Это зависит от обработчика и события, а не от самого наличия JavaScript на странице. Web Workers тоже выполняют JS, но не могут напрямую работать с DOM страницы вместо её основного потока.

Ловушка делегирования событий

Не любой обработчик на body мешает прокрутке: важны тип события и возможность отменить действие по умолчанию. Например, некоторые touch- и wheel-обработчики могут заставить браузер ждать решения JavaScript. Делегирование кликов само по себе не превращает всю страницу в блокирующую область прокрутки.

document.body.addEventListener('touchstart', event => {
  // ...
}, { passive: true });

Пассивный обработчик ({ passive: true }) — это ваше обещание браузеру: «я не буду отменять прокрутку». Браузер верит и прокручивает сразу, не дожидаясь вашего кода. Поэтому preventDefault() внутри такого обработчика ничего не отменит. Если прокрутку действительно нужно запретить, есть два пути: обработчик с { passive: false } или, что обычно проще, CSS-свойство touch-action. Например, touch-action: pan-x разрешает только горизонтальную прокрутку пальцем.

Поиск цели события

Когда compositor передаёт событие основному потоку, тот сначала делает hit test: по paint records определяет, какой элемент лежит под этой точкой.

Объединение событий

Устройство ввода может передавать координаты чаще, чем экран показывает новые кадры. Браузер может объединять непрерывные события движения, чтобы не вызывать лишние обработчики. Частоты и правила зависят от устройства и реализации; числа из статьи не являются ограничением веб-платформы. Дискретные события вроде нажатия клавиши обрабатываются отдельно от такого объединения движений.

Если нужны промежуточные точки (рисование линии), используйте event.getCoalescedEvents():

window.addEventListener('pointermove', event => {
  for (const e of event.getCoalescedEvents()) {
    drawTo(e.pageX, e.pageY);
  }
});
