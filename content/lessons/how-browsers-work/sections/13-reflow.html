Reflow и repaint dev.to «Understanding Reflow and Repaint», web.dev

Reflow, или layout, — повторный расчёт размеров и положения блоков. Repaint — повторная подготовка рисования изменившегося содержимого, например после смены цвета. Изменение геометрии может затронуть соседей, родителей и потомков, но объём работы зависит от раскладки. Не каждая правка требует заново вычислять и рисовать всю страницу.

Таблица показывает типичные последствия изменений видимого содержимого, а не гарантирует выполнение каждой стадии при любой записи свойства. Значение могло не измениться, элемент может быть скрыт, несколько записей могут объединиться. Подробности: web.dev о layout и чередовании чтений и записей. Справочник CSS Triggers используйте как ориентир, а не замену измерению.

Осторожно с комментариями

В обсуждении под статьёй встречается утверждение, что браузер при любом изменении пересчитывает всю страницу. Это неточно. Благодаря dirty bit пересчитывается только затронутая часть. Но есть и правда: изменение корневого шрифта или размера окна инвалидирует почти всё.

Как уменьшить число reflow

  • Не менять стили по одному. Лучше переключить класс или обновить style.cssText одним присваиванием.
  • Группировать изменения DOM. Сначала подготовьте изменения, затем применяйте их вместе. DocumentFragment может помочь собрать новые узлы вне страницы. Не скрывайте элемент только ради обещания «двух reflow»: число перерасчётов зависит от чтений геометрии и объединения изменений браузером.
  • Не запрашивать вычисленные стили повторно. Кэшировать в переменную.
  • Разделять чтения и записи. Сначала все чтения, потом все записи.
  • Анимировать через transform и opacity, а не через top/left/width.

Layout thrashing на примере

Чтение геометрии после записи заставляет браузер досчитать layout прямо сейчас. Если чередовать чтение и запись в цикле, получится reflow на каждой итерации.

// плохо: чтение и запись чередуются, layout на каждой итерации
boxes.forEach(box => {
  const h = box.clientHeight;          // чтение (принудительный layout)
  box.style.height = (h + 10) + 'px';  // запись (инвалидация)
});

// лучше: сначала читаем всё, потом пишем
const heights = boxes.map(box => box.clientHeight);
boxes.forEach((box, i) => {
  box.style.height = (heights[i] + 10) + 'px';
});

В примере из статьи на шести блоках «плохой» вариант давал 7 layout-ов, а оптимизированный 2. Посмотреть такое можно во вкладке Performance в DevTools.

Layout thrashing — повторное принудительное вычисление геометрии из-за чередования чтения и записи. Сначала соберите необходимые размеры, затем меняйте стили. DocumentFragment помогает собрать узлы вне страницы, но сам по себе не гарантирует ускорения или определённого числа layout. Измеряйте результат.
