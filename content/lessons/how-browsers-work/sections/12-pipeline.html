Бюджет кадра

Для примера возьмём экран с частотой 60 Гц: он обновляется 60 раз в секунду, каждое обновление это один кадр. На кадр уходит 1000 / 60 ≈ 16,66 мс. Но у браузера есть и собственные накладные расходы, поэтому ваша работа должна укладываться примерно в 10 мс. Не уложились, кадры пропускаются, и картинка дёргается: это называется jank.

Для разных задач цели разные. Для анимаций критично уложиться в бюджет кадра. Для дискретных изменений интерфейса (переход из одного состояния в другое без движения) главное, чтобы реакция казалась мгновенной. Обычно называют 100 мс, а порог «хорошо» у метрики INP (Interaction to Next Paint) составляет 200 мс или меньше, чтобы учесть слабые устройства.

Пять стадий, на которые вы влияете

  1. JavaScriptили CSS-анимации, Web Animations API
  2. Styleкакие правила к каким элементам
  3. Layoutгеометрия
  4. Paintподготовка рисования; затем растеризация получает пиксели
  5. Compositeсборка слоёв в правильном порядке

Не каждый кадр проходит все стадии. Есть три типичных пути, в порядке убывающей цены:

Полный путь

JS/CSS → Style → Layout → Paint → Composite

Меняется геометрия: width, height, top, left, отступы, шрифт. Браузер пересчитывает раскладку страницы, перерисовывает затронутое и собирает слои.

Без layout

JS/CSS → Style → Paint → Composite

Меняется только внешний вид: color, background-image, box-shadow. Дорогой layout пропускается.

Только composite

JS/CSS → Style → Composite

Меняется то, что не требует ни layout, ни paint, например transform и opacity. Самый дешёвый путь для анимаций и прокрутки.

Производительность это искусство избегать работы и делать необходимую работу эффективнее. Цель не бороться с браузером, а работать вместе с ним.

Главный поток и event loop

На основном потоке работает цикл событий (event loop): он выполняет задачи JavaScript и обработчики, а между подходящими задачами браузер получает возможность обновить изображение. Layout и paint — этапы обновления, а не обычные события, поставленные в очередь как click. Compositor, растеризация и другие службы выполняют часть работы отдельно.

Долгая задача JavaScript задерживает другие работы основного потока, включая обновление интерфейса. RequestAnimationFrame вызывает функцию перед очередным обновлением изображения, но не переносит её в другой поток: обработчик должен оставаться коротким. Подходящие вычисления можно вынести в Web Worker, а работу на основном потоке — разделить на небольшие задачи с передачей управления браузеру.

function tick() {
  // небольшая порция работы на один кадр
  updateOnlyWhatChanged();
  requestAnimationFrame(tick);
}
requestAnimationFrame(tick);
