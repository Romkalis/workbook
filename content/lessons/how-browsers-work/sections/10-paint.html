После layout браузер знает, где стоит каждый блок, но ещё не знает, в каком порядке их рисовать. Обычно рисуют по порядку разметки, но z-index может поднять элемент из конца страницы поверх остальных. Поэтому браузер сначала составляет список команд («фон, потом текст, потом рамка»), а рисует уже по нему. Этот список называется paint records. Похоже на рисование на <canvas>: там вы тоже даёте команды по очереди.

Порядок рисования блока

По CSS2 внутри stacking context блок рисуется так: цвет фона, фоновое изображение, рамка, потомки, outline. Сами контексты идут от задних к передним.

Подготовка рисования и растеризация

  1. составить список команд рисования;
  2. заполнить пиксели. Это растеризация.

Значит, здесь два разных шага: составить список команд (paint) и закрасить по нему пиксели (растеризация). На схемах их часто рисуют одним блоком, но в DevTools на вкладке Performance они могут быть отдельными полосками. Поэтому полоска с подписью Paint не всегда показывает всё время рисования.

Повторная отрисовка

При первой загрузке рисуется весь экран, дальше браузер перерисовывает только затронутые области (инвалидирует прямоугольник). Но есть важная связь между стадиями: результат предыдущей используется для следующей. Если изменилось дерево layout, порядок отрисовки нужно составить заново для затронутых частей. Если вы анимируете элемент, браузер повторяет эти операции перед каждым кадром.
