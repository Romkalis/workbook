.gitignore

Не всё в папке проекта должно попасть в репозиторий. Файл .gitignore перечисляет, что Git не должен отслеживать (руководство Atlassian «.gitignore», документация).

Что игнорировать

  • Зависимости: node_modules/ — восстанавливаются через npm install.
  • Результаты сборки: dist/, build/, .next/ — создаются из исходников.
  • Секреты: .env с паролями и ключами.
  • Логи и временные файлы: *.log, *.tmp.
  • Файлы системы и редактора: .DS_Store (macOS), Thumbs.db (Windows), .idea/. Их лучше вынести в глобальный список (ниже).

Готовые шаблоны для разных языков и фреймворков — в репозитории github/gitignore; GitHub предлагает их при создании репозитория.

Шаблоны

# зависимости и сборка
node_modules/
dist/
# логи, кроме одного
*.log
!keep.log
# только в корне
/config.local.js
# любые .env, кроме образца
.env
.env.*
!.env.example
ШаблонЧто значит
# текстКомментарий
*.log* — любые символы, кроме /. Все файлы с расширением .log в любой папке
dist/Слеш в конце — только папки с таким именем, на любом уровне
/config.local.jsСлеш в начале — только в той же папке, где лежит .gitignore
**/logs, logs/**** — любое число вложенных папок
!keep.log! — исключение: снова отслеживать то, что игнорировал шаблон выше

Проверка на учебном репозитории: из пятнадцати созданных файлов Git показал только четыре — .env.example, .gitignore, keep.log и src/config.local.js. Заметьте: src/dist/b.js игнорируется (папка dist/ на любом уровне), а src/config.local.js нет (шаблон со слешем в начале действует только в корне).

У исключений есть ограничение: если игнорируется сама папка (logs/), вернуть файл внутри неё через !logs/важный.log нельзя — Git даже не заглядывает в игнорируемую папку. Нужно игнорировать содержимое: logs/* и !logs/важный.log.

Почему файл игнорируется?

$ git check-ignore -v app.log src/dist/b.js .env.local keep.log src/config.local.js
.gitignore:5:*.log	app.log
.gitignore:3:dist/	src/dist/b.js
.gitignore:11:.env.*	.env.local
.gitignore:6:!keep.log	keep.log

Для каждого файла видно, какая строка какого файла сработала. Для keep.log последним совпал шаблон с ! — значит, файл не игнорируется. src/config.local.js в выводе нет: ни один шаблон его не задел.

Файл уже в репозитории

.gitignore действует только на неотслеживаемые файлы. Если файл уже закоммичен, добавление его в .gitignore ничего не даст — проверено: Git продолжил показывать изменения в secret.txt. Нужно убрать файл из индекса, оставив на диске:

$ echo "secret.txt" >> .gitignore
$ git rm --cached secret.txt
$ git status -s
D  secret.txt       # будет удалён из репозитория, но файл на диске остался
$ git commit -m "Убрать secret.txt из репозитория"
Секрет уже на GitHub

Если в репозиторий попал пароль или ключ, git rm --cached не поможет: он остаётся в старых коммитах, и любой может их посмотреть. Секрет нужно сразу сменить (выпустить новый ключ, поменять пароль), а уже потом при необходимости чистить историю специальными инструментами.

Личные и глобальные правила

  • .gitignore в репозитории — общий для всей команды, коммитится. Таких файлов может быть несколько, в разных папках.
  • .git/info/exclude — правила только для вашей копии этого репозитория, не коммитится.
  • Глобальный файл — для всех ваших репозиториев. Удобно для файлов системы и редактора:
git config --global core.excludesFile ~/.gitignore_global
echo ".DS_Store" >> ~/.gitignore_global

Если игнорируемый файл всё же нужно закоммитить, есть git add -f файл — но обычно это признак, что правило в .gitignore слишком широкое.

Пустые папки

Git отслеживает только файлы, а не папки: пустая папка empty не появилась даже в git status. Чтобы сохранить её в репозитории, туда кладут пустой файл, по соглашению .gitkeep (особого смысла для Git у этого имени нет, это договорённость). После этого git status показал ?? empty/.gitkeep.
