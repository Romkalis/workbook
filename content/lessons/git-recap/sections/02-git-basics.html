Повторение: Git в ежедневной работе

Git — распределённая система контроля версий. Она хранит историю изменений проекта, позволяет вернуться к любой точке и работать параллельно в ветках — независимых линиях истории, например одна для новой функции, другая для исправления бага. «Распределённая» значит, что у каждого разработчика на компьютере лежит полная копия репозитория со всей историей, а GitHub — лишь ещё одна копия, через которую удобно обмениваться изменениями.

Глава Pro Git «Что такое Git» выделяет главную идею: Git хранит не список изменений, а снимки (snapshots). Каждый коммит — это снимок всего проекта на момент коммита. Файлы, которые не менялись, не копируются заново: снимок просто ссылается на уже сохранённую версию. Почти все операции локальные и поэтому быстрые, а целостность данных обеспечивают хеши (о них ниже). У файла в Git три состояния: изменён (modified), подготовлен (staged) и зафиксирован (committed).

Команды на каждый день

КомандаЧто делает
git init / git clone <url>Создать репозиторий / скачать существующий
git statusЧто изменено, что подготовлено к коммиту. Самая полезная команда: запускайте её постоянно
git add <файл>Подготовить изменения к коммиту (положить в индекс)
git commit -m "..."Зафиксировать подготовленное в истории
git log --onelineИстория коротко: хеш и сообщение
git diff / git diff --stagedИзменения, ещё не добавленные / уже добавленные в индекс
git switch -c <ветка>Создать ветку и перейти в неё (git switch <ветка> — просто перейти)
git merge <ветка>Влить (слить, merge) другую ветку в текущую: её коммиты станут частью текущей
git pull / git pushЗабрать изменения с сервера / отправить свои

Команды switch и restore появились в Git 2.23 (2019). До этого всё делала одна перегруженная git checkout: и переключала ветки, и откатывала файлы. В статьях Atlassian и старых туториалах вы увидите именно checkout; ниже рядом с новыми командами указаны старые аналоги.

Сообщение коммита пишут так, чтобы через полгода было понятно, что и зачем изменилось: «Добавить поиск по названию», а не «fix» или «правки». Часто используют соглашение Conventional Commits: feat: добавить поиск, fix: исправить пустой список. В требованиях к заданиям RS School оно часто встречается.
