Отмена и исправление коммитов

Исправить последний коммит

$ git commit -m "Добавть b"            # опечатка
$ git commit --amend -m "Добавить b"   # заменить сообщение
$ git log --oneline
ddffd94 Добавить b
6c3b002 Первый коммит

--amend не редактирует коммит, а заменяет его новым: хеш изменился (было c249abc, стало ddffd94). Забыли добавить файл — git add забытый.txt, потом git commit --amend --no-edit (сообщение оставить прежним).

Достать старую версию файла

git restore --source=HEAD~2 hello.txt   # старый вариант: git checkout HEAD~2 -- hello.txt

Файл в рабочей папке станет таким, каким был два коммита назад, а история не изменится. Проверено: содержимое вернулось к «привет», git status показал обычное изменение M hello.txt, которое можно закоммитить или отменить. Просто посмотреть старую версию, не трогая файл: git show HEAD~2:hello.txt.

revert: отменить опубликованный коммит

$ git revert --no-edit HEAD
[main bcbc1f4] Revert "Версия 3"
$ git log --oneline -2
bcbc1f4 Revert "Версия 3"
aad07a7 Версия 3

revert создаёт новый коммит, который делает обратные изменения. Старый коммит остаётся в истории. Это единственный безопасный способ отменить коммит, который уже отправлен на сервер и мог попасть к коллегам: история только растёт, ничего не переписывается. Отменить можно и коммит из середины истории: git revert <хеш>.

reset: переместить ветку

git reset <коммит> переставляет текущую ветку (и HEAD) на указанный коммит. Режим определяет, что станет с индексом и рабочей папкой — это и есть три дерева в действии:

РежимHEAD (ветка)ИндексРабочая папкаКогда нужен
--softпереезжаетне меняетсяне меняетсяСклеить последние коммиты в один: изменения остаются подготовленными
--mixed (по умолчанию)переезжаеткак в коммитене меняетсяРазобрать коммит и закоммитить иначе: правки остаются в файлах
--hardпереезжаеткак в коммитекак в коммитеВыбросить всё: и коммиты, и незакоммиченные правки

Проверено по шагам. После git reset --soft HEAD~1 последний коммит исчез из log, а его изменения стоят в индексе (M  hello.txt). После git reset HEAD (mixed) они ушли из индекса, но остались в файле ( M hello.txt). После git reset --hard HEAD правки исчезли совсем.

Опасность --hard и правило публичной истории

reset --hard удаляет незакоммиченные изменения без возможности восстановления. Закоммиченное можно вернуть через reflog. Второе правило: не делайте reset (и --amend, и rebase — команду, которая переписывает цепочку коммитов, о ней ниже) для коммитов, которые уже отправлены в общую ветку. Вы переписываете историю, а у коллег осталась старая; придётся делать git push --force — принудительно заменить историю на сервере своей, и их работа может потеряться. Для опубликованного — revert.

Перезапись истории

Глава Pro Git «Перезапись истории» показывает инструмент для правки нескольких последних коммитов — интерактивный rebase: git rebase -i HEAD~3. Откроется список трёх коммитов, где у каждого можно заменить слово pick: reword — поменять сообщение, squash — слить с предыдущим, edit — остановиться и изменить содержимое, drop или удаление строки — выбросить коммит; строки можно менять местами. Так приводят в порядок свою ветку перед пул-реквестом (запросом на слияние ветки в основную на GitHub). Правило то же: только для коммитов, которые ещё никто не забрал. Если что-то пошло не так посреди rebase, git rebase --abort вернёт всё как было.
