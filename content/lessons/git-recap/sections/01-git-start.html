Зачем снова Git

Первые недели работы с Git обычно сводятся к трём командам: add, commit, push. Пока всё идёт гладко, этого хватает. Но рано или поздно вы закоммитите не тот файл, отправите пароль в репозиторий, сотрёте нужное командой reset --hard или окажетесь в загадочном состоянии «detached HEAD». Тогда спасает не очередная команда из поисковика, а понимание того, как Git устроен.

Этот урок о том, что происходит внутри: где Git хранит данные, что такое хеш коммита и HEAD, чем рабочая папка отличается от индекса. На этой основе отмена изменений перестаёт быть магией: для каждой ситуации есть своя команда, и понятно, что она делает.

Что разберём

  • Коротко повторим ежедневные команды Git.
  • Три дерева: рабочая папка, индекс и HEAD.
  • Объекты Git, хеши SHA-1, ссылки, HEAD и reflog.
  • Как отменить изменения в файлах, убрать файл из индекса, удалить неотслеживаемые файлы.
  • Как исправить последний коммит, достать старую версию файла, отменить опубликованный коммит, откатить ветку и вернуть «потерянное».
  • .gitignore: шаблоны, исключения, глобальные правила, пустые папки, файл, который уже в репозитории.
Как устроен модуль

Программа модуля отводит около 4 часов. Теория — четыре руководства Atlassian (ссылки и reflog, отмена изменений, reset/checkout/revert, .gitignore) и главы книги Pro Git. Практика — тест «[St1] Git & GitHub #2» в RS App, раздел Auto Test. Для тренировки модуль советует интерактивный курс Learn Git Branching (есть на русском) и пошаговый Git How To.

Все команды и их вывод в уроке получены в учебном репозитории (git 2.39). Хеши у вас будут другими: они зависят от содержимого, автора и времени. Пробуйте команды в отдельной папке, а не в рабочем проекте, — часть из них удаляет данные.
