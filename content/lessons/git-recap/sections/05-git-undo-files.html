Отмена изменений до коммита

Руководство Atlassian «Undoing Commits & Changes» делит отмену на уровни: рабочая папка, индекс, коммиты. Начнём с того, что ещё не закоммичено. Глава Pro Git «Операции отмены» описывает то же на русском.

Отменить правку в файле

git restore hello.txt          # старый вариант: git checkout -- hello.txt

Вернёт файл в рабочей папке к версии из индекса (а если в индексе изменений нет — к версии из HEAD). Правки будут потеряны безвозвратно: их не было ни в одном коммите, reflog не поможет. Отменить всё в проекте: git restore ..

Убрать файл из индекса

git restore --staged hello.txt # старый вариант: git reset HEAD hello.txt

Файл перестанет быть подготовленным к коммиту, но правки в рабочей папке останутся. Проверено: из состояния M  hello.txt файл перешёл в M hello.txt, содержимое на диске не изменилось. Это безопасная команда.

Удалить неотслеживаемые файлы

git restore и reset не трогают файлы, которых Git ещё не видел (??). Для них есть git clean, и с ним нужна осторожность: удалённые файлы не попадают в корзину.

$ git clean -n       # «пробный прогон»: только показать
Would remove tmp.log
$ git clean -nd      # -d — включая папки
Would remove build/
Would remove tmp.log
$ git clean -fd      # -f — действительно удалить
Removing build/
Removing tmp.log

Без -f Git откажется удалять (защита от случайности). Флаг -x удалит ещё и игнорируемые файлы — например, node_modules и .env; с ним будьте особенно аккуратны. Привычка: всегда сначала -n.

Отложить, а не удалять

Если правки жалко, но сейчас они мешают (нужно срочно переключиться на другую ветку), спрячьте их: git stash (stash — «тайник») убирает изменения в специальное хранилище, git stash pop возвращает. Это не входит в программу модуля, но спасает от потери работы (из общих знаний).
