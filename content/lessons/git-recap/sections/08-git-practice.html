Какую команду выбрать

СитуацияКоманда
Испортил файл, не коммитилgit restore файл
Добавил в индекс лишнееgit restore --staged файл
Опечатка в последнем коммите, ещё не запушенgit commit --amend
Нужна версия файла из прошлогоgit restore --source=<коммит> файл
Отменить коммит, который уже на GitHubgit revert <хеш>
Убрать последние локальные коммиты, сохранив правкиgit reset --soft или --mixed HEAD~N
Выбросить всё и вернуться к коммитуgit reset --hard <коммит>
«Потерял» коммит после resetgit reflog, затем git reset --hard HEAD@{n}
Мусорные неотслеживаемые файлыgit clean -n, затем -fd
Закоммитил файл, который надо игнорироватьдобавить в .gitignore, git rm --cached файл

Упражнения

  1. Создайте учебный репозиторий, сделайте три коммита. Посмотрите git cat-file -p HEAD и cat .git/HEAD.
  2. Добейтесь состояния MM в git status -s и объясните, что попадёт в коммит.
  3. Проверьте все три режима reset по таблице, после каждого смотрите status и log.
  4. Сделайте reset --hard на два коммита назад и верните их через reflog.
  5. Напишите .gitignore для проекта на Vite и проверьте его через git check-ignore -v.
  6. Пройдите разделы «Основы» и «Удалённые репозитории» в Learn Git Branching.

Вопросы

Чем revert отличается от reset?

revert добавляет новый коммит с обратными изменениями, история сохраняется — подходит для опубликованных коммитов. reset передвигает ветку назад, коммиты пропадают из истории ветки — только для локальных.

Почему после --amend изменился хеш?

Хеш вычисляется из содержимого коммита, включая сообщение и время. --amend создаёт новый коммит взамен старого.

Что такое detached HEAD и опасно ли это?

HEAD указывает прямо на коммит, а не на ветку. Смотреть код безопасно, но новые коммиты легко потерять после переключения — создайте ветку через git switch -c.

Почему файл в .gitignore продолжает отслеживаться?

.gitignore действует только на неотслеживаемые файлы. Уберите файл из индекса: git rm --cached.

Можно ли вернуть изменения после git restore файла?

Нет, если их не было ни в одном коммите и не было в stash. Reflog хранит только перемещения по коммитам.

Словарь

Рабочая папка
Файлы на диске, которые вы редактируете.
Индекс (staging area)
Черновик следующего коммита; туда кладёт git add.
HEAD
Указатель «где я сейчас»: обычно на ветку, в detached-режиме — прямо на коммит.
Снимок (snapshot)
Состояние всего проекта, сохранённое в коммите.
blob, tree, commit
Объекты Git: содержимое файла, папка, снимок с метаданными.
SHA-1
Хеш из 40 шестнадцатеричных символов, имя объекта Git.
Ссылка (ref)
Имя, указывающее на коммит: ветка, тег, HEAD.
Reflog
Локальный журнал перемещений HEAD и веток.
Неотслеживаемый файл
Файл, который Git видит, но ни разу не добавлял (??).
.gitignore
Список шаблонов файлов, которые Git не должен отслеживать.
.gitkeep
Пустой файл по соглашению, чтобы сохранить в Git пустую папку.
