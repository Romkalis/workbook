Три дерева

Глава Pro Git «Раскрытие тайн reset» объясняет Git через три «дерева» — три набора файлов, с которыми он работает. «Дерево» здесь значит просто «набор файлов с папками».

Рабочая папка (working directory)
Обычные файлы на диске, которые вы видите и редактируете. Песочница: здесь можно менять что угодно.
Индекс (index, staging area)
Черновик следующего коммита. git add копирует файл из рабочей папки в индекс. Коммит создаётся из индекса, а не из рабочей папки.
HEAD
Последний коммит текущей ветки — то, что уже сохранено в истории.

Как читать git status -s

Короткий формат показывает два символа: первый — разница между индексом и HEAD, второй — между рабочей папкой и индексом. Проверим:

$ echo "мир" >> hello.txt
$ git status -s
 M hello.txt        # изменён в рабочей папке, в индекс не добавлен
$ git add hello.txt
$ git status -s
M  hello.txt        # изменение в индексе, попадёт в коммит
$ echo "!!" >> hello.txt
$ git status -s
MM hello.txt        # одна правка в индексе, ещё одна только в рабочей папке

Состояние MM часто удивляет: в коммит попадёт версия на момент git add, а последняя правка — нет. git diff показывает разницу «рабочая папка — индекс», git diff --staged — «индекс — HEAD». ?? означает неотслеживаемый файл: Git его видит, но ни разу не добавлял.
