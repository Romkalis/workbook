Найти элемент

querySelector и querySelectorAll

const title = document.querySelector('h1'); // первый h1 или null
const cards = document.querySelectorAll('.card'); // все .card, NodeList
const search = document.querySelector<HTMLInputElement>('#search'); // тип подсказан явно

Оба метода принимают тот же CSS-селектор, что и стили: #id, .class, [data-id="5"], ul > li. querySelector возвращает первый подходящий элемент или null, если ничего нет. querySelectorAll возвращает коллекцию NodeList — она бывает пустой, но никогда не null.

Искать можно не только во всём документе, но и внутри элемента: card.querySelector('.price') ищет только среди потомков карточки. Так код карточки не зацепит цену соседней.

Задача 1. Сколько товаров на странице ★☆☆ разминка

Напишите countByCategory(root, category): возвращает число элементов .card внутри root, у которых data-category равен переданному. Значение категории в строку селектора не подставляйте.

Зачем: поиск внутри нужного блока не даёт посчитать лишнее, например карточки из соседнего блока «Вы смотрели». А данные, вставленные в строку селектора, — та же ловушка, что данные в innerHTML: кавычка в значении ломает запрос.

Решение и разбор
// count.ts
export function countByCategory(root: ParentNode, category: string): number {
  return [...root.querySelectorAll<HTMLElement>('.card')].filter((card) => card.dataset.category === category).length;
}

Селектор постоянный (.card), а сравнение с данными идёт в JavaScript через dataset. Можно было бы написать .card[data-category="${category}"], но категория a"b сломала бы такой селектор с ошибкой. Экранировать значение умеет CSS.escape (есть в браузерах, но, например, нет в jsdom), а сравнение строк в коде не требует экранирования вообще. Поиск идёт внутри root, а не во всём документе: функция работает для любого блока.

null — это не ошибка, а вопрос

querySelector честно признаётся: «может, такого элемента нет». Опечатка в селекторе, скрипт подключён раньше разметки, элемент удалили — всё это реальные ситуации. TypeScript требует их обработать:

export function getRequired<T extends Element>(root: ParentNode, selector: string, type: new () => T): T {
  const el = root.querySelector(selector);
  if (!(el instanceof type)) {
    throw new Error(`Не найден элемент ${selector} нужного типа`);
  }
  return el;
}
// const input = getRequired(document, '#search', HTMLInputElement); // HTMLInputElement, не null

Проверка instanceof HTMLInputElement решает две задачи: исключает null и уточняет тип, после неё доступно input.value. Утверждение document.querySelector('#search')! (оператор !) тоже убирает ошибку компилятора, но ничего не проверяет: если элемента нет, программа упадёт позже и в другом месте (почему ! опасен). Громкая ошибка с понятным текстом при запуске лучше тихого undefined через час.

Задача 2. Обязательный элемент ★☆☆ разминка

Используя getRequired из раздела (или свою версию), найдите в разметке поле поиска #search и кнопку #reset. Напишите setupSearch(root), которая возвращает { input, button } с правильными типами, а при отсутствии элемента бросает понятную ошибку. Ни одного ! и as.

Зачем: ошибка «не найден #search» при старте страницы сразу показывает причину: опечатку в селекторе или изменённую вёрстку. Тихий null всплывёт позже как «Cannot read properties of null» в обработчике клика, и искать причину придётся дольше.

Решение и разбор
// setup.ts
function getRequired<T extends Element>(root: ParentNode, selector: string, type: new () => T): T {
  const el = root.querySelector(selector);
  if (!(el instanceof type)) throw new Error(`Не найден элемент ${selector} нужного типа`);
  return el;
}

export function setupSearch(root: ParentNode) {
  return {
    input: getRequired(root, '#search', HTMLInputElement),
    button: getRequired(root, '#reset', HTMLButtonElement),
  };
}

Тип результата выводится сам: { input: HTMLInputElement; button: HTMLButtonElement }. Конструктор (HTMLInputElement) работает и как проверка во время выполнения, и как источник типа. Все элементы ищутся один раз при старте: если вёрстка сломана, вы узнаете сразу, а не после первого клика.

NodeList и массивы

NodeList похож на массив, но не массив: у него есть forEach и цикл for...of, а map и filter нет. Нужны методы массива — превратите: [...cards] или Array.from(cards). querySelectorAll возвращает «снимок»: если потом добавить новую карточку, старый NodeList о ней не узнает.

Задача 3. Сумма цен со страницы ★☆☆ разминка

На странице карточки с ценой в атрибуте data-price (копейки). Напишите sumPrices(root) через querySelectorAll и методы массива map/reduce.

Зачем: NodeList не массив, и это частая причина ошибки «map is not a function». Превращение в массив — привычка, которая нужна каждый день.

Решение и разбор
// sum.ts
export function sumPrices(root: ParentNode): number {
  return [...root.querySelectorAll<HTMLElement>('[data-price]')]
    .map((el) => Number(el.dataset.price))
    .reduce((sum, price) => sum + price, 0);
}

Spread [...nodeList] даёт настоящий массив. Значения dataset — строки, поэтому Number. Без него reduce склеил бы строки. Обобщение querySelectorAll<HTMLElement> нужно, чтобы TypeScript разрешил dataset: у общего Element его нет. Учтите, что хранить истину в DOM не лучшая идея. В уроке о состоянии цены будут браться из данных, а DOM только показывает их.

closest: подняться к родителю

element.closest('.card') идёт вверх от элемента (включая его самого) и возвращает первого предка, подходящего под селектор, или null. Это главный инструмент для событий: кликнули по иконке внутри кнопки внутри карточки — closest найдёт карточку. Подробно — в следующем уроке.

Задача 4. Найти карточку по клику внутри ★★☆ практика

Напишите productIdFrom(target): по любому элементу внутри карточки (кнопка, иконка в кнопке, текст) возвращает data-id ближайшей .card, или null, если элемент не в карточке. Аргумент может быть любым EventTarget или null.

Зачем: это заготовка для делегирования событий из следующего урока: один обработчик на список и closest, чтобы понять, по какой карточке кликнули. Аргумент типа EventTarget | null — ровно то, что лежит в event.target.

Решение и разбор
// closest.ts
export function productIdFrom(target: EventTarget | null): string | null {
  if (!(target instanceof Element)) return null;
  const card = target.closest<HTMLElement>('.card');
  return card?.dataset.id ?? null;
}

event.target может быть не элементом (например, документом или окном), поэтому сначала instanceof Element: у других целей нет closest. closest проверяет и сам элемент, так что клик прямо по карточке тоже работает. ?. и ?? null превращают «не в карточке» и «нет data-id» в один честный ответ null.
