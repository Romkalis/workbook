Изменить элемент

textContent и innerHTML

title.textContent = 'Каталог'; // текст как есть
list.innerHTML = '<li>Первый</li>'; // строка разбирается как HTML

textContent вставляет текст: угловые скобки останутся скобками на экране. innerHTML разбирает строку как HTML: создаст элементы, атрибуты, обработчики событий. Если в строку попал текст пользователя, он станет кодом:

const name = '<img src=x onerror="alert(document.cookie)">'; // ввёл пользователь
card.innerHTML = `<h3>${name}</h3>`; // браузер создаст img и выполнит onerror
card.querySelector('h3')!.textContent = name; // безопасно: покажет текст как есть

Это XSS (cross-site scripting) — внедрение чужого скрипта на вашу страницу. Скрипт работает с правами пользователя: читает данные, отправляет запросы от его имени. Правило простое: данные — через textContent, разметка — через создание элементов или шаблоны. innerHTML допустим только для строк, которые вы написали сами, без подстановки данных.

Данные «из своего API» — тоже данные пользователя: название товара кто-то ввёл в админке, отзыв написал покупатель. Безопасность не должна зависеть от того, насколько вы доверяете источнику.

Задача 5. Найдите и закройте XSS ★☆☆ разминка

Функция ниже показывает отзыв покупателя. Найдите уязвимость и перепишите функцию без innerHTML с данными, сохранив разметку: имя в <b>, текст в <p>.

export function renderReview(container: HTMLElement, review: { author: string; text: string }) {
  container.innerHTML = `<b>${review.author}</b><p>${review.text}</p>`;
}

Зачем: отзыв пишет кто угодно. Строка <img src=x onerror=...> в поле «текст» выполнится в браузере каждого, кто откроет страницу товара. Это хранимый XSS, самый опасный вид.

Решение и разбор
// review.ts
export function renderReview(container: HTMLElement, review: { author: string; text: string }): void {
  const author = document.createElement('b');
  author.textContent = review.author;
  const text = document.createElement('p');
  text.textContent = review.text;
  container.replaceChildren(author, text);
}

Разметку создаём элементами, данные вставляем через textContent, и никакая строка не станет HTML. replaceChildren заменяет старый отзыв целиком, как это делал innerHTML. Проверка ниже подсовывает в отзыв тег img и убеждается, что такой элемент не появился.

Задача 6. Подсветка найденного без innerHTML ★★★ с подвохом

Напишите highlight(text, query): возвращает DocumentFragment, в котором каждое вхождение query (без учёта регистра) обёрнуто в <mark>, а остальной текст — обычные текстовые узлы. Пустой запрос — весь текст без подсветки. Никакого innerHTML.

Зачем: «найти и обернуть в mark» через innerHTML и replace — популярный способ открыть XSS, ведь и текст, и запрос пришли от пользователя. Сборка из текстовых узлов безопасна по построению.

Подсказка

Ищите позиции в text.toLowerCase() через indexOf(q, from), а куски берите из исходного text, чтобы сохранить регистр. Текстовый узел создаёт document.createTextNode.

Решение и разбор
// highlight.ts
export function highlight(text: string, query: string): DocumentFragment {
  const fragment = document.createDocumentFragment();
  const q = query.trim().toLowerCase();
  if (q === '') {
    fragment.append(text);
    return fragment;
  }
  const lower = text.toLowerCase();
  let from = 0;
  let at = lower.indexOf(q, from);
  while (at !== -1) {
    if (at > from) fragment.append(document.createTextNode(text.slice(from, at)));
    const mark = document.createElement('mark');
    mark.textContent = text.slice(at, at + q.length);
    fragment.append(mark);
    from = at + q.length;
    at = lower.indexOf(q, from);
  }
  if (from < text.length) fragment.append(text.slice(from));
  return fragment;
}

Позиции ищутся в строке нижнего регистра, а вырезаются из исходной, поэтому «Код» в «Чистый Код» подсветится с заглавной буквы. append со строкой сам создаёт текстовый узел, это короче createTextNode. Запрос <b> найдётся как обычный текст и попадёт в mark текстом. Ограничение: для языков, где toLowerCase меняет длину строки (например, немецкое ß в верхнем регистре), позиции могут сместиться. Для русского и английского это не проблема (из общих знаний).

Атрибуты и свойства

У элемента есть атрибуты (то, что написано в HTML) и свойства (поля объекта DOM). Часто они связаны: img.src и атрибут src. Но не всегда. У <input value="1"> атрибут value — начальное значение, а свойство input.value — то, что сейчас в поле. Пользователь печатает — меняется свойство, атрибут остаётся "1". Поэтому значение поля читают через свойство input.value.

getAttribute/setAttribute нужны для атрибутов без удобного свойства, например aria-*. Логические атрибуты (disabled, hidden, checked) удобнее менять свойствами: button.disabled = true.

Задача 7. Атрибут или свойство ★☆☆ разминка

Напишите isChanged(input): возвращает true, если пользователь изменил значение поля по сравнению с тем, что было в HTML. И resetField(input), которая возвращает полю исходное значение.

Зачем: разница между атрибутом и свойством не теоретическая: на ней построены кнопки «Сбросить» и предупреждения «у вас несохранённые изменения». Атрибут помнит начало, свойство знает текущее.

Решение и разбор
// field.ts
export function isChanged(input: HTMLInputElement): boolean {
  return input.value !== input.defaultValue;
}

export function resetField(input: HTMLInputElement): void {
  input.value = input.defaultValue;
}

defaultValue — свойство, которое отражает атрибут value, то же самое, что getAttribute('value') ?? '', только с правильным типом. Сравнение «текущее против исходного» не требует хранить копию данных в переменной: исходное значение уже лежит в разметке.

classList и dataset

export function setStock(card: HTMLElement, stock: number): void {
  card.dataset.stock = String(stock); // атрибут data-stock="0"
  card.classList.toggle('card--empty', stock === 0); // класс есть, только если товара нет
  const button = card.querySelector('button');
  if (button) button.disabled = stock === 0;
}

classList.add/remove/toggle/contains меняют классы, не трогая остальные (в отличие от className = '...', который перезапишет всё). toggle(name, condition) со вторым аргументом ставит класс, когда условие истинно, — одна строка вместо if/else.

dataset — доступ к атрибутам data-*: data-product-id читается как dataset.productId. Значения всегда строки. Сюда кладут идентификатор, по которому обработчик потом найдёт товар.

Задача 8. Карточка без остатка ★☆☆ разминка

Напишите updateStock(card, stock): пишет остаток в data-stock, ставит класс card--empty при нуле и снимает его при положительном остатке, блокирует кнопку и меняет её текст на «Нет в наличии» / «В корзину». Одной функцией, без style.

Зачем: одна функция, которая приводит карточку в соответствие с данными, надёжнее нескольких мест, где по отдельности меняют класс, кнопку и текст. Рано или поздно одно из мест забудут.

Решение и разбор
// stock.ts
export function updateStock(card: HTMLElement, stock: number): void {
  const empty = stock === 0;
  card.dataset.stock = String(stock);
  card.classList.toggle('card--empty', empty);
  const button = card.querySelector('button');
  if (button) {
    button.disabled = empty;
    button.textContent = empty ? 'Нет в наличии' : 'В корзину';
  }
}

Функция идемпотентна: вызов с тем же остатком дважды даёт тот же результат, а toggle со вторым аргументом не зависит от прошлого состояния класса. Это важное свойство. Такую функцию можно вызывать после любого изменения данных, не думая, что уже было на экране.

Классы вместо style

el.style.color = 'red' работает, но смешивает оформление с логикой: дизайнер не найдёт этот цвет в CSS, а тёмная тема его не перекрасит. Почти всегда лучше переключить класс (card--empty) и описать вид в CSS. style оставляют для по-настоящему вычисляемых значений: координаты, ширина полосы прогресса. Для показа и скрытия есть атрибут hidden: el.hidden = true.

Задача 9. Когда style уместен ★★☆ практика

Сделайте полосу прогресса бесплатной доставки: updateDeliveryBar(bar, subtotal, threshold) задаёт ширину внутреннего .bar__fill в процентах (не больше 100) через style, а при достижении порога ставит класс bar--done и пишет в .bar__text «Доставка бесплатна», иначе «Ещё N ₽ до бесплатной доставки».

Зачем: ширина зависит от числа, и описать её заранее в CSS нельзя: это настоящий случай для style. А цвет «готово» — фиксированное оформление, ему место в классе. Задача учит различать эти два случая.

Решение и разбор
// bar.ts
export function updateDeliveryBar(bar: HTMLElement, subtotal: number, threshold: number): void {
  const fill = bar.querySelector<HTMLElement>('.bar__fill');
  const text = bar.querySelector('.bar__text');
  if (!fill || !text) throw new Error('Неверная разметка полосы');

  const percent = Math.min(100, Math.round((subtotal / threshold) * 100));
  const done = subtotal >= threshold;
  fill.style.width = `${percent}%`;
  bar.classList.toggle('bar--done', done);
  text.textContent = done
    ? 'Доставка бесплатна'
    : `Ещё ${Math.ceil((threshold - subtotal) / 100)} ₽ до бесплатной доставки`;
}

Math.min(100, ...) не даёт полосе вылезти за край при сумме больше порога. Остаток округлён вверх (Math.ceil): «ещё 0 ₽» при недостающих 50 копейках выглядело бы как ошибка. Для доступности у полосы стоит добавить role="progressbar" и aria-valuenow, а текст рядом уже дублирует смысл (из общих знаний).

Задача 10. Показать и скрыть сообщение ★☆☆ разминка

Напишите showMessage(el, text): если текст непустой, показывает элемент с этим текстом, иначе прячет его и очищает. Используйте атрибут hidden, не style.display.

Зачем: hidden — смысловой атрибут: «сейчас не актуально». Его понимают программы чтения с экрана и тесты, и не нужно помнить, каким был display до скрытия (flex? grid?).

Решение и разбор
// message.ts
export function showMessage(el: HTMLElement, text: string): void {
  el.textContent = text;
  el.hidden = text.trim() === '';
}

Свойство hidden ставит и снимает одноимённый атрибут. В CSS у класса с display: flex атрибут может «проиграть». Тогда добавляют правило [hidden] { display: none !important; } (из общих знаний). Пустой текст очищается тоже, чтобы скрытый элемент не хранил старое сообщение.
