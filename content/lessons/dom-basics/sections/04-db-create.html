Создать и вставить

createElement и append

export interface Product {
  id: string;
  title: string;
  price: number;
}

export function formatPrice(kopecks: number): string {
  return `${(kopecks / 100).toFixed(2)} ₽`;
}

export function createCard(product: Product): HTMLElement {
  const card = document.createElement('article');
  card.className = 'card';
  card.dataset.id = product.id;

  const title = document.createElement('h3');
  title.textContent = product.title;

  const price = document.createElement('p');
  price.className = 'card__price';
  price.textContent = formatPrice(product.price);

  const button = document.createElement('button');
  button.type = 'button';
  button.textContent = 'В корзину';

  card.append(title, price, button);
  return card;
}

Функция «данные → элемент» — основной кирпич ванильного фронтенда. Она ничего не знает о том, куда карточку вставят, поэтому её легко тестировать и переиспользовать. Все данные идут через textContent, поэтому название <script> станет просто текстом.

Вставка: parent.append(...nodes) — в конец, prepend — в начало, el.before(x) / el.after(x) — рядом, el.remove() — удалить. parent.replaceChildren(...nodes) заменяет всё содержимое за один вызов: удобно, когда список перерисовывается целиком.

Задача 11. Карточка из данных ★☆☆ разминка

Напишите createProductCard(product) для товара { id, title, price, category, stock }. Карточка — article.card с data-id и data-category, заголовок h3, цена в рублях, подпись категории по-русски из словаря и кнопка «В корзину» (заблокирована при нулевом остатке).

Зачем: это основная функция всего раздела: в следующих уроках к ней добавятся события и данные с сервера. Чем лучше она отделена от остального кода, тем проще будут следующие шаги.

Решение и разбор
// product-card.ts
export interface Product {
  id: string;
  title: string;
  price: number;
  category: 'books' | 'games' | 'home';
  stock: number;
}

const CATEGORY_LABELS: Record<Product['category'], string> = {
  books: 'Книги',
  games: 'Игры',
  home: 'Для дома',
};

function el<K extends keyof HTMLElementTagNameMap>(tag: K, text?: string, className?: string): HTMLElementTagNameMap[K] {
  const node = document.createElement(tag);
  if (text !== undefined) node.textContent = text;
  if (className) node.className = className;
  return node;
}

export function createProductCard(product: Product): HTMLElement {
  const card = el('article', undefined, 'card');
  card.dataset.id = product.id;
  card.dataset.category = product.category;

  const button = el('button', 'В корзину');
  button.type = 'button';
  button.disabled = product.stock === 0;

  card.append(
    el('h3', product.title),
    el('p', CATEGORY_LABELS[product.category], 'card__category'),
    el('p', `${(product.price / 100).toFixed(2)} ₽`, 'card__price'),
    button,
  );
  return card;
}

Помощник el убирает повторение «создать, заполнить текст, задать класс». Его тип HTMLElementTagNameMap[K] даёт точный результат: el('button') имеет тип HTMLButtonElement, и button.disabled доступен без приведения типов. Словарь подписей типизирован через Record по union категорий: новая категория без подписи — ошибка компиляции.

Задача 12. Заменить одну карточку ★★☆ практика

Напишите replaceCard(container, product, createCard): находит в контейнере карточку с data-id товара и заменяет её новой, созданной из данных. Если карточки нет — ничего не делает и возвращает false.

Зачем: перерисовать весь список проще, но иногда дорого или неудобно: собьётся фокус в поле количества, прокрутка, анимация. Точечная замена — второй инструмент, и важно знать оба.

Решение и разбор
// replace.ts
export function replaceCard<T extends { id: string }>(
  container: HTMLElement,
  product: T,
  createCard: (p: T) => HTMLElement,
): boolean {
  const old = [...container.querySelectorAll<HTMLElement>('[data-id]')].find((el) => el.dataset.id === product.id);
  if (!old) return false;
  old.replaceWith(createCard(product));
  return true;
}

replaceWith ставит новый элемент ровно на место старого, порядок списка не меняется. Карточка создаётся той же функцией, что и при полной отрисовке, поэтому «точечная» карточка не будет отличаться от остальных. Это главное условие, чтобы два способа обновления не разошлись.

Задача 13. Удалить карточку и показать пустое состояние ★☆☆ разминка

Напишите removeCard(container, id): удаляет карточку с этим data-id. Если после удаления карточек не осталось, вставляет сообщение «Корзина пуста». Возвращает число оставшихся карточек.

Зачем: переход «последний элемент удалён → пустое состояние» — классическое место бага: список исчез, а сообщение не появилось, и пользователь видит белую пустоту.

Решение и разбор
// remove.ts
export function removeCard(container: HTMLElement, id: string): number {
  [...container.querySelectorAll<HTMLElement>('[data-id]')].find((el) => el.dataset.id === id)?.remove();
  const left = container.querySelectorAll('[data-id]').length;
  if (left === 0) {
    const empty = document.createElement('p');
    empty.textContent = 'Корзина пуста';
    container.replaceChildren(empty);
  }
  return left;
}

Карточка ищется сравнением dataset.id, а не селектором с подставленным id, по той же причине, что в задаче про подсчёт. ?.remove() спокойно ничего не делает, если карточки нет. Число оставшихся считается по документу после удаления, а не вычитанием «было минус один»: так функция не врёт, если карточки и не было. В уроке о состоянии эту логику перевернём: данные изменятся, а список перерисуется из них, и такого рода баги исчезнут сами.

Задача 14. Таблица заказов ★★☆ практика

Напишите createOrdersTable(orders): возвращает <table> с заголовком (thead: «№», «Дата», «Сумма») и строками заказов. Дата 2026-11-18 показывается как 18.11.2026, сумма — в рублях. Последняя строка в tfoot — итог по всем заказам.

Зачем: таблица — данные с двумя измерениями, и семантическая разметка (th, thead, tfoot) делает её понятной программе чтения с экрана. Итог считается из данных, а не из ячеек таблицы.

Решение и разбор
// table.ts
export interface Order {
  id: number;
  date: string;
  total: number;
}

const rub = (k: number) => `${(k / 100).toFixed(2)} ₽`;
const ruDate = (iso: string) => iso.split('-').reverse().join('.');

function row(cells: string[], tag: 'td' | 'th'): HTMLTableRowElement {
  const tr = document.createElement('tr');
  tr.append(...cells.map((text) => Object.assign(document.createElement(tag), { textContent: text })));
  return tr;
}

export function createOrdersTable(orders: readonly Order[]): HTMLTableElement {
  const table = document.createElement('table');
  const thead = table.createTHead();
  thead.append(row(['№', 'Дата', 'Сумма'], 'th'));
  const tbody = table.createTBody();
  tbody.append(...orders.map((o) => row([String(o.id), ruDate(o.date), rub(o.total)], 'td')));
  const tfoot = table.createTFoot();
  tfoot.append(row(['Итого', '', rub(orders.reduce((s, o) => s + o.total, 0))], 'td'));
  return table;
}

createTHead, createTBody, createTFoot — специальные методы таблицы, создающие нужные части. Object.assign(element, { textContent }) — короткий способ создать элемент с текстом в одну строку. Дата переформатирована строкой, без new Date: new Date('2026-11-18') трактуется как полночь UTC, и в часовом поясе западнее Гринвича превратилась бы в 17 ноября (из общих знаний).

Много элементов за раз

Каждая вставка в документ — повод для браузера пересчитать раскладку. Сто вставок по одной — сто поводов. Удобнее собрать элементы и вставить один раз:

import { createCard, type Product } from './card.js';

export function renderProducts(container: HTMLElement, products: readonly Product[]): void {
  if (products.length === 0) {
    const empty = document.createElement('p');
    empty.textContent = 'Ничего не найдено';
    container.replaceChildren(empty);
    return;
  }
  container.replaceChildren(...products.map(createCard));
}

replaceChildren с массивом карточек — одна операция с документом. На сотне элементов разница почти незаметна, но привычка «собрать, потом вставить» спасает на тысячах (из общих знаний). Ещё есть DocumentFragment — контейнер, который можно наполнять и вставить целиком; replaceChildren и append(...nodes) чаще его заменяют.

Задача 15. Список с пустым состоянием ★☆☆ разминка

Напишите renderList(container, products, createCard): заменяет содержимое контейнера карточками за одну операцию; для пустого массива показывает <p class="empty">Ничего не найдено</p>. Функцию создания карточки принимайте параметром.

Зачем: пустое состояние — тоже состояние, его дизайн и текст нужно продумать заранее. Функция-параметр делает список универсальным: тот же код нарисует товары, отзывы или заказы.

Решение и разбор
// render-list.ts
export function renderList<T>(container: HTMLElement, items: readonly T[], createCard: (item: T) => HTMLElement): void {
  if (items.length === 0) {
    const empty = document.createElement('p');
    empty.className = 'empty';
    empty.textContent = 'Ничего не найдено';
    container.replaceChildren(empty);
    return;
  }
  container.replaceChildren(...items.map(createCard));
}

Generic T связывает тип элементов массива и параметр createCard: передать список товаров и функцию для отзывов не получится. items.map(createCard) безопасен: map передаёт ещё индекс и массив, но createCard объявлена с одним параметром, и лишние аргументы она игнорирует.

Задача 16. Заглушки на время загрузки ★★☆ практика

Напишите renderSkeletons(container, count): показывает count пустых карточек-заглушек div.card.card--skeleton с атрибутом aria-hidden="true", а у контейнера ставит aria-busy="true". И clearBusy(container), которая снимает aria-busy.

Зачем: заглушки той же формы, что и карточки, не дают странице «прыгать», когда данные придут. aria-busy сообщает вспомогательным технологиям, что содержимое ещё меняется, а aria-hidden прячет от них пустые серые блоки.

Решение и разбор
// skeleton.ts
export function renderSkeletons(container: HTMLElement, count: number): void {
  const items = Array.from({ length: count }, () => {
    const card = document.createElement('div');
    card.className = 'card card--skeleton';
    card.setAttribute('aria-hidden', 'true');
    return card;
  });
  container.replaceChildren(...items);
  container.setAttribute('aria-busy', 'true');
}

export function clearBusy(container: HTMLElement): void {
  container.removeAttribute('aria-busy');
}

Array.from({ length: count }, фабрика) создаёт массив новых элементов. С fill(card) получился бы массив из одного и того же элемента, и в документ попала бы одна заглушка. clearBusy вызывают после отрисовки настоящих карточек, в том числе когда пришла ошибка: иначе область навсегда останется «занятой».

Задача 17. Обновить список, сохранив существующие карточки ★★★ с подвохом

Напишите syncList(container, products, createCard): приводит список к массиву products, но переиспользует существующие карточки с тем же data-id (не пересоздаёт их), создаёт новые для новых товаров, удаляет лишние и выстраивает порядок как в массиве.

Зачем: так в упрощённом виде работают фреймворки с ключами (key в React): элементы, которые остались, не пересоздаются, поэтому сохраняются фокус, введённый текст и анимации. Написав это сами, вы поймёте, зачем фреймворку ключи.

Решение и разбор
// sync.ts
export function syncList<T extends { id: string }>(
  container: HTMLElement,
  products: readonly T[],
  createCard: (p: T) => HTMLElement,
): void {
  const existing = new Map<string, HTMLElement>();
  for (const child of container.querySelectorAll<HTMLElement>(':scope > [data-id]')) {
    existing.set(child.dataset.id ?? '', child);
  }
  const next = products.map((p) => existing.get(p.id) ?? createCard(p));
  container.replaceChildren(...next);
}

Карточки собираются в Map по id, это даёт поиск за O(1) вместо перебора. replaceChildren с массивом, где часть элементов уже в документе, переставляет их, а не копирует: узел DOM может быть только в одном месте. Карточки, которых нет в новом массиве, просто не попадут в результат и исчезнут. Ограничение: переиспользованная карточка не обновляет свои данные. Если товар изменился (новая цена), её нужно пересоздать или обновить. Ключ говорит «это тот же товар», а не «это та же цена». Селектор :scope > берёт только прямых детей контейнера.

Шаблон template

Когда разметка карточки большая, собирать её из createElement утомительно. Тег <template> хранит разметку, которую браузер не показывает и не выполняет. Её клонируют и заполняют:

<template id="card-template">
  <article class="card">
    <h3 class="card__title"></h3>
    <p class="card__price"></p>
    <button type="button">В корзину</button>
  </article>
</template>
import { formatPrice, type Product } from './card.js';

export function createCardFromTemplate(template: HTMLTemplateElement, product: Product): HTMLElement {
  const fragment = template.content.cloneNode(true) as DocumentFragment;
  const card = fragment.querySelector<HTMLElement>('.card');
  const title = fragment.querySelector('.card__title');
  const price = fragment.querySelector('.card__price');
  if (!card || !title || !price) throw new Error('Шаблон карточки повреждён');
  card.dataset.id = product.id;
  title.textContent = product.title;
  price.textContent = formatPrice(product.price);
  return card;
}

Разметка живёт в HTML, где её видят верстальщик и редактор, а данные по-прежнему вставляются через textContent. cloneNode(true) копирует шаблон глубоко, со всеми потомками; без true скопировался бы пустой тег. as DocumentFragment здесь безопасно: cloneNode объявлен как возвращающий Node, хотя для content это всегда фрагмент.

Задача 18. Карточка из шаблона ★★☆ практика

В HTML есть <template id="review-template"> с разметкой отзыва: .review__author, .review__stars, .review__text. Напишите createReview(template, review): клонирует шаблон и заполняет поля, а оценку показывает звёздочками: 4 из 5 — «★★★★☆».

// review.html
<template id="review-template">
  <article class="review">
    <b class="review__author"></b>
    <span class="review__stars" aria-label=""></span>
    <p class="review__text"></p>
  </article>
</template>

Зачем: шаблон отделяет разметку (её правит верстальщик в HTML) от логики заполнения (в TypeScript). А звёзды — хороший повод вспомнить про доступность: символы ★ программа чтения с экрана прочтёт неразборчиво, поэтому смысл дублируется в aria-label.

Решение и разбор
// review.ts
export interface Review {
  author: string;
  rating: number;
  text: string;
}

export function stars(rating: number): string {
  const full = Math.max(0, Math.min(5, Math.round(rating)));
  return '★'.repeat(full) + '☆'.repeat(5 - full);
}

export function createReview(template: HTMLTemplateElement, review: Review): HTMLElement {
  const fragment = template.content.cloneNode(true) as DocumentFragment;
  const root = fragment.querySelector<HTMLElement>('.review');
  const author = fragment.querySelector('.review__author');
  const starsEl = fragment.querySelector('.review__stars');
  const text = fragment.querySelector('.review__text');
  if (!root || !author || !starsEl || !text) throw new Error('Шаблон отзыва повреждён');

  author.textContent = review.author;
  starsEl.textContent = stars(review.rating);
  starsEl.setAttribute('aria-label', `Оценка ${review.rating} из 5`);
  text.textContent = review.text;
  return root;
}

Функция stars вынесена отдельно и ограничивает оценку диапазоном 0–5. Без этого оценка 7 из кривых данных дала бы ошибку repeat с отрицательным числом. Шаблон проверяется целиком при каждом вызове. Если верстальщик переименует класс, ошибка назовёт причину. Возвращается сам article, а не фрагмент: так функцию можно использовать в replaceWith и в тестах.
