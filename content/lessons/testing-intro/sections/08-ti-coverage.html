Покрытие кода (coverage)

Покрытие показывает, какие строки вашего кода хоть раз выполнились во время тестов. Jest считает его по флагу --coverage:

npx jest --coverage
# в задании для этого есть готовый скрипт:
npm run test:coverage

Jest напечатает таблицу в терминале и создаст папку coverage/. Откройте в браузере coverage/lcov-report/index.html: там список файлов, а внутри каждого — код с подсветкой. Зелёные строки выполнялись, красные — нет.

В таблице четыре колонки (из общих знаний о формате отчёта):

  • Statements — доля выполненных инструкций;
  • Branches — доля пройденных веток if/else, ? :, ||. Самая полезная колонка: показывает непроверенные условия;
  • Functions — доля вызванных функций;
  • Lines — доля выполненных строк.

100% покрытия не значит «без ошибок»

function calculateCartSubtotal(cart) {
  return cart.reduce((sum, item) => sum + item.price, 0); // забыли quantity!
}

test('считает сумму', () => {
  expect(calculateCartSubtotal([{ price: 100, quantity: 1 }])).toBe(100);
});

Покрытие 100%: каждая строка выполнилась. Но функция неправильная — количество не учитывается, а тест этого не заметил, потому что взял quantity: 1. Покрытие отвечает на вопрос «что выполнялось», а не «что проверено». Используйте его как подсказку, где тестов нет совсем, а не как цель.

В задании Testing Intro покрытие не влияет на оценку: нужен только скриншот отчёта в PR.

Задача 21. Тест, который ловит ошибку при 100% покрытии ★★☆ практика

В разделе выше функция забыла умножить на quantity, а тест с покрытием 100% это пропустил. Напишите тест, который поймает эту ошибку. Затем проверьте себя: временно вставьте ошибку в функцию и убедитесь, что тест красный.

// subtotal.js
function calculateCartSubtotal(cart) {
  return cart.reduce((sum, item) => sum + item.price * item.quantity, 0);
}
module.exports = { calculateCartSubtotal };

Зачем: покрытие говорит, что код выполнялся, но не говорит, что результат проверен содержательно. Данные с «удобными» значениями (количество 1, цена 0) маскируют ошибки. Привычка «а что будет, если сломать вот эту строку?» — главный способ проверить качество тестов.

Решение и разбор
// subtotal.test.js
const { calculateCartSubtotal } = require('./subtotal');

test('учитывает количество каждого товара', () => {
  const cart = [{ price: 100, quantity: 3 }, { price: 50, quantity: 2 }];
  expect(calculateCartSubtotal(cart)).toBe(400);
});

Количество больше 1, и у разных строк оно разное, поэтому ошибочная версия даст 150, а не 400. Ручная проверка «сломать и посмотреть» называется мутационным тестированием. Все тесты этого урока проверены именно так: к каждой задаче на написание тестов есть сломанная версия кода, и решение обязано на ней упасть.

Задача 22. Найдите непокрытую ветку ★★☆ практика

Для calculateOrderTotal уже есть два теста. Запустите npx jest --coverage, найдите в отчёте непокрытую ветку (колонка Branches) и допишите тест, который её покрывает и проверяет правильный результат.

// order.js
function calculateOrderTotal(subtotal, promoCode) {
  let discount = 0;
  if (promoCode === 'SAVE10') {
    if (subtotal >= 20000) {
      discount = Math.round(subtotal * 0.1);
    }
  }
  const delivery = subtotal >= 50000 ? 0 : 30000;
  return { discount, delivery, total: subtotal - discount + delivery };
}
module.exports = { calculateOrderTotal };
// order.test.js
const { calculateOrderTotal } = require('./order');
test('без промокода, с доставкой', () => {
  expect(calculateOrderTotal(10000)).toEqual({ discount: 0, delivery: 30000, total: 40000 });
});
test('SAVE10 и бесплатная доставка', () => {
  expect(calculateOrderTotal(60000, 'SAVE10')).toEqual({ discount: 6000, delivery: 0, total: 54000 });
});

Зачем: колонка Branches показывает условия, которые ни разу не пошли по одной из дорог. Это самые вероятные места непроверенных ошибок: правило «скидка только от 20 000» никем не проверено, хотя строки выполнялись.

Решение и разбор
// order.branch.test.js
const { calculateOrderTotal } = require('./order');

test('SAVE10 не действует на сумму меньше 20 000', () => {
  expect(calculateOrderTotal(19999, 'SAVE10')).toEqual({ discount: 0, delivery: 30000, total: 49999 });
});

Отчёт показывает 100% строк, но 83,33% веток, а в колонке Uncovered Line — номер строки с if (subtotal >= 20000). Её «ложная» дорога ни разу не выполнялась: ни один тест не проходит случай «промокод верный, но суммы не хватает». Новый тест закрывает именно эту дорогу и ловит мутанта, который забыл про порог. Учтите: если записать то же условие одной строкой через && в тернарном операторе, отчёт может показать 100% веток, хотя случай по-прежнему не проверен. Покрытие зависит от формы кода, а не только от смысла.
