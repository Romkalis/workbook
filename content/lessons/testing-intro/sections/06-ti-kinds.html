Какие бывают тесты

Тесты различаются тем, какой кусок программы они проверяют. В модуле RS School перечислены основные виды.

  • Модульные (unit) — проверяют одну функцию или маленький модуль отдельно от остального. Быстрые (миллисекунды), их много. Все тесты в задании Testing Intro — модульные.
  • Интеграционные (integration) — проверяют, что несколько частей правильно работают вместе: например, корзина вместе с каталогом и сохранением в localStorage.
  • Сквозные (end-to-end, E2E) — запускают настоящий браузер и проходят путь пользователя: открыть каталог, нажать «В корзину», увидеть сумму. Самые близкие к реальности, но медленные и капризные. Инструменты — Playwright, Cypress.
  • Ручное тестирование — человек проходит сценарии сам. Не исчезает: дизайн, удобство и «странное поведение» автотест не оценит.

Есть и тесты по другой оси — что проверяем, а не какой кусок: безопасности (можно ли украсть данные или выполнить чужой код) и производительности (выдержит ли сайт нагрузку, быстро ли открывается страница).

Пирамида тестов

Почему так? Модульный тест упал — вы сразу знаете, какая функция сломана. E2E-тест упал — виновата может быть любая из сотни частей, а сам тест выполняется секунды или минуты. Поэтому основную логику проверяют модульными тестами, а E2E оставляют для самых важных путей: регистрация, оплата. Подробнее — пирамида и уровни тестов в основном уроке.

Задача 18. Вытащите логику из обработчика ★★☆ практика

Обработчик ниже смешивает работу с DOM и расчёт. Вынесите расчёт в чистую функцию calcLine(price, quantityText): она возвращает сумму строки или null при неверном количестве. Напишите на неё модульные тесты. Обработчик после этого только читает поля, вызывает функцию и пишет результат.

input.addEventListener('input', () => {
  const qty = Number(input.value);
  if (!Number.isInteger(qty) || qty < 1) {
    total.textContent = '—';
    return;
  }
  total.textContent = String(Number(input.dataset.price) * qty);
});

Зачем: пирамида тестов держится на основании: много быстрых модульных тестов. Это возможно, только если логика не прибита к DOM. Чистую функцию проверяет тест за миллисекунды, а для обработчика нужен браузер или его эмуляция.

Решение и разбор
// line.js
function calcLine(price, quantityText) {
  const qty = Number(quantityText);
  if (!Number.isInteger(qty) || qty < 1) return null;
  return price * qty;
}
module.exports = { calcLine };

// line.test.js
const { calcLine } = require('./line');

test('цена × количество', () => expect(calcLine(250, '4')).toBe(1000));
test.each(['', '0', '-1', '2.5', 'abc'])('неверное количество %j даёт null', (q) => {
  expect(calcLine(250, q)).toBeNull();
});

Функция не знает про input и textContent: на вход значения, на выход результат. Обработчик стал «тонким», и тестировать в нём почти нечего. Его проверят один-два интеграционных или E2E-теста, а все правила (пустая строка, ноль, дробь) покрыты быстрыми модульными. Решение вернуть null, а не '—': как показать ошибку, решает интерфейс, а функция только сообщает, что количество неверное.
