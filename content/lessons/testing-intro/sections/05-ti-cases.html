Как придумывать тесты

Самый трудный вопрос новичка — не «как написать тест», а «какие тесты писать». Помогает простой список: для каждой функции подумайте о трёх группах случаев.

  1. Обычный случай — то, ради чего функция существует. Категория 'books' возвращает книги.
  2. Граничный случай — края допустимого: пустой массив, ноль, одна штука, максимальное количество на складе, сумма ровно 20 000 копеек.
  3. Неправильный ввод — то, чего «не должно быть», но будет: несуществующая категория, ID строкой '1' вместо числа, NaN, пробелы вместо запроса.

Задание Testing Intro построено ровно так: для каждой функции три сценария по три кейса. Посмотрите на таблицу для getProductById: товар существует (обычный), числовой ID отсутствует (граница), ID неверного типа (неправильный ввод).

Структура теста: Arrange, Act, Assert

Хороший тест читается в три шага:

test('не меняет исходный массив', () => {
  // Arrange — подготовка данных
  const catalog = [{ id: 1, stock: 2 }, { id: 2, stock: 0 }];

  // Act — вызов проверяемой функции
  getAvailableProducts(catalog);

  // Assert — проверка результата
  expect(catalog).toEqual([{ id: 1, stock: 2 }, { id: 2, stock: 0 }]);
});

Комментарии писать не обязательно, но мысленно делить тест на эти части полезно. Подробнее — в разделе AAA основного урока.

Признаки хорошего теста

  • Одна мысль на тест. Если тест упал, по названию сразу понятно, какое правило нарушено.
  • Понятное название. «возвращает пустой массив для пустого каталога» вместо «test 5».
  • Конкретные ожидания. Сравнивайте с готовым значением ([1, 2]), а не пересчитывайте его в тесте той же логикой, что в коде: иначе тест повторит ошибку кода.
  • Независимость. Тесты не должны зависеть друг от друга и от порядка запуска. Если один тест меняет общие данные, другой может внезапно упасть.
  • Повторяемость. Никаких случайных чисел, текущего времени и сети в проверках: результат должен быть одинаковым при каждом запуске.

Какие случаи вы бы проверили у функции removeFromCart(cart, productId)?

Обычный: удаляет нужный товар, остальные остаются. Граничный: удаление единственного товара даёт пустую корзину. Неправильный ввод: ID товара, которого нет, — корзина не меняется. Ровно эти три теста есть в задании.
