Jest: как устроен тест

Установка и запуск

Jest ставится в проект как dev-зависимость — пакет, который нужен только при разработке, а не пользователю сайта:

npm install --save-dev jest

В package.json добавляют скрипт:

{
  "scripts": {
    "test": "jest"
  }
}

Теперь npm test запускает Jest, а тот находит все файлы, которые заканчиваются на .test.js (или лежат в папке __tests__), и выполняет их. Можно запустить только часть: npx jest tests/catalog выполнит тесты из одной папки.

Анатомия тестового файла

Вот готовый пример из задания Testing Intro (сокращён):

const products = require('../../src/data/products');
const { getAvailableProducts } = require('../../src/catalog');

describe('getAvailableProducts', () => {
  test('исключает товары с нулевым остатком', () => {
    const catalog = [{ id: 1, stock: 2 }, { id: 2, stock: 0 }, { id: 3, stock: 5 }];
    expect(getAvailableProducts(catalog)).toEqual([{ id: 1, stock: 2 }, { id: 3, stock: 5 }]);
  });

  test('возвращает пустой массив для пустого каталога', () => {
    expect(getAvailableProducts([])).toEqual([]);
  });
});

Разберём каждую часть:

  • require('../../src/catalog') — подключение кода из другого файла. Это синтаксис CommonJS, старый стандарт модулей Node; в проекте задания используется он. Аналог в современных модулях — import { getAvailableProducts } from '../../src/catalog.js'. Путь ../../ значит «подняться на две папки вверх».
  • describe('название', () => { ... }) — группа тестов. Обычно одна группа на одну функцию. Группы можно вкладывать друг в друга.
  • test('название', () => { ... }) — один тест, одна проверяемая мысль. Вместо test можно писать it, это синоним. Название пишут так, чтобы оно читалось как правило: «исключает товары с нулевым остатком».
  • expect(фактическое).toEqual(ожидаемое) — проверка. expect принимает то, что вернула функция, а метод после точки — матчер — говорит, как сравнивать.

describe, test и expect не нужно импортировать: Jest сам делает их доступными во всех тестовых файлах.

Как читать результат

Если все тесты прошли, Jest печатает зелёные галочки и сводку вида Tests: 9 passed, 9 total. Если какой-то упал, вы увидите его название красным и разницу (diff):

✕ исключает товары с нулевым остатком

  expect(received).toEqual(expected)

  - Expected  - 0
  + Received  + 4

  @@ ... @@
  +   Object {
  +     "id": 2,
  +     "stock": 0,
  +   },

Строки с - есть в ожидаемом, но нет в фактическом. Строки с + — наоборот, лишние. Здесь функция вернула товар с stock: 0, которого быть не должно. Ниже Jest показывает номер строки в тестовом файле. (Вывод приведён по общим знаниям о формате Jest и может немного отличаться в вашей версии.)

Если тест упал, сначала поймите, кто прав: код или тест. Тест тоже может быть написан с ошибкой. Но в задании Testing Intro тесты корзины трогать нельзя — там правы они.

test.todo и test.each

test.todo('название') — тест-заметка «надо написать». Он не выполняется и показывается в отчёте как todo. В задании все тесты каталога заданы именно так: вам нужно превратить каждый todo в настоящий тест.

test.each запускает один и тот же тест на нескольких наборах данных. Подробно — в разделе с решением.
