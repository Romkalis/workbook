Основные матчеры

Матчер — метод после expect(...), который решает, считается ли результат правильным. Вот те, что нужны в задании и в 90% обычных тестов.

МатчерЧто проверяетПример
toBe(x)Строгое равенство, как Object.is. Для чисел, строк, true/false — и для проверки «это тот же самый объект».expect(calculateCartSubtotal([])).toBe(0)
toEqual(x)Глубокое сравнение: одинаковое содержимое объектов и массивов.expect(ids).toEqual([1, 2])
toBeNull()Значение равно null.expect(getProductById(products, 0)).toBeNull()
toHaveLength(n)Длина массива или строки.expect(list).toHaveLength(4)
toContain(x)Элемент есть в массиве (или подстрока в строке).expect(ids).toContain(3)
toThrow(Тип)Функция бросает ошибку (указанного типа).expect(() => addToCart([], lamp, 0)).toThrow(RangeError)
.notОтрицание любого матчера.expect(result).not.toBe(catalog)

toBe или toEqual

Самая частая ошибка новичка — проверять массив через toBe:

expect(filterByCategory(products, 'books')).toBe([products[2], products[5]]); // упадёт
expect(filterByCategory(products, 'books')).toEqual([products[2], products[5]]); // пройдёт

filter возвращает новый массив, и он не тот же самый объект, что массив в правой части. Правило простое: примитивы (числа, строки) — toBe, объекты и массивы по содержимому — toEqual. А вот когда важно, что функция вернула именно тот же объект, а не копию — toBe. Так в задании проверяется getProductById: она должна вернуть объект товара из каталога.

toThrow: нужна обёртка-функция

// Неправильно: addToCart выполнится сразу, ошибка вылетит до expect,
// и тест упадёт с этой ошибкой вместо проверки
expect(addToCart([], lamp, 0)).toThrow(RangeError);

// Правильно: передаём функцию, Jest сам вызовет её и поймает ошибку
expect(() => addToCart([], lamp, 0)).toThrow(RangeError);

RangeError — встроенный тип ошибки JavaScript для значений «вне допустимого диапазона». Его используют тесты корзины для неправильного количества товара.
