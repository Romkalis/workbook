Основные матчеры

Матчер — метод после expect(...), который решает, считается ли результат правильным. Вот те, что нужны в задании и в 90% обычных тестов.

МатчерЧто проверяетПример
toBe(x)Строгое равенство, как Object.is. Для чисел, строк, true/false — и для проверки «это тот же самый объект».expect(calculateCartSubtotal([])).toBe(0)
toEqual(x)Глубокое сравнение: одинаковое содержимое объектов и массивов.expect(ids).toEqual([1, 2])
toBeNull()Значение равно null.expect(getProductById(products, 0)).toBeNull()
toHaveLength(n)Длина массива или строки.expect(list).toHaveLength(4)
toContain(x)Элемент есть в массиве (или подстрока в строке).expect(ids).toContain(3)
toThrow(Тип)Функция бросает ошибку (указанного типа).expect(() => addToCart([], lamp, 0)).toThrow(RangeError)
.notОтрицание любого матчера.expect(result).not.toBe(catalog)

toBe или toEqual

Самая частая ошибка новичка — проверять массив через toBe:

expect(filterByCategory(products, 'books')).toBe([products[2], products[5]]); // упадёт
expect(filterByCategory(products, 'books')).toEqual([products[2], products[5]]); // пройдёт

filter возвращает новый массив, и он не тот же самый объект, что массив в правой части. Правило простое: примитивы (числа, строки) — toBe, объекты и массивы по содержимому — toEqual. А вот когда важно, что функция вернула именно тот же объект, а не копию — toBe. Так в задании проверяется getProductById: она должна вернуть объект товара из каталога.

Задача 11. Неверные матчеры ★☆☆ разминка

Оба теста ниже написаны с ошибкой матчера: первый падает, хотя функция работает, а второй проходит, хотя проверяет не то. Исправьте матчеры.

// starter.js
test('возвращает книги', () => {
  expect(filterByCategory(products, 'books')).toBe([products[0]]);
});
test('находит именно объект из каталога, а не копию', () => {
  expect(getById(products, 1)).toEqual(products[0]);
});
// catalog.js
const products = [{ id: 1, category: 'books' }, { id: 2, category: 'games' }];
const filterByCategory = (list, category) => list.filter((p) => p.category === category);
const getById = (list, id) => list.find((p) => p.id === id) ?? null;
module.exports = { products, filterByCategory, getById };

Зачем: toBe и toEqual отвечают на разные вопросы: «тот же объект?» и «то же содержимое?». Перепутав их, вы получаете либо ложные падения, либо, что опаснее, ложные успехи.

Решение и разбор
// catalog.test.js
const { products, filterByCategory, getById } = require('./catalog');

test('возвращает книги', () => {
  expect(filterByCategory(products, 'books')).toEqual([products[0]]);
});

test('находит именно объект из каталога, а не копию', () => {
  expect(getById(products, 1)).toBe(products[0]);
});

filter всегда создаёт новый массив, поэтому сравнивать его надо по содержимому (toEqual). А во втором тесте название обещает проверить тот же объект. toEqual прошёл бы и для копии, так что тест не проверял то, что обещал. Мы проверили: функция-мутант, возвращающая копию { ...found }, проходит исходный тест, но падает на исправленном с toBe.

Задача 12. toHaveLength, toContain, toBeNull и not ★☆☆ разминка

Напишите по тесту на каждый матчер: getTags возвращает 3 тега (toHaveLength), среди тегов есть "sale" (toContain), findProduct для неизвестного id возвращает null (toBeNull), getTags не возвращает исходный массив, а делает копию (not.toBe).

// tags.js
const product = { id: 1, tags: ['new', 'sale', 'hit'] };
const getTags = (p) => [...p.tags];
const findProduct = (list, id) => list.find((p) => p.id === id) ?? null;
module.exports = { product, getTags, findProduct };

Зачем: точный матчер даёт точное сообщение об ошибке. expect(list.length === 3).toBe(true) при провале скажет «ожидали true, получили false», а toHaveLength(3) напишет «длина 2, а ожидали 3».

Решение и разбор
// tags.test.js
const { product, getTags, findProduct } = require('./tags');

test('у товара три тега', () => {
  expect(getTags(product)).toHaveLength(3);
});

test('среди тегов есть sale', () => {
  expect(getTags(product)).toContain('sale');
});

test('неизвестный id даёт null', () => {
  expect(findProduct([product], 99)).toBeNull();
});

test('возвращает копию, а не исходный массив', () => {
  expect(getTags(product)).not.toBe(product.tags);
});

Последний тест защищает от тонкой ошибки: если getTags вернёт исходный массив, вызывающий код может его изменить (tags.push(...)) и тем самым испортить товар. Мутант с undefined вместо null ловит toBeNull: он строже, чем «что-то пустое».

toThrow: нужна обёртка-функция

// Неправильно: addToCart выполнится сразу, ошибка вылетит до expect,
// и тест упадёт с этой ошибкой вместо проверки
expect(addToCart([], lamp, 0)).toThrow(RangeError);

// Правильно: передаём функцию, Jest сам вызовет её и поймает ошибку
expect(() => addToCart([], lamp, 0)).toThrow(RangeError);

RangeError — встроенный тип ошибки JavaScript для значений «вне допустимого диапазона». Его используют тесты корзины для неправильного количества товара.

Кроме типа, toThrow умеет проверять сообщение: toThrow('Неверное количество') пройдёт, если текст ошибки содержит эту строку. Это полезно, когда функция бросает один тип ошибки по разным причинам и важно, какая из них сработала. Не проверяйте сообщение дословно целиком без нужды: поправят формулировку — тест упадёт, хотя поведение не изменилось.

Задача 13. Проверка ошибки ★☆☆ разминка

Напишите тесты для parseQuantity: строка "3" даёт 3, а для "abc", "0" и "1.5" бросается RangeError. В одном тесте проверьте и текст ошибки.

// quantity.js
function parseQuantity(input) {
  const n = Number(input);
  if (!Number.isInteger(n) || n < 1) {
    throw new RangeError(`Неверное количество: ${input}`);
  }
  return n;
}
module.exports = { parseQuantity };

Зачем: ошибочный ввод — такое же требование, как правильный. Если не проверить, что функция отказывает, кто-то «упростит» проверку, и в корзину попадёт 0 или 1,5 штуки.

Решение и разбор
// quantity.test.js
const { parseQuantity } = require('./quantity');

test('переводит строку в число', () => {
  expect(parseQuantity('3')).toBe(3);
});

test.each(['abc', '0', '1.5'])('отклоняет %j', (input) => {
  expect(() => parseQuantity(input)).toThrow(RangeError);
});

test('сообщение называет неверное значение', () => {
  expect(() => parseQuantity('abc')).toThrow('Неверное количество: abc');
});

Каждый вызов обёрнут в стрелочную функцию () => ...: Jest сам вызовет её и поймает ошибку. Без обёртки исключение вылетело бы до expect. toThrow со строкой проверяет, что сообщение содержит этот текст. Мутант, который пропускает 0 и 1,5, наши тесты ловят.
