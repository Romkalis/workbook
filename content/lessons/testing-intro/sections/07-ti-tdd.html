TDD: сначала тест, потом код

Обычно код пишут, а потом (если хватит времени) тестируют. TDD (Test-Driven Development, разработка через тестирование) переворачивает порядок: сначала пишем тест для того, чего ещё нет, и только потом код. Звучит странно, но вторая часть задания Testing Intro устроена именно так: тесты корзины уже написаны, а функции — пустые заглушки.

Цикл красный — зелёный — рефакторинг

Зачем видеть красный тест? Чтобы убедиться, что тест вообще что-то проверяет. Тест, который зелёный ещё до появления кода, бесполезен: он пройдёт и с ошибкой.

Пример на removeFromCart

Красный. Тест из задания уже есть, функция — заглушка:

// tests/cart/cart.test.js
test('удаляет выбранный товар', () => {
  const cart = [{ ...headphones, quantity: 1 }, { ...lamp, quantity: 2 }];
  expect(removeFromCart(cart, 1)).toEqual([{ ...lamp, quantity: 2 }]);
});

// src/cart.js
function removeFromCart() { return notImplemented(); }

Запускаем npm run test:cart — тест красный с ошибкой «Корзина ещё не реализована».

Зелёный. Читаем тест как требование: «вернуть корзину без товара с этим ID». Пишем минимум:

function removeFromCart(cart, productId) {
  return cart.filter((item) => item.id !== productId);
}

Запускаем снова — зелёный. Заодно проходят и два других теста на removeFromCart: пустая корзина и отсутствующий ID. filter их уже покрывает.

Рефакторинг. Здесь улучшать нечего. В функциях побольше на этом шаге выносят повторяющийся код и придумывают понятные имена, проверяя тестами, что ничего не сломалось.

Плюсы и минусы

  • Плюсы: тесты точно есть; вы заранее продумываете, как функцией будут пользоваться; рефакторить не страшно.
  • Минусы: поначалу медленнее; тяжело применять, когда сами требования ещё не понятны (например, в прототипе интерфейса).

Рядом с TDD часто упоминают BDD (Behavior-Driven Development): тесты описывают поведение языком, понятным не только программисту, — «когда покупатель вводит SAVE10 при заказе от 200 ₽, он получает скидку 10%». Названия тестов в задании Testing Intro написаны как раз в этом духе. Подробнее — TDD и BDD.
