Часть 2: корзина по готовым тестам

Теперь наоборот: тесты в tests/cart/cart.test.js уже есть, а в src/cart.js только заглушки. Это TDD в чистом виде, только тесты за вас написал автор задания. Запустите npm run test:cart: все 19 тестов красные. Наша задача — сделать их зелёными, не меняя тесты.

Сначала читаем тесты как требования

Прежде чем писать код, выпишите из тестов правила. В начале файла объявлены два товара:

const headphones = { id: 1, name: 'Наушники', price: 49900, stock: 8 };
const lamp = { id: 4, name: 'Настольная лампа', price: 27900, stock: 3 };

Товар в корзине — тот же объект товара плюс поле quantity: { ...headphones, quantity: 2 }. Из названий и ожиданий тестов получается список:

  • addToCart(cart, product, quantity): новый товар добавляется с количеством; повторный — увеличивает количество; 0 или больше остатка — RangeError.
  • changeQuantity(cart, productId, quantity): меняет количество; 0 или больше остатка — RangeError; товара нет — корзина без изменений.
  • removeFromCart(cart, productId): убирает товар; если его нет — корзина та же.
  • calculateCartSubtotal(cart): сумма «цена × количество»; пустая корзина — 0.
  • calculateOrderTotal(cart, promoCode): объект { subtotal, discount, delivery, total }. SAVE10 даёт 10% при сумме от 20 000; доставка 30 000, если сумма меньше 50 000, иначе бесплатно.

Удобно идти от простого к сложному и после каждой функции запускать тесты: removeFromCart → calculateCartSubtotal → calculateOrderTotal → changeQuantity → addToCart.

Константы правил

Числа 20000, 50000, 30000 и 0.1 лучше не разбрасывать по коду, а назвать. Так их видно в одном месте и понятно, что они значат (принцип «нет магических чисел» из Clean Code):

const PROMO_CODE = 'SAVE10';
const PROMO_RATE = 0.1;
const PROMO_MIN_SUBTOTAL = 20000;
const FREE_DELIVERY_FROM = 50000;
const DELIVERY_PRICE = 30000;

removeFromCart и calculateCartSubtotal

function removeFromCart(cart, productId) {
  return cart.filter((item) => item.id !== productId);
}

function calculateCartSubtotal(cart) {
  return cart.reduce((sum, item) => sum + item.price * item.quantity, 0);
}

filter оставляет всё, кроме товара с этим ID, и возвращает новый массив. reduce проходит по корзине и копит сумму, начиная с 0 — поэтому пустая корзина сразу даёт 0. Проверка из теста: 49 900 × 1 + 27 900 × 2 = 105 700.

calculateOrderTotal

function calculateOrderTotal(cart, promoCode) {
  const subtotal = calculateCartSubtotal(cart);
  const discount =
    promoCode === PROMO_CODE && subtotal >= PROMO_MIN_SUBTOTAL
      ? Math.round(subtotal * PROMO_RATE)
      : 0;
  const delivery = subtotal >= FREE_DELIVERY_FROM ? 0 : DELIVERY_PRICE;
  return { subtotal, discount, delivery, total: subtotal - discount + delivery };
}

Сверим с тестом «применяет SAVE10 к заказу от 20 000 копеек»: сумма 49 900, скидка 4 990, сумма меньше 50 000 — доставка 30 000, итог 49 900 − 4 990 + 30 000 = 74 910. Совпадает.

В условии не сказано, от какой суммы считать бесплатную доставку — до скидки или после. Тесты этого не различают: во всех случаях со скидкой сумма меньше 50 000 и до, и после. Я считаю от суммы товаров (subtotal), как написано в README: «при сумме меньше 50 000 копеек». Math.round — страховка: 10% от суммы, не кратной 10, дало бы дробные копейки.

Проверка количества

addToCart и changeQuantity одинаково проверяют количество. Вынесем проверку в отдельную функцию, чтобы не повторяться:

function assertQuantity(quantity, stock) {
  if (!Number.isInteger(quantity) || quantity < 1 || quantity > stock) {
    throw new RangeError(`Количество должно быть от 1 до ${stock}`);
  }
}

throw new RangeError(...) — «бросить» ошибку. Выполнение функции прерывается, и тест с toThrow(RangeError) её поймает. Number.isInteger заодно отсекает 1.5 и NaN — тестов на это нет, но в реальной корзине пригодится.

changeQuantity

function changeQuantity(cart, productId, quantity) {
  const existing = cart.find((item) => item.id === productId);
  if (!existing) return cart;
  assertQuantity(quantity, existing.stock);
  return cart.map((item) => (item.id === productId ? { ...item, quantity } : item));
}

Порядок важен: сначала ищем товар. Если его нет, тест ждёт ту же корзину, а не ошибку. Если есть — проверяем количество по его остатку (stock лежит прямо в товаре корзины) и через map собираем новую корзину, где у нужного товара новый quantity. { ...item, quantity } — копия товара с заменённым полем; старый объект не меняется.

addToCart

function addToCart(cart, product, quantity = 1) {
  const existing = cart.find((item) => item.id === product.id);
  const nextQuantity = (existing ? existing.quantity : 0) + quantity;
  assertQuantity(quantity, product.stock);
  assertQuantity(nextQuantity, product.stock);

  if (!existing) return [...cart, { ...product, quantity }];
  return cart.map((item) =>
    item.id === product.id ? { ...item, quantity: nextQuantity } : item,
  );
}
  • Сначала проверяем само добавляемое количество: 0 не пропускаем.
  • Затем итоговое количество: если в корзине уже 2 лампы из 3, добавить ещё 2 нельзя. Тестов на этот случай в задании нет, но иначе можно обойти ограничение склада, добавляя по одной.
  • Нового товара нет в корзине — добавляем его копию с quantity в конец. Уже есть — увеличиваем количество через map.

Запустите npm test: все тесты зелёные. Я прогнал это решение вместе с тестами каталога из первой части — 64 из 64. Откройте cart.html в браузере: корзина заработала, и это приятный момент — тесты вели вас, а интерфейс подтверждает результат.

Все функции возвращают новые массивы и не меняют переданную корзину. Тесты этого прямо не требуют, но так безопаснее, и так устроен готовый интерфейс задания. Почему — в уроке об иммутабельности.
