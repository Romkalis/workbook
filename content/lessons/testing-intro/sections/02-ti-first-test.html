Функция-проверка

Писать if (...) throw каждый раз неудобно. Вынесем сравнение в функцию. Такую функцию принято называть assert (англ. «утверждать»): мы утверждаем, что результат такой-то, и если это не так — ошибка.

function assertEqual(actual, expected, name) {
  if (actual === expected) {
    console.log(`✓ ${name}`);
  } else {
    console.log(`✗ ${name}: ожидали ${expected}, получили ${actual}`);
  }
}

assertEqual(calculateCartSubtotal([]), 0, 'пустая корзина');
assertEqual(calculateCartSubtotal([{ price: 27900, quantity: 2 }]), 55800, 'две лампы');
assertEqual(
  calculateCartSubtotal([{ price: 49900, quantity: 1 }, { price: 27900, quantity: 2 }]),
  105700,
  'наушники и две лампы',
);

Здесь есть два важных слова. actual — фактический результат, то, что вернула функция. expected — ожидаемый, то, что должно было получиться. Эти слова встретятся в любом тестовом инструменте.

Почему === не хватает

const cart = [{ id: 1, quantity: 2 }];
console.log(cart === [{ id: 1, quantity: 2 }]); // false!

Массивы и объекты в JavaScript сравниваются по ссылке: === отвечает на вопрос «это один и тот же объект в памяти?», а не «у них одинаковое содержимое?». Два разных массива с одинаковыми элементами не равны (см. значения и ссылки). Значит, для объектов нужно сравнивать содержимое по всем полям — глубокое сравнение. Писать его самому долго, и это первая причина взять готовый инструмент.

Зачем нужен тестовый фреймворк

Наш самодельный вариант быстро упрётся в ограничения. Тестовый фреймворк (Jest, Vitest, встроенный в Node node:test) берёт на себя всё скучное:

  • сам находит файлы с тестами по имени (*.test.js) и запускает их одной командой;
  • умеет сравнивать объекты, массивы, ошибки и многое другое;
  • если один тест упал, остальные всё равно выполняются;
  • показывает понятный отчёт: что прошло, что нет, и чем отличается результат от ожидаемого;
  • считает покрытие кода (об этом ниже).

В задании RS School используется Jest — один из самых популярных фреймворков для JavaScript.
