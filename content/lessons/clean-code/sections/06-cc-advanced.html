Продвинутый уровень: семантика, alt, БЭМ

Три правила из html-and-css-extended.md, по 5 баллов каждое.

1.1. Семантика

Используйте теги по назначению: h1–h6 для заголовков, p для абзацев, a для ссылок, button для действий, header, main, section, article, aside для областей страницы. Это нужно не для красоты:

  • программа экранного доступа объявляет «ссылка», «кнопка», «заголовок 2-го уровня» и даёт прыгать по ним с клавиатуры;
  • поисковики лучше понимают, где на странице главное;
  • код читается легче: <nav> понятнее, чем <div class="nav">.
<!-- Плохо: не фокусируется с клавиатуры, не объявляется как ссылка -->
<div onclick="goToRecommendations();">All recommendations</div>

<!-- Хорошо -->
<a href="recommendations/">All recommendations</a>

В TODO-приложении обёртки div напрашиваются на замену: верхний блок с картинкой и ссылкой — это header или section, основная часть — main, у списка «Todo» и «Completed» — по section с заголовком. Заголовки там h3 без h1 и h2; из общих знаний, порядок уровней тоже часть семантики.

1.2. Альтернатива для медиа

У каждой картинки есть alt. Для смысловой — описание того, что на ней: alt="Eisenhower matrix". Для декоративной — пустой alt="", тогда экранный диктор её пропустит. Без атрибута вовсе диктор может прочитать имя файла. У видео — субтитры через <track kind="captions">.

Тонкость из общих знаний: в приложении кнопка удаления содержит только картинку-корзину. Если дать картинке alt="", у кнопки не останется названия вообще. Здесь alt должен называть действие: alt="Delete", тогда кнопка будет объявлена как «Delete, кнопка».

2.1. БЭМ

БЭМ — Блок, Элемент, Модификатор. Методология из Яндекса для именования классов. Интерфейс делится на независимые блоки (menu), у блока есть элементы, которые без него не существуют (menu__item), а у тех и других — модификаторы состояния или вида (menu__item_active).

<li class="task task_edit-mode">
  <input class="task__checkbox" type="checkbox">
  <label class="task__label">Go Shopping</label>
  <input class="task__input" type="text" value="Go Shopping">
  <button class="task__button task__button_edit">Save</button>
</li>
.task__label { … }
.task_edit-mode .task__label { display: none; }

Модификатор пишется вместе с базовым классом: class="task task_edit-mode", а не один task_edit-mode. Элемент элемента не бывает: не task__row__button, а task__button. В исходном приложении класс task висит и на label, и на input, а режим редактирования задан классом editMode в camelCase. Это хороший кандидат на переделку по БЭМ.

Правило 3.1 начального уровня разрешает «дефис или БЭМ». Если вы делаете продвинутое правило 2.1, БЭМ автоматически закрывает и 3.1. Гайд разрешает такое пересечение в одном коммите, если в сообщении названы оба правила.
