DRY, KISS, YAGNI

DRY — не повторяйся

Don't Repeat Yourself. Формулировка из книги Эндрю Ханта и Дэвида Томаса «Программист-прагматик» (1999): «каждое знание должно иметь единственное, однозначное, авторитетное представление в системе». Речь именно о знании, то есть о правиле или решении, а не просто об одинаковых строках. Если правило «выходные — это суббота и воскресенье» записано в трёх местах, его придётся менять в трёх местах, и одно вы забудете.

В CSS дублирование убирают группировкой селекторов и общими классами:

/* Повтор */
h1 { color: #ff0000; font-family: Arial; }
h2 { color: #ff0000; font-family: Arial; }

/* Группировка */
h1,
h2 {
  color: #ff0000;
  font-family: Arial;
}

В JavaScript повтор выносят в цикл или функцию. Пример из материалов модуля в исходном виде не запустится: в одном файле дважды объявлена const today, и Node.js 22 выдаёт SyntaxError: Identifier 'today' has already been declared. К тому же параметр функции назван weekday, хотя в неё передают дату. Исправленный вариант:

function logDayPlan(date, tasks) {
  console.log(`Today is ${date.toDateString()} so my day plan includes: ${tasks}`);
}

function isWeekend(date) {
  const day = date.getDay();
  return day === 0 || day === 6;
}

const today = new Date(2026, 10, 7); // суббота, 7 ноября 2026
logDayPlan(today, isWeekend(today) ? 'sleep, eat, rest' : 'work, work, work');
// Today is Sat Nov 07 2026 so my day plan includes: sleep, eat, rest

Знание «что такое выходной» теперь живёт в одной функции isWeekend, а формат сообщения — в logDayPlan. Заодно мы перестали сравнивать строку 'Sunday', которая зависит от языка: getDay() возвращает число.

У DRY есть обратная сторона (из общих знаний). Два куска кода могут выглядеть одинаково, но означать разное: например, проверка длины пароля и длины никнейма. Если склеить их в одну функцию, а потом правила разойдутся, функция обрастёт флагами. Повтор двух-трёх строк дешевле неправильной абстракции.

KISS — делай проще

Keep It Simple, Stupid. Принцип приписывают авиаконструктору Кларенсу «Келли» Джонсону и инженерам ВМС США 1960-х: самолёт должен чинить механик в поле с обычным набором инструментов. Для кода это значит: самое понятное решение обычно лучшее, хитрые трюки и преждевременная оптимизация вредят.

Пример из модуля — деление на 2 сдвигом x >> 1 вместо x / 2. Читать труднее, а в JavaScript это ещё и даёт другой результат. Сдвиг сначала превращает число в 32-битное целое со знаком (проверено в Node.js 22):

4 >> 1;        // 2 — совпало
-5 >> 1;       // -3, а Math.trunc(-5 / 2) === -2
7.9 >> 1;      // 3 — дробная часть отброшена молча
2 ** 31 >> 1;  // -1073741824 — переполнение, знак сменился

«Оптимизация» не просто менее понятна, она неверна на части входов. Пишите x / 2, а если нужно целое — Math.floor(x / 2) или Math.trunc(x / 2), явно.

YAGNI — вам это не понадобится

You Aren't Gonna Need It. Не пишите функциональность «на будущее», пока она не нужна. Причины из материалов модуля:

  • время уходит не на то, что нужно сейчас;
  • лишний код тоже надо тестировать, документировать и поддерживать;
  • к тому моменту, когда функция понадобится, требования изменятся, и написанное окажется не тем;
  • лишний код мешает добавлять нужное и усложняет программу (нарушает KISS);
  • одна «заготовка» тянет за собой другие, и получается снежный ком.

Мартин Фаулер, на которого ссылается модуль, уточняет: YAGNI относится только к возможностям, встроенным «на всякий случай» под предполагаемую функцию. К усилиям, которые делают код проще менять, он не относится. Рефакторинг, самопроверяющийся код и понятная структура нужны всегда, запрещено только строить функции, о которых пока никто не просил.
