Инструменты: линтер, форматтер, редактор

Модуль называет инструменты одной строкой, а в задании S1E1 автоформаттер запрещён: нужно руками пройти каждое правило. В реальной работе всё наоборот — оформление проверяет машина, а люди обсуждают смысл. Раздел целиком из общих знаний.

ИнструментЧто делает
EditorConfigФайл .editorconfig в корне задаёт отступы, кодировку, перевод строки и удаление пробелов в конце строк для любого редактора.
PrettierФорматтер: сам расставляет отступы, кавычки, переносы. Спорить о стиле больше не о чем.
ESLintЛинтер JS/TS: находит ошибки и подозрительный код (неиспользуемые переменные, == вместо ===), часть исправляет сам.
StylelintТо же для CSS: опечатки в свойствах, повторы, порядок.
Husky + commitlintПроверяют сообщение коммита перед сохранением: не по Conventional Commits — коммит не пройдёт.
CommitizenЗадаёт вопросы (тип, область, описание) и собирает сообщение коммита за вас.

Задание S1E1 упоминает Commitizen и Husky как необязательные подсказки. Пользоваться ими можно, запрещены только инструменты, которые форматируют код.

VS Code помогает рефакторить

  • F2 — переименовать символ во всех местах использования (для JS). Для CSS-классов надёжнее поиск по проекту: Ctrl/Cmd + Shift + F.
  • Лампочка рядом с кодом (Ctrl/Cmd + .) — извлечь функцию или константу.
  • Настройки editor.renderWhitespace и files.trimTrailingWhitespace показывают и убирают лишние пробелы.
  • Внизу справа в строке состояния видно «Spaces: 2» или «Tab Size: 4». По нему можно переключить отступ и преобразовать файл («Convert Indentation to Spaces»). Это не форматтер, а одна точечная операция, но если сомневаетесь, сделайте руками.

Книга «Чистый код»

Модуль рекомендует книгу Роберта Мартина «Чистый код» (2008). Её стоит прочитать, но критически: примеры там на Java, и некоторые советы (функции по 2–4 строки, почти никаких аргументов) многие разработчики считают чрезмерными. Для JavaScript удобнее начать с репозитория clean-code-javascript, где идеи книги переложены на JS с примерами «плохо/хорошо».
