Комментарии, имена и мелочи оформления

Комментарий объясняет «почему»

Лучший комментарий — тот, который не понадобился: имя переменной и функции уже всё сказали. Если код можно сделать понятнее, переименовав или разбив на функции, делайте это вместо комментария. Комментарий нужен там, где из кода не видно причины решения.

// Плохо: повторяет имя
const MAIN_TEXT_COLOUR = '#000000'; // цвет основного текста

// Хорошо (пример из Lodash): объясняет, почему код выглядит странно
function addSetEntry(set, value) {
  // Don't return `set.add`, as this call chain doesn't work in Internet Explorer 11
  set.add(value);
  return set;
}

В TODO-приложении из задания много комментариев первого типа: var label = document.createElement("label"); //label. Такие комментарии ничего не добавляют и устаревают при первой правке кода.

TODO

Запланированную, но не срочную правку отмечают комментарием с префиксом TODO:. Используйте только этот формат, тогда все такие места находятся одним поиском, и редактор их подсвечивает.

// TODO: move this magic number (15 rows) to the configuration file
for (let i = 0; i < 15; i++) {
  table.append(document.createElement('tr'));
}

Из общих знаний: TODO не должен жить в коде годами. Хорошая практика — ссылка на задачу в трекере: // TODO(#42): ….

Пробелы в конце строк и имена файлов

Пробелы в конце строки ничего не значат, но git видит их как изменение. В diff появляются строки, где «ничего не поменялось», и ревьюеру приходится их разглядывать. В VS Code включите настройку files.trimTrailingWhitespace, и редактор будет убирать их при сохранении.

Имена файлов — в одном стиле на весь проект, обычно kebab-case: image-slider.js, right-arrow.svg. Раскладывать файлы можно по типам (/js, /styles, /assets) или по компонентам (всё про слайдер в одной папке). Главное — выбрать одно и придерживаться.

Имена в JavaScript — из общих знаний

  • Переменные и функции — camelCase, классы — PascalCase, константы-настройки — UPPER_SNAKE_CASE.
  • Функция называется глаголом: createTask, isWeekend. Булево значение отвечает на вопрос «да/нет»: isDone, hasError.
  • Без шифров и сокращений: incompleteTaskHolder лучше ith, а класс .aaa из задания не говорит ничего.
  • Одно понятие — одно слово. Если в одном месте «task», не называйте то же самое в другом «item».
