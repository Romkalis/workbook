Зачем код должен быть чистым

Код пишут один раз, а читают десятки раз: вы сами через полгода, напарник по команде, ментор на ревью. Чистый код — это код, который понятен без автора: по именам видно, что делает функция, по оформлению видна структура, а в истории коммитов видно, почему что-то менялось.

Материал модуля объясняет, почему важна даже мелочь вроде кавычек или регистра букв. Когда весь проект написан в одном стиле, глаз узнаёт конструкции мгновенно: с большой буквы — класс, с маленькой — переменная. Чужой код не раздражает, если он оформлен так же, как ваш. И не нужно каждый раз решать, как назвать переменную: правило уже есть.

Что входит в модуль

  • Общие принципы: DRY, KISS, YAGNI, комментарии, TODO, пробелы в конце строк, имена файлов.
  • Git: что класть в один коммит, как писать сообщение, как оформить pull request.
  • HTML и CSS: 16 правил начального уровня (15 из них обязательные) и 3 продвинутых: семантика, альтернативный текст, БЭМ.
  • Практика: задание Clean Code S1E1 — рефакторинг маленького TODO-приложения по этим правилам, максимум 45 баллов, и тест «[St1] Clean-code» в RS App.

На модуль отводится около 10 часов, и большая часть уходит на задание: каждое правило оформляется отдельным коммитом.
