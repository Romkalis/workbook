Динамический import()

Статический import нельзя поставить в условие или вычислить путь. Для загрузки по требованию есть выражение import(путь) (глава «Динамические импорты»). Оно возвращает промис с объектом модуля и работает и в обычных скриптах, не только в модулях.

button.addEventListener('click', async () => {
  const { default: openEditor } = await import('./editor.js');
  openEditor();
});

Проверено в Node.js: const { default: helper } = await import('./helper.js') загрузил модуль и вернул функцию по умолчанию. Экспорт по умолчанию в объекте модуля лежит под ключом default, поэтому его переименовывают при деструктуризации.

Зачем это нужно:

  • Разделение кода (code splitting): тяжёлый редактор, график или карта загружаются, только когда пользователь их открыл. Первая загрузка страницы становится быстрее. Сборщики видят import() и сами выносят модуль в отдельный файл.
  • Загрузка по условию: разные модули для разных языков интерфейса — import(`./locales/${lang}.js`).
  • Подключение ES-модуля из CommonJS в Node.js.

Ошибки обрабатываются как у любого промиса: модуль может не загрузиться из-за сети, поэтому await import() оборачивают в try...catch (урок «Обработка ошибок»).
