Как жили без модулей

JavaScript создали в 1995 году за десять дней как простой язык для небольших сценариев на странице. Модулей в нём не было до стандарта ES2015 (ES6) — версии языка 2015 года. Меган (Meaghan) во втором видео делит историю на четыре эпохи: до модулей, «модули своими руками», спецификации (CommonJS, AMD) и стандартизация (ES-модули).

Глобальные переменные

Сначала скрипты подключали тегами <script> по очереди. Все они делили одну глобальную область видимости: переменная из одного файла видна во всех остальных. В лекции RS School это названо главной проблемой. Если два разработчика назовут переменные одинаково, один молча перезапишет другого. Чужой скрипт может испортить ваши данные. А зависимости приходилось держать в голове: скрипт, который использует jQuery, обязан стоять в HTML после jQuery.

В 2006 году команда Yahoo в статье «Global Domination» предложила мерить качество программы на JavaScript числом глобальных переменных: чем их больше, тем хуже.

Пространство имён

Первое решение — сложить всё в один глобальный объект: YAHOO.util.Dom.get(...), jQuery, $. Глобальная переменная одна, внутри — дерево свойств.

var MyApp = MyApp || {};
MyApp.utils = {
  formatDate: function (date) { /* ... */ },
};

Минусы остались: объект можно перезаписать одной строкой, все его свойства доступны и изменяемы снаружи, проблема порядка скриптов не решена.

IIFE и паттерн «модуль»

IIFE (immediately invoked function expression) — функция, которая вызывается сразу после объявления. Каждая функция создаёт свою область видимости, поэтому переменные внутри не видны снаружи. А благодаря замыканию (функция помнит переменные места, где её создали) возвращённые функции продолжают иметь к ним доступ. Это и есть паттерн «модуль»:

var counterModule = (function () {
  var count = 0;                       // приватная переменная
  function increment() { count += 1; }
  function print() { console.log('count =', count); }
  return { increment: increment, print: print };  // публичный интерфейс
})();

counterModule.increment();
counterModule.print();          // count = 1
console.log(counterModule.count); // undefined — снаружи не достать

Глобальная переменная одна (counterModule), счётчик защищён от посторонних. Вариант revealing module («раскрывающий модуль») объявляет всё внутри, а в return только перечисляет то, что нужно показать, — как в примере выше. Зависимости передавали параметрами: (function ($) { ... })(jQuery). Проблему порядка скриптов и загрузки IIFE не решает.
