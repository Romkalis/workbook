ES-модули: export и import

В ES2015 модули стали частью языка. Сейчас их поддерживают все браузеры и Node.js. Подробный разбор синтаксиса — в главе «Экспорт и импорт» на learn.javascript.ru (оригинал — javascript.info) и в руководстве MDN.

Именованный экспорт

Экспортировать можно сколько угодно значений, каждое под своим именем. Слово export ставят перед объявлением или одним списком в конце файла:

// counter.js
export let count = 0;
export function increment() { count += 1; }
export const settings = { theme: 'light' };

// или в конце файла
// export { count, increment, settings };

Импортируют по тем же именам, в фигурных скобках:

import { count, increment } from './counter.js';

Лектор RS School советует держать импорты вверху файла, а экспорты списком внизу: так видно, что модуль берёт и что отдаёт, а логика в середине не смешана с экспортами. Это вопрос стиля; главное — единообразие в проекте.

Экспорт по умолчанию

Один (и только один) экспорт в файле может быть «главным» — export default. Его импортируют без фигурных скобок и под любым именем:

// counter.js
export default function reset() { count = 0; }

// main.js
import reset from './counter.js';
import resetCounter from './counter.js'; // то же самое, другое имя

Можно сочетать: import reset, { count, increment } from './counter.js';.

Переименование и импорт всего модуля

import { settings as config } from './counter.js'; // взять под другим именем
import * as counter from './counter.js';            // всё в один объект
counter.increment();
console.log(Object.keys(counter)); // [ 'count', 'default', 'increment', 'settings' ]

Экспорт по умолчанию в таком объекте лежит под именем default. Переименовывать можно и при экспорте: export { sum as add }.

Именованный или по умолчанию?

Лектор RS School и статья Дмитрия Павлютина «4 Best Practices to Write Quality JavaScript Modules» советуют предпочитать именованные экспорты. При импорте по умолчанию имя придумывает тот, кто импортирует, и одну функцию в разных файлах могут звать по-разному: поиск по проекту её не найдёт, а переименование в редакторе не обновит импорты. Именованный экспорт тоже можно переименовать, но явно, через as. Экспорт по умолчанию уместен, когда модуль отдаёт ровно одну главную вещь — например, компонент React в своём файле.

Реэкспорт

Чтобы собрать модули папки в одну «точку входа» (часто файл index.js), используют реэкспорт:

// index.js
export { increment, default as resetCounter } from './counter.js';
export * from './counter.js';

Проверено: export * переносит все именованные экспорты, но не экспорт по умолчанию — его нужно реэкспортировать явно, как resetCounter выше. В итоговом модуле оказались count, increment, resetCounter, settings.

Импорт ради выполнения

import './polyfills.js'; — ничего не берёт, только выполняет модуль. Так подключают стили в сборщиках (import './style.css') или код, который что-то настраивает при загрузке. Лектор называет это плохой практикой для обычного кода: непонятно, что модуль меняет.
