Хорошие модули, практика и словарь

Как писать хорошие модули

Четыре совета из статьи Дмитрия Павлютина:

  1. Предпочитайте именованные экспорты — имена стабильны, их находит поиск и автодополнение (раздел о синтаксисе).
  2. Не выполняйте работу при импорте. Код верхнего уровня модуля выполняется в момент импорта. Тяжёлые вычисления или запросы там замедляют загрузку всего, что от модуля зависит. Делайте работу в функциях, которые вызывают по необходимости.
  3. Высокая связность (cohesion): всё в модуле относится к одной задаче. Модуль utils.js со всем подряд — признак низкой связности: он тянет лишние зависимости и его трудно понять.
  4. Избегайте длинных относительных путей вроде '../../../../components/Button'. Настройте псевдонимы путей в сборщике или TypeScript: '@/components/Button'.

Упражнения

  1. Напишите счётчик в виде IIFE, затем в виде ES-модуля. Сравните, что видно снаружи.
  2. Создайте модуль с тремя именованными экспортами и одним по умолчанию. Импортируйте их всеми способами из урока, включая import * as.
  3. Сделайте index.js, который реэкспортирует модули папки. Проверьте, попал ли туда экспорт по умолчанию через export *.
  4. Повторите пример с живыми привязками и тот же счётчик на CommonJS. Объясните разницу.
  5. Подключите модуль на странице через <script type="module">, откройте её сначала как файл, потом через локальный сервер.
  6. Загрузите тяжёлый модуль по клику через import() и найдите отдельный запрос во вкладке Network.

Вопросы

Почему CommonJS не подходит для браузера напрямую?

require синхронный: на каждый модуль страница ждала бы загрузку файла по сети. Поэтому в браузере CommonJS собирают сборщиком, а для асинхронной загрузки придумали AMD и затем ES-модули.

Изменит ли модуль B объект, экспортированный из модуля A, для модуля C?

Да. Модуль выполняется один раз, все импортёры получают один и тот же объект. Нельзя только переприсвоить саму импортированную переменную.

Попадёт ли export default в export * from?

Нет. export * переносит только именованные экспорты; экспорт по умолчанию реэкспортируют явно: export { default } from './x.js' или с новым именем.

Почему import нельзя написать внутри if?

Статические импорты обрабатываются до выполнения кода, чтобы построить граф зависимостей. Для загрузки по условию есть import().

Словарь

Модуль
Файл со своей областью видимости, интерфейсом (экспортами) и зависимостями (импортами).
Глобальная область видимости
Общее пространство, где переменные видны из любого скрипта.
IIFE
Функция, вызванная сразу после объявления; создаёт изолированную область.
Паттерн «модуль»
IIFE, которая возвращает публичный интерфейс и прячет остальное в замыкании.
CommonJS
Формат Node.js: require и module.exports, синхронная загрузка.
AMD
Асинхронный формат для браузера: define, загрузчик RequireJS.
UMD
Обёртка, которая работает как AMD, CommonJS или глобальная переменная.
ES-модули
Стандартные модули языка: import и export.
Именованный экспорт / экспорт по умолчанию
Экспорт под фиксированным именем / один главный экспорт, импортируемый под любым именем.
Живая привязка
Импорт как ссылка на переменную модуля, а не копия значения.
Циклическая зависимость
Модули, которые прямо или через другие импортируют друг друга.
Динамический импорт
import() — загрузка модуля во время работы, возвращает промис.
Загрузчик модулей
Программа, которая загружает модули во время работы (RequireJS, SystemJS).
Сборщик
Программа, которая заранее собирает модули в файлы для браузера (webpack, Vite).
Tree shaking
Удаление неиспользуемых экспортов при сборке.
