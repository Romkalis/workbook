Модули в браузере, загрузчики и сборщики

script type="module"

Браузер понимает ES-модули без сборщика, если подключить скрипт с атрибутом type="module":

<script type="module" src="./main.js"></script>

Глава «Модули, введение» перечисляет отличия модулей от обычных скриптов в браузере:

  • Модули всегда отложенные (как атрибут defer): загружаются параллельно с разбором HTML и выполняются после него, по порядку.
  • Модуль с другого домена загружается только по правилам CORS — сервер должен разрешить (урок «Клиент-серверное взаимодействие»).
  • Открыть страницу с модулями двойным кликом по файлу (file://) не получится: браузер их заблокирует. Нужен локальный сервер, например Live Server в VS Code или npx vite.
  • Путь в import должен быть полным: './utils.js', а не './utils'. «Голые» имена пакетов вроде import _ from 'lodash' браузер сам не понимает — их понимают сборщики или карты импортов (<script type="importmap">), где имени сопоставлен адрес.
  • Для старых браузеров без поддержки модулей был атрибут nomodule; сейчас он почти не нужен.

Эти правила взяты из javascript.info и MDN; в браузере при подготовке урока они отдельно не проверялись.

Загрузчики и сборщики

Лекция RS School рассказывает, как фронтенд пришёл к сборке. Инструменты Grunt и Gulp автоматизировали задачи, затем webpack стал собирать модули: он начинает с точки входа (entry), проходит по всем import и require, строит граф зависимостей и выдаёт один или несколько файлов для браузера (output), по пути пропуская файлы через загрузчики вроде babel-loader. Babel — транспайлер: переводит новый синтаксис JavaScript в старый, понятный старым браузерам.

Зачем сборщики, если браузер понимает модули сам:

  • сотни мелких модулей — сотни запросов; сборщик объединяет их в несколько файлов;
  • можно подключать пакеты из npm по имени, CommonJS-модули, CSS и картинки как модули;
  • tree shaking выбрасывает неиспользуемый код, минификация (удаление пробелов, комментариев и сокращение имён) уменьшает размер;
  • TypeScript, JSX и другие форматы превращаются в обычный JavaScript.

Лекция 2021 года строится вокруг webpack и SystemJS. Сегодня для новых проектов чаще берут Vite: в разработке он отдаёт браузеру настоящие ES-модули без сборки (поэтому запускается мгновенно), а для продакшена собирает проект. webpack по-прежнему работает во многих существующих проектах. SystemJS сейчас используется редко.

Ещё одна неточность лекции: там сказано, что ES-модули «не часть JavaScript» и «V8 их не распознаёт», а работают благодаря инструментам. Это было отчасти верно в 2017–2018 годах. Сейчас модули — часть стандарта языка, V8 и все современные движки выполняют их сами, и примеры этого урока запускались в Node.js без сборщика.
