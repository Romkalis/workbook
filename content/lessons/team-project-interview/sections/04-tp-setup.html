Каркас проекта и CI

Один участник создаёт каркас в отдельной ветке, второй ревьюит. Команды из гайда задания:

npm create vite@latest team-store-app -- --template vanilla-ts
cd team-store-app
npm install
npm install -D vitest
npm pkg set "scripts.test=vitest run --passWithNoTests"

Флаг --passWithNoTests нужен, чтобы npm test не падал, пока тестов ещё нет. Уберите его, когда появятся тесты: тогда случайно удалённые тесты не пройдут незамеченными.

Структура папок

src/
  domain/          чистые функции и типы, без DOM
    products.ts    тип Product, данные, filterProducts
    cart.ts        addToCart, calculateCart
    sort.ts        sortProducts
  state/
    cart-store.ts  состояние корзины + localStorage
  ui/              всё, что трогает document
    about.ts
    catalog.ts
    cart.ts
  route.ts         parseRoute
  main.ts          точка входа: слушает hashchange и рисует нужный экран
tests/

Правило одно: из domain нельзя импортировать ui. Тогда всё в domain тестируется без браузера, и именно оттуда берутся функции для live coding. Принцип разобран в Clean Code.

CI на GitHub Actions

CI (continuous integration) — автоматический запуск сборки и тестов на каждый PR. В паре это главный страж main: напарник увидит красный крестик раньше, чем начнёт читать код. Файл .github/workflows/ci.yml из гайда:

name: Проверки проекта

on:
  push:
    branches: [main]
  pull_request:

jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
      - run: npm ci
      - run: npm run build
      - run: npm test

npm ci ставит ровно то, что записано в package-lock.json, поэтому lock-файл обязательно коммитят (зачем он нужен). Когда настроите ESLint и Prettier (урок про линтеры), добавьте в CI шаг npm run lint. Сборка Vite типы не проверяет; в шаблоне vanilla-ts скрипт build начинается с tsc, поэтому ошибки типов CI всё-таки поймает. Проверьте это в своём package.json.
