Сдача и чек-лист

У команды один репозиторий, но сдаёт каждый сам, своим PR:

  1. После слияния всех фич в main создайте ветку, например submission/ваш-логин.
  2. Добавьте файл submissions/ваш-логин.md.
  3. Откройте PR в main общего репозитория с теми же сведениями в описании. Не сливайте его до конца проверки.
  4. Ссылку на свой PR отправьте в RS App → Cross-Check: Submit.

Чек-лист перед отправкой

  • Деплой открывается в инкогнито и начинается со страницы «О нас» с обоими участниками.
  • На доске у задач есть исполнители, статусы отражают реальность.
  • В репозитории видны PR от обоих участников с комментариями ревью.
  • npm test запускается из чистого клона после npm ci.
  • В видео слышны оба голоса, код и вывод тестов читаются, видео открывается в инкогнито без входа.
  • В видео есть все четыре блока: знакомство, проект с доской и репозиторием, вопросы, live coding с запуском.
  • В PR сдачи ссылка именно на запись, где автор PR — кандидат.

Проверьте себя

Почему лучше делить задачи по фичам, а не «вёрстка / логика»?

Тогда у каждого есть своя функция для live coding, свой опыт и в UI, и в тестах, и меньше ожидания друг друга. Обоим есть что рассказать о личном вкладе.

Зачем выносить расчёт корзины из обработчика клика?

Чистую функцию можно протестировать без браузера и взять на live coding. Обработчик только вызывает её и рисует результат.

Тест на записи упал. Что делать?

Прочитать сообщение, найти место в коде, решить, кто неправ — тест или код, и объяснить вслух. Задание оценивает ход рассуждений.
