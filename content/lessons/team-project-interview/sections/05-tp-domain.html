Код: каталог, корзина и состояние

Код ниже — ядро магазина. Он запущен и покрыт тестами; DOM-слой (src/ui) не показан, он у каждой команды свой.

Товары и фильтрация

// src/domain/products.ts
export interface Product {
  id: string;
  title: string;
  category: string;
  /** Цена в копейках: целые числа не теряют точность при сложении */
  price: number;
}

export interface ProductFilters {
  search?: string;
  category?: string;
  minPrice?: number;
  maxPrice?: number;
}

export function filterProducts(products: readonly Product[], f: ProductFilters): Product[] {
  const query = f.search?.trim().toLowerCase() ?? '';
  return products.filter(
    (p) =>
      (query === '' || p.title.toLowerCase().includes(query)) &&
      (f.category === undefined || p.category === f.category) &&
      (f.minPrice === undefined || p.price >= f.minPrice) &&
      (f.maxPrice === undefined || p.price <= f.maxPrice),
  );
}

export const PRODUCTS: readonly Product[] = [
  { id: 'b1', title: 'Чистый код', category: 'books', price: 150000 },
  { id: 'b2', title: 'Грокаем алгоритмы', category: 'books', price: 99000 },
  { id: 'g1', title: 'Каркассон', category: 'games', price: 249000 },
];

Все фильтры в одной функции, потому что по гайду они «действуют одновременно». Неуказанный фильтр — undefined — не применяется. Пустая строка поиска тоже не фильтрует, а trim() прощает случайный пробел.

// src/domain/sort.ts
import type { Product } from './products.js';

export type SortOrder = 'default' | 'price-asc' | 'price-desc';

export function sortProducts(products: readonly Product[], order: SortOrder): Product[] {
  const copy = [...products];
  if (order === 'price-asc') copy.sort((a, b) => a.price - b.price);
  if (order === 'price-desc') copy.sort((a, b) => b.price - a.price);
  return copy;
}

Сортировка делает копию [...products]: метод sort меняет массив на месте. Без копии «исходный порядок» после первой сортировки было бы не восстановить. Такое как раз ловят на ревью.

Корзина и промокод

// src/domain/cart.ts
export interface CartLine {
  productId: string;
  price: number;
  quantity: number;
}

export interface CartTotals {
  subtotal: number;
  discount: number;
  total: number;
}

const PROMO_CODES: Readonly<Record<string, number>> = { SALE10: 10 };

export function addToCart(cart: readonly CartLine[], item: Omit<CartLine, 'quantity'>): CartLine[] {
  const existing = cart.find((line) => line.productId === item.productId);
  if (!existing) return [...cart, { ...item, quantity: 1 }];
  return cart.map((line) => (line === existing ? { ...line, quantity: line.quantity + 1 } : line));
}

export function calculateCart(cart: readonly CartLine[], promo?: string): CartTotals {
  const subtotal = cart.reduce((sum, line) => sum + line.price * line.quantity, 0);
  const percent = promo === undefined ? 0 : (PROMO_CODES[promo.trim().toUpperCase()] ?? 0);
  const discount = Math.round((subtotal * percent) / 100);
  return { subtotal, discount, total: subtotal - discount };
}
  • addToCart не меняет старую корзину, а возвращает новую. Её легко тестировать (старое значение осталось для сравнения), и подписчики стора видят новое значение.
  • Промокоды в словаре, а не в if (promo === 'SALE10'): новый код — одна строка. С флагом noUncheckedIndexedAccess PROMO_CODES[code] имеет тип number | undefined, и компилятор заставляет подставить ?? 0.
  • Скидка не «накапливается», потому что функция ничего не хранит: каждый раз считает от суммы заново. Требование гайда «повторный ввод не накапливает скидку» выполнено самим устройством функции, без отдельного флага.
  • Math.round — единственное место округления. На live coding это пригодится.

Состояние корзины и localStorage

// src/state/cart-store.ts
import { addToCart, type CartLine } from '../domain/cart.js';

/** Часть localStorage, которая нужна стору. В тестах подставляем объект с теми же методами. */
export interface KeyValueStorage {
  getItem(key: string): string | null;
  setItem(key: string, value: string): void;
}

const KEY = 'team-store:cart';

function isCartLine(x: unknown): x is CartLine {
  return (
    typeof x === 'object' && x !== null &&
    'productId' in x && typeof x.productId === 'string' &&
    'price' in x && Number.isInteger(x.price) &&
    'quantity' in x && Number.isInteger(x.quantity) && (x.quantity as number) >= 1
  );
}

export function loadCart(storage: KeyValueStorage): CartLine[] {
  try {
    const data: unknown = JSON.parse(storage.getItem(KEY) ?? '[]');
    return Array.isArray(data) ? data.filter(isCartLine) : [];
  } catch {
    return [];
  }
}

export function createCartStore(storage: KeyValueStorage) {
  let cart = loadCart(storage);
  const listeners = new Set<(cart: readonly CartLine[]) => void>();

  function set(next: CartLine[]) {
    cart = next;
    storage.setItem(KEY, JSON.stringify(cart));
    listeners.forEach((fn) => fn(cart));
  }

  return {
    get: (): readonly CartLine[] => cart,
    add: (item: Omit<CartLine, 'quantity'>) => set(addToCart(cart, item)),
    remove: (productId: string) => set(cart.filter((l) => l.productId !== productId)),
    subscribe(fn: (cart: readonly CartLine[]) => void) {
      listeners.add(fn);
      return () => listeners.delete(fn);
    },
  };
}

Три решения, которые стоит уметь объяснить:

  • Хранилище передаётся параметром, а не берётся из глобального localStorage. В браузере передаём localStorage, в тестах — объект на Map. Это внедрение зависимости (подробнее), и тесты идут без браузера.
  • Прочитанное из storage — unknown. Пользователь мог поправить данные руками, старая версия приложения могла сохранить другую форму. Битые данные дают пустую корзину, а не белый экран.
  • Подписка (subscribe): UI корзины и счётчик в шапке подписываются на изменения и перерисовываются сами. Это паттерн «Наблюдатель» из урока Design Patterns.
