У слова «прототип» здесь два похожих обозначения. [[Prototype]] — внутренняя ссылка уже созданного объекта. User.prototype — обычное свойство конструктора User: объект, который используется как прототип при new User. Начните с экземпляра и проследите одну стрелку: экземпляр → User.prototype.

У большинства объектов есть внутренняя ссылка [[Prototype]]: она указывает на другой объект или на null. Эту ссылку нельзя прочитать напрямую, но получить её можно через Object.getPrototypeOf. Свойства по ней движок ищет только при чтении: сначала в самом объекте, затем в прототипе, затем в следующем объекте цепочки.

const animal = {
  eats: true,
  describe() { return `${this.name} ест`; },
};
const rabbit = Object.create(animal);
rabbit.name = 'Кролик';

rabbit.eats;                              // true — найдено в animal
rabbit.describe();                        // 'Кролик ест'
Object.getPrototypeOf(rabbit) === animal; // true
Object.hasOwn(rabbit, 'eats');             // false

Унаследованный метод вызывается с объектом перед точкой в качестве this. Поэтому describe читает rabbit.name, хотя сам метод находится в animal. Запись rabbit.eats = false создаст или изменит свойство у rabbit, а не перепишет значение у прототипа.

Два значения слова «прототип»

У объекта есть внутренняя ссылка на прототип. А у функции-конструктора свойство prototype — обычный объект, который станет прототипом экземпляров, созданных этой функцией через new. Это связанные, но не одинаковые вещи.

function User(name) {
  this.name = name;
}
User.prototype.sayHi = function () {
  return `Привет, ${this.name}`;
};

const user = new User('Оля');
Object.getPrototypeOf(user) === User.prototype; // true
user.sayHi(); // 'Привет, Оля'

Создание цепочки

Object.create(proto) создаёт объект, у которого proto сразу назначен прототипом. Это простой способ делегировать поиск свойств другому объекту. Для новых объектов предпочтительнее задать прототип при создании, а не менять его позже: Object.setPrototypeOf существует, но динамическая смена прототипа может ухудшить производительность.

Прототипом может быть только объект или null. Например, Object.create(null) создаёт объект без прототипа:

const dictionary = Object.create(null);
dictionary.apple = 'яблоко';
Object.getPrototypeOf(dictionary); // null
Object.hasOwn(dictionary, 'apple'); // true
dictionary.toString; // undefined: Object.prototype не унаследован

У такого объекта нет унаследованных методов вроде toString. Для проверки собственных свойств используйте Object.hasOwn, а не метод, которого у объекта может не быть. Аргумент proto для Object.create обязателен: вызов без него завершится ошибкой.

Не путайте с __proto__

[[Prototype]] — внутренняя ссылка объекта, а __proto__ — исторический геттер/сеттер для чтения и изменения этой ссылки. Это не то же самое, что Constructor.prototype. Через __proto__ нельзя назначить примитив или создать цикл: недопустимое значение не станет прототипом, а цикл вызовет TypeError. В новом коде используйте Object.getPrototypeOf для чтения и Object.create для создания.

Методы проверки прототипа и свойств

Object.getPrototypeOf(object) возвращает прототип объекта. animal.isPrototypeOf(rabbit) отвечает на вопрос «есть ли animal где-то в цепочке прототипов rabbit?». А propertyIsEnumerable(key) проверяет, есть ли у объекта собственное свойство с таким ключом и видно ли оно при переборе, например в Object.keys.

const animal = { eats: true };
const rabbit = Object.create(animal);
rabbit.name = 'Кролик';

Object.getPrototypeOf(rabbit) === animal; // true
animal.isPrototypeOf(rabbit);             // true
rabbit.propertyIsEnumerable('name');       // true
rabbit.propertyIsEnumerable('eats');       // false: свойство унаследовано

Почему не стоит менять встроенные прототипы

Не добавляйте свои методы в Array.prototype, Object.prototype и другие встроенные прототипы в обычном коде. Такое изменение затрагивает все объекты соответствующего типа, может конфликтовать с библиотеками и неожиданно менять перебор свойств. Исключение — корректный polyfill (полифилл): реализация метода или другой возможности, уже описанной в стандарте JavaScript, для среды, где эта возможность ещё не поддерживается. Полифилл должен следовать спецификации и проверять, что встроенной реализации действительно не существует.

«Перечисляемое» свойство — свойство, у которого включён специальный признак enumerable. Например, Object.keys показывает только собственные перечисляемые строковые ключи. Наличие свойства и попадание в такой список — разные проверки.
