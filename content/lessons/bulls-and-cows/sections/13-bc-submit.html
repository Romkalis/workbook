Шаг 11. Деплой, PR и сдача

Деплой

Сайт статический: index.html, style.css и папка dist/ после npm run build. Подойдёт любой хостинг статики.

Репозиторий приватный, а GitHub Pages для приватных репозиториев на бесплатном аккаунте недоступен (из общих знаний о тарифах GitHub; проверьте свой аккаунт — у GitHub Education Pro он может работать). Самый простой выход — Netlify или Vercel: подключаете приватный репозиторий, указываете ветку bulls-and-cows, команду сборки npm run build и корень публикации .. Ещё вариант — Netlify Drop: собрать проект локально и перетащить папку в браузер.

После деплоя откройте ссылку в режиме инкогнито и пройдите игру целиком. Частая ошибка — 404 на dist/main.js или на импортах без .js: смотрите вкладку Network.

Чек-лист поведения

  • Длина 2–6 и bin/oct/dec/hex доступны до старта и недоступны во время раунда.
  • В bin недоступны все длины, кроме 2.
  • Поле не принимает недопустимые символы; A–F принимаются наравне с a–f.
  • После каждой попытки появляется запись с bulls/cows; повтор не задваивает историю.
  • Угаданное число завершает игру, показываются попытки и время.
  • Рекорд виден после перезагрузки страницы.
  • «Новая игра» возвращает к настройкам без перезагрузки.

Pull Request

Откройте PR из bulls-and-cows в main своего репозитория и не мержите. Описание — по шаблону RS School (ссылка на задание, скриншот, деплой, дата сдачи, самооценка), плюс четыре пункта из задания:

  1. ссылка на деплой;
  2. подтверждение порядка коммитов — удобно таблицей «функция → хэш теста → хэш реализации»;
  3. ссылка на DESIGN.md;
  4. пройденный чек-лист поведения с отметками.

Хэши для таблицы даёт команда:

git log --oneline --reverse main..bulls-and-cows

Ожидаемая картина истории:

chore: set up typescript, vitest, eslint, prettier and husky
test: add failing tests for createDigitValidator
feat: implement createDigitValidator
test: add failing tests for isValidGuess
feat: implement isValidGuess
test: add failing tests for evaluateGuess
feat: implement evaluateGuess
test: add failing tests for generateSecret
feat: implement generateSecret
test: add failing tests for countPossibleSecrets
feat: implement countPossibleSecrets
test: add failing tests for game state and records
feat: add immutable game state and records
feat: add settings, game and records screens
docs: add design document

Приватный репозиторий проверяющие не увидят, пока вы не дадите им доступ. Как именно его выдавать в этом потоке, уточняйте в чате курса: в README задания про это не сказано.

Сдача

Ссылку на PR отправьте в RS App → Cross-Check: Submit. Задание проверяется кросс-чеком: другие студенты пройдут ваш чек-лист на деплое, посмотрят коммиты и запустят npm test. Поэтому npm ci && npm test на чистом клоне должен проходить без дополнительных действий.
