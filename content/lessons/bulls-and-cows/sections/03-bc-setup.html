Шаг 1. Репозиторий и инструменты

Репозиторий и ветки

Создайте приватный репозиторий. В main кладутся только README и .gitignore, вся работа идёт в ветке bulls-and-cows, которую в конце не мержат: PR из неё в main и есть то, что смотрят проверяющие.

git init bulls-and-cows && cd bulls-and-cows
printf "node_modules/\ndist/\ncoverage/\n" > .gitignore
echo "# Bulls and Cows" > README.md
git add . && git commit -m "init: add readme and gitignore"
git branch -M main
git remote add origin git@github.com:<ваш-логин>/bulls-and-cows.git
git push -u origin main
git switch -c bulls-and-cows

Сообщения коммитов пишите по конвенции RS School: префикс типа (init, feat, fix, refactor, docs, test, chore), двоеточие, затем что сделано в повелительном наклонении. Подробнее — в разделе про git урока Clean Code.

Зависимости и скрипты

Бандлер не нужен: TypeScript компилируется обычным tsc в ES-модули, и результат подключается в index.html через <script type="module">. Бандлер — инструмент вроде Webpack или Vite, который склеивает модули в один файл; в этом задании без него можно. Я беру Vitest, а не Jest: он понимает TypeScript и ES-модули без дополнительной настройки (из общих знаний; Jest тоже разрешён).

npm init -y
npm i -D typescript vitest eslint @eslint/js typescript-eslint prettier eslint-config-prettier husky lint-staged

В package.json добавьте "type": "module" и скрипты. Обязательные — lint, format, test:

{
  "type": "module",
  "scripts": {
    "build": "tsc",
    "dev": "tsc --watch",
    "lint": "eslint .",
    "format": "prettier --write .",
    "test": "vitest run --passWithNoTests",
    "prepare": "husky"
  },
  "lint-staged": {
    "*.ts": ["eslint --fix", "prettier --write"],
    "*.{json,md,html,css}": "prettier --write"
  }
}

Флаг --passWithNoTests нужен для самого первого коммита: тестов ещё нет, и без флага Vitest завершится с ошибкой, а значит хук pre-push не даст ничего отправить. README прямо говорит об этом: раннер не должен считать пустой набор ошибкой.

tsconfig.json

{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ES2022",
    "moduleResolution": "bundler",
    "lib": ["ES2022", "DOM", "DOM.Iterable"],
    "rootDir": "src",
    "outDir": "dist",
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "skipLibCheck": true
  },
  "include": ["src"],
  "exclude": ["src/**/*.test.ts"]
}

Главная ловушка сборки без бандлера: tsc не дописывает расширения к импортам. Если в исходнике написано import { evaluateGuess } from './game', браузер запросит файл /game без .js и получит 404. Пишите импорты сразу с расширением .js: from './game.js'. TypeScript поймёт, что речь о game.ts, а Vitest тоже разрешит такой путь.

ESLint и Prettier

ESLint 9 читает плоский конфиг eslint.config.js. Последним подключается eslint-config-prettier: он выключает правила оформления, чтобы ESLint и Prettier не спорили о пробелах и кавычках.

// eslint.config.js
import js from '@eslint/js';
import tseslint from 'typescript-eslint';
import prettier from 'eslint-config-prettier';

export default tseslint.config(
  { ignores: ['dist', 'node_modules', 'coverage'] },
  js.configs.recommended,
  ...tseslint.configs.recommended,
  prettier,
);
// .prettierrc
{ "singleQuote": true, "printWidth": 100 }

Husky: два хука с разными задачами

Git-хук — скрипт, который git запускает сам: перед коммитом (pre-commit) или перед отправкой на GitHub (pre-push). Если скрипт завершился с ошибкой, git отменяет действие. Husky хранит хуки в папке .husky/ внутри репозитория, чтобы они работали у всех, кто склонировал проект. Скрипт prepare в package.json подключает их автоматически после npm install.

npx husky init
echo "npx lint-staged" > .husky/pre-commit
echo "npm test" > .husky/pre-push

husky init создаёт pre-commit с командой npm test. Её обязательно нужно заменить на npx lint-staged. Если тесты запускаются на коммите, вы не сможете закоммитить падающие тесты, а это первый обязательный шаг TDD. За неверный pre-commit снимают баллы.

Получается такая логика. pre-commit только форматирует и линтит изменённые файлы, поэтому «красный» коммит проходит. pre-push гоняет все тесты, поэтому одинокий красный коммит отправить нельзя: красный и зелёный коммиты функции уходят на GitHub одним push.

Проверьте npm run lint, npm run format и npm test, затем зафиксируйте настройку отдельным коммитом: chore: set up typescript, vitest, eslint, prettier and husky.
