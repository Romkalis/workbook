Шаг 10. DESIGN.md

Документ в корне репозитория стоит 20 баллов, и критерии требуют конкретики: не «использованы чистые функции», а «evaluateGuess в src/game.ts — чистая функция, потому что…». Ниже шаблон с содержанием, которое можно адаптировать под свой код. Обозначения: n — длина секрета, b — система счисления, h — число попыток в истории.

Структуры данных и алгоритмы

  • Секрет и попытка — строки. Сохраняют ведущий ноль и hex-буквы; для сравнения разворачиваются в массив символов.
  • Состояние игры — неизменяемый объект GameState. Каждое действие возвращает новый объект, поэтому старые версии остаются целыми, а отладка и тесты проще.
  • История — массив Attempt[]: порядок важен, добавление только в конец через spread.
  • Set — в isValidGuess для поиска повторов и в evaluateGuess для проверки «цифра есть в секрете» за O(1).
  • Map — кэш в memoize.
  • Алгоритм evaluateGuess: быки — число совпадающих позиций; общие — число цифр попытки, которые есть в секрете; коровы = общие − быки. Корректно, потому что цифры уникальны.
  • Алгоритм countPossibleSecrets: размещения без повторений, P(b, n) = b × P(b − 1, n − 1), P(b, 0) = 1; результаты кэшируются.

Сложность

ФункцияВремяОбоснование
generateSecretO(n · b)n шагов рекурсии, на каждом filter копирует пул из не более чем b символов. Глубина рекурсии n, память O(n · b) на копии пула.
evaluateGuessO(n)Построение Set — O(n), два прохода filter по n символов, проверка has — O(1).
isValidGuessO(n)Проверка длины O(1), every по n символам, каждый вызов валидатора — поиск в строке алфавита длиной до 16, то есть константа; Set — O(n).
countPossibleSecretsO(n) первый вызов, O(1) повторныйРекурсия уменьшает length на 1, глубина n. Затем ответ берётся из Map. Ключ JSON.stringify короткий, это константа.

Поиск повтора в applyGuess — O(h), его тоже можно упомянуть. Если хранить ещё и Set угаданных строк, станет O(1), но для десятков попыток это лишнее усложнение (YAGNI) — так и напишите.

Принципы чистого кода

Каждый пункт — с указанием места:

  • Single responsibility: game.ts — правила, state.ts — переходы состояния, storage.ts — localStorage, dom.ts и main.ts — интерфейс.
  • DRY: createDigitValidator — единственное место, которое знает, что такое цифра системы; normalize — единственное место приведения регистра.
  • KISS: коровы считаются вычитанием, а не вложенным перебором.
  • Говорящие имена: secretDigits, applyGuess, compareRecords.
  • Нет магических значений: ALPHABET, LENGTHS, BASES, ключ localStorage — именованные константы.
  • Побочные эффекты на краях: случайность и время передаются параметрами, DOM и хранилище вынесены из ядра.
