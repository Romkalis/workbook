requestAnimationFrame

Когда анимацию нельзя описать в CSS (физика, анимация по данным, рисование на canvas), её делают в JavaScript. requestAnimationFrame(callback) просит браузер вызвать функцию перед следующей отрисовкой. Колбэк получает отметку времени, а частота совпадает с частотой экрана: 60, 120 Гц и так далее.

export interface AnimateOptions {
  duration: number;
  draw: (progress: number) => void;
  easing?: (t: number) => number;
  raf?: (cb: (time: number) => void) => number;
}

export function animate({ duration, draw, easing = (t) => t, raf = requestAnimationFrame }: AnimateOptions): Promise<void> {
  return new Promise((resolve) => {
    let start: number | null = null;
    const frame = (time: number) => {
      start ??= time;
      const t = Math.min((time - start) / duration, 1);
      draw(easing(t));
      if (t < 1) raf(frame);
      else resolve();
    };
    raf(frame);
  });
}

Главное правило: прогресс считается от прошедшего времени, а не от числа кадров. Анимация «по 2 пикселя за кадр» на экране 120 Гц пройдёт вдвое быстрее, чем на 60 Гц, а при тормозах растянется. Math.min(…, 1) гарантирует, что последний кадр нарисует ровно конечное состояние. Параметр raf позволяет подставить в тестах поддельные кадры.

Отменяют запланированный кадр через cancelAnimationFrame(id). В фоновой вкладке браузер приостанавливает колбэки requestAnimationFrame, и это экономит батарею. У setInterval такой экономии нет, к тому же он не попадает в такт с отрисовкой.

Функции времени (easing)

Функция времени превращает линейный прогресс t от 0 до 1 в «ощущаемый». ease-out быстро стартует и плавно тормозит, им хорошо показывать появление. ease-in наоборот, он подходит для ухода. В CSS это ключевые слова и cubic-bezier(...), в JavaScript — обычные функции:

export const easeOutCubic = (t: number) => 1 - (1 - t) ** 3;
export const easeInOutQuad = (t: number) => (t < 0.5 ? 2 * t * t : 1 - (-2 * t + 2) ** 2 / 2);

Задача 8. Анимация с отменой ★★☆ практика

Возьмите animate из раздела и добавьте отмену: функция возвращает { finished: Promise<boolean>, cancel() }. finished выполняется значением true, если анимация дошла до конца, и false, если её отменили. После отмены draw больше не вызывается. Кадры и их отмену передайте параметрами raf и caf.

Зачем: анимацию, которую нельзя остановить, нельзя и использовать в реальном интерфейсе. Пользователь закрыл окно, пока оно открывалось, и новая анимация должна заменить старую, а не драться с ней за один элемент.

Решение и разбор
type Raf = (cb: (time: number) => void) => number;

export function animate({
  duration,
  draw,
  easing = (t: number) => t,
  raf = requestAnimationFrame,
  caf = cancelAnimationFrame,
}: {
  duration: number;
  draw: (progress: number) => void;
  easing?: (t: number) => number;
  raf?: Raf;
  caf?: (id: number) => void;
}) {
  let id = 0;
  let finish: (completed: boolean) => void = () => {};
  const finished = new Promise<boolean>((resolve) => (finish = resolve));
  let start: number | null = null;
  const frame = (time: number) => {
    start ??= time;
    const t = Math.min((time - start) / duration, 1);
    draw(easing(t));
    if (t < 1) id = raf(frame);
    else finish(true);
  };
  id = raf(frame);
  return {
    finished,
    cancel() {
      caf(id);
      finish(false);
    },
  };
}

Запоминается id последнего запрошенного кадра: каждый кадр запрашивает следующий, и отменять нужно именно его. Повторный finish безопасен: промис выполняется один раз. Поэтому cancel после завершения ничего не сломает. Почему boolean, а не отклонение? Отмена — не ошибка, а нормальный сценарий. С отклонением каждый вызывающий был бы обязан писать catch.

Задача 9. Обработчик прокрутки раз в кадр ★★☆ практика

Событие scroll срабатывает много раз за кадр, и тяжёлый обработчик тормозит прокрутку. Напишите rafThrottle(fn, raf): сколько бы раз за кадр ни вызвали обёртку, fn выполнится один раз перед отрисовкой, с аргументами последнего вызова.

Зачем: нет смысла пересчитывать положение элемента чаще, чем экран может это показать. Привязка к requestAnimationFrame — естественный «тормоз» для любых визуальных обновлений: прокрутки, движения мыши, изменения размера окна.

Решение и разбор
export function rafThrottle<A extends unknown[]>(fn: (...args: A) => void, raf: (cb: () => void) => number = requestAnimationFrame) {
  let scheduled = false;
  let lastArgs: A;
  return (...args: A) => {
    lastArgs = args;
    if (scheduled) return;
    scheduled = true;
    raf(() => {
      scheduled = false;
      fn(...lastArgs);
    });
  };
}

Флаг scheduled не даёт запросить второй кадр, пока первый не наступил, а lastArgs каждый раз перезаписывается. В итоге к моменту кадра используется самое свежее значение. Флаг сбрасывается до вызова fn: если fn сама вызовет обёртку, следующий кадр запросится правильно. Отличие от debounce из урока Async JS: debounce ждёт тишины, а rafThrottle срабатывает регулярно, пока событие продолжается.

Задача 10. Счётчик кадров ★★☆ практика

Напишите createFpsMeter() с методом frame(time), который вызывают из колбэка requestAnimationFrame, и геттером fps — числом кадров за последнюю секунду. Старые отметки должны удаляться, чтобы память не росла.

Зачем: «анимация тормозит» — это ощущение, а FPS — число, которое можно сравнить до и после правки. Свой маленький счётчик полезен и в отладке, и чтобы понять, как устроены инструменты вроде панели Performance в DevTools.

Решение и разбор
export function createFpsMeter() {
  const times: number[] = [];
  return {
    frame(time: number): void {
      times.push(time);
      while (times.length > 0 && time - times[0]! > 1000) times.shift();
    },
    get fps(): number {
      return times.length;
    },
  };
}

Хранится скользящее окно отметок за последнюю секунду. Новая отметка добавляется в конец, устаревшие удаляются с начала, поэтому массив не больше числа кадров в секунду. Для сотен элементов shift достаточно быстр. Для больших окон пишут кольцевой буфер. Настоящий FPS зависит от экрана: на 120 Гц плавная анимация даёт около 120, а не 60.

Задача 11. Свои функции времени ★☆☆ разминка

Напишите easeInCubic, easeOutQuad и easeOutBack — последняя слегка «перелетает» конец и возвращается (формула ниже). Проверьте, что каждая даёт 0 в начале и 1 в конце. Для какой из них draw должен уметь получать прогресс больше 1?

// easeOutBack: c1 = 1.70158, c3 = c1 + 1
// 1 + c3 * (t - 1) ** 3 + c1 * (t - 1) ** 2

Зачем: функция времени — это просто отображение отрезка [0, 1] в «ощущение». Когда это понятно, любую кривую из CSS (cubic-bezier) или с сайта easings.net можно перенести в JavaScript и обратно.

Решение и разбор
export const easeInCubic = (t: number) => t ** 3;
export const easeOutQuad = (t: number) => 1 - (1 - t) ** 2;

const c1 = 1.70158;
const c3 = c1 + 1;
export const easeOutBack = (t: number) => 1 + c3 * (t - 1) ** 3 + c1 * (t - 1) ** 2;

easeOutBack посередине выходит за 1 (около 1,1 при t ≈ 0,6). Если draw ограничивает значение через Math.min(p, 1), эффект «перелёта» пропадёт. Для прозрачности (opacity) значения больше 1 бессмысленны, а для сдвига и масштаба нормальны. Формула взята из коллекции easings.net (из общих знаний).
