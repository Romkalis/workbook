Что такое API и REST

API (Application Programming Interface) — договорённость о том, как одна программа обращается к другой. Статья AWS «What is an API?» сравнивает API с официантом: вы не идёте на кухню, а говорите официанту, что нужно, и он приносит результат. Фронтенд не лезет в базу данных сервера, а отправляет HTTP-запрос по договорённому адресу и получает ответ в договорённом формате.

AWS выделяет несколько видов API по способу общения: SOAP (сообщения в XML по строгому протоколу), RPC (вызов удалённой функции), WebSocket (постоянный двусторонний канал) и REST — самый распространённый стиль для веба. По доступу API бывают приватные (только для своей компании), публичные (для всех), партнёрские (для избранных компаний) и составные (composite: несколько запросов объединены в один).

REST (Representational State Transfer, «передача состояния представления») — архитектурный стиль, который Рой Филдинг описал в диссертации 2000 года. Это не протокол и не стандарт, а набор ограничений. Если API их соблюдает, его называют RESTful. Шесть ограничений подробно разобраны в уроке «Клиент-серверное взаимодействие»; кратко:

  • клиент — сервер: интерфейс и хранение данных разделены;
  • без состояния: каждый запрос несёт всё нужное для обработки, сервер не помнит предыдущих;
  • кешируемость: ответ сообщает, можно ли его кешировать;
  • многоуровневость: клиент не знает, что за сервером — прокси, балансировщик или цепочка сервисов;
  • единообразный интерфейс: ресурсы адресуются URL, действия выражаются методами HTTP;
  • код по требованию — необязательное ограничение.
Поправки к лекции

1. Лектор объясняет «stateless» так: сколько бы раз и в каком порядке ни отправлять запросы, ответ будет один и тот же. Это смешение двух понятий. Отсутствие состояния означает, что сервер не хранит контекст клиента между запросами (например, кто вошёл), а не то, что ответы не меняются: после POST список пользователей станет другим. «Повторный запрос даёт тот же итог» — это идемпотентность метода (раздел о запросах ниже).
2. «RESTful» в лекции переведено как «REST-подобный», в отличие от «полного REST». Обычно RESTful означает «соответствующий REST». Мысль лектора при этом верная: большинство API, называющих себя RESTful, соблюдают не все ограничения (особенно HATEOAS), и точнее было бы называть их REST-like или «HTTP API».

Что разберём

  • Анатомию запроса: адрес, метод, заголовки, тело; CRUD и коды ответов.
  • Как проектировать адреса: ресурсы, вложенность, фильтры, сортировка, пагинация, версии.
  • json-server: учебный REST-сервер из одного JSON-файла, его старую и новую версии.
  • Клиент на fetch для REST-API.
