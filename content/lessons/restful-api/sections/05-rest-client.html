Клиент для REST-API на fetch

Во второй половине лекции методы API пишутся в коде. Хорошая практика, которую показывает лектор: собрать все обращения к серверу в отдельный модуль (часто api.js), а в остальном коде импортировать готовые функции. Тогда базовый адрес, заголовки и обработка ошибок живут в одном месте. Версия ниже доработана: добавлена проверка статуса, которой в лекции нет (без неё fetch не заметит 404, урок «Клиент-серверное взаимодействие»).

const BASE_URL = 'http://localhost:3000';
const EMPLOYEES = `${BASE_URL}/employees`;

async function request(url, options = {}) {
  const response = await fetch(url, {
    ...options,
    headers: { 'Content-Type': 'application/json', ...options.headers },
  });
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  return response.status === 204 ? null : response.json();
}

export const getEmployees = (params = {}) =>
  request(`${EMPLOYEES}?${new URLSearchParams(params)}`);
export const getEmployee = (id) => request(`${EMPLOYEES}/${id}`);
export const createEmployee = (data) =>
  request(EMPLOYEES, { method: 'POST', body: JSON.stringify(data) });
export const updateEmployee = (id, patch) =>
  request(`${EMPLOYEES}/${id}`, { method: 'PATCH', body: JSON.stringify(patch) });
export const deleteEmployee = (id) => request(`${EMPLOYEES}/${id}`, { method: 'DELETE' });
  • URLSearchParams собирает строку запроса из объекта и кодирует спецсимволы: { role: 'developer' } → role=developer. Лектор собирает её вручную через map и join('&') — это работает, но забывает про кодирование пробелов и кириллицы.
  • Тело запроса — строка: объект превращают в JSON через JSON.stringify. Лектор на демо забыл это и получил ошибку — частая ошибка новичков.
  • Ответ 204 не имеет тела, и response.json() на нём упал бы, поэтому для него возвращаем null.

Модуль запущен в Node.js 22 против обеих версий json-server. getEmployees({ role: 'developer' }) вернул Аню и Петю; createEmployee создал запись со строковым id; updateEmployee поменял роль; после deleteEmployee запрос этой записи бросил HTTP 404.

Пагинация с общим числом записей

Чтобы нарисовать кнопки страниц, нужно знать, сколько их. В json-server 0.x число записей приходит в заголовке X-Total-Count. Лектор показывает, что console.log(response.headers) выводит пустой с виду объект: заголовки читают методом get, а значение всегда строка.

// json-server 0.16–0.17
async function getPage(page, limit) {
  const response = await fetch(`${EMPLOYEES}?${new URLSearchParams({ _page: page, _limit: limit })}`);
  const total = Number(response.headers.get('X-Total-Count'));
  return { items: await response.json(), total, pages: Math.ceil(total / limit) };
}
// getPage(2, 3) → { items: [Оля], total: 4, pages: 2 }

// json-server 1.0: всё в теле ответа
const page = await getEmployees({ _page: 2, _per_page: 3 });
// page.pages = 2, page.items = 4, page.data = [Оля]

Если фронтенд и json-server работают на разных портах, браузеру понадобятся заголовки CORS. json-server отдаёт их сам, поэтому учебные запросы с localhost:5173 на localhost:3000 проходят. Чужой заголовок вроде X-Total-Count браузер даёт прочитать только если сервер перечислил его в Access-Control-Expose-Headers — json-server 0.17 делает и это: проверка запросом с заголовком Origin показала Access-Control-Expose-Headers: X-Total-Count, Link. Версия 1.0 отвечает Access-Control-Allow-Origin: *, а число записей отдаёт в теле, так что заголовок ей не нужен (раздел «Заголовки CORS»).

Задача 11. Клиент, который не теряет ошибку сервера ★★☆ практика

Функция request из раздела бросает Error("HTTP 400"), и текст ошибки от сервера ({ "message": "email занят" }) теряется. Напишите класс HttpError с полями status и message и новую request(url, init?):

  • при !response.ok бросает HttpError с сообщением из тела, если оно есть, иначе "HTTP <код>";
  • тело ошибки может быть не JSON (например, HTML-страница прокси), и это не должно ломать обработку;
  • 204 → null.

Зачем: интерфейсу нужно и что сломалось (код: 401 — на вход, 409 — подсветить поле), и почему (текст для человека). Класс ошибки позволяет различать их через instanceof и не разбирать строки.

Решение и разбор
export class HttpError extends Error {
  constructor(
    readonly status: number,
    message: string,
  ) {
    super(message);
    this.name = 'HttpError';
  }
}

async function messageFrom(response: Response): Promise<string> {
  try {
    const data: unknown = await response.json();
    if (typeof data === 'object' && data !== null && 'message' in data && typeof data.message === 'string') {
      return data.message;
    }
  } catch {
    // тело не JSON — оставим стандартный текст
  }
  return `HTTP ${response.status}`;
}

export async function request(url: string, init: RequestInit = {}): Promise<unknown> {
  const response = await fetch(url, init);
  if (!response.ok) throw new HttpError(response.status, await messageFrom(response));
  return response.status === 204 ? null : response.json();
}

catch без переменной пустой не случайно: ошибка разбора здесь ожидаема и не важна, ведь важен исходный код ответа. Результат имеет тип unknown: проверку формы данных берёт на себя вызывающий код (предикат или схема). В тесте fetch подменяется на функцию, которая возвращает настоящий объект Response. В Node 18+ он есть глобально, как и в браузере.

Задача 12. Строка запроса без «undefined» ★☆☆ разминка

Вызов getEmployees({ role: undefined, page: 2 }) из раздела отправит ?role=undefined&page=2. Напишите buildUrl(base, params), которая пропускает undefined, null и пустые строки, а числа и булевы значения превращает в строки.

Зачем: сервер честно отфильтрует сотрудников с ролью "undefined" и вернёт пустой список. Такая ошибка не падает, а тихо показывает «ничего не найдено», и её долго ищут.

Решение и разбор
type Param = string | number | boolean | null | undefined;

export function buildUrl(base: string, params: Record<string, Param> = {}): string {
  const search = new URLSearchParams();
  for (const [key, value] of Object.entries(params)) {
    if (value === undefined || value === null || value === '') continue;
    search.append(key, String(value));
  }
  const query = search.toString();
  return query ? `${base}?${query}` : base;
}

0 и false не пропускаются: это настоящие значения фильтра («страница 0» — ошибка клиента, но решать это должен сервер). Вопросительный знак добавляется, только если есть параметры. URLSearchParams сам кодирует пробелы и кириллицу, поэтому склеивать строку вручную не нужно.

Задача 13. Одна страница из двух версий json-server ★★☆ практика

Проект должен работать с обеими версиями json-server. Напишите toPage(response, perPage), которая возвращает { items, total, pages }:

  • версия 0.x: тело — массив, общее число в заголовке X-Total-Count;
  • версия 1.0: тело — объект { data, items, pages }, где items — общее число записей.

Если формат не распознан, бросьте ошибку.

Зачем: это паттерн «адаптер»: различия внешнего API прячутся в одной функции, а остальной код работает с одним форматом. Обновили json-server — правится одна функция, а не каждый экран.

Решение и разбор
export interface PageResult {
  items: unknown[];
  total: number;
  pages: number;
}

export async function toPage(response: Response, perPage: number): Promise<PageResult> {
  const body: unknown = await response.json();
  if (Array.isArray(body)) {
    const header = response.headers.get('X-Total-Count');
    const total = header === null ? body.length : Number(header);
    return { items: body, total, pages: Math.ceil(total / perPage) };
  }
  if (typeof body === 'object' && body !== null && 'data' in body && Array.isArray(body.data) && 'items' in body && typeof body.items === 'number') {
    return { items: body.data, total: body.items, pages: Math.ceil(body.items / perPage) };
  }
  throw new TypeError('Неизвестный формат страницы');
}

В версии 1.0 поле items — это число, а сами записи лежат в data. Неудачное название, и его легко перепутать, поэтому адаптер переименовывает поля в однозначные. Если заголовка нет, например CORS не разрешил его читать, честный запасной вариант — длина массива. Подробнее про такую обёртку — в уроке «Паттерны проектирования».
