json-server: REST-API за минуту

Фронтенд часто нужно делать раньше, чем готов бэкенд, или для учебного проекта, где бэкенда нет вовсе. Лектор показывает json-server — пакет, который превращает обычный JSON-файл в полноценный REST-API с CRUD, фильтрами и пагинацией, «без кода за 30 секунд», как обещают его авторы. На нём же построен сервер для задания Async Race.

Запуск

Нужен Node.js (урок «Основы Node.js»). Создаём проект, ставим пакет и файл с данными:

npm init -y
npm install json-server
// db.json
{
  "employees": [
    { "id": "1", "name": "Аня", "role": "developer", "salary": 2000 },
    { "id": "2", "name": "Вася", "role": "manager", "salary": 1500 },
    { "id": "3", "name": "Петя", "role": "developer", "salary": 2500 },
    { "id": "4", "name": "Оля", "role": "designer", "salary": 1800 }
  ]
}
npx json-server db.json --port 3000

Каждый ключ верхнего уровня (employees) становится ресурсом: GET /employees, GET /employees/1, POST /employees, PUT, PATCH и DELETE /employees/1. Все изменения сразу записываются в db.json. У новых записей json-server сам генерирует строковый id, например "HfXDCD4".

Две версии — разные правила

Лекция и большинство учебных проектов RS School (сервер Async Race использует json-server ^0.16.3) работают со старой веткой 0.x. Сейчас npm install json-server ставит версию 1.0 (пока beta), где часть параметров изменилась. Обе версии проверены одним и тем же db.json:

Задача0.16–0.17 (лекция, Async Race)1.0 (ставится по умолчанию)
Фильтр?role=developer?role=developer
Больше или равно?salary_gte=2000?salary:gte=2000 (старая запись тоже сработала)
Сортировка по убыванию?_sort=salary&_order=desc?_sort=-salary; запрос в старом виде вернул пустой массив
Пагинация?_page=2&_limit=3 → массив?_page=2&_per_page=3 → объект; с _limit пришло "data": []
Сколько всего записейзаголовок X-Total-Count: 4 и заголовок Link со ссылками first/next/lastполя в теле: { first, prev, next, last, pages, items, data }
Ответ на DELETE{}, 200удалённый объект, 200
Запуск с наблюдением за файломjson-server --watch db.jsonjson-server db.json (наблюдает сам)

Вывод: всегда смотрите, какая версия стоит в проекте (package.json), и читайте документацию именно её. Для задания с готовым сервером ничего ставить не нужно — его версия уже зафиксирована. Если хотите поведение как в лекции, ставьте npm install json-server@0.17.

Проверка в Postman

Лектор проверяет все методы в Postman: для POST, PUT и PATCH на вкладке Body выбирают raw → JSON (Postman сам добавит Content-Type: application/json). На вопрос из чата «зачем сторонние программы-костыли» лектор отвечает: Postman — обычный инструмент для работы с API, и аналогов много (Insomnia, Thunder Client, файлы .http в редакторе). Для статики во время разработки он советует расширение Live Server для VS Code: оно поднимает локальный сервер и перезагружает страницу при сохранении.
