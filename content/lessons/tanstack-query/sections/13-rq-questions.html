Вопросы для самопроверки

Сначала ответьте сами, потом раскройте ответ.

Почему серверные данные неудобно хранить в обычном useState?

Их может изменить кто-то другой, они устаревают, нужны в разных компонентах и проходят через состояния загрузки и ошибки. С useState всё это пришлось бы писать вручную: кеш, повторные запросы, флаги.

Что произойдёт, если номер страницы используется в queryFn, но не попал в queryKey?

При смене страницы ключ останется прежним, и библиотека покажет данные первой страницы из кеша. Всё, от чего зависит ответ, должно быть в ключе.

Чем isLoading отличается от isFetching?

isLoading — данных ещё нет и идёт первый запрос. isFetching — идёт любой запрос, в том числе фоновый, когда данные уже на экране. Скелетон показывают по isLoading.

Данные устарели (stale). Они пропадут с экрана?

Нет. Устаревшие данные продолжают показываться, просто при следующем удобном случае библиотека их обновит. Удаляются из памяти только неиспользуемые данные после gcTime.

Какие ключи затронет invalidateQueries({ queryKey: ['games'] })?

Все, которые начинаются с 'games': ['games'], ['games', 'slots'], ['games', { page: 2 }]. Только ровно ['games'] — с exact: true.

Зачем в оптимистичном обновлении вызывают cancelQueries?

Если в этот момент идёт запрос того же ключа, его ответ может прийти позже и затереть изменение, которое мы только что показали. cancelQueries отменяет такие запросы.

Почему после выхода из аккаунта вызывают queryClient.clear()?

В кеше остались данные прошлого пользователя. Без очистки следующий человек может их увидеть, пока не придут его собственные.

Словарь

Серверное состояние
Данные, которые хранятся на сервере, а в браузере есть только их копия.
Кеш
Хранилище уже полученных ответов, чтобы не запрашивать их снова.
queryKey
Массив, который однозначно называет запись в кеше.
Мутация
Запрос, который меняет данные на сервере: POST, PUT, PATCH, DELETE.
Инвалидация
Пометка «эти данные устарели, их нужно перезапросить».
Stale
Устаревшие данные: их можно показывать, но при случае стоит обновить.
Prefetch
Загрузка данных заранее, до того как пользователь их запросил.
Polling (опрос)
Повторение запроса по таймеру.
Оптимистичное обновление
Изменение экрана до ответа сервера с откатом при ошибке.
