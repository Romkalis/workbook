useQuery: читаем данные

useQuery принимает объект настроек. Обязательны два поля: queryKey (адрес в кеше) и queryFn (функция, которая сходит за данными и вернёт Promise).

const { data, error, isPending, isLoading, isFetching, isError, refetch } = useQuery({
  queryKey: ['games', categoryId],
  queryFn: () => fetchGames(categoryId),
  staleTime: 5 * 60 * 1000,  // 5 минут
  enabled: !!categoryId,     // не запускать, пока categoryId нет
});

queryFn и fetch: проверяйте response.ok

Библиотека узнаёт об ошибке только одним способом: Promise из queryFn отклонился (функция выбросила ошибку). Встроенный fetch не выбрасывает ошибку на ответы 404 или 500, для него это обычный ответ. Поэтому проверку нужно написать самим:

async function fetchGames(categoryId) {
  const res = await fetch(`/api/games?category=${categoryId}`);
  if (!res.ok) {
    throw new Error(`Ошибка ${res.status}`);
  }
  return res.json();
}

Без этой проверки тело ответа с ошибкой (например, { message: 'boom' }) попадёт в data, и компонент попробует показать его как список игр. Мы проверили это на библиотеке: при ответе 500 запрос считается успешным. Axios и похожие клиенты сами выбрасывают ошибку на статусы 4xx и 5xx.

Статусы: isPending, isLoading, isFetching

Эти три флага чаще всего путают. Разница в том, есть ли уже данные в кеше и идёт ли сейчас запрос.

ФлагКогда trueЧто показать
isPendingДанных ещё нет совсем (запрос мог даже не начаться, например при enabled: false)Заглушку
isLoadingДанных нет и запрос идёт прямо сейчас. Это первая загрузкаСкелетон
isFetchingИдёт любой запрос, в том числе фоновое обновление, когда данные уже на экранеМаленький индикатор, данные не прятать
isErrorПоследний запрос закончился ошибкой, сама ошибка лежит в errorСообщение об ошибке
isSuccessДанные полученыДанные

Практический вывод: скелетон рисуйте по isLoading, а не по isFetching. Иначе каждый фоновый запрос будет прятать уже показанный список, и экран начнёт мигать.

if (isLoading) return <Skeleton />;
if (isError) return <p>Не удалось загрузить: {error.message}</p>;
return (
  <>
    {isFetching && <small>Обновляем…</small>}
    <GamesGrid games={data} />
  </>
);
Уточнение к конспекту

В пятой версии isLoading вычисляется как isPending && isFetching. Если запрос выключен через enabled: false, то isPending будет true, а isLoading — false: данных нет, но и загрузки нет.
