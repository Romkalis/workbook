Когда данные обновляются сами

Библиотека повторяет запрос в нескольких ситуациях. Все они срабатывают только для устаревших данных: если staleTime ещё не прошёл, запроса не будет. Каждую можно выключить в настройках.

НастройкаПо умолчаниюКогда срабатывает
refetchOnMounttrueНа экране появился компонент с этим запросом
refetchOnWindowFocustrueПользователь вернулся во вкладку
refetchOnReconnecttrueВернулся интернет
refetchIntervalвыключеноКаждые N миллисекунд (опрос, polling)

Обновление при фокусе особенно полезно: человек ушёл на 10 минут в другую вкладку, вернулся, и баланс обновился сам. Если оно мешает (например, на странице с формой), его выключают для конкретного запроса: refetchOnWindowFocus: false.

У refetchOnMount есть значение 'always': запрос при монтировании пойдёт даже для свежих данных. Пример есть в разборе хука useLeaderboard в следующем уроке.

Опрос по таймеру

refetchInterval: 5000 обновляет данные каждые 5 секунд. Пока вкладка в фоне, опрос стоит на паузе. Чтобы он шёл и в фоне, добавляют refetchIntervalInBackground: true.

Вместо числа можно передать функцию. Она получает запрос и возвращает интервал или false, чтобы остановиться. Так удобно ждать окончания долгой задачи на сервере:

useQuery({
  queryKey: ['task', taskId],
  queryFn: () => fetchTask(taskId),
  refetchInterval: (query) =>
    query.state.data?.status === 'completed' ? false : 2000,
});

Если сервер умеет сам присылать события (WebSocket или SSE), опрос не нужен: лучше обновлять кеш по событию. Чем отличаются эти способы, разобрано в уроке «TanStack Query на реальном коде».
