useMutation и обновление кеша

useQuery читает данные. Чтобы их изменить (запросы POST, PUT, PATCH, DELETE), используют useMutation. Главное отличие: мутация не запускается сама при появлении компонента, только когда вы вызовете mutate.

const queryClient = useQueryClient();

const { mutate, isPending, isError } = useMutation({
  mutationFn: (newGame) => createGame(newGame),
  onSuccess: (createdGame) => {
    // createdGame — ответ сервера
    queryClient.invalidateQueries({ queryKey: ['games'] });
  },
  onError: (error) => {
    showToast(`Не получилось: ${error.message}`);
  },
  onSettled: () => {
    // вызывается в любом случае: и после успеха, и после ошибки
    closeForm();
  },
});

// где-то в обработчике
mutate({ title: 'Новая игра', category: 'puzzle' });

Кнопку на время запроса блокируют по isPending: <button disabled={isPending}>. У мутаций нет isLoading, только isPending.

mutate или mutateAsync

  • mutate — «запустил и забыл». Результат обрабатывается в onSuccess и onError. Исключений не бросает, поэтому try/catch не нужен.
  • mutateAsync возвращает Promise, его можно ждать через await. При ошибке Promise отклоняется, поэтому вызов нужно обернуть в try/catch, иначе получите необработанную ошибку.
// mutate: колбэк можно передать и прямо в вызов
mutate(data, { onSuccess: () => showToast('Создано!') });

// mutateAsync: когда нужно дождаться результата
try {
  const game = await mutateAsync(data);
  navigate(`/games/${game.id}`);
} catch (error) {
  // ошибку уже увидел onError, здесь просто не даём ей «упасть»
}

В большинстве случаев хватает mutate.

invalidateQueries: «эти данные устарели»

После мутации данные на сервере изменились, а в кеше лежит старая копия. invalidateQueries помечает записи как устаревшие и сразу перезапрашивает те, что сейчас на экране. Остальные обновятся, когда снова понадобятся.

Ключ сравнивается по началу. Это значит, что вызов с ['games'] затронет все ключи, которые с него начинаются:

// затронет ['games'], ['games', 'slots'], ['games', { page: 2 }]
queryClient.invalidateQueries({ queryKey: ['games'] });

// только ровно ['games'], без вложенных
queryClient.invalidateQueries({ queryKey: ['games'], exact: true });

// несколько разных веток сразу
await Promise.all([
  queryClient.invalidateQueries({ queryKey: ['games'] }),
  queryClient.invalidateQueries({ queryKey: ['user', 'balance'] }),
]);
Ошибка в исходном конспекте

В конспекте и в презентации курса вызов без exact подписан как «точное совпадение», а для сравнения по началу предлагается exact: false. На самом деле exact: false — это и есть значение по умолчанию, а точное совпадение включается через exact: true. Мы проверили это на библиотеке.

Именно поэтому ключи строят от общего к частному: одним вызовом с коротким ключом обновляется целая ветка кеша.

Если перезапрашивать сразу не нужно, есть опция refetchType: 'none': данные только помечаются устаревшими, а запрос пойдёт при следующем обращении. Пример — в разборе хука useLiveBalanceSync.
