useQueryClient: ручное управление кешем

useQueryClient() возвращает тот самый QueryClient, который передан в провайдер. Через него можно работать с кешем напрямую: в обработчиках событий, в мутациях, в своих хуках.

МетодЧто делает
invalidateQueriesПомечает данные устаревшими и перезапрашивает активные
getQueryDataЧитает данные из кеша без запроса
setQueryDataЗаписывает данные в кеш руками
prefetchQueryЗагружает данные заранее, до того как они понадобятся
cancelQueriesОтменяет идущие запросы
resetQueriesВозвращает запросы в начальное состояние
clearОчищает весь кеш

Ниже пять типичных ситуаций.

1. Мутация затронула несколько списков

После пополнения счёта изменились и баланс, и история операций. Обновляем оба:

useMutation({
  mutationFn: depositMoney,
  onSuccess: () => {
    queryClient.invalidateQueries({ queryKey: ['balance'] });
    queryClient.invalidateQueries({ queryKey: ['transactions'] });
  },
});

2. Данные уже есть: берём из кеша

function handleClick(gameId) {
  const game = queryClient.getQueryData(['game', gameId]);
  if (game) {
    openModal(game);           // мгновенно, без запроса
  } else {
    fetchAndOpenModal(gameId); // в кеше нет — загружаем
  }
}

В TypeScript тип данных указывают так: getQueryData<Game>(['game', gameId]).

3. Загрузка заранее при наведении

Пользователь навёл курсор на карточку — начинаем грузить подробности. Когда он кликнет, данные уже в кеше, и загрузки не видно.

function handleMouseEnter(id) {
  queryClient.prefetchQuery({
    queryKey: ['game', id],
    queryFn: () => fetchGame(id),
    staleTime: 60 * 1000, // если данные моложе минуты, запроса не будет
  });
}

На телефоне наведения нет, поэтому это лишь ускорение, а не обязательная часть работы.

4. Оптимистичное обновление

Обычно интерфейс ждёт ответа сервера. Оптимистичное обновление меняет экран сразу, будто сервер уже согласился. Если сервер вернул ошибку, возвращаем всё как было. Так делают для быстрых действий вроде «убрать из избранного».

useMutation({
  mutationFn: removeFavorite,
  onMutate: async (gameId) => {
    // 1. отменяем идущие запросы избранного, чтобы их ответ не затёр наши изменения
    await queryClient.cancelQueries({ queryKey: ['favorites'] });
    // 2. запоминаем, как было, чтобы откатиться
    const previous = queryClient.getQueryData(['favorites']);
    // 3. сразу меняем кеш — экран обновится без ожидания
    queryClient.setQueryData(['favorites'], (old) =>
      old?.filter((g) => g.id !== gameId)
    );
    return { previous }; // попадёт в onError третьим аргументом
  },
  onError: (error, gameId, context) => {
    // 4. сервер отказал — возвращаем как было
    queryClient.setQueryData(['favorites'], context?.previous);
  },
  onSettled: () => {
    // 5. в любом случае сверяемся с сервером
    queryClient.invalidateQueries({ queryKey: ['favorites'] });
  },
});

В исходном конспекте функция обновления написана как (old) => old.filter(...). Если избранное ещё ни разу не загружалось, old равен undefined, и код упадёт. Поэтому здесь стоит old?.filter. А в презентации курса в этом примере пропущены шаги 1 и 5.

5. Выход из аккаунта

При выходе кеш очищают целиком. Иначе следующий человек за этим компьютером может на секунду увидеть чужой профиль или баланс.

function handleLogout() {
  logout();
  queryClient.clear(); // весь кеш удалён
  navigate('/');
}
