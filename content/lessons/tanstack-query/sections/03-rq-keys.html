Ключ запроса (queryKey)

queryKey — это «адрес» данных в кеше. Он всегда записывается массивом. По ключу библиотека:

  • находит уже загруженные данные;
  • решает, можно ли отдать их сразу или нужен новый запрос;
  • понимает, какие данные обновить после изменения на сервере.
['games']                          // все игры
['game', '123']                    // одна игра с id 123
['games', 'slots']                 // игры категории slots
['games', { page: 2, limit: 20 }]  // вторая страница по 20 штук

Ключи сравниваются по содержимому, а не по ссылке. Поэтому ['games', { page: 2 }], созданный в двух разных компонентах, — это одна и та же запись. А ['game', '123'] и ['game', '456'] — две разные.

Главное правило

Всё, от чего зависит ответ сервера, должно быть в ключе. Если запрос использует userId, categoryId и page, все три значения кладутся в массив.

// Плохо: page не в ключе
useQuery({ queryKey: ['games'], queryFn: () => fetchGames(page) });

// Хорошо
useQuery({ queryKey: ['games', { page }], queryFn: () => fetchGames(page) });

В первом варианте при смене страницы ключ не меняется. Библиотека считает, что это те же данные, и показывает первую страницу вместо второй.

Ключи удобно строить от общего к частному: сначала сущность, потом уточнения. Почему это важно, станет видно в разделе про invalidateQueries. Как держать все ключи в одном месте, разобрано в уроке «TanStack Query на реальном коде».
