Подключение: QueryClient и провайдер

Библиотека ставится одной командой:

npm install @tanstack/react-query

QueryClient — это хранилище всех запросов и их ответов, то есть кеш. В приложении он один. В нём лежат данные, статусы и общие настройки.

QueryClientProvider передаёт этот клиент всем компонентам через React Context. Без провайдера useQuery и useMutation не найдут кеш и выбросят ошибку.

import { QueryClient, QueryClientProvider } from '@tanstack/react-query';

const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 60 * 1000, // данные свежие 1 минуту (для всех запросов)
      retry: 2,             // при ошибке повторить 2 раза
    },
  },
});

export function App() {
  return (
    <QueryClientProvider client={queryClient}>
      <Routes />
    </QueryClientProvider>
  );
}

defaultOptions избавляет от повторов: настройку, заданную здесь, получит каждый useQuery. Конкретный запрос всё равно может её переопределить.

Клиент создаётся один раз

Обратите внимание: new QueryClient() стоит вне компонента. Если написать его внутри функции компонента, при каждом рендере будет создаваться новый пустой кеш, и все данные пропадут. Если клиент всё же нужно создать внутри компонента (так делают в Next.js), его кладут в useState(() => new QueryClient()): тогда он создаётся один раз. (из документации TanStack Query)

Стандартные настройки

Если ничего не задавать: staleTime = 0, gcTime = 5 минут, неудачный запрос повторяется 3 раза с растущей паузой, обновление при фокусе окна, монтировании и восстановлении сети включено. Что это значит, разберём дальше.
