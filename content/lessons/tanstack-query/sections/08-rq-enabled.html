enabled, зависимые запросы и select

Опция enabled включает и выключает автоматический запуск. Пока enabled: false, запрос не уходит.

Зависимые запросы

Иногда второму запросу нужны данные первого: например, чтобы загрузить заказы, нужен id пользователя. Без enabled второй запрос ушёл бы сразу с undefined вместо id.

const { data: user } = useQuery({
  queryKey: ['user'],
  queryFn: getCurrentUser,
});

const { data: orders } = useQuery({
  queryKey: ['orders', user?.id],
  queryFn: () => fetchOrders(user.id),
  enabled: !!user?.id, // ждём, пока появится id
});

!! превращает значение в true или false: !!undefined даёт false, !!'42' — true.

select: берём из ответа только нужное

select — функция, которая преобразует данные при чтении. В кеше остаётся полный ответ, а компонент получает только нужную часть. Несколько компонентов могут читать один запрос с разными select, и запрос при этом будет один.

const { data: gameIds } = useQuery({
  queryKey: ['games'],
  queryFn: fetchGames,
  select: (games) => games.map((g) => g.id), // в data будут только id
});

Запрос по кнопке

Иногда запрос должен уйти только после действия пользователя. Классический пример — поиск: не нужно отправлять запрос на каждую букву, только по Enter или кнопке.

Самый понятный способ: хранить отдельно то, что пользователь набирает, и то, что он отправил. В ключ кладём только отправленное.

const [input, setInput] = useState('');  // текст в поле
const [term, setTerm] = useState('');    // отправленный запрос

const { data, isFetching } = useQuery({
  queryKey: ['search', term],
  queryFn: () => searchGames(term),
  enabled: term !== '', // пустой поиск не отправляем
});

return (
  <form onSubmit={(e) => { e.preventDefault(); setTerm(input); }}>
    <input value={input} onChange={(e) => setInput(e.target.value)} />
    <button disabled={isFetching}>Найти</button>
  </form>
);

Пока человек печатает, меняется только input, ключ остаётся прежним, запросов нет. После отправки меняется term, а с ним и ключ, и уходит ровно один запрос. Повторный поиск того же слова возьмёт ответ из кеша.

Чем плохи варианты из конспекта

В конспекте предложены два паттерна, и у обоих в ключе лежит текст поля query, который меняется при каждой букве.

enabled: false + refetch(). Работает: refetch() запускает запрос даже при выключенном enabled. Но с каждой новой буквой ключ меняется, по новому ключу данных нет, и результаты прошлого поиска пропадают с экрана ещё до нажатия кнопки.

enabled: submitted. После первой отправки submitted навсегда остаётся true, и дальше запрос уходит на каждую букву. То есть ровно то, от чего хотели уйти.
