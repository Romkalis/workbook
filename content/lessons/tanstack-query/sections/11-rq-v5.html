Чем v5 отличается от v4

В интернете много статей про четвёртую версию. Код оттуда в пятой часто не работает. Вот главные отличия.

v4v5
useQuery(key, fn, options)useQuery({ queryKey, queryFn, ...options }) — только объект
cacheTimegcTime (garbage collection time — время до удаления)
status: 'loading', isLoading у мутацийstatus: 'pending', isPending
onSuccess, onError в useQueryУбраны (у useMutation остались)
keepPreviousData: trueplaceholderData: keepPreviousData
useInfiniteQuery без начальной страницыОбязательный initialPageParam

Почему убрали onSuccess у useQuery

Колбэк срабатывал на каждый успешный запрос, включая фоновые. Если в нём показывали уведомление, оно выскакивало снова и снова. А если один запрос использовали три компонента, колбэк вызывался трижды.

Для реакции на ошибку в компоненте подойдёт useEffect:

const { isError } = useQuery({ queryKey: ['games'], queryFn: fetchGames });

useEffect(() => {
  if (isError) showToast('Ошибка загрузки');
}, [isError]);

Если уведомление об ошибке нужно для всех запросов сразу, его задают один раз при создании клиента. Этого способа нет в материалах курса, он из документации TanStack Query:

import { QueryCache, QueryClient } from '@tanstack/react-query';

const queryClient = new QueryClient({
  queryCache: new QueryCache({
    onError: (error) => showToast(`Ошибка: ${error.message}`),
  }),
});

keepPreviousData

Когда меняется номер страницы, меняется ключ, и по новому ключу данных ещё нет. Без настройки список на мгновение исчезнет. placeholderData: keepPreviousData оставляет на экране прошлую страницу, пока грузится новая. Подробно разобрано в уроке «TanStack Query на реальном коде».

import { keepPreviousData, useQuery } from '@tanstack/react-query';

useQuery({
  queryKey: ['games', { page }],
  queryFn: () => fetchGames(page),
  placeholderData: keepPreviousData,
});
