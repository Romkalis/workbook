Зачем нужен TanStack Query

В React-приложении живут два разных вида данных, и путать их не стоит.

Состояние клиента существует только в браузере: открыто ли модальное окно, какая вкладка выбрана, что пользователь набрал в поле. Его создаёте вы, и только вы его меняете. Для него подходят useState, Zustand или Redux.

Серверное состояние приходит с сервера: список товаров, профиль, баланс. У него другие свойства:

  • оно хранится не у вас, и его может изменить другой человек или другой процесс;
  • пока пользователь смотрит на экран, данные могут устареть;
  • одни и те же данные нужны в разных компонентах, и запрашивать их каждый раз заново расточительно;
  • у запроса есть состояния: «грузится», «готово», «ошибка».

Как это выглядит без библиотеки

Вот обычный способ загрузить список через useEffect. Уже здесь три useState, а кеша, повторной загрузки и защиты от устаревших ответов ещё нет.

function GamesList() {
  const [data, setData] = useState(null);
  const [isLoading, setIsLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    let ignore = false; // защита от ответа, который пришёл слишком поздно
    fetch('/api/games')
      .then((res) => res.json())
      .then((json) => { if (!ignore) setData(json); })
      .catch((err) => { if (!ignore) setError(err); })
      .finally(() => { if (!ignore) setIsLoading(false); });
    return () => { ignore = true; };
  }, []);
  // ...
}

Если тот же список нужен в шапке и на странице, второй компонент сделает второй такой же запрос. Если пользователь ушёл на другую вкладку и вернулся через час, он увидит старые данные. Всё это придётся дописывать руками.

TanStack Query (раньше назывался React Query) берёт эту работу на себя: хранит ответы в общем кеше, следит за статусами, сам обновляет устаревшие данные и не делает лишних запросов. С ним тот же компонент выглядит так:

function GamesList() {
  const { data, isLoading, error } = useQuery({
    queryKey: ['games'],
    queryFn: fetchGames,
  });
  // ...
}
